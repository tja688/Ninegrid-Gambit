Lesson 0007 · ScriptableObject 玩法

状态栈很好用——但你们用的是正交轴 + 模式

作者的 State Manager SO 用栈表达「选中→移动预览→瞄准」的逐层进入与右键逐层取消。你们把相近问题拆成了：谁拥有输入、主线忙不忙、是否在 BoardSelect、流程壳在哪一相。

作者为什么用 Stack

战棋操作常层层套进：

Selected → Moving → Prepare → Applying
栈顶取消一次 → 回到上一层，并让 Rules 回滚、Visual 重画

对外只暴露 PushState / CancelState / ResetState， 内部 Stack + 进入/取消事件。适合「菜单式返回」与「预览可撤销」。

取消不只是改 transform： 可能还要恢复逻辑坐标、占格、行动点、临时路径——所以回滚在 Rules，不在 Visual。 （你的总结第七、十四节。）

你们没有一份「战斗操作栈 SO」，但有四类相近物

作者栈要表达的 NineGrid 落点
现在谁在交互 CurrentOwner（ProtectedField / Overlay / Opening / BoardSelect）
现在能不能再点主线动作 MainlineBusy（与所有权正交，ADR-0004）
进入一层可取消的选目标模式 BoardCardSelectModeController Begin / End / RequestAbort
宏观流程在哪一相 GameFlowShellState（MainMenu / Battle / RoomChoice…）
关键差别： 作者常把「交互层」压成一条栈； 你们把「谁拥有输入」和「主线忙」做成两轴，避免 Busy 与 Owner 缠成一种伪状态机。 BoardSelect 更像压入一层模式；Esc/停泊点击 Abort 像 Cancel 一层——但是局部模式，不是全局 PlayerRound 栈。 
// 进入选卡模式前先过 Intake（像申请进栈）
intake.Submit(BoardSelectBegin, ProtectedField, ...);
PresentationInputGates.SetBoardSelect(true);

// 取消
RequestAbort(reason) → SelectionAbortedAsync → End() 清门禁

对照：取消一次发生什么

State Manager Cancel BoardSelect Abort / 门禁复位
状态结构 Pop 栈顶，恢复下层 结束模式、清 SelectedUids、SetBoardSelect(false)
业务回滚 RulesModel 撤销预览影响 Abort 回调里回手 / 不提交 UseItem 等
表现恢复 听 OnStateEntered(下层) 会话/Presenter 按 Abort 路径清预览
全局形态 一份栈 SO 管整段回合操作 模式对象 + 两轴 + 壳相位，分散但可测

若给 NineGrid 加作者那种栈

适合加在哪里？

  • 较适合：未来若有「移动预览 → 技能瞄准 → 确认」多层可撤销 UI，且要右键逐层退
  • 不适合取代：MainlineBusy（互斥真相）、GameFlowShellState（宏观相位）、Core 占格
  • 形态：可以是普通 C# 栈（System 持有），不必是 StateManager.asset——除非你真要 Inspector 可视化栈
不要用栈冒充两轴： 「Busy」不是「Selected 的下一层」。 把互斥推进栈，会重新制造 ADR-0004 想拆掉的缠绕状态机。

优点 / 缺点（状态层）

State Manager 栈 两轴 + 模式 + 壳相位
逐层取消手感 非常自然 要在各模式里各自实现 Abort
概念清晰度 一种结构打天下（也易滥用） 轴正交，语义硬，学习曲线在 ADR
与规则回滚 约定 Cancel → Rules Abort 回调显式接会话 / Core
可视化 栈可做 SO 调试 靠日志 / 测试 / 调试窗
