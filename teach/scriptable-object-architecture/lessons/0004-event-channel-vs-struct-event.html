Lesson 0004 · ScriptableObject 玩法

Event Channel：广播「发生了一次」

Field 回答「现在是什么」；Event 回答「刚才发生了什么」。你们仓库里连注释都写过这句——本课把它和作者的 Channel SO 对齐。

先收半寸上一句

「带通知的资产 SO」对；更贴的说法是： 带通知的共享当前事实（载体刚好是资产）。 本课的 Event 也常是资产，但通常不保存当前值。

作者怎么玩

class AbilityEventChannelSO : ScriptableObject {
  event Action<AbilityDataSO> Raised;
  void Raise(AbilityDataSO ability) => Raised?.Invoke(ability);
  void Register(...) / Unregister(...);
}

技能按钮、快捷键、教程都可以 Raise； 范围、说明、消耗预览各自 Register。 发送者不知道监听者是谁——经典发布/订阅，通道是一份可拖的 Event Channel SO。

和 Field 的判据（作者总结原话精神）：
「玩家点击了火球术」→ 事件频道
「当前选中的技能是火球术」→ Field SO
晚加入的监听者：Event 可能已错过；Field 还能读到 Value。

别把 Hook 当成 Event Channel： AttackInputHook.WireController 是 Cards↔Presentation 的装配缝； code-map 写明禁止新增业务静态 Sink。 作者的 Channel SO 承担的是「业务/表现广播」；你们把广播放在架构 SendEvent，把装配缝单独叫 Hook。

动手：三分类

Field / Event / Hook——点选归类。

若用 Event Channel SO 重做你们的事件

  • 每个 struct XxxEvent 可改成一个 XxxEventChannelSO 资产
  • 优点：Prefab 可在 Inspector 选频道、跨场景拖拽复用、Hipple 式可调试列表
  • 代价：频道数量膨胀；重命名方法/签名易弄断 UnityEvent；调用链藏 Inspector
  • 与你们现状：类型即频道，IDE 能 Find All References；结构测试更好扫
Event Channel SO struct Event + 架构总线
发现调用方 弱（看谁拖了资产 / UnityEvent） 强（类型引用）
设计师接线 强 弱（代码订阅）
错过事件 一样会错过（不存当前值） 一样；需要当前值就配 Field/Bindable
与 Field 分工 必须自觉拆 你们已有「属性 + ChangedEvent」先例

经典原型：Hipple GameEvent — Unite2017 样例 / 讲座。
