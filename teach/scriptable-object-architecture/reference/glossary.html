Reference · Glossary

术语表

本课与后续课共用的词汇。左右对照时，优先用这里的定义，避免把「MVC」当万能标签。

职责拆分

把输入、规则、状态、事件、表现分成不同对象/模块。SO 玩法与 NineGrid 都做这件事。它本身不等于「用了 ScriptableObject」。

资产接线

多个 Prefab / 场景对象通过引用同一个 .asset 来共享状态或事件，从而解耦。这是 SO 玩法相对你们组合根装配的独特手段。

配置 SO

相对稳定的数据资产（技能伤害、特效参数、遭遇配置）。通常不持有战斗中的「当前选中」这类运行时事实。NineGrid 大量已有（如 CardEffectSO）。

Field SO

带读写与变化通知的共享变量资产（「当前选中技能」）。表达的是当前事实，不是「刚刚发生了一下」。

Event Channel SO

通常不保存当前值，只 Raise / Register。表达「发生了一件事」。经典原型见 Hipple 的 GameEvent。

Rules Model SO

作者扩展层：把业务规则做成可引用的 SO 服务（合法性、应用、回滚）。功能上靠近你们的 Core + Intake，形态上是资产而非程序集内 System。

Bridge

场景侧 MonoBehaviour：吃 Unity 生命周期 / 输入 / 动画事件，转发到规则或事件。对应你们的 Controller / HitProxy / 部分 Hook。

Composition Root

NineGrid：PresentationCompositionRoot.Install —— 唯一生产装配入口，用代码把 System / Controller 与场景绑定接到一起。

IntentIntake

NineGrid 输入唯一收口（ADR-0004）：两轴门禁（MainlineBusy × 输入所有权）后再进编排。功能角色接近「所有 Bridge 必须经过的规则门」，实现不是 SO。
