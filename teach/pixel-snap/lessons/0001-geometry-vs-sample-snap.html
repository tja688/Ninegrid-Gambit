Lesson 0001 · TableNine Pixel Snap

为什么关全屏 snap、改材质 snap，字就清晰了

你已经亲眼看见效果。本课只钉死一件事：snap 发生在几何还是采样——这决定它打不打到 TMP。

先记住一句话

Sprite 要的是「方块落在整像素上」；SDF 文字要的是「边缘仍能按亚像素采样」。 全屏 UV snap 把第二种也干掉了；顶点 snap 只做第一种。

两条管线，打在不同的东西上

你们仓库里其实同时存在过两种 snap（现在全屏那条默认关着）：

  1. 采样吸附 — SelectiveLook Pass1 用量化 UV 重读整屏颜色： 
    float2 snapped = (floor(uv * res) + 0.5) / res;
return tex2D(_BlitTexture, snapped);
    卡面、文字、特效……凡是已经画进颜色缓冲的，一律被「按格重采样」。
  2. 几何吸附 — Sprite 材质在顶点阶段把 clip 坐标折到 960×540 格： 
    ndc = positionCS.xy / positionCS.w;
pixel = (ndc * 0.5 + 0.5) * res;
snapped = floor(pixel) + 0.5;
// 写回 positionCS.xy
    只移动这个 mesh 的四个角。TMP 用另一套材质，根本不进这个函数。

对应代码： TableNineSelectiveLook.shader Pass1； TableNinePixelSnapVertex.hlsl。

为什么小字灾难？ TMP 的 SDF 把字形边缘存在距离场的灰度渐变里，靠连续采样做出 AA （见 TMP · About SDF fonts）。 全屏 UV snap 等于把已经画好的细边缘，再按低分辨率格「取一个代表色填一整块」——笔画宽度只有几个屏幕像素时，边缘信息直接被踩碎。
为什么卡面还行？ 像素卡面的「硬边」主要来自 nearest 贴图本身。把四边形顶点吸到像素格，减少的是整张牌在亚像素上左右蹭造成的抖边； 它没有去量化已经画好的 framebuffer，所以不会误伤旁边的字。 Unity 的 Pixel Perfect Camera 也把 Pixel Snapping 描述为渲染时对齐、不改 Transform （PPC 参考）——同属「对齐几何」，不是「压扁整屏」。

动手：同一亚像素偏移，两种 snap

拖亚像素滑杆，分别开关两种 snap。目标：左栏 Sprite 变稳，右栏字边缘在 UV snap 打开时明显变糊。

和 Godot「取经」到底取了什么

Lost For Swords / Godot 4 的常见做法是变换或顶点对齐到像素 （项目设置 snap_2d_transforms_to_pixel，见 ProjectSettings）， 而不是用一张全屏 shader 把颜色缓冲量化。CRT grille 可以打在文字上——糊的元凶几乎总是破坏性 snap。

你们落地的同构版：LookRig.pixelSnap = 0（全屏关）+ spritePixelSnap = 1（材质开）+ TMP 继续用自己的材质。扫描线仍可全屏。
