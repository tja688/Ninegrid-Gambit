# 音频与特效内容真源（NineGrid.Content · Audio + Vfx）

> 覆盖范围：`Audio/` 全部 6 文件、`Vfx/` 全部 16 文件。
> 运行时消费方在 `NineGrid.Presentation`（`AudioSystem` / `MusicSystem` / `VfxSystem` 与各播放器）；编辑器作者工具见 [05](./05-内容编辑器与卫生工具.md) / [06](./06-编辑器工作台体系.md)。

## 职责综述

按 ADR-0036 / ADR-0040 的四层组织（稳定语义声明 → 持久化绑定 → 运行时播放 → 诊断与工作台），本子域承载其中「持久化绑定」与「素材真源」两层的**数据模型与解析规则**：业务代码只发稳定的声音提示（Audio Cue）/ 视觉特效提示（VFX Cue）或提交唯一期望状态（音乐状态 / 视觉槽状态），**不选素材**；「响不响、放什么、怎么放」由 JSON 绑定表回答。本层全部是纯数据 + 解析逻辑，不含播放实现。

三份运行时 JSON 真源（均在 `Assets/Resources/` 下、随包发布，Save 即写正式文件、无本机第三层覆盖）：

| JSON | Resources 键 | 模型 |
|------|------|------|
| `Assets/Resources/audio/audio_bindings.json` | `audio/audio_bindings` | `AudioBindingCatalog`（SFX 提示绑定） |
| `Assets/Resources/audio/audio_music.json` | `audio/audio_music` | `MusicBindingCatalog`（BGM 状态绑定） |
| `Assets/Resources/VFX/vfx_bindings.json` | `VFX/vfx_bindings` | `VfxBindingCatalog`（cueBindings[] + stateBindings[]） |

音频素材唯一正式根 `Assets/Resources/audio/`（BGM/ SFX/ 子目录），配 `audio_manifest.json` 固定清单；特效素材帧经 `visual_effects.json` 索引 + ContentArt Resources 根解析。

## 核心流程与数据流

### SFX 提示解析（AudioCue → 播放决策）

```
业务/表现代码：TriggerPulseHub 发 AudioCueRequest（cueId + 稳定上下文）
   ▼
AudioBindingCatalog.TryResolve(request)
   ├─ 过滤：CueId 精确相等 且 五维选择器全部「空或相等」
   └─ 择优：SelectorSpecificity（非空选择器个数）最高者；同分取**靠后**条目（后写覆盖前写）
   ▼
AudioBinding：clipKey（或 variants 随机音频池，独立随机源、不消费 Core RNG）、
volumeDb、startOffsetSeconds（音频起播点，只跳素材内部前导，不允许负延迟）、
bindingDelaySeconds（对齐表现的必播延迟）、minimumIntervalSeconds（频率窗）、enabled
   ▼
Presentation AudioSystem → MMSoundManager Adapter 实际播放
```

覆盖解析语义即 ADR-0036 的「联合内容标识 → 单一内容标识 → 基础提示」：基础绑定（无选择器）打底，内容专属覆盖靠选择器特异性取胜。`enabled=false` 命中即 `Suppressed`（可观察静音，不选变体不播放）。`TryFromJson` 是**严格**解析（空/坏 JSON、null bindings 失败且不产出 catalog）——工作台热应用必须走它，防止坏补丁静默换成空表；`FromJson`/`LoadFromResources` 是运行时容错版（失败给空表）。

### BGM 状态解析

流程层提交 `MusicStateRequest`（`DesiredMusicState` + 必填 stableSource 来源标识）；`MusicBindingCatalog.TryResolve` 按 state **从后往前**取第一条（同 state 后行覆盖前行）。切歌代数、淡出收口、幽灵 BGM 审计全部在 Presentation 的 Music 模块，本层只有数据。BGM 不走 Cue 脉冲、不参与工作台 live 热换（预览+保存）。

### 音频素材真源纪律

`AudioAssetPaths.FormalRoot = Assets/Resources/audio`（BGM/SFX 两子根）；manifest（`audio_manifest.json`）由 Editor 迁移/卫生工具生成，运行时 `AudioAssetManifestLoader` 只按固定 Resources 键查询（`IsKnownFormalKey` 供绑定校验），**从不扫目录**。legacy 根（`Arts/audios`、`Arts/音频`）与隔离区（`AudioQuarantine`、路径含「拒绝用」）常量供 Editor 迁移工具与卫生校验识别边界。

### VFX 提示/状态解析

与 Audio 同构但 DTO 独立（ADR-0040：只共享确实载体无关的基础设施，不抽万能 Effect 框架）。差异点：

- 绑定分两类：`cueBindings[]`（一次性 Pulse）与 `stateBindings[]`（持续视觉状态，`owner+slot+state` 语义在运行时层，绑定里带 `exitMode`（immediate/有限退出段）与 `exitLoopLimit`）。
- 每条绑定声明 `playerId`（稳定播放器）与 `spatialOwnership`（attached/independent，缺省 Cue=independent、State=attached）。
- **Strict 解析**（`TryResolveCueStrict`/`TryResolveStateStrict`）在同 identity 同特异性多条命中时报 `Ambiguous`（带冲突双方 BindingKey）——这是显式错误（ADR-0040「未绑定、非法绑定是显式错误」），宽松版（运行时快路径）则取靠后条目。
- `VfxSelectorRules.SelectorsCanBothMatch` 供 Editor 卫生校验预判「两条绑定可能同时命中」的覆盖冲突。

### 播放器与素材解析

`VfxPlayerRegistry` 首版四播放器：

| playerId | 类型 | materialKey 语义 | Pulse | State |
|---|---|---|---|---|
| `sprite-sheet` | 素材型 | `visual_effects.json` 条目 id 或直接资产路径 | ✓ | ✓ |
| `gold-flight` | 程序化（金币飞入，#203） | 不用 | ✓ | ✗ |
| `particle` | 程序化（Shuriken 运行时装配） | `VfxParticlePresetIds` 预设 ID | ✓ | ✓（仅 `particle.loop.*`） |
| `projectile` | 程序化（源→靶弹道） | `VfxProjectilePresetIds` 预设 ID | ✓ | ✗ |

素材型播放器可被绑定调参并按 `paramOverrideWhitelist` 显式覆盖（`AllowsParamOverride` 白名单：materialKey/fps/speed/scale/startOffsetSeconds/timeBase/tint 四通道）；程序化播放器自治算法与内部参数，总控只校验 playerId、能力位、空间所有权（ADR-0040「不伪造万能参数 schema」）。粒子/弹道预设的**发射参数本体**在表现层 `VfxParticlePresetLibrary` / `VfxProjectilePresetLibrary`，与本层 ID 表以契约测试一一对应。

素材帧加载：`VfxMaterialFrameSource.TryLoadFrames(materialKey)` → 查 `VisualEffectCatalog` 拿 sheetPath（查不到则把 key 直接当路径）→ `CardPresentationContentArt.TryGetResourcesRelativeKey` → `Resources.LoadAll<Sprite>` → `VfxSpriteSheetFrameOrder.CompareNames` 排序保证帧序确定。**索引的 defaultFps/defaultScale 不合并进播放**——播放参数只来自绑定。

### 空间上下文

发射方构造 `VfxSpatialContext`：`SemanticRole`（语义角色）+ 可选 `IVfxDomainHost`（附着型宿主：金币 HUD 域宿主等实现在表现层）+ `PositionSnapshot`（发射时位置快照）+ `TargetPositionSnapshot`（弹道终点，2026-08-12 增）+ `Amount`（语义数量，如金币增量）。运行时身份只用于本次定位与生命周期，**不进绑定主键**——这是绑定可持久化、可跨会话复用的关键约束。

## 对外通信面

- **入**：三份 Resources JSON + `audio_manifest.json`；Editor 工作台经 `TryFromJson` 热应用工作副本。
- **出**：`AudioBinding` / `MusicBinding` / `VfxCueBinding` / `VfxStateBinding` 值对象，供 Presentation 的 `AudioSystem` / `MusicSystem` / `VfxSystem` 消费；`BindingKey` 是编辑器 Play Mode 定位与历史聚合的稳定键。
- 结构护栏（Presentation 侧 EditMode 测试强制）：业务代码不得直调 AudioKit/MMSoundManager、不得裸拼 `sfx.effect.<uid>` 动态绑定键；VFX 播放失败不播回退表现、必须留可归因错误且不阻断主线。

## 关联 ADR

ADR-0036（声音提示绑定、调音真源、唯一音乐状态、作者态/玩家音量分权）、ADR-0040（VFX 绑定单一真源、Attached/Independent、Persistent Slot、程序化播放器自治、金币迁移）、ADR-0008（单一 Resources 根原则的延伸）、ADR-0007/0018（表现消费与可见时序，运行时侧约束）。

## 不变量与坑

- **五维选择器是全部合法维度**：cardDefId/skillId/roomId/itemDefId/contentId，精确相等匹配（无通配/前缀）；运行时 UID、坐标、Transform 永不入键。
- **同特异性并列的行为分叉**：宽松解析取靠后条目、Strict 解析报 Ambiguous——作者工具用 Strict 暴露冲突，改绑定表后跑 VFX 卫生校验（`VfxBindingCatalogHygieneValidator`）。
- Audio 与 Vfx 的 Request/BindingKey/AuthoringStatuses 是**刻意的同构双份**，不要「顺手」抽公共基类（ADR-0040 明说不做万能 Effect 框架）。
- `AudioBindingCatalog.TryFromJson` 接受合法空数组 `bindings:[]`（成功装空表），但 `bindings:null` 失败——工作台清空绑定是合法操作，坏 JSON 不是。
- `VfxBindingPlayback.ResolveTint` 把「四通道全 0」当成「未配置→白色」——想要真正的全透明黑需至少给 alpha 一个极小非零值（作者侧注意）。
- `particle.loop.*` 预设只准配 State 绑定、其余只准 Pulse（`IsLoopPreset`；卫生校验强制）；projectile 全部预设无 State 形态。
- `startOffsetSeconds` 是音频/动画**素材内部**起读点，不是负延迟、不表示相对事件提前播（CONTEXT「音频起播点」）。
- BGM `MusicBindingCatalog.FromJson` 全容错（坏文件→空表静默），没有 Strict 版；BGM 缺绑定的症状是「不切歌」，查表内容而非解析代码。
