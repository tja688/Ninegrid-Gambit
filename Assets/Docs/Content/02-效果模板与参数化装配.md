# 效果模板与参数化装配（NineGrid.Content · 效果链路与描述契约）

> 覆盖范围：`Catalog/EffectTemplateCatalog.cs`、`Catalog/EffectAssemblyResolver.cs`、`Catalog/EffectDesignTextParameterizer.cs`、`CardPresentation/CardDescriptionTokenRules.cs`。
> 上游：一卡一文件 JSON 的 `effectAssemblies` 字段（见 [01](./01-内容目录与加载链路.md)）；下游：Core `EffectSystem` 消费 `ContentEffectDefinition`。

## 职责综述

ADR-0009 把效果从「卡专属具名一次性实例」改成「**参数化模板 + 卡上装配引用**」：模板（`effect_templates.json`）描述一类效果诉求与占位参数（`{{amount}}` 等），卡 JSON 里一条 `EffectAssemblyDto` 给出模板 id 与实参。本子域负责：模板表加载、模板+实参 → 可执行效果定义的解析、模板作者文案的参数化显示，以及玩家可见描述里 `{装配id.键}` 令牌的强契约校验（ADR-0035）。

效果的适用边界由模板 `requires`（适用声明）与 body 内 `conditions`（玩法条件）**自陈**（ADR-0010）——本层只做搬运与替换，不做任何容器门禁（`typeTag`/`verb` 校验已在 ADR-0009 取消；旧 `EffectOwnerScopeGate` 已删除）。

|------|------|------|
| `EffectTemplateCatalog` | `Catalog/EffectTemplateCatalog.cs` | `effect_templates.json` 静态缓存：id → `EffectTemplateDefinition`；`Invalidate()` 由 Bootstrap 调用 |

| `EffectDesignTextParameterizer` | `Catalog/EffectDesignTextParameterizer.cs` | 把模板 `design_text` 里的预设字面量（阿拉伯/中文数字）换回 `{param}`，避免编辑器展示被 peer 实参数值误导 |
| `CardDescriptionTokenRules` | `CardPresentation/CardDescriptionTokenRules.cs` | ADR-0035 描述令牌契约纯函数：`{装配id.键}` 唯一式、`projectKey` 限定式、描述格 ≤26 计量 |

## 核心流程与数据流

### 模板表 schema（`effect_templates.json`）

每行：`id`（模板主键，如 `tpl.trap.flame.move`）、`state`（`ContentImplementationState`，缺省 RawDesignOnly）、`design_text`（作者备注，不进玩家右键详述——ADR-0037 后详述改词条行）、`requires_json`（字符串数组，适用声明）、`conditions_json`（字符串数组，玩法条件自陈，通常与 body 内 conditions 对齐，供未触发探查 #72）、`body`（效果 DSL JSON 字符串，含 `{{name}}` 占位符）。

### 装配解析（`EffectAssemblyResolver.Resolve`）

```
EffectAssemblyDto { id, templateId, containerType, argsJson }
   │  ParseArgsJson：argsJson → 大小写不敏感 Dictionary<string,object>
   ▼
SubstitutePlaceholders(body, args)
   ├─ 先替换 "{{key}}"（带引号形态）→ 类型化 JSON 字面量（数字不带引号、bool、字符串转义）
   └─ 再替换裸 {{key}} → 去引号字面量
   ▼
HasUnresolvedPlaceholders？ 有剩余 {{ → FormatException（装配缺参是硬错误，不静默）
   ▼
EffectJson.Parse（Core 侧 DSL 解析器）→ body 对象
   ├─ 剔除身份键：id / typeTag / verb / containerType / requires（模板不得走私身份）
   ├─ 注入 root["id"]=mountId、root["containerType"]、root["requires"]=模板 Requires
   ▼
EffectJsonWriter.Write → 最终效果 JSON
   ▼
new ContentEffectDefinition(mountId, containerType, json, template.State, template.DesignText)
   → GameContentCatalog.AddEffect（由 ContentJsonCatalogProjector 调用）
```

要点：**无模板默认值间接层**——body 里每个 `{{name}}` 都必须被实参填上，这是「一卡一文件看得全」的执行面；`containerType` 由装配声明（Unknown 即拒绝），仅作分类/检索，不再是运行时准入门禁。

辅助 API：`ExtractPlaceholderNames`（去重保序抽占位名）、`SuggestArgsJson`（装配 UI 用：优先复用同模板 peer 实参，否则按占位名生成最小 JSON，数值键默认 0——数值键白名单 `value/amount/delta/count/weight/every/threshold/min/max/slot`）。

### 作者文案参数化（`EffectDesignTextParameterizer`）

编辑器展示模板时，`design_text` 里往往写着某个 peer 卡的具体数值（「造成 10 点伤害」）。`Parameterize(designText, bodyJson, args)` 把与占位参数对应的字面量换回 `{name}`：

- 只处理**数值键**（同上白名单）；标识类键（`reason/cause/source/actor/defId/kind/zone/stat/op/atom/…`，`IsOpaqueArgKey`）不替换。
- 实参有非零值时按值找字面量：阿拉伯数字 + 中文数字「一…十」+「两」；替换只发生在 `{}` 之外（`ReplaceFirstOutsideBraces`），长字面量优先。
- 找不到对应字面量的参数按占位顺序「吃掉」文案里剩余的数字：优先阿拉伯数字；中文数字只在后跟量词（点/金/次/层/张/个/枚）时才算（避免把「一张」「格三」误判）。
- `JoinBriefs`：多条装配简要描述用「；」拼接（自动卡面描述用途）。

这是**显示层启发式**，不改 JSON 本体；卡面正式文本仍由人手写（ADR-0009 #4）。

### 描述令牌契约（`CardDescriptionTokenRules`，ADR-0035）

范围：`kind ∈ {Trap, Relic, HelpCard}` 且非归档（`deck.relic_archive`/`deck.help_archive`）。范围外恒返回空错误列表。校验点：

1. 每条装配必须有稳定 `id`（描述引用的锚）。
2. `description` / `faceIntro` 中的 `{token}` 必须是 `{装配id.键}` 限定式：限定符精确等于本卡某条装配 id（大小写不敏感），键必须真实存在于该装配 `argsJson` 实参——简单式 `{value}`、defId 前缀式、templateId 限定式全部报错。
3. 实参含 `projectKey`（倒计时投影令牌键，#156）时，其值必须是「**本装配id**.键」限定式（倒计时剩余经 `EffectCountdownChanged` → Settled 提交到机关 `ActionCount` 槽或遗物栏计数 TMP，描述本体恒静态）。
4. 描述格：`CountUnits` 把普通字符、每个 `{…}`、每个 `[…]`、每个 `[[…]]` 各计 1 格（`[[…]]` 优先于单括号，未闭合括号按 1 格继续）；`description` 与 `faceIntro` 各自硬上限 **26**。

消费方：`ContentHygieneValidator.ValidateDescriptionTokenContract`（磁盘全量扫）与 EditMode 边界测试共用同一纯函数。

### 实例（`trap_flame.json`）

```json
"description": "每移动{trap.flame.move.every}次，对[adjacent]的玩家造成{trap.flame.move.amount}点伤害，{trap.flame.remove.every}次后[death]",
"effectAssemblies": [
  { "id": "trap.flame.move",   "templateId": "tpl.trap.flame.move",   "containerType": "Trap", "argsJson": "{\"amount\":1,\"every\":1}" },
  { "id": "trap.flame.remove", "templateId": "tpl.trap.flame.remove", "containerType": "Trap", "argsJson": "{\"reason\":\"trap.flame\",\"every\":3,\"projectKey\":\"trap.flame.remove.every\"}" }
]
```

描述里三个令牌分别指向两条装配的实参；`projectKey` 限定符 = 本装配 id `trap.flame.remove`；`[adjacent]`/`[death]` 是词条表内联图标（ADR-0037，表现层解析，本层只计格）。

## 对外通信面

- **入**：`effect_templates.json`（经 `ContentCatalogTableLoader.ResolveTablesDirectory`）；卡 JSON `effectAssemblies`。
- **出**：`ContentEffectDefinition` → `GameContentCatalog.Effects` → Core `EffectSystem`（DSL 原子执行、requires/conditions 分诊、`ProbeWhyNotTriggered` 探查）。
- 编辑器消费：`EffectTemplateEditorIO`（Editor 程序集，模板表读写）、卡牌表现编辑器「效果装配」栏（`SuggestArgsJson` / `Parameterize`）。

## 关联 ADR

ADR-0009（参数化模板；本子域是其存储与解析形态）、ADR-0010（责任自陈；Requires/Conditions 两栏的由来与诊断分级）、ADR-0035（`{装配id.键}` 唯一化、描述格 26、`projectKey` Settled 提交）、ADR-0037（`[[词条]]` / `[code]` 括号语法；本层只负责计格不负责渲染）、ADR-0008（模板表的磁盘位置与加载方式）。

## 不变量与坑

- **缺参即抛**：`Resolve` 对未填占位符抛 `FormatException`；上游 `ContentJsonCatalogProjector` 捕获后 LogWarning 跳过该效果——症状是「卡在、效果不响」，排查先看 Console 的 `Failed resolving` 告警。
- 占位符替换是**纯字符串替换**：`"{{amount}}"`（带引号）先于裸 `{{amount}}`，数值实参会正确落为 JSON 数字；但若模板把同一占位名用在字符串和数字两种上下文，靠的是这套顺序，不要在模板里玩花活。
- 身份键剔除（`IsIdentityKey`）意味着模板 body 里写 `id`/`requires` 等会被**静默丢弃**并以模板表/装配声明为准。
- `design_text` 编码历史遗留：表内早期行的中文在某些工具下显示乱码（GBK 写入历史）；`EffectTemplateCatalog` 按 `File.ReadAllText` 默认 UTF-8 读，作者备注仅编辑器展示、不进玩家界面，影响有限但新写入应统一 UTF-8。
- `requires` 与 `conditions` 诊断级别不同（装配错误 vs 正常玩法），模板作者两栏都要如实填；`conditions_json` 目前主要供探查 API，运行时真正判定在 body 内。
- 描述令牌契约只约束「玩家可见数字」，`[…]` 图标与 `[[…]]` 词条的**存在性**不在本层校验（词条表匹配在表现层）。
- 数值键白名单在 `EffectAssemblyResolver.IsNumericArgKey` 与 `EffectDesignTextParameterizer.IsNumericArgKey` **各有一份**（内容相同）——新增数值键要两处同步。
