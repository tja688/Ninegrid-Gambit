# 内容目录与加载链路（NineGrid.Content · Catalog 主链路）

> 覆盖范围：`Assets/Scripts/NineGrid.Foundation/NineGrid.Content/Catalog/` 中的目录装配、表加载、遭遇牌组、主题卡组契约与卫生校验；`ContentAssemblyMarker.cs`。
> 关联文档：[02-效果模板与参数化装配](./02-效果模板与参数化装配.md)、[03-卡面表现JSON与视觉目录](./03-卡面表现JSON与视觉目录.md)。

## 职责综述

`NineGrid.Content` 是**内容运行时层**：把磁盘上的内容数据（一卡一文件 JSON + tables JSON）投影成规则核可消费的纯 C# `GameContentCatalog`（定义在 `NineGrid.Core.Content`，因 Core `noEngineReferences: true` 不能直接读盘/引 UnityEngine，本程序集就是那层「源 → Catalog」投影）。设计决策见 ADR-0008（一卡一文件 JSON 是内容唯一权威，废除 Luban，Resources 加载）与 ADR-0009（效果参数化模板 + 装配引用）。

内容数据本体在两处磁盘目录，互为镜像：

| 目录 | 角色 |
|------|------|
| `Assets/Arts/ContentVisual/cards/*.json` + `_index.json` | **Authoring 权威**（编辑器写入源；Editor 下优先读取） |
| `Assets/StreamingAssets/ContentVisual/cards/*.json` | 运行时（Player）副本，须与 Authoring **字节一致** |
| `Assets/Arts/ContentVisual/tables/*.json`（Editor）/ `StreamingAssets/ContentVisual/tables/`（Player） | 表 JSON：`effect_templates.json`、`reward_pools.json`、`economy.json`、`node_deck_rules.json`、`monster_decks.json`、`visual_effects.json`（另有 legacy `effects.json`、`reward_entries.json`） |

## 核心流程与数据流

### 全链路（JSON 磁盘 → 索引 → 运行时目录 → 消费方）

```
Assets/Arts/ContentVisual/cards/*.json  (一卡一文件, Authoring 权威)
        │  字节镜像（编辑器保存时双写）
        ▼
Assets/StreamingAssets/ContentVisual/cards/*.json  (Player 运行时副本)
        │
        │  CardPresentationConfigCatalog.EnsureLoaded()
        │  （Editor: 先 Arts 后 Streaming 补缺；Player: 只读 Streaming；见 03 篇）
        ▼
CardPresentationConfigDto 内存目录（contentId → DTO）
        │
        │  ContentCatalogBootstrap.Load()
        │    ① Invalidate（CardPresentationConfigCatalog / EffectTemplateCatalog /
        │       MonsterDeckTableCatalog 三个静态缓存；Disable Domain Reload 下必须重读盘）
        │    ② ContentCatalogTableLoader.ApplyToCatalog —— 表 JSON
        │    ③ ContentJsonCatalogProjector.ApplyToCatalog —— 逐 DTO 投影
        │         卡（HelpCard/Monster/Trap/Item…）→ Catalog.Cards
        │         Skill → Catalog.Skills；Relic → Catalog.Relics；Room → Rewards.Rooms
        │         effectAssemblies → EffectAssemblyResolver.Resolve → Catalog.Effects（见 02 篇）
        │    ④ MonsterDeckCatalogBuilder.ApplyToCatalog —— monster_decks.json 行 +
        │       卡面 deckId 归属 → Catalog.MonsterDecks
        │    ⑤ RewardPoolQueryExpander.ExpandAll（NineGrid.Core 侧）—— 查询规则展开为奖池条目
        ▼
GameContentCatalog（纯 C#，无 UnityEngine 依赖）
        │
        ▼
消费方：NineGrid.Core（ContentSystem.CreateDraft 造卡、RewardSystem 发牌/奖池、
        RunModel 层主题绑定）；NineGrid.Presentation（卡面装配、描述投影、店/奖/鉴预览）
```

`_index.json` 是 cards 目录的**磁盘快照索引**（`schemaVersion` + 升序 `contentIds[]`）。运行时加载**不依赖**索引（`CardPresentationConfigCatalog` 直接扫目录）；索引的作用是给卫生校验与外部工具一个可比对的清单。导出索引必须扫盘、不得由编辑器会话状态合成（#140，历史上曾因漏抄漂移）。

### 表加载细节（`ContentCatalogTableLoader`）

- `ResolveTablesDirectory()`：Editor 下若 `Assets/Arts/ContentVisual/tables` 存在且含 `effect_templates.json`（或 legacy `effects.json`）则用它；否则回退 `StreamingAssets/ContentVisual/tables`。**全程序集所有表加载器共用此解析**（EffectTemplateCatalog / MonsterDeckTableCatalog / VisualEffectCatalog）。
- 所有表 JSON 都是**顶层数组**，用 `"{\"items\":" + raw + "}"` 包一层再走 `JsonUtility`（JsonUtility 不支持顶层数组）。
- `reward_pools.json`：每行 `id` + `pick_count`，`kind` 非空时构造 `RewardPoolQueryRule`（稀有度白名单与权重、role 白名单、tags_any、`BalanceMinAttack/Defense` 均衡下限、default_weight）——这是 ADR-0009「156 条白名单塌缩成 9 条查询规则」的落点；实际展开由 Core 侧 `RewardPoolQueryExpander` 在 Bootstrap 末尾执行。
- `reward_entries.json`：legacy 白名单，文件存在才合并（生产以查询规则为主）。
- `economy.json`：取 `id=="default"` 行（否则首行），写 6 个经济常数（怪物移除金、未用道具金、跳过道具/遗物选择金、遗物丢弃金、商店删卡金）。
- `node_deck_rules.json`：每行 `node_index` + `seq1..seq5` 抽卡张数 → `NodeDeckRule`（节点 4 / 7 非战斗，表中无行）。

### 卡投影细节（`ContentJsonCatalogProjector`）

- 准入：`contentId` 非空且 `schemaVersion >= 2`（`MinSchemaVersion`）。
- kind 解析：`HelpCard`/`Help`、`Monster` 显式；其余走 `Enum.TryParse<CardKind>`，**Relic 被显式排除在 Cards 之外**（走 `TryProjectRelic`）；`Skill` → `SkillContentDefinition`（`containerType` 缺省 MonsterSkill）；`Room` → contentId 必须能解析成 `RoomKind` 枚举（Shop/Fountain/Boss…），带 `weight`/`rewardPoolId`/`shopOfferCount`/`openingInjects`。
- 怪物专项：`gold` → `KillGold`（其它卡种 → `Price`）；`level` 只认「层主 / FloorBoss / Boss」→ `MonsterRank.FloorBoss`，其余 Normal；`attackPattern` 解析失败**保持 `Unspecified` 交由 `ValidateCatalog` 报错**（不得静默当「无」，ADR-0011）；节奏 `rhythmSource`+`rhythmPeriod`（period 缺省镜像 `stats.action`），缺源同样保持 Unspecified 交校验报错（ADR-0038，禁止静默沿用旧 3/5）。
- `DetectSyncRhythmSkills`：扫本卡与所挂技能的装配模板 body 是否含 `OnCardRhythmFire` 字符串 → `WithSyncRhythmSkills`，供卡面「是否有技能同步触发」图标。
- 效果挂载 `ApplyEffectMounts`：优先 `effectAssemblies`（每条把 `assembly.id` 记入 EffectIds，并经 `TryResolveAssemblyIntoCatalog` 解析模板+实参进 `Catalog.Effects`；模板缺失 / containerType Unknown / 解析异常都 LogWarning 不中断）；无装配时回退 legacy `effectIds`。
- 层数数值叠加（每层攻 +1 / 血 +2）**不在本层**：由 Core `ContentSystem.CreateDraft` 按 `RunModel.Floor` 注入，本层只投影第 1 层 JSON 基准值。

### 遭遇牌组（`MonsterDeckTableCatalog` + `MonsterDeckCatalogBuilder`）

`monster_decks.json` 行只登记 deck_id / deck_kind / display_name；**成员列表不写表**，由 Builder 遍历 `Catalog.Cards` 按卡面 `deckId`（大小写不敏感）推导。deck_kind 解析兼容新旧词汇：`normal|weakelite`→WeakElite（第 1 层池）、`medium|strongelite`→StrongElite（第 2 层）、`hard|boss`→Boss（第 3 层）、`reserve`→Reserve（归档，不进层池）。display_name 缺省回退该 deckId 的卡面 JSON displayName。

### 主题卡组四层契约（#127/#128/#134 / ADR-0029）

1. `ThemeDeckStableMapping`：**代码快照**，七套 × 5 槽唯一 contentId。deckId/contentId 是历史残留不透明主键（ADR-0014），契约不承载主题语义；displayName 可变、禁止断言。
2. `ThemeDeckMappingVerifier`：「映射正确」层——`slot_duplicate` / `slot_gap` / `slot_mismatch` / `member_out_of_range` / `content_reused` / `boss_flag`（序列 5 恒 IsBoss，1–4 非）。
3. `ThemeDeckFormalReadiness`：「正式可达」层——`deck_not_in_table` / `deck_reserve` / `deck_floor_tier_mismatch`（对照 `ThemeDeckFloorTierMapping`）/ `slot_card_reserve` / `transition_not_cleared`（`deck.transition` 不得残留非 Reserve 怪）。#134 起 Blockers 清空，`Reachable=true` 是常绿正向门禁。
4. `ThemeDeckNarrowContract`：单套交付期窄校验（槽位+Boss+非 Reserve+已登记），绿 ≠ 全局可达。

### 卫生校验（`ContentHygieneValidator.ValidateAll`）

九类 Finding（`Category` 字段）：

| Category | 校验内容 |
|---|---|
| `index` | `_index.json` ↔ 磁盘双向覆盖、索引无重复、磁盘无重复 contentId、Authoring/Streaming 两侧索引字节一致（实现在 `CardPresentationIndexIO`，见 03 篇） |
| `mirror` | Authoring/Streaming 文件名集合双向相等 + 内容逐字节一致 |
| `skill-link` | 所有 `skillIds` 指向磁盘上存在的 Skill JSON |
| `assembly` | 装配须有 id、templateId，且模板存在于 `effect_templates.json` |
| `template-ref` | 模板 body 里 `defId|sourceDefId|targetDefId|excludeSourceDefId` 引用的 contentId（非 `{{占位符}}`）必须存在 |
| `empty-shell` | Skill 不得既无装配也无 effectIds（归档投影不得留成正式空技能） |
| `archive-grant` | 归档卡（`deck.relic_archive`/`deck.help_archive` 成员）不得被房间 openingInject / 正式挂载模板的 body defId / legacy 白名单授予；archive→archive 死数据豁免（`ComputeFormalOwnedTemplates`） |
| `usable-outside-battle` | ADR-0032：`usableOutsideBattle=true` 的卡全部装配模板 `target.atom` 必须是 `Player`（无盘面依赖） |
| `description-contract` | ADR-0035 描述令牌契约（委托 `CardDescriptionTokenRules.ValidateCard`，见 02 篇） |

纯磁盘 + 运行时 API，EditMode 测试与编辑器菜单（`NineGrid.Content.Editor` 内容卫生汇总菜单）共用。

## 对外通信面

- **入**：磁盘 JSON（cards + tables）；无任何场景/SO 依赖（视觉 SO 族见 03 篇，已非权威）。
- **出**：`GameContentCatalog`（Core 类型）。业务代码一律消费 Catalog，不直读 JSON。
- 静态缓存失效协议：任何要「重读盘」的调用方走 `ContentCatalogBootstrap.Load()`（其内部先 Invalidate）；单测注入走 `CardPresentationConfigCatalog.UpsertForTests` / `MonsterDeckTableCatalog.UpsertForTests`，TearDown 必须 Invalidate。

## 关联 ADR

ADR-0008（单一权威 + Resources）、ADR-0009（模板+装配、分类三轴、奖池查询）、ADR-0011（攻击模式内生）、ADR-0014（主题 ID 不透明）、ADR-0022（节点装填）、ADR-0029（稳定槽位契约）、ADR-0030（常规机关池，消费方 `RegularTrapPool` 在 Core）、ADR-0032（非战斗可用）、ADR-0033（稀有度分级投放，消费方 `HelpCardDecks` 在 Core）、ADR-0035（描述令牌契约）、ADR-0038（卡级节奏双通道）。

## 不变量与坑

- **每次 `Load()` 必须重读盘**：Disable Domain Reload 下静态缓存跨 Play 残留，Bootstrap 首三行 Invalidate 是刚性防御，新增静态缓存必须同步加进来。
- **投影顺序有依赖**：表 → 卡 → 遭遇牌组 → 奖池展开。`MonsterDeckCatalogBuilder` 依赖已投影的 Cards；`RewardPoolQueryExpander` 依赖完整的 Cards/Relics 分类轴。
- **攻击模式 / 节奏源缺失不是回退是错误**：投影层故意保留 `Unspecified` 让 `ValidateCatalog` 爆出来，写内容时不要以为空字符串等于「无」。
- `TryParseCardKind` 会放行 `Item` 等 CardKind（注释：当前生产表仅 Help/Monster/Trap），但 Relic 永不落入 Cards。
- `ContentJsonCatalogProjector.TryProjectCard` 的两参重载（无 catalog）**不解析装配进 Effects**，只挂 EffectIds——EditMode 里若需要效果实体请走带 catalog 的重载或完整 Bootstrap。
- 经济表 / 节点规则表缺文件仅 LogWarning，返回 0——Player 若缺 StreamingAssets 表现为空目录静默降级，卫生校验和构建流程要保证表在包体内。
- `IsQuantityUnit`（描述参数化）与本链路无关，见 02 篇。
- `deck.transition`、`deck.relic_archive`、`deck.help_archive`、怪物 `isReserve` 是**归档语义**：JSON 保留（模板仍可按 defId 直生其成员），只是不进正式遭遇/奖池/授予，勿当死数据删除。
