# 01 架构装配与动作管线

> 本篇覆盖：QFramework 架构装配、GameAction 动作基类、动作管线（Action Pipeline）、触发器系统（TriggerSystem）、命令定义与结果类型、Query 与三个 Utility。文件基准路径：`Assets/Scripts/NineGrid.Foundation/NineGrid.Core/`。

## 职责综述

NineGrid.Core 基于 QFramework 的 Architecture / Model / System / Utility / Command 分层。本篇是整个规则核的"骨架"：

- **`NineGridArchitecture`** 是唯一的装配点，注册全部 9 个 Model（含卡面投影账本 `CardFaceLedgerModel`，ADR-0045）、13 个 System、3 个 Utility。
- **一切状态变更都通过 `GameAction`**：动作在 `ActionPipelineSystem` 中串行解算，产出 `CoreGameEvent` 事实流与 follow-up 动作。
- **触发器（TriggerSystem）** 在每个动作的 Pre/Post 时机派发 `TriggerContext`，效果系统与各 System 级反应（击杀赏金、离开机关洗入等）都以 `ITriggerReaction` 注册于此。
- **命令（CoreCommands）** 是表现层进入 Core 的白名单入口，每条命令转发到 `IPhaseSystem` 的对应门禁方法，返回 `CoreCommandResult`。

## 核心流程与数据流

### 动作解算循环（ActionPipelineSystem）

```
Execute(action) = Enqueue + RunToCompletion
RunToCompletion:
  while (反应栈或队列非空):
    action = 反应栈.Pop() 优先，否则 队列.Dequeue()
    ResolveAction(action, depth=0):
      1. EventLog.Append(ActionStarted)
      2. Dispatch Pre 触发点（默认 BeforeAction）→ 触发产出的动作立即按栈序解算（depth+1）
      3. result = action.Apply(context)
      4. EventLog.AppendRange(result.Events)
      5. CardFaceReconciliation.ReconcileAfterAction —— 卡面投影统一对账缝（ADR-0045）：
         扫新事件进账本 → oracle 重算盘面九格+Avatar → diff 有变才补发
         BaseStatModified/ActionCountdownChanged（Cause=faceReconcile），紧邻因果动作
      6. Dispatch Post 触发点（默认 AfterAction；各动作自定义如 OnDamage/OnKill…）
      7. 逆序压栈 result.FollowUpActions 并立即解算（depth+1）
      8. EventLog.Append(ActionFinished)
```

要点：

- **反应栈优先于队列**（LIFO），触发反应产生的动作在父动作完结前解算完；深度超过 64 直接抛异常（防触发环）。
- `IsRunning` 期间再调 `RunToCompletion` 抛异常——管线不可重入；触发反应内只能 `Enqueue`/返回动作，不能自跑管线。
- `RejectCommand`：门禁拒绝也会写入 `ActionRejected` 事件、发 QF 事件 `Evt_ActionRejected`，并派发 `OnActionRejected` Post 触发点（拒绝也是事实）。
- `EventLog`（见第 10 篇）跨命令累积；`CoreCommandDispatcher` 按 startIndex 截取本命令新增事件切片构建表现批次。

### 触发派发（TriggerSystem）

- 注册键为 `Timing:Point` 字符串；`Dispatch` 时对反应列表拍快照再遍历（反应期间可安全注册/反注册）。
- 系统级常驻反应：`EconomySystem`（OnRemove→移除赏金）、`RewardSystem`（OnKill→精英/层主掉落）、`DeckSystem`（OnKill→层主房离开机关洗入）；效果实例经 `EffectSystem.EffectTriggerReaction` 注册。
- `TriggerContext.TryReserveFragmentMerge`：同一触发批次内 (无头骷髅, 骷髅头) 邻接对只允许合并一次（供 `FragmentRecombineDedup` 消费）。

### 命令面（CoreCommands 全集）

战斗交互：`StartNode`、`Attack`、`CombatHit`（可信命中，无门禁）、`PickupItem`、`ClickEmpty`、`UseItem` / `ApplyUseItem`（可信版）、`RevealFace`、`MoveAvatar`。
导演分拍：`ResolvePostKillBoard`（整拍兼容）、`AdvanceInteractionCount`、`ResolveBoardStabilization`、`ResolvePostKillRotate`、`RegisterEnemyActionPhase`、`ResolveNextEnemyAction`、`ResolveEnemyActionFinale`。
选择与经济：`SelectReward`、`SkipHelpChoice`、`DiscardRelic`、`RecycleItemSlot` / `ApplyRecycleItemSlot`、`RefreshShop`、`SelectRoom`、`EnterRoom`。
批次回执：`PresentationFinished`（转发 `IPresentationSyncSystem.FinishBatch`，见第 10 篇）。

`Apply*` 前缀命令 = 表现层可信通道：跳过相位合法性门禁（IntentIntake 已在表现层裁决过），仍校验对象存在性/区域等硬约束。

### 确定性随机（DeterministicRngUtility）

- xorshift128 变体；`SetSeed` 用 splitmix 风格 Mix 从 ulong 种子派生 4 个非零 uint。
- `RngState`（X/Y/Z/W/Step）可整体捕获与恢复——跑图存档（ADR-0041）靠"恢复 RNG 状态后重跑发牌"实现盘面复现。
- 全 Core 只此一个随机源；表现层/音频随机**不得**消费本 RNG（见 CONTEXT「随机音频池」）。

## 对外通信面

- 表现层唯一驱动入口：`CoreCommandDispatcher.Send(ICommand<CoreCommandResult>)`（文件在 `Presentation/`，详见第 10 篇）。
- 触发系统与管线对表现层不直接暴露；表现层只消费 `PresentationBatch` 指令与 `CoreViewSnapshot` 快照。
- `Evt_ActionRejected`（QF 事件）供表现层展示拒绝反馈。

## 关联 ADR

- ADR-0001（Batch-ack 时间线：`ResolvedActions` / 批次由命令边界切分）
- ADR-0010（`OnActionRejected` 触发点：拒绝也是可探查事实）
- ADR-0041（RngState 捕获/恢复 = 存档发牌复现）
- ADR-0045（`ResolveAction` 内的卡面投影统一对账缝，见第 10 篇）

## 不变量与坑

- **管线不可重入**：`IsRunning` 时再 `RunToCompletion` 抛异常。系统级反应（DelegateTriggerReaction）必须返回动作列表而不是自己 Execute。
- **触发深度上限 64**：互相触发的效果链过深会直接炸；设计效果时避免 A 触发 B、B 又触发 A 的无收敛环。
- `InitialGameFactory` 会 `TriggerSystem.Clear()`（清掉一切反应，包括系统级），因此 Economy/Reward/Deck 三系统提供 `RebindSystemTriggers()`，Clear 后必须重绑（见第 8 篇）。
- `ActionPipelineSystem.Clear()` 清事件日志、重置 actionId 并复位卡面投影账本（`CardFaceLedgerModel.Reset`，扫描游标与日志长度锁步），但**不**清 TriggerSystem；两者生命周期独立。
- `Range(min, max)` 是 `min + Next % span`，有极轻微模偏差——同种子跨平台一致性优先于统计均匀性。
