# 04 棋盘、卡组与盘面稳定化

> 本篇覆盖：`Systems/BoardSystem.cs`、`Systems/DeckSystem.cs`、`Systems/BoardStabilizationSystem.cs`、`Domain/Actions/BoardDeckActions.cs`、`Domain/AvatarWalkPathfinder.cs`、`Domain/MonsterBoardRules.cs`。文件基准路径：`Assets/Scripts/NineGrid.Foundation/NineGrid.Core/`。

## 职责综述

九宫盘面的几何裁决（邻接、可用格）、节点卡组装填与开局发牌、补牌/旋转/换位三类盘面动作，以及"盘面稳定化"（欠补位判定与逐切片补牌）这一稳定边界权威。另含非战斗 Avatar 跳格的 BFS 寻路与怪-怪虚拟邻接规则。

## 核心流程与数据流

### 节点装填 → 开局发牌（RUL_发牌）

```
DeckSystem.SetupNode(options) 或 PhaseSystem.StartNode 内联同序：
  1. SetupNodeDeckAction
     - 反激活所有非持久（非 Avatar、非道具卡格）卡的运行时效果
     - 清盘面 + 清战斗区（保留 ItemSlots）+ 从 Registry 删除非持久卡
     - ResetLeaveTrapProgress；按 PlayerCards/EnemyCards Draft 造卡（ContentSystem.ApplyContentToCard 激活效果）
     - 玩家侧 HelpCard 打 playerSideDeck 计数标记；真怪登记 OpeningTrueMonster（Boss 另记）
     - EnemyCards 含 trap.leave 时 MarkLeaveTrapInserted
  2. OpeningDealAction
     - 玩家侧池直摆随机空格（最多 PlayerOpeningCount=3）
     - 敌方 SelectCards：RequireElite 时全部 Elite Counter>0 者必选（层主全上场），再顺序补足到 EnemyOpeningCount=3；直摆上盘
     - 双暂存池余量并入抽牌堆 → 洗牌（PreserveDealOrder=true 跳过）→ LeaveTrapDrawPileRules.EnsureInSecondHalf
  3. FillEmptySlotsAction 补满余格（DealOpeningCards 相位时先发 AvatarAppeared）
```

### 盘面稳定化（ADR-0034）

- `NeedsRefill` = InteractionLoop 相位 ∧ 未清关 ∧ 抽牌堆非空 ∧ 存在按 FillOrder 可填的非 Avatar 空格。
- `ResolveNextSlice`：把"延后抽牌"（融合/重组结果，`ShuffleIntoDrawPileAction(deferRefill:true)` 登记）临时排到牌堆尾部 → 执行一轮 `FillEmptySlotsAction` → 恢复剩余牌原相对顺序。只剩延后卡时放行（不留永久空洞）。
- `ResolveUntilStable(max=64)`：循环切片直至稳定（开局与旧整拍入口用）；导演路径逐切片 Resolve → Present → ack。
- `Complete()`：稳定后把标记"恢复置顶"的延后卡放回牌堆顶并清空延后集合。

### 补牌的两遍分派与机关空位

`RemoveCardAction` 在来源 defId 以 `trap.` 开头且被移除卡在场时 `BoardModel.MarkTrapVacated(slot)`；`FillEmptySlotsAction` 先填正常空位，第二遍才填机关空位且 `CardDealt` 事件带 `cause=refillAfterTrapRemoval`——捕熊陷阱等"补牌触发型"效果以 `EventFilterExcludeCause` 排除响应（ADR-0034 补记）。

### 邻接裁决（BoardSystem.AreAdjacent）

正交相邻 → 真；否则查 `VirtualAdjacency`（成对怪规则，双向查）与 `GlobalMonsterAdjacency`（场上任一怪持有即全场怪互视邻接，仅技能邻接语义，不影响攻击距离与齐射）。玩家 Attack/Pickup/ClickEmpty/RevealFace 的互动范围判定统一走此门面。

### Avatar 跳格寻路（ADR-0019/0020）

`TryFindPath(board, from, to, out path, isDestination, isSoftBlocked)`：
1. **PreferEmpty 阶段**：途经格必须 Core 空且非软占；终点若被 `isDestination` 认可（离开/导航图标格）即使非空也可达，普通终点须空且非软占。
2. 失败则 **AllowSoft 阶段**：途经可踩软占与真卡（盘面堆满的兜底）。
无谓词重载保持旧行为（全空才可走）。`TryGetNextStep` 取路径首步供逐跳 MoveAvatar。

## 对外通信面

- 表现层经命令面驱动：`ResolveBoardStabilizationCommand`（逐切片）、旋转/换位一般作为动作由 Core 内部触发。
- `IBoardStabilizationSystem.NeedsRefill / PendingEmptySlotCount` 供表现层 `BoardStabilizationScheduler` 只读检查。
- `FillEmptySlotsAction.FillOrder` / `RotateBoardClockwiseAction.ClockwisePath` 公开为常量表，表现层与稳定化系统共用。

## 关联 ADR

- ADR-0034（盘面稳定化归 Core、机关空位补牌豁免、登场批/开局铺场豁免）
- ADR-0026（离开机关洗入落点：普通房后半段 / 层主房击破层主后置顶）
- ADR-0022（发牌机制：直摆 + RequireElite 全层主第一波上场）
- ADR-0019 / ADR-0020（跳格寻路与图标格终点）
- ADR-0042（PreserveDealOrder 教学保序发牌）

## 不变量与坑

- **清关判定唯一真相**：`DeckSystem.IsNodeCleared()` 只读 `BattleContextModel.IsLeaveTrapBroken`；`HasPendingEnemyCards` 等真怪检查已不参与清关。
- **旋转路径与补格序是两张不同的表**：旋转 1,2,3,6,9,8,7,4（外圈环），补格 1,2,3,6,9,8,7,4,5（含中心 5 最后）。
- 敌方行动阶段期间**不补牌不旋转**（盘面冻结）；稳定化只会在导演批间隙推进。
- `OpeningDealAction` 直摆失败（盘面放不下）时选中卡退回抽牌堆，不吞卡。
- `DeckSystem` 的 OnKill 反应只对**开局编入 UID** 计进度；局中新生怪（复活石、召唤）不加速出门。
- BFS 途经格集合不含起点；同格路径返回空列表且 true。
- 融合结果的延后抽牌**只由 Core 管理**；表现层不得改抽牌堆（ADR-0034 明令）。
