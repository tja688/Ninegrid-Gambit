# 08 内容目录、装填、奖励经济与存档

> 本篇覆盖：`Content/` 全部 5 个文件、`Systems/ContentSystem.cs`、`Systems/RewardSystem.cs`、`Systems/EconomySystem.cs`、`Domain/Actions/ContentActions.cs`、`Setup/` 全部 3 个文件。文件基准路径：`Assets/Scripts/NineGrid.Foundation/NineGrid.Core/`。

## 职责综述

从内容数据到局内实体的整条链：`GameContentCatalog`（Core 侧内容真相，由 NineGrid.Content 装载后经 ConfigUtility 注入）→ `ContentSystem`（造 Draft、激活效果、内容卫生校验）→ `RewardSystem`（节点装填、奖池、房间、商店/卡店/特殊房货架）→ `EconomySystem`（金币事实）→ `ContentActions`（改基础值、授予遗物/道具、会话 Offer 动作）→ `Setup`（开局工厂、职业表、跑图存档快照）。

## 核心流程与数据流

### 节点装填总装（RewardSystem.BuildNodeDeckOptions）

```
1. EnsureOpeningRoomAssigned：节点 1/5 自动摇房（排除精英与属性房，保证开局道具 ≤7，ADR-0022 修订）；节点 8 强制 Boss
2. 层内节点号归一化（壳层传全局序号 → (n-1)%8+1）查 NodeDeckRule
3. 玩家侧 AddRunPlayerSideCards：固定卡占容量预算 → 余量从来源池按常规稀有度加权随机（高60/中30/低10，`RollRegularItemDefIdWeighted`，档内均匀、缺档不参与）→ 房间注入（不占容量）
4. 怪物侧：按规则表序列 1..5 各抽 N 张（同序列内随机）；Seq5Count>0 ⇒ RequireElite（层主第一波必上场）
5. 房间怪物侧注入（困难房注入本层序列 3/4 各 1 张等）
6. AppendRegularTrapCards：RegularTrapPool 无放回随机 3 张常规机关
7. AppendOpeningLeaveTrapCard：非层主房编入离开机关（层主房走击破层主后洗入，DeckSystem OnKill 反应）
```

### 奖池抽取（RollPool）

候选 = 池条目排除已持有遗物 → 有稀有度权重（Query 或 legacy 硬编码：help.choice / shop.helpCards 60/30/10〔ADR-0033 修订〕、蓝箱 40/50/10、金箱蓝50金50）时先摇稀有度档再在档内按权重抽；无则直接加权无放回抽 PickCount 张 → `EnforceRoleBalance` 按 Query 的 BalanceMinAttack/MinDefense 从剩余候选替换补足 → 遗物"连续出现降权"：上次露面未被选中的遗物本次权重减半（`RememberUnselectedRelics` 记录，抽完即清）。

### 房间会话（ResolveRoom）

Shop → 4 货架（随机属性卡 40/40/20 + 药水 + 食品 + 未满级时道具牌格升级）；Tavern → 3 服务（数值强化 +3 / 道具卡固定 / 扩容，各 50 金；「固定」二级候选从来源池按常规稀有度加权抽）；TreasureReward → 1 宝箱 + 3 随机道具；ItemReward → 2 属性 + 3 随机道具（两处「随机道具」均从来源池按 60/30/10 加权）；其余房间按 `RewardPoolId` / `ShopOfferCount` 发 Offer。宝箱卡渠道收口（ADR-0033 修订）：商店不上架宝箱、精英房混合注入池不含宝箱。

### 击杀掉落（RewardSystem.ReactToKill）

层主死亡 → 固定洗入 1 金宝箱 + 2 金币卡；精英死亡 → `kill.elite` 池结果洗入牌堆。普通怪的移除赏金走 EconomySystem OnRemove 反应（MonsterRemovedGold=5 或卡面 KillGold，Trap 与清场移除跳过）。

### 内容卫生（ContentSystem.ValidateCatalog）

五类：效果 JSON 可解析且 DSL 校验通过；卡/技能/遗物的效果与技能引用存在；怪物攻击模式必填；怪物节奏（需节奏者必有源与周期 >0；OnCardRhythmFire 效果禁带 every）；房间注入声明合法（side/count/池权重/序列范围）。

### 跑图存档（RunSaveGame，ADR-0041）

- **捕获**：战斗节点开始、BuildNodeDeckOptions 消耗 RNG 之前。内容 = Run 进度 + 壳层节点号 + PlayerModel 全量（含一次性遗物效果消费标记 `consumedRelicEffectIds`，ADR-0049）+ 道具卡格 defId 序列 + Avatar 基础属性与计数器（含遗物 Run 作用域倒计时）+ 遗物 run 贡献 + RNG 四字状态。
- **恢复**（固定顺序）：职业/容量/来源池与固定卡（均经 `FilterRegularSourcePool` 守卫过滤旧存档特殊卡/归档卡）→ **消费标记写回**（必须先于遗物重装，否则一次性效果恢复时重复发放）→ 遗物对齐（多余弃、缺失补装并冲刷 OnActivate）→ 道具卡格重造（经 `FilterLiveHelpCards` 只放行 live 道具卡——特殊档允许驻留、归档卡拦截）→ Avatar 属性/计数器覆写 → run 贡献 + Persistent modifier 重装 → 金币/互动数绝对对齐 → Run 进度 + SetPhase(NodeCompleted) → **最后**恢复 RNG。相同 RNG 重跑装填即发牌复现。跨层重引导的 `RunInventorySnapshot`（表现层 `BattleSessionExecutor`）同样捕获、同套守卫，并先写回消费标记。

## 对外通信面

- Catalog 注入：表现层 `ContentCatalogBootstrap.Load` 构建 `GameContentCatalog` 后写入 `IConfigUtility["tableNine.defaultCatalog"]`；Core 各系统经 `TryReloadFromConfig` 懒加载。
- 存档序列化与落盘在表现层（`RunSaveService` + ES3 桥）；Core 只出 DTO 与捕获/恢复逻辑。

## 不变量与坑

- **归档四道闸**：`RewardPoolQueryExpander.MatchesCard/Relic` 排除归档；`GrantRelicAction` 拒授归档遗物；`ProfessionCatalog.AppendHelpCardsFromDeck` 排除归档 + 非常规稀有度；存档/跨层恢复经 `FilterRegularSourcePool`（来源池/固定卡）与 `FilterLiveHelpCards`（道具卡格）拦截归档卡——归档卡仍在 Catalog 中可被 `CreateDraft` 重造，缺这道闸旧存档会把倍增塔/瞭望塔等老道具带回正式局。
- **InitialGameFactory 的 Clear + Rebind 纪律**：`TriggerSystem.Clear()` 会连系统级反应一起清，必须随后 `RebindSystemTriggers()`（Economy/Reward/Deck 三处）；否则击杀赏金、离开机关洗入静默失效。新局另清 `IStatSystem.RuleModifiers`（全局单表不随卡实例消亡）；存档恢复由 `RestoreAfterCreate` 重装遗物 Persistent 修正，卡侧修正随节点重新激活。
- `ModifyBaseStatAction` 的 Hp 负增量钳到最低 1（防 0 血卡不死站场）；击破只由伤害结算走 Kill。
- `HelpCardGrantRouting`：局外授予（非 InteractionLoop/DealOpeningCards 相位）直写道具卡格，局内洗入战斗牌堆——同一 GrantRewardChoice 两种落点。效果 DSL 的 `Spawn` 帮助卡投 `PlayerCardPool` 同样按此路由：InteractionLoop 相位改走 `ShuffleIntoDrawPileAction`（ADR-0049）——`PlayerCardPool` 是仅供开局发牌消费的暂存池，互动期投入会滞留死区、下节点 `ClearBattleZones` 直接丢卡（黄金鱼竿宝箱卡消失事故）。
- `RewardOfferFaceProjection`：Offer 时用 CreateDraft 只读投影攻/甲/血（"拿了就是"），不造卡进 Registry。
- 新增"跨战斗持久"状态必须同步 `RunSaveSnapshot` + `RestoreAfterCreate` 并升 version，否则读档静默丢失（ADR-0041 检查单）。
- 属性房三选二相关动作（OfferAttributePickSession/SelectAttributeCandidate）与 `RewardSystem.AttributePickCount` 为废止路径遗留，正式流程不触发。
