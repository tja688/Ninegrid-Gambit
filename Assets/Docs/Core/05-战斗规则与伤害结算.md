# 05 战斗规则与伤害结算

> 本篇覆盖：`Domain/CardCombatRules.cs`、`Domain/CombatEngagementOrder.cs`、`Domain/AvatarDefeatFollowUp.cs`、`Systems/BattleScopeSystem.cs`、`Domain/Actions/BattleScopeActions.cs`、`Domain/Actions/CoreActions.cs`、`Domain/Actions/FaceOrientationActions.cs`、`Domain/FaceDownTickCounters.cs`。文件基准路径：`Assets/Scripts/NineGrid.Foundation/NineGrid.Core/`。

## 职责综述

交战与伤害的全部规则：双桶（可交战 / 真怪物）、先手还击、交战作用域（OnBattle 门禁）、标准伤害公式（三层护甲 + 减免 + 无视护甲 + 金甲）、治疗/叠甲/移甲/金币/移除/击杀六类基础动作、牌面朝向三动作与背面计时，以及 Avatar 判死不变量。

## 核心流程与数据流

### 标准伤害公式（DealDamageAction.Apply，ADR-0028）

```
0. 目标已在坟场/移除区 → no-op；目标背面 → no-op（ADR-0016 背面不可被伤害）
1. 门保护：目标持 DoorProtection 且本次不是「交战中玩家出手」→ no-op
2. baseDamage = max(0, Amount)                       // 调用方给出（有效攻或技能伤）
3. multiplied = max(0, round(EvaluateRule(DamageMultiplier, baseDamage)))
   flat       = round(EvaluateRule(DamageFlatDelta, 0))        // baseDamage>0 才计
   afterRules = max(0, multiplied + flat)
4. reduction  = max(0, round(EvaluateRule(DamageReduction, 0)))  // 受击方累加
   damage     = max(0, afterRules - reduction)
5. Consume(DamageMultiplier, Once) → 反激活 effect: 前缀来源的效果（一次性乘区用毕即失效）
6. IgnoreArmor?
   是：hpLoss = min(hp, damage)；甲不动、金甲不触发
   否：armorDamage = min(当前甲, damage)
       金甲（GoldArmorAbsorb，仅 Avatar）：每 5 金抵 1 点拟甲伤 → goldAbsorbed
       armorLoss = armorDamage - goldAbsorbed
       hpLoss = min(hp, max(0, damage - 当前甲))     // 溢出按吸收前当前甲计，与金抵正交
7. 写回 CurrentArmor 与 Hp；发 GoldModified(金甲) / ArmorChanged / HpChanged / DamageDealt(带 WithDamageSplit)
8. HP≤0：Avatar → DefeatIfAvatarDeadAction follow-up；其他 → KillIfDeadAction follow-up
```

Post 触发点按是否在交战作用域分两组：作用域内多派发 `OnBattle`（#78 / ADR-0012——单向打击、技能直伤不触发 OnBattle）。

### 玩家交战（PhaseSystem.Attack 编排，动作在本篇）

```
BeginPlayerMonsterEngagement(target)      // 换敌清 UntilEnemyChanges；开窗口
神圣决斗标记结算（先结算旧标记：目标为他怪且旧持有者在场正面 → 对玩家 2 伤；再记/转移标记——目标同为持有者时先罚后转标，惩罚不被吞掉）
if 怪先手（FirstStrike 且未被 CounterAttackBanned 短路）:
    DealDamage(怪→玩家) → ConditionalDealDamageIfAlive(玩家→怪)
else:
    DealDamage(玩家→怪) → 若怪无 CounterAttackBanned: ConditionalDealDamageIfAlive(怪→玩家)
EndBattleScopeCleanup                     // 关窗口 + 清 UntilBattleEnds
```

- `ConditionalDealDamageIfAliveAction`（见第 9 篇文件归属）保证死者不再出手；"双方同时致命"表现为先出手方的伤害已成立。
- 机关（Trap）激活时静默挂 `CounterAttackBanned`（ADR-0017），玩家砍机关不挨反击；远程武器技能同理让怪不先手不反击。
- 表现层分拍路径用 `ApplyCombatHit`（单段伤害，无门禁无反击），由导演逐拍编排先手/反击。

### 移除 vs 击杀

- `RemoveCardAction`：门保护可拦（清场扫描 `clearResidualBoard/Trap` 除外）；清场扫描只派发 AfterAction Post（不触发 OnRemove/OnCumulative——死亡召唤不得在清场拍留实体，ADR-0026 补记）；机关来源移除标记机关空位。
- `KillAction`：血清零、入坟场、发 CardKilled + CardRemoved、反激活 owner 效果、真怪按 GoldReward 计数器发赏金（Trap 无赏金）。
- 两者都在收尾对场上"带条件 Permanent Attack"的卡补提交有效攻卡面（邻接光环宿主离场后的显示刷新）。

### 牌面朝向与背面计时（ADR-0016）

- 三个动作共同点：改 `CardInstance.FaceUp` → `EffectSystem.SyncOwnerFaceSuppression(uid)`（背面临时卸下非豁免被动修正器）→ 发 `CardFaceChanged`（ResultValue=0/1）→ Post `OnFlip`。
- `FlipCardAction` 是 toggle；`ConcealFaceAction` 仅正面→背面；`RevealFaceAction` 仅背面→正面。翻面/盖面同时清神圣决斗标记（持有者朝向变化即标记失效）。
- `FaceDownTickCounters`：只有显式 `Register(card, id, period)` 的键才在敌方行动报名时对背面卡 −1；减至 0 记入 fired 列表（效果侧自行翻回/注销）。与 `attackPattern.countdown`（背面冻结）完全隔离。

### Avatar 判死闭环（ADR-0039）

- 唯一谓词 `AvatarDefeatFollowUp.IsAvatarDefeated`：AvatarUid≤0 ∨ 注册表查无 ∨ HP≤0，**不看 Zone**。
- 挂载点：`DealDamageAction`、`ModifyBaseStatAction`（钳血后）→ `DefeatIfAvatarDeadAction` follow-up；`PhaseSystem.StartNode` 末尾兜底补跑。
- `DefeatIfAvatarDeadAction`：终端相位与开局管线相位（BuildEnemyPool/ResetNode/DealOpeningCards）内 no-op；触发时先 `ResetBattleScopedCountdownsAction` 再 `ChangePhase(Defeat)`。

## 对外通信面

- 伤害/治疗/金币等全部以 `CoreGameEvent` 事实进入批次：`DamageDealt`（带甲/血拆分）、`HpChanged`、`ArmorChanged`、`GoldModified`、`CardKilled`、`CardRemoved`、`CardFaceChanged`。
- 卡面数值提交约定见第 10 篇（`CardFaceEventValues` 旁路）。

## 关联 ADR

- ADR-0028（标准伤害公式全量）、ADR-0012（OnBattle 仅交战作用域；齐射引用本公式）、ADR-0017（双桶、Trap 无赏金、静默 CounterAttackBanned）、ADR-0026（门/魔免/清场扫描不派发死亡 Post）、ADR-0016（背面不可伤害、faceDownTick）、ADR-0039（判死唯一谓词与终端相位粘性）、ADR-0011（FirstStrike 更名先手还击）。

## 不变量与坑

- **伤害只此一个入口**：任何"造成伤害"最终都构造 `DealDamageAction`；绕过它就绕过了门/魔免/减免/金甲/判死全部规则。
- **门保护对 Kill 无效**：`KillAction` 不查 DoorProtection——门只挡非交战伤害与直接移除，致命伤害走 Kill 仍可击破（这正是清关手段）。
- **魔免不在本层**：魔免过滤发生在效果系统的目标解析后（第 9 篇），交战裸伤不受魔免影响。
- `HealAction` 上限用**有效 MaxHp**、当前血用 base——治疗可及于光环加成的上限。
- `TransferArmorAction` 只动当前甲；来源无甲时整体 no-op（不发空事件）。
- `ModifyGoldAction` 可负值且不钳下限——金币可为负的防护由调用方负责（商店购买前查余额）。
- 背面卡的 `AttackPatternCountdown` 冻结由报名逻辑保证（跳过背面），动作本身不改计数器。
