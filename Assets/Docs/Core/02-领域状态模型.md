# 02 领域状态模型（Models 与基础类型）

> 本篇覆盖：`Models/` 全部 9 个状态模型，以及 Domain 基础类型 `SlotId`、`CoreEnums`、`CoreConstants`、`ModifierSource`、`CardDraft`。文件基准路径：`Assets/Scripts/NineGrid.Foundation/NineGrid.Core/`。

## 职责综述

Core 的全部权威状态集中在 9 个 QF Model（外加卡牌实例本身；第 9 个是卡面投影账本 `CardFaceLedgerModel`，文件在 `Presentation/CardFaceReconciliation.cs`，属投影侧簿记而非规则状态，见第 10 篇与 ADR-0045）。它们只是**数据 + 最小自洽约束**，不含流程；一切变更由 GameAction / System 驱动。每个 Model 携带 `Version`（BindableProperty），任何写操作 `Touch()` 递增，`CoreViewSnapshot` 用各 Model Version 之和作为快照版本号。

## 核心数据关系（状态模型总图）

```
RunModel (Floor/NodeIndex/Phase/Seed/Room/本层主题卡组)
  └─ 每个战斗节点 → BattleContextModel (交战窗口/敌方行动窗口/挂起位移队列/清关标志/开局真怪进度)
PlayerModel (金币/互动数/遗物/双容量/来源池)  RelicRunContributionModel (遗物run贡献)
CardRegistry (uid → CardInstance)
  ├─ BoardModel  按 SlotId 引用 uid（占格权威；AvatarUid 独立字段）
  └─ DeckModel   按 uid 列表引用（DrawPile 有序 / PlayerPool / EnemyPool / ItemSlots）
PendingChoiceModel (奖励·房间·导航待决项；商店/卡店会话态)
```

关键约定：

- **卡的位置真相**是 `CardInstance.Zone + Slot`，但**占格真相**在 `BoardModel`（两者由动作同步维护；`BoardModel.PlaceCard` 同时改写两边）。Avatar 特殊：`Zone=ZoneId.Avatar`，`BoardModel.AvatarSlot` 单独记录，Avatar 不占 `mCardUidsBySlot`（一个格位可同时有 Avatar 与图标/软占的几何来源即此）。
- **DeckModel 的 PlayerCardPool / EnemyCardPool 仅为节点装填暂存**——`OpeningDealAction` 直摆上盘后将两池余量并入抽牌堆，战斗内不再存在"敌方牌库"概念。
- **ItemSlots（道具卡格）是唯一跨节点持有容器**（ADR-0025）：`SetupNodeDeckAction` 清卡时以 ItemSlots 为保留名单；`ClearBattleZones` 不清它。
- `CounterBag` 是卡上任意整数计数的统一容器：击杀赏金、精英/层主标记、Level、卡级共享倒计时（`attackPattern.countdown`）、效果倒计时（`effect.<instanceId>.*`）、背面计时（`faceDownTick.*`）都存在这里，键前缀互相隔离（`CoreCounterKeys`）。
- `CardInstance.FaceUp` 是牌面朝向唯一权威（ADR-0016），默认正面；表现层 DisplayMode 不得当朝向真相。
- `RunModel.AdvanceNode()`：NodeIndex+1；到 8 时若 Floor≥3 返回 true（通关），否则 Floor+1、NodeIndex=0 并清空本层卡组绑定。
- `BattleContextModel.AreAllOpeningMonstersDefeated()`：开局真怪 N=0 视为已清完——决定清关时是否自动兑金场上残留道具（ADR-0026）。
- `PendingChoiceModel` 的池 id 语义静态方法族（`IsShopPool` / `IsTavernPool` / `IsRelicRewardPool` / `IsSpecialRewardPool`…）是全部消费房会话分流的唯一判定源；`TrySuspendConsumerSessionForRelicOverlay` 支持"房内开宝箱→遗物三选一→回到货架"的嵌套会话。

## 对外通信面

- Model 对表现层只读（QF `GetModel` 可拿到，但 code-map 约定表现层只经 `CoreViewSnapshot` / 结算指令消费）。
- `BindableProperty`（Zone/Slot/Coins/Phase…）技术上可订阅，但表现层规范禁止战中直读对账（ADR-0005）。

## 不变量与坑

- **道具卡格容量钳制**：`SetItemSlotsCapacity` 钳在 [3,5]；`IsItemSlotsFull` / `CanAcceptIntoItemSlots` 是所有"写入道具卡格"路径的唯一裁决（满则拒入，不挤旧卡）。
- **遗物栏上限 12**，`AddRelic` 对重复 defId 与满栏静默 no-op——同名遗物不可重复持有。
- **一次性遗物效果消费标记（ADR-0049）**：键 = 目录效果 id（如 `relic.golden_coffer.grant`），由 `DeactivateSelfEffect`（缺省路径）落标记、`ContentSystem.ActivateRelic` 读标记跳挂；遗物丢弃/消耗时清除，`Reset` 清空；新增跨战斗持久态，已同步 `RunSaveSnapshot.consumedRelicEffectIds` 与跨层 `RunInventorySnapshot`。
- `RunModel.TryBindFloorMonsterDeck` 同层只认首次绑定；跨层 `AdvanceNode` 清空绑定，已用卡组列表跨层累积（用尽后 RewardSystem 允许同层难度档内复用）。
- `BoardModel.PlaceCard` 对已占格位抛异常（占格冲突是硬错误不是静默覆盖）；`MarkTrapVacated` 标记在该格被任何卡占用时自动消费。
- `CardDraft.Create`：Armor>0 时同时初始化 `CurrentArmor`；有节奏需求且源/周期合法时把共享倒计时初始化为周期 X；`GoldReward/IsElite/IsBoss/Level` 全部落到 CounterBag。
- `NodeDeckOptions.PreserveDealOrder` 仅教学关卡置 true（ADR-0042），正式流程恒 false。
- `PendingChoiceModel.AttributeSelectedDefIds` 与 `RunModel.AttributePickDefIds` 属**已废止**的属性房三选二会话（ADR-0031），代码保留但正式流程不再触发。
