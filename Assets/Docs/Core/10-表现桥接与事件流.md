# 10 表现桥接与事件流（Events + Presentation）

> 本篇覆盖：`Domain/Events/` 全部 4 个文件与 `Presentation/` 全部 9 个文件。文件基准路径：`Assets/Scripts/NineGrid.Foundation/NineGrid.Core/`。

## 职责综述

Core 与表现层之间的**单向事实通道**（ADR-0001 Batch-ack 的 Core 半边）：

1. 动作解算产出 `CoreGameEvent` 追加进 `EventLog`；
2. `CoreCommandDispatcher.Send` 在命令前后按 EventLog 增量切片，经 `PresentationEventMap`（事件类型 → 指令种类 / 表演锚点 / 是否锁输入）过滤成 `PresentationBatch`，附带 `CoreViewSnapshot` 全量快照；
3. 含阻塞指令的批次经 `PresentationSyncSystem.OpenBatch` 锁输入，表现层播完发 `PresentationFinishedCommand` → `FinishBatch` 解锁（就位回执 ack）。

另含卡面数值单一口径与统一对账缝（`CardFaceEventValues` + `CardFaceReconciliation`，ADR-0045）、奖励 Offer 编解码、动作日志投影。

## 核心流程与数据流

### 命令 → 批次（CoreCommandDispatcher.Send）

```
startIndex = pipeline.EventLog.Entries.Count
wasLocked  = sync.IsInputLocked
commandResult = architecture.SendCommand(command)          // 门禁 + 动作解算全在此内完成
batch = PresentationBatchFactory.FromEventLog(log, startIndex, nextBatchId++, CoreViewSnapshotFactory.Capture())
if (!wasLocked && 命令不是 PresentationFinished && commandResult.Accepted):
    sync.OpenBatch(batch)      // 拒收命令不得开批，否则导演门 ActiveBatchId>0 却 Accepted=false 卡死
```

- 批次只收映射表 `RequiresPlayback=true` 的事件；`RequiresAcknowledgement` = 任一指令 `LocksInput`。
- **锁定期内发出的命令**（如 Present 中的 SelectReward）事件不再开新批——表现层依赖非锁步冲刷消费该切片。

### 映射表要点（PresentationEventMap）

- 锚点归属：`DamageDealt/HpChanged/ArmorChanged/Healed/GoldModified/EffectTriggered` → **Impact**；`CardKilled/CardDealt/CardSpawned/AvatarAppeared/BaseStatModified/ActionCountdownChanged/EffectCountdownChanged(Cleared)/CardFaceChanged/RewardOffered` → **Settled**；其余 None（构造期强制写理由）。
- `AvatarMoved` 与 `CardRhythmFireOpened` 不进批（RequiresPlayback=false）：前者由 AvatarWalkRunner 自播 hop，后者纯逻辑驱动。
- `FindMissingCoreEvents` / `FindNoneBeatsMissingReason` 供穷尽性护栏测试——新增 CoreEventType 必须补映射行。

### 卡面数值口径与统一对账缝（ADR-0045）

- **单一口径（oracle）**：卡面显示与伤害结算共用同一组函数——攻＝`CardFaceEventValues.GetFaceAttack`（有效攻，怪物另加 `EnemyAttackDelta` 规则修正；`PhaseSystem.GetAttackDamage` 与 `EstimateWillKillQuery` 直接调用它）；玩家卡面攻＝`GetProjectedPlayerBattleAttack`（下一次对怪交战的乘区/平加投影，以盘面第一只怪为代理目标，无怪/无规则时退化为有效攻）；甲＝`StatArmorUtility.GetCurrentArmor`；血＝基础血；行动倒计时＝`attackPattern.countdown` 计数器。
- **发射完整性自动化**：`ActionPipelineSystem.ResolveAction` 在每个动作（含嵌套触发/FollowUp）自身事件入日志后调用 `CardFaceReconciliation.ReconcileAfterAction`：扫新事件进账本 → 对盘面九格 + Avatar 重算 oracle → 与账本 diff → 有变化才追加绝对值提交事件（`BaseStatModified`/`ActionCountdownChanged`，`Cause=faceReconcile`）。对账事件直接进事件日志（不进 result.Events、不参与规则触发），紧邻因果动作、复用既有 Settled 锚点。
- **旧补扫家族已删除**：`AppendPermanentAttackFaceCommit` / `AppendProjectedBattleAttackFaceCommit` / `AppendConditionalPermanentAttackFaceCommitsForBoard` / `AppendEnemyAttackDeltaFaceCommitsForBoardMonsters` / `AppendCurrentArmorFaceCommit` / `CommitPermanentAttackFaceAction` 及其全部 call site 均已废除（清单见 ADR-0045），新增数值源零手工接线。
- **保留（主事件正确性，非补丁）**：生成类 `WithFaceAbsolutes`/`AddWithFaceAbsolutes`（攻写 ResultValue、血/当前甲写 Remaining*，有活跃节奏的卡再补 `ActionCountdownChanged`）；`ModifyBaseStatAction` Attack 分支的 `ResultValue=GetFaceAttack`（持有区卡不在对账范围）；交战命中帧的 `HpChanged`/`ArmorChanged`（Impact 时机语义，同步进账本、对账缝对其零发射）。
- **首见静默对齐**：账本某通道为 null（存档恢复、测试直摆盘面等无生成事件入场）时首次对账按当前 oracle 播种、不发事件；账本随 `ActionPipelineSystem.Clear()` 复位，卡离场（CardKilled/CardRemoved）即删条目，uid 复用安全。

### 批次 ack（PresentationSyncSystem）

`ActiveBatchId` 是打开中批次的唯一真相；`FinishBatch` 批次号不匹配发 `Evt_PresentationBatchFinishRejected` 并拒绝。**无阻塞指令的批次也须 FinishBatch 关闭**（IsInputLocked 只表示"含阻塞指令"，不等于"批次开着"）。`Clear()` 供跨局/导演硬清兜底（`InitialGameFactory` 调用，防 IsInputLocked 粘连拒掉 StartNode）。

### 快照（CoreViewSnapshot）

每次建批全量捕获：`RunView`（相位/节点/层/房/种子）、`PlayerView`（金币/互动数/遗物/Avatar 双值属性）、`BoardView`（9 格逐格 uid+双值数值+祝福标记；Avatar 格特判并入）、`DeckView`（四容器 uid 列表）、`ChoiceView`（待决选择全量）、`Cards`（场上+四容器可见卡的 CardView）。表现层 Opening 白名单 SyncFromCore 即消费此快照；战中禁止直读对账（ADR-0005）。

## 关联 ADR

- ADR-0001（统一时间线 / Batch-ack）、ADR-0005（卡面数值表演锚点提交；表现层仍不对账）、ADR-0045（Core 发射侧统一对账缝，废除手工补扫）、ADR-0007（多处理器统一表现管线的消费侧约定）、ADR-0018（EffectTriggered=Impact 驱动基础触发表现）、ADR-0035（倒计时投影 Settled 提交）。

## 不变量与坑

- **映射表穷尽 + None 必写理由**：`PresentationEventMapEntry` 构造器直接抛异常；新增事件类型漏配会在 `PresentationEventMap.Get` 抛 `InvalidOperationException`。
- **拒收命令绝不开批**——历史 bug 教训写在 Dispatcher 注释里。
- `numbers 不累加`：数值类指令携带结算后绝对值，卡面赋值不做增量叠加（CONTEXT「结算指令」）。
- `EventLog` 只增不裁剪（Clear 仅整体重置）：长局内存持续增长，日志导出与批切片都依赖全局 Sequence 稳定。
- `CoreViewSnapshot.Version` 是各 Model Version 的**算术和**——只用于变更检测提示，不可当精确脏区判定。
- **对账不变量（ADR-0045）**：任意动作批执行完毕后，按表现层消费语义重放事件日志得到的卡面值 == oracle 重算值（回归护栏 `CardFaceReconciliationRegressionTests`）；对账提交事件位于其因果动作事件窗口内（自身事件之后、`ActionFinished` 之前）；diff 后才发事件，同值不发。
