# 03 属性与规则修正管线（Stats）

> 本篇覆盖：`Domain/Stats/` 全部 6 个文件与 `Systems/StatSystem.cs`。文件基准路径：`Assets/Scripts/NineGrid.Foundation/NineGrid.Core/`。

## 职责综述

两条并行的修正管线：

- **StatModifier 管线**：作用于单卡 `StatBlock`，把基础值（base）加工成**有效值**（effective）——攻击、护甲、上限血等。
- **RuleModifier 管线**：作用于全局 `RuleModifierRegistry`，回答"某条规则此刻数值是多少"——伤害乘区/平板/减免、先手还击、禁反击、门、魔免、嘲讽、虚拟邻接等（`RuleId` 全集见 `CoreEnums`）。

两者共享同一套三层求值顺序（Persistent → Conditional → Temporary）、同一套 Op（Add / Multiply / Override）、同一套条件接口 `IStatCondition` 与作用域清理（`ModifierScope`）。

## 关键类型表

| 类型 | 文件 | 一句话职责 |
|---|---|---|
| `StatBlock` | `Domain/Stats/StatBlock.cs` | 单卡属性容器：base 字典 + StatModifier 列表；按来源/作用域批量移除 |
| `StatModifier` / `RuleModifier` | `Domain/Stats/StatModifier.cs` | 修正器：Stat（或 Rule）+ Op + Value + Layer + Source + Scope + 可选条件；StatModifier 另支持 ValueProvider 动态求值 |
| `StatPipeline` | `Domain/Stats/StatPipeline.cs` | 有效值求值：base → 按 Persistent/Conditional/Temporary 三层逐个套用激活修正器 |
| `IStatCondition` 与 14 个实现、`StatEvaluationContext` | `Domain/Stats/StatConditions.cs` | 修正器激活条件（在某格/血量低于/邻接/目标 uid/行动来源/排除前缀…）与求值上下文（Owner/Registry/Board/Player/ActionSource/Actor/Target） |
| `RuleModifierRegistry` | `Domain/Stats/RuleModifierRegistry.cs` | 全局规则修正器表：三层求值 `Evaluate`；`Consume` 移除并回收 Once 作用域修正器 |
| `StatArmorUtility` | `Domain/Stats/StatArmorUtility.cs` | 三层护甲读写：基础甲（Armor base）/ 有效甲（管线）/ 当前甲（CurrentArmor base，无键时回退基础甲） |
| `IStatSystem` / `StatSystem` | `Systems/StatSystem.cs` | 对外门面：CreateContext、GetEffectiveValue/Int、增删修正器、EvaluateRule |

## 核心流程与数据流

### 有效值求值

```
GetEffectiveValue(card, stat):
  value = card.Stats.GetBase(stat)
  for layer in [Persistent, Conditional, Temporary]:
    for m in card.Stats.Modifiers where m.Stat==stat && m.Layer==layer && m.IsActive(ctx):
      value = ApplyOp(value, m.Op, m.EvaluateValue(ctx))   // Add/Multiply/Override
  return value
```

- 同层内按**添加顺序**套用；`Override` 直接替换当前累计值。
- `StatEvaluationContext` 每次求值新建（`StatSystem.CreateContext`），可携带 `ActionSource(actionName, sourceDefId, cause)`、`Actor`、`Target`——这是 `ActionSourceCondition` / `ExcludeSourcePrefixCondition` 等条件的取材来源（如"仅玩家出手时生效"）。

### 规则求值与消费

- `EvaluateRule(rule, baseValue, ctx)`：与属性同构的三层求值，遍历全局注册表中匹配 rule 且条件激活的修正器。典型用法：`DealDamageAction` 对受击方求 `DamageMultiplier`（乘区，基值=伤害）→ `DamageFlatDelta`（平板，基值 0）→ `DamageReduction`（减免，基值 0）。
- `Consume(rule, scope, ctx, out consumed)`：把匹配且激活的修正器**移除**并返回——`ModifierScope.Once` 的一次性乘区（庇佑 ×0、暴力 ×2）在伤害结算时被消费，随后 `DealDamageAction` 反查 `source id` 以 `effect:` 前缀反激活对应效果实例。
- 布尔型规则（FirstStrike / CounterAttackBanned / DoorProtection / MagicImmunity / HolyDuel / ActionBanned / GlobalMonsterAdjacency）约定 `Evaluate(rule,0)>0` 即持有；针对单卡的挂载用 `TargetUidCondition` 限定 Owner。

### 三层护甲（StatArmorUtility，ADR-0028）

| 层 | 存取 | 语义 |
|---|---|---|
| 基础护甲 | `StatId.Armor` base | 出生值与永久成长（`ModifyBaseStat(Armor)`） |
| 有效护甲 | 管线求值 | 基础 + 遗物/图腾等修正；节点开始时用于重置当前甲；HUD 显示层 |
| 当前护甲 | `StatId.CurrentArmor` base | 本关可消耗缓冲；受伤优先扣、局内 GainArmor/TransferArmor 只动它；卡面「甲」显示层 |

`GetCurrentArmor` 在无 `CurrentArmor` 键时回退基础甲——因此改基础甲前必须先取样当前甲（`ModifyBaseStatAction` 的注释即此坑）。

### 作用域清理（谁在何时清）

| Scope | 清理时机 |
|---|---|
| `Permanent` | 不自动清（随实例销毁/效果 Deactivate 时按记录回收）；新局开局 `InitialGameFactory` 整表 `RuleModifiers.Clear()`——registry.Clear 后 uid 复用不再误命中旧局按 uid 挂的规则（禁反击、神圣决斗等残留） |
| `UntilBattleEnds` | `BattleScopeSystem.EndCurrentBattle`（交战窗口关闭）；清关 `ClearNodeTransientModifiersAction` 一并清 |
| `UntilEnemyChanges` | `BeginPlayerMonsterEngagement` 换敌时；清关一并清 |
| `Once` | 结算路径 `Consume`；清关一并清 |
| `UntilNodeEnds` | 清关 `ClearNodeTransientModifiersAction`（`CompleteNodeIfCleared` 内，NodeCompleted 之后）；`PhaseSystem.StartNode` 开局兜底清理（#116）保留 |

清关的统一重置（「对战残留不出局」）：`ClearNodeTransientModifiersAction` 清上述四档临时修正 + `ResetCurrentArmorAction` 把当前甲回落到有效甲——非对战相位卡面即恢复干净数值，玩家卡面攻回落由统一对账缝提交（ADR-0045）；放在 `NodeCompleted` 之后，保证 OnNodeEnd 类效果先在原数值语境下结算。

## 对外通信面

- `IStatSystem` 是全 Core 读属性/规则的唯一门面；`EffectiveStatQuery`（第 1 篇）是表现层只读入口。
- 修正器的增删主要经 `AddStatModifierAction` / `AddRuleModifierAction` / 效果系统 Activate（Modifier / RuleModifier 类效果），少数系统路径直接调 `IStatSystem`（遗物 run 贡献重装、Trap 静默 CounterAttackBanned）。

## 不变量与坑

- **求值无缓存**：每次读有效值都全量遍历修正器；修正器数量大时是热点，但保证条件类修正（邻接光环等）实时正确。
- `RuleModifierRegistry` 是**全局单表**：挂"针对某卡"的规则必须带 `TargetUidCondition`，忘带就是全场生效。
- `StatModifier.ValueProvider` 非空时 `Value` 字段被忽略（DSL `value` 为表达式对象时走此路径）。
- `AttackTargetRestriction`（嘲讽）的 Value 语义特殊：存的是**嘲讽者 uid** 而非布尔（`EffectSystem.ResolveRuleModifierValue` 自动以 Owner uid 填值；`PhaseSystem.ResolvePlayerAttackTargetUid` 直接把求值结果当 uid 用）。
- `StatConditions` 中 `SourceAdjacentToUidCondition` 与 `OwnerAdjacentHasCardCondition` 已对齐 `IBoardSystem.AreAdjacent` 的虚拟邻接语义——后者对怪-怪邻接额外认 `MonsterBoardRules.HasVirtualAdjacency`（双向）与天涯若比邻（`HasGlobalMonsterAdjacency`），链接近战等怪技不再漏判；其余邻接条件（AdjacentCondition 等）只看几何正交——扩展邻接类效果时注意选对条件。
- 当前甲不是修正器管线的产物，而是独立 base 值；任何"读甲"逻辑先想清楚要哪一层。
