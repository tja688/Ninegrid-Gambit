# NineGrid.Content — 内容层总览

> 源码考古文档。仅依据 `NineGrid.Content` / `NineGrid.Content.Editor` 源码与 `Assets/Tools/Luban` 文件名结构整理；不引用策划 Docs。

## 1. 定位

`NineGrid.Content` 是 **玩法内容数据装载与表现元数据** 层：

- 把「卡牌 / 效果 / 遗物 / 技能 / 奖励 / 房间 / 经济」填充为 Core 定义的 `GameContentCatalog`
- 把「内容描述 / 框色 / 图标卡面」组装为 Content 自有的 Visual / FrameStyle / Sprite Catalog
- **不**实现战斗、效果 DSL 解释、奖励抽取逻辑（这些在 `NineGrid.Core`）

`NineGrid.Content.Editor` 是 Editor-only 工具集：从手写 Catalog 导出 Luban 源数据、配图窗口、xlsx 读写、迁移菜单、Regenerate Luban。

## 2. 程序集与依赖

| asmdef | 平台 | references |
|--------|------|------------|
| `NineGrid.Content` | Runtime | `NineGrid.Core`, `Luban.Runtime` |
| `NineGrid.Content.Editor` | Editor | `NineGrid.Core`, `NineGrid.Content`, `Luban.Runtime` |

根命名空间：`NineGrid.Content` / `NineGrid.Content.Editor`。  
生成代码命名空间：`cfg` / `cfg.tablenine`（Luban 输出，位于 Content 程序集内）。

## 3. 手写 vs 生成边界

```
NineGrid.Content/
├── ContentAssemblyMarker.cs          ← 手写（空标记）
├── Catalog/**                        ← 全部手写
└── Generated/Luban/**                ← 全部 Luban 自动生成（文件头 <auto-generated>）
```

| 边界 | 事实 |
|------|------|
| 手写 Catalog | 定义运行时目录类型、Bootstrap、Factory、Resolver、Sprite SO |
| 生成 `cfg.Tables` + `Tb*` + `*Row` | 仅反序列化 JSON 表；不引用 Core 类型 |
| Factory 桥接 | `TableNineLubanCatalogFactory` / `TableNineVisualCatalogFactory` / `TableNineCardFrameStyleCatalogFactory` 把 `cfg.*` 行映射成 Core / Content 运行时对象 |
| 回退源 | `TableNineContentCatalog.CreateDefault()` 纯 C# 硬编码同一套玩法内容（Auto 模式下 Luban 不可用时回退） |

## 4. Catalog vs Generated

| 维度 | Catalog（手写） | Generated/Luban |
|------|-----------------|-----------------|
| 职责 | 运行时可用对象、查询 API、Bootstrap 策略 | 表行 Bean + 表容器 |
| 玩法内容目标类型 | `NineGrid.Core.Content.GameContentCatalog` 等 | `cfg.tablenine.*Row` |
| 表现内容目标类型 | `ContentVisualCatalog` / `CardFrameStyleCatalog` / Sprite SO | `ContentVisualRow` / `CardFrameStyleRow` |
| 谁消费谁 | Factory 读 Generated，写出 Catalog | 被 Factory / Editor 读取 |

数据流（玩法内容）：

```
Hardcoded: TableNineContentCatalog.CreateDefault()
       → GameContentCatalog
       ↘ Editor: TableNineLubanDataExporter → Assets/Tools/Luban/Datas/*.json

Luban:    StreamingAssets/.../tablenine_tb*.json
       → cfg.Tables
       → TableNineLubanCatalogFactory
       → GameContentCatalog

Bootstrap: ContentCatalogBootstrap.Load(Auto|Luban|Hardcoded)
```

数据流（表现）：

```
xlsx (content_visual / card_frame_style)
  → gen_table_nine → StreamingAssets JSON + Generated 代码
  → TableNineVisualCatalogFactory / TableNineCardFrameStyleCatalogFactory
  → ContentVisualCatalog / CardFrameStyleCatalog
  → ContentVisualResolver(+ SpriteCatalog SO) → ContentVisualResolvedView
```

## 5. 与 Core 的边界

| Content 做 | Core 做（Content 只依赖其类型） |
|------------|--------------------------------|
| 填充 / 加载 `GameContentCatalog` | 定义 `GameContentCatalog`、`CardContentDefinition`、`ContentEffectDefinition`、`RewardConfig`、`EconomyConfig` 等 |
| 解析效果 JSON 字符串为表字段并挂到定义上 | 解释效果 DSL、战斗与奖励系统 |
| `ContentVisual*`、框色、Sprite Catalog | 不拥有视觉目录类型 |
| 枚举字符串 → Core 枚举（`CardKind`、`ContentRarity` 等） | 拥有这些枚举与玩法语义 |

Content **不反向**被 Core 引用；Core 通过注入的 `GameContentCatalog` 使用内容。
