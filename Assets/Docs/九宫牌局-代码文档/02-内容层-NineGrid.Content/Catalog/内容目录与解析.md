# Catalog — 内容目录与解析

> 覆盖 `NineGrid.Content/Catalog/**` 全部手写类型：玩法 Catalog 装载、表现 Catalog、Sprite SO、解析 API。

## 1. 两类运行时目录

| 目录 | 目标类型 | 数据来源 | 用途 |
|------|----------|----------|------|
| 玩法内容 | `NineGrid.Core.Content.GameContentCatalog` | 硬编码 / Luban 玩法表 | 战斗与流程消费的定义 |
| 表现元数据 | `ContentVisualCatalog` + `CardFrameStyleCatalog` + Sprite SO | Luban 视觉表 + Arts SO | UI/卡面显示 |

玩法与表现 **分离**：`TableNineLubanCatalogFactory` 不读 `TbContentVisual`；`TableNineVisualCatalogFactory` 不产出 `GameContentCatalog`。

## 2. 玩法内容：装载入口

### 2.1 `ContentCatalogSourceKind` / `ContentCatalogBootstrap`

| 路径 | 类型 | 职责 | 关键依赖 |
|------|------|------|----------|
| `Catalog/ContentCatalogBootstrap.cs` | `ContentCatalogSourceKind` | `Hardcoded` / `Luban` / `Auto` | — |
| 同上 | `ContentCatalogBootstrap` | 目录探测与加载 | Luban Factory / Hardcoded Catalog |

**目录探测** `ResolveLubanDataDirectory()` 候选（按序，首个同时存在目录且含 `tablenine_tbeffect.json` 者胜出）：

1. `Application.streamingAssetsPath/TableNine/LubanData`
2. `Environment.CurrentDirectory` + `TableNineLubanCatalogFactory.DefaultDataRelativePath`（`Assets/StreamingAssets/TableNine/LubanData`）
3. `AppDomain.CurrentDomain.BaseDirectory/TableNine/LubanData`
4. BaseDirectory 向上相对到 `Assets/StreamingAssets/TableNine/LubanData`

**`Load(source, lubanDataDirectory)` 行为：**

| source | 行为 |
|--------|------|
| `Hardcoded` | 直接 `TableNineContentCatalog.CreateDefault()` |
| `Luban` | `TryLoadLubanCatalog`；失败抛 `InvalidOperationException` |
| `Auto`（默认） | 先试 Luban；失败回退 Hardcoded |

`TryLoadLubanCatalog`：目录无效或 IO/Unauthorized → `false`；成功则 `TableNineLubanCatalogFactory.CreateFromDirectory`。

### 2.2 `TableNineLubanCatalogFactory`

| 路径 | 类型 | 职责 | 关键依赖 |
|------|------|------|----------|
| `Catalog/TableNineLubanCatalogFactory.cs` | `TableNineLubanCatalogFactory` | JSON 目录 → `cfg.Tables` → `GameContentCatalog` | `cfg.Tables`, Core.Content |

**公开 API：**

- `DefaultDataRelativePath = "Assets/StreamingAssets/TableNine/LubanData"`
- `CreateFromDirectory(string)`：`new cfg.Tables(file => LoadJson(...))`，`LoadJson` 读 `{dataDirectory}/{file}.json`
- `CreateFromTables(cfg.Tables)`：映射入口

**映射步骤（顺序固定）：**

1. `AddEffects` ← `TbEffect`
2. `AddCards` ← `TbCard`
3. `AddSkills` ← `TbSkill`
4. `AddRelics` ← `TbRelic`
5. `AddRewards` ← `TbRewardPool` + `TbRewardEntry`
6. `AddMonsterDecks` ← `TbMonsterDeck`
7. `AddNodeDeckRules` ← `TbNodeDeckRule`
8. `AddRooms` ← `TbRoom`
9. `ApplyEconomy` ← `TbEconomy.GetOrDefault("default")`

**字段映射要点：**

| Luban 行 | Core 目标 | 关键转换 |
|----------|-----------|----------|
| `EffectRow` | `ContentEffectDefinition` | `ContainerType`/`State` → 枚举；`Json`/`DesignText` 原样 |
| `CardRow` | `CardContentDefinition` | Kind/Rarity 枚举；Stats；`Tags`/`EffectIds`/`SkillIds` 按 `;|\|,` 切分 |
| `SkillRow` | `SkillContentDefinition` | ContainerType 枚举；EffectIds 切分 |
| `RelicRow` | `RelicContentDefinition` | Rarity；Tags/EffectIds 切分 |
| `RewardPoolRow` | `RewardPoolDefinition` | Id + PickCount |
| `RewardEntryRow` | `pool.Add(...)` | 按 PoolId 挂入；Kind 枚举 |
| `MonsterDeckRow` | `MonsterDeckDefinition` | Kind 枚举；MonsterDefIds 切分 |
| `NodeDeckRuleRow` | `NodeDeckRule` | DeckKind 枚举 |
| `RoomRow` | `RoomDefinition` | Kind → `RoomKind` |
| `EconomyRow` | `catalog.Economy.*` | 仅 id=`default` |

**未使用的 Generated 表：** `TbContentVisual`、`TbCardFrameStyle`（由视觉 Factory 消费）。

### 2.3 `TableNineContentCatalog`（硬编码权威副本）

| 路径 | 类型 | 职责 | 关键依赖 |
|------|------|------|----------|
| `Catalog/TableNineContentCatalog.cs` | `TableNineContentCatalog` | 纯代码填充默认玩法 Catalog | Core.Content / Effects |

**公开 API：** 仅 `CreateDefault()`。

**内部填充管线：**

1. `AddEffects` — 大量 `Impl(...)`，效果 JSON 由 `Triggered` / `Modifier` / `Rule` 字符串拼装；状态固定 `ContentImplementationState.Implemented`
2. `AddHelpCards` — `help.*` + `CardKind.HelpCard`
3. `AddRelics` — `relic.*`
4. `AddMonsterSkills` — `skill.*`，`EffectContainerType.MonsterSkill`（原玩家技能已并入 `AddRelics`）
5. `AddMonsterCards` — 六套 `MonsterDeckDefinition` + 怪物卡 + 技能挂接
6. `AddRewardsAndRooms` — 奖励池、房间权重、节点 1–9 组牌规则；经济沿用 `EconomyConfig` 默认值（本方法不写 Economy 字段）

**辅助工厂：** `Help` / `Relic` / `Skill` / `Deck` / `Monster` / `AddNodeRule` / `Impl` / `Triggered` / `Modifier` / `Rule` / `TypeTag`。

**与 Luban 关系：** Editor 的 `TableNineLubanDataExporter` 以本 Catalog 为源写出 `Assets/Tools/Luban/Datas/*.json`，再经 gen 脚本进入 StreamingAssets。

## 3. 表现 Catalog

### 3.1 数据类型

| 路径 | 类型 | 职责 | 关键依赖 |
|------|------|------|----------|
| `Catalog/ContentVisualKind.cs` | `ContentVisualKind` | Unknown, HelpCard, Monster, Relic, Skill, Room, MonsterDeck, Avatar, ChoiceOption | 无 |
| `Catalog/ContentVisualDefinition.cs` | `ContentVisualDefinition` | `ContentId` / `Kind` / `Description`（只读属性） | Kind |
| `Catalog/ContentVisualCatalog.cs` | `ContentVisualCatalog` | `Add` / `TryGet` / `Entries` | Definition |
| `Catalog/ContentColor.cs` | `ContentColor` | R/G/B/A float；`White` 常量 | 无 |
| `Catalog/CardFrameStyleDefinition.cs` | `CardFrameStyleDefinition` | StyleId + Color | ContentColor |
| `Catalog/CardFrameStyleCatalog.cs` | `CardFrameStyleCatalog` | Add/TryGet；预置 style 常量与 `RequiredStyleIds` | Definition |

**预置框色 ID：**

| 常量 | 值 |
|------|-----|
| `StyleWhite` | `frame.white` |
| `StyleBlue` | `frame.blue` |
| `StyleGold` | `frame.gold` |
| `StyleRed` | `frame.red` |
| `StyleNormal` | `frame.normal` |
| `StyleElite` | `frame.elite` |
| `StyleBoss` | `frame.boss` |

### 3.2 Factory / Bootstrap

| 路径 | 类型 | 职责 | 关键依赖 |
|------|------|------|----------|
| `Catalog/TableNineVisualCatalogFactory.cs` | `TableNineVisualCatalogFactory` | TbContentVisual → ContentVisualCatalog；`LoadTables` 共用 | cfg.Tables |
| `Catalog/TableNineCardFrameStyleCatalogFactory.cs` | `TableNineCardFrameStyleCatalogFactory` | TbCardFrameStyle → CardFrameStyleCatalog | Visual.LoadTables |
| `Catalog/ContentVisualBootstrap.cs` | `ContentVisualBootstrap` | 同时加载 visual+frame；要求两 JSON 均存在 | 上述 Factory |

`ContentVisualBootstrap.TryLoad`：需存在 `tablenine_tbcontentvisual.json` 与 `tablenine_tbcardframestyle.json`。  
`Load()` 失败抛 `InvalidOperationException`。  
`ResolveLubanDataDirectory()` 直接委托 `ContentCatalogBootstrap`。

### 3.3 `ContentVisualResolver`

| 路径 | 类型 | 职责 | 关键依赖 |
|------|------|------|----------|
| `Catalog/ContentVisualResolver.cs` | `ContentVisualResolver` | 合成 `ContentVisualResolvedView` | Core Catalog + Visual + Frame + SpriteProvider |
| `Catalog/ContentVisualResolvedView.cs` | `ContentVisualResolvedView` | 最终展示 DTO | Sprite, ContentColor |

**`TryResolve(contentId, core, visual, frame, spriteProvider, out view)`：**

1. 从 `visualCatalog` 取 `ContentVisualDefinition`（缺则失败）
2. `ResolveFrameStyleId`：按 Kind 查 Core 卡/遗物稀有度或 Boss/Elite → styleId
3. `spriteProvider.TryGetDirectSlots(kind, id, out slots)`（可为 null；含主图标/背景/卡背三件套）
4. 组装 DisplayName（来自 Core）与 Description（visual 空则回退 DisplayName）

**框色规则摘要：**

- HelpCard / Relic：稀有度 → white/blue/gold/red
- Monster：Boss → `frame.boss`；Elite → `frame.elite`；否则 `frame.normal`
- 其他：`frame.normal`

**DisplayName 特例：** Avatar → `"玩家"`；ChoiceOption：`Attack`/`Armor`/`Hp` → 中文选项名；Room 将 contentId 解析为 `RoomKind`。

## 4. Sprite Catalog（ScriptableObject）

| 路径 | 类型 | 职责 | 关键依赖 |
|------|------|------|----------|
| `Catalog/ContentVisualSpriteCatalogSO.cs` | `ContentVisualSpriteEntry` | contentId + icon/face + backBorder/Shirt/Logo | Unity |
| 同上 | `ContentVisualDirectSlotSprites` | 直暴露五项结构体 | — |
| 同上 | `IContentVisualSpriteProvider` | `TryGet` + `TryGetDirectSlots` | Kind |
| 同上 | `ContentVisualSpriteCatalogSO` | 抽象 SO：查找、回退 icon、EnsureEntry、ApplyDefaultFace | Entry |
| 同上 | `ContentVisualSpriteCatalogSet` | 六类 SO 引用集合；按 Kind 分派 | 具体 SO |
| `Catalog/ContentVisualSpriteCatalogBootstrapSO.cs` | `ContentVisualSpriteCatalogBootstrapSO` | Resources 路径 `ContentVisual/SpriteCatalogBootstrap` | CatalogSet |
| `Catalog/HelpCardVisualCatalogSO.cs` | `HelpCardVisualCatalogSO` | Kind=HelpCard | 基类 |
| `Catalog/MonsterVisualCatalogSO.cs` | `MonsterVisualCatalogSO` | Kind=Monster | 基类 |
| `Catalog/RelicVisualCatalogSO.cs` | `RelicVisualCatalogSO` | Kind=Relic | 基类 |
| `Catalog/SkillVisualCatalogSO.cs` | `SkillVisualCatalogSO` | Kind=Skill | 基类 |
| `Catalog/MiscVisualCatalogSO.cs` | `MiscVisualCatalogSO` | Kind 属性返回 Avatar；Set 中 Avatar/Room/MonsterDeck 共用本 SO | 基类 |
| `Catalog/ChoiceOptionVisualCatalogSO.cs` | `ChoiceOptionVisualCatalogSO` | Kind=ChoiceOption | 基类 |

**`ContentVisualSpriteCatalogSet.ResolveCatalog`：**

| Kind | SO 字段 |
|------|---------|
| HelpCard | `helpCards` |
| Monster | `monsters` |
| Relic | `relics` |
| Skill | `skills` |
| ChoiceOption | `choiceOptions` |
| Avatar / Room / MonsterDeck | `misc` |
| 其他 | null |

**运行时查询：** `TryGetWithFallback` — icon 空时用 `FallbackIcon`；face **不**自动用 `DefaultFace`（DefaultFace 仅编辑器一次性 `ApplyDefaultFaceToAllEntries`）。

**引导：** `ContentVisualSpriteCatalogBootstrapSO.TryLoadCatalogSet()` → `Resources.Load` 常量路径。

## 6. Luban 表 → 运行时可用内容（一句话流程）

1. 源数据在 `Assets/Tools/Luban/Datas`（JSON 玩法表 + xlsx 视觉表）  
2. `gen_table_nine` 生成 StreamingAssets 的 `tablenine_tb*.json` 与 `Generated/Luban` 代码  
3. 运行时 `ContentCatalogBootstrap` / `ContentVisualBootstrap` 定位 LubanData 目录  
4. Factory 经 `cfg.Tables` 读表并映射为 Core / Content Catalog 对象  
5. UI 再经 `ContentVisualResolver` + Sprite Catalog SO 得到最终 `ContentVisualResolvedView`
