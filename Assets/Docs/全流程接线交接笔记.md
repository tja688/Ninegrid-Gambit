# 全流程接线落地 · 交接笔记

> 目标：把「主菜单 → 序章/战斗0 → 岛屿 → 路线 → 事件 → 战斗N → …→ 胜利结算 → 主菜单」这条**流程主干**跑通并可循环。
> 本轮**只做流程接线与必要的小状态机/子系统**，不碰伤害结算、强化叠加、仓库、金币等**核心数值逻辑**——这些留了明确的接轨点，见文末「交接要点」。

## 0. 先读这条：Play 模式「帧 1 冻结」是测试假象，不是 bug

排障期一直卡在「进 Play 后画面停在第 1 帧、`Update` 只跑一次」。**根因不是代码**：

- `ProjectSettings > Player > Run In Background` 原为 **关闭**（`runInBackground: 0`）。
- 当 Unity 编辑器窗口**失去 OS 焦点**（我全程用 MCP 后台驱动、窗口不在前台），**Player Loop 会整体暂停**，只有 Editor Loop 还在跑（所以 MCP 仍能响应、`editor_state` 仍在刷新，造成「没卡死但游戏不动」的错觉）。
- 已修复：**开启 `runInBackground`**（现为 `runInBackground: 1`，落在 `ProjectSettings.asset`）。开启后失焦实测 CPU 从 ~1% 跳到 200%+，游戏正常推进。

**结论**：正常在编辑器里（窗口有焦点）点 Play 一直是好的。若以后又遇到「Play 不动」，先确认窗口有没有焦点 / `runInBackground` 有没有被改回去，再怀疑代码。排障期加的诊断日志、心跳、临时脚本 `NinegridEditorQuickFix.cs` 均已清理。

## 1. 架构主干：GameFlow 只管状态，SceneFlowDirector 管场景

原来的 `GameFlowController` **不加载场景**（`Advance()` 只改 `CurrentState`）。本轮新增了一个常驻编导把「状态」翻译成「真实场景加载 + 节点入场」：

```
GameFlowController (状态机, 常驻)
        │  StateChanged(prev, next)
        ▼
SceneFlowDirector (常驻, 本轮新增)
        ├─ 按 GameFlowScenes.GetSceneName(state) 加载场景（黑场淡入淡出）
        ├─ 场景就绪后调 GameFlowController.RunNodeEntry(state)（触发序章演出 / 战斗入场）
        ├─ 战斗态：订阅 BattleController.BattleFinished → 自动 Advance()
        └─ 过场态(Event*/Victory)：不加载专属场景，短暂停留后自动 Advance()
```

### 关键改动
- `GameFlowController`
  - 新增静态开关 `DeferNodeEntry`：为 true 时 `OnEnterState` 不自己跑节点入场，交给编导（`SceneFlowDirector` 在 `RuntimeInitialize(BeforeSceneLoad)` 里置 true）。
  - 新增 `IsBooted` 属性 + `Boot()` 结束时**补发一次 `StateChanged`**（QFramework 的 `FSM.StartState` 只触发 `OnEnter`、**不触发** `OnStateChanged`，外部订阅者收不到开局状态，这里手动补）。
  - 节点入场逻辑抽成 `public RunNodeEntry(state)`，供编导在场景加载完成后调用。
  - 战斗/序章入场统一走 `StartBattleEntrance(bool includeDialogue)`：序章 `true`（含教学对话），其余战斗 `false`（只播船只入场、无对话）。
- `SceneFlowDirector`（新增，`Assets/Scripts/GameFlow/SceneFlowDirector.cs`）
  - `PersistentMonoSingleton` + `RuntimeInitializeOnLoadMethod` 自举：**任何场景都不用手动挂**，运行时自动建常驻实例（场景里已放也会复用）。
  - 自带一层最高 `sortingOrder` 的黑场 Canvas 做过渡蒙版（代码生成，无需美术）。
  - `Event1..6`、`VictorySettlement` 作为**过场节点**：不加载专属场景。Event 立即推进；Victory 弹一条通关提示（`victoryHold` 秒）后回主菜单。
  - `OnBattleFinished(won)` 目前**不分胜负**，一律推进下一节点（真实胜负判定见交接要点）。

> 注意：`GameFlow.md` 里「不自动加载场景 / 战斗结束暂不 Advance()」两句已过时，以本文与 `SceneFlowDirector` 为准。

## 3. 单场景行为速查

- **主菜单（MainMenu）**：点「开始」→ `StartNewRun()` → 进序章/战斗0。
- **序章/战斗0（MainScene）**：`ProloguePerformance` 播船只入场（序章含 `prologue_intro` 对话）→ `BeginBattlePhase()` 交 `BattleController`。
- **战斗（MainScene 复用）**：
  - 点敌人**撞击**前必须**先锻造出钻头**，否则弹提示拦截。
  - 每成功撞击一次消耗船锚一格（`AnchorHpTracker`），累计 3 次 → 胜利 → `BattleFinished(true)` → 编导 `Advance()`。
  - 锻造：`ForgeStationController` 三按钮驱动 `HydraulicSceneController`；材料在常规进出间保留，锻造成功后 `ForgeCommitted` 触发钻头出现（`BoreManager`）。
- **岛屿（IslandScene）**：精炼厂 / 船坞面板缓动开合；「离开」→ `Advance()` 进路线。
- **路线（RouteScene）**：多「事件」点，任选其一 → `Advance()`。
- **事件（Event*）**：占位过场，编导直接推进到下一战斗。
- **胜利结算（VictorySettlement）**：弹通关提示 → 回主菜单。

## 4. 交接要点：接轨真实战斗 / 数值 / 经济（后续要做的）

这些是本轮**故意留的占位**，接真实逻辑时从这里下手：

1. **胜负判定**
   - 现在战斗是「撞满 3 次锚 = 胜」的占位，且 `SceneFlowDirector.OnBattleFinished` **不看 won**。
   - 接真实战斗后：`BattleController` 依据敌我血量/回合结算真实 `won`；`OnBattleFinished(false)` 应走 `NotifyPlayerDefeated()`（失败结算/回主菜单），而非无脑 `Advance()`。

2. **伤害 / 强化叠加**
   - 目前锻造只驱动「钻头是否出现」这一门禁，**不计算任何数值**。
   - `Assets/ScriptableObjects/Data` 下有全部矿石与强化 SO 资产（原汇总脚本丢失、SO 仍在）。接轨时需要：重建/补一个「汇总目录」入口（`ScriptableObject` 或运行时注册表），把 SO 读进战斗数值系统；`HydraulicMaterialBoard` 的砧位占用（已暴露查询接口）就是「本次锻造投入了哪些材料」的数据源。
   - `HullModSlotsController` / `HoverNoticePresenter` 现在显示占位文案，接真实强化数据后替换 `message` 来源。

3. **仓库 / 金币 / 经济**
   - 岛屿的精炼厂、船坞面板目前只有**开合动画**，无背后数据。接仓库/金币系统时在 `IslandController` 的面板里挂真实 UI 与数据绑定。
   - 矿石库 `OreInventoryPanel` 同理，现为纯 UI 开合，待接真实库存。

4. **事件系统**
   - `Event*` 现为空过场。要做真实事件（抉择/奖励/风险）时，把它从「过场节点」改成「加载事件场景/面板」：在 `SceneFlowDirector.IsPassThrough` 里移出，并给它一个场景或面板控制器，结束时自己 `Advance()`。

5. **路线分支**
   - `RouteController` 现在所有事件点都等价地 `Advance()` 到同一下一节点（线性）。真实分支（不同路线→不同战斗/事件）需要在这里根据被选点决定 `ForceState(...)` 目标。

6. **存档 / 全局强化**
   - 项目里有 Easy Save 3；跨节点的强化累积、金币、run 进度都还没接存档。真实数值系统落地时一并规划持久化。

### 6.3 伤害公式（与 web 完全一致）

```
totalDamage = floor( Σ_slots [ (Σ_cards finalValue) × slotMultiplier ] × extraMultiplier )

card finalValue = (baseValue + permanentBonus + battleBonus + tempBonus)    // getCardBaseValue
                + [预热: 下方预热矿给 floor(源点数/2)]                        // ON_CALC_VALUE
                + [合群: 相邻格每张+1] [齐心: 同格每张+1]
                × [熔核: ×2]                                                  // ON_CALC_FINAL
                + 叠牌 cardBonus                                               // 每4张起+1

slotMultiplier = 1 + roundBonus + 叠牌 slotBonus                               // 每2张+1
```

叠牌表（web `getStackingBonus`）：
| 砧台矿石数 | slotBonus | cardBonus |
|-----------|-----------|-----------|
| 0-1 | 0 | 0 |
| 2-3 | 1 | 0 |
| 4-5 | 1 | 1 |
| 6-7 | 2 | 1 |
| 8-9 | 2 | 2 |
| 10 | 3 | 2 |

### 6.4 战斗循环（Unity 映射）

```
战斗开始(EnterBattle → ResetBattleState → InitBattle: 建牌库/洗牌/设HP)
  → Active 状态
  → 点击玩家船 → 进入锻造(HydraulicScene.Enter)
  → EnterCompleted → AutoDeliver(5): 管道自动出货5块(从矿舱抽到桌面)
  → 拖拽矿石到砧台 → OnPlacedOnAnvil: 淬火触发(永久+GrowAmount)
  → 显示屏实时显示 前/中/后+合计 伤害预览
  → 点击锻造按钮 → PlayHydraulic → 锤头下压前 OnForgeCommitted:
      ├─ 读砧台 GetAnvilStacks + 桌面 GetTableCards
      ├─ CombatModel.CommitForge → 算 totalDamage → 存 PendingRamDamage
      └─ 全部矿石入矿渣堆(消耗)
  → 锤头落位 → 钻头亮起(ShowBores) → 场景退场 → 回主场景
  → 点击敌人 → 抛锚 → 互撞演出 → OnRamSucceeded:
      ├─ CombatModel.ApplyRam → 敌舰扣 PendingRamDamage
      ├─ 敌死 → _won=true → ExitBattle(胜利)
      ├─ 敌活 → 玩家挨1锚(ConsumeOne) → 玩家死 → ExitBattle(失败)
      └─ 都活 → 钻头隐藏 → 玩家可再进锻造(下回合)
          └─ 重洗矿渣堆→矿舱(BeginTurn) → 下回合进锻造时 AutoDeliver(5)
```

1. **船体改造（HullMod）**：`HullModDataSO` / `HullModCatalog` 已有资产但未接入战斗。web 的 relic 效果（`slot_bonus` 冲击龙骨 +1 倍率、`turn_monster_damage` 小型撞角 50/turn 等）未实现。`ExtraMultiplier` 默认 1，`slotUpgrades` 默认 [0,0,0]。接入时在 `CombatModel.InitBattle` 里读 relic 列表、设 `SlotState.Multiplier` 和 `State.ExtraMultiplier`。

### 6.8 验证方式
