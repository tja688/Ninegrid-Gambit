# 00 · 架构总览

> 权威代码事实快照 · 2026-08-12。综合 `CONTEXT.md`、`docs/code-map/`、43 篇 ADR 并抽查代码写成；与代码冲突时以代码为准。

## 1. 一句话画像

《Ninegrid Gambit（九宫牌局）》：Unity 6.3 LTS · URP 2D · 像素风卡牌 Roguelike。玩法核心是一块 3×3 九宫格棋盘：玩家 Avatar 常驻其上，怪物/机关/道具卡被发到格位，玩家通过「九宫格互动」（交战、拾取、点空格）推动战斗；跑图由 3 层 × 每层 8 个地图节点构成，战斗房以击破「离开机关卡」为唯一清关手段。

## 2. 分层架构


## 3. 核心运行循环（Run → Floor → Node → Battle）

进度真相全部在 Core（ADR-0021）：`RunModel`（`NineGrid.Core/Models/RunModel.cs`）持 Floor / NodeIndex / Seed / 本层主题卡组；表现层壳（`GameFlowShellSystem`）只读投影。

1. **开局**：主菜单 `GameFlowController.BeginFormalRun` → `GameFlowRunOptions.CreateFormal`（QuickTest 走 `CreateQuickTest`、读档走 `CreateRestore`、教学走 `CreateTutorial`——「载荷即模式」范式）→ `GameFlowOrchestrator.Start`。首次游玩无教学完成标记时先派教学局（ADR-0042）。新开局种子由 Guid 派生（`InitialGameOptions.CreateForNewRun`），非 Seed=1 锁死。
2. **跑图**：3 层 × 8 节点（`MapNodeProgression`，Core/Domain）。节点 4/7 非战斗（4=离开导航、7=层主房战前缓冲），不进 `InteractionLoop`；其余节点：战斗 → 奖励 → 清关后放房间图标 → 玩家 BoardWalk 踩图标驻留 1 秒进下一房（ADR-0019/0020）。消费房（商店/卡店/奖励房）是「场地即交互面」的就地货架会话，不是浮层。
3. **战斗节点**：`GameFlowOrchestrator.PlayRealBattleAsync` → 捕获存档检查点（ADR-0041，`BuildNodeDeckOptions` 消耗 RNG 之前）→ `RewardSystem.BuildNodeDeckOptions`（怪物侧按主题卡组序列抽卡 + 常规机关 3 张 + 离开机关编入；玩家侧固定卡 + 来源池随机 + 房间注入，ADR-0022/0026/0030）→ `StartNode` 开局发牌 → `InteractionLoop`。
4. **清关**：击破离开机关卡是唯一清关手段（ADR-0026）；真怪清零不清关。清关拍清残场、按条件兑金，进 `RoomChoice` 放下一批图标。
5. **终局**：第 3 层节点 8 清关 → Victory；Avatar HP≤0 → Defeat（ADR-0039 硬不变量）。`ShowBattleEndAndReturnAsync` 结算面板 → 清检查点与自动存档 → 回主菜单。

## 4. 关键架构范式（均已抽查代码核实）

### 4.1 统一时间线 + Batch-ack（ADR-0001）

战斗表演收敛为唯一串行 `BattleTimeline`，由 `PresentationDirector` 独占（均在 `NineGrid.Presentation/Flow/Presentation/`）。Core 解算不再一口气算完整局，而是被拆成一拍一 Batch，经 `PresentationSyncSystem`（`NineGrid.Core/Presentation/`）的 OpenBatch/FinishBatch 由表演**就位回执（ack）**驱动前进——「请 Core 解算下一批」与「播一段表演」在同一条时间线交替。逻辑占格真相唯一在 Core `BoardModel`；表现侧只持几何注册（格位→认领者）。特效/音效退化为发即完成的脉冲 Trigger，不占主线 ack。

### 4.2 Command / Query / Event（QFramework）

- 写 → `NineGridArchitecture.Interface.SendCommand(...)`（`Presentation/Commands/` 25 个写意图）；
- 读 → `SendQuery` / `GetSystem<T>()` 只读 API（`Queries/` 11 个）；
- 下→上 → struct Event（多在 `Flow/Presentation/`）或 BindableProperty；
- 编排 → `PresentationDirector` / `BattleTimeline` / `IPresentChannel` 普通 C# 深模块，由 System 持有。
- 静态 `*Hook`（约 20 个）是 Cards/Flow 目录 ↔ Controllers 的**装配缝**（避免历史环依赖），不是业务 Sink；禁止新增跨层读写规则状态的静态 Sink。

### 4.3 IntentIntake 两轴门禁（ADR-0004）

所有玩家输入唯一经 `IntentIntakeSystem`（`Presentation/Systems/IntentIntakeSystem.cs`）收口，按两个正交轴裁决：**时序互斥**（`PresentationDirector.IsMainlineBusy` 唯一互斥真相）×**输入所有权**（受保护场地/场地覆层/棋盘选择模式，`PresentationInputStateSystem` 只读投影）。主线忙时棋盘动作一律 Reject（strict-drop，不缓冲）；忙时额外点击发「冲动轻点」脉冲给当前 no-op 的加速通道。门禁内禁用壁钟。

### 4.4 卡面 Commit 与统一表现管线（ADR-0002/0005/0007/0018）

卡面显示值**只**来自结算指令（`PresentationBatch.Instructions`，数值为结算后绝对值），在表演锚点（Impact/Settled，`NineGrid.Core.PresentationBeat`）经唯一分发出口 `BattleBeatScheduler` → 第一个认领的 `IBattleBeatHandler`（卡面数值 `CardFaceStatHandler`、HUD、飘字/FX/金币装饰）提交；锚点归属统一登记在 `PresentationEventMap`（Core）。禁止队列外直读 Core 写卡面；无兜底、无强制对账。触发可见因果（ADR-0018）：效果后果上屏前其触发条件必须已可见。

### 4.5 命中与场地交互（ADR-0006/0023/0024/0020）

Windows Player 高回报率鼠标走 `RIDEV_NOLEGACY` + 轮询注入（`Platform/WindowsHighPollingMouseMitigation.cs`）；命中统一 `PointerHitRouter` 轮询 `IPointerHitTarget`，禁 `OnMouse*`。九宫格命中权威是场景格位命中框（九框恒开），棋盘作单一「场地面」注册（`GroundFieldHitSurface`），格位→认领者查 `SlotClaimRegistry`，一格一认领者、命中恒成功、合法性交 IntentIntake。落格对象尺寸权威在预制体，不 SetParent 到格位锚点。

### 4.6 内容单一权威（ADR-0008/0009/0010/0014）

一卡一文件 JSON（`Assets/Arts/ContentVisual/cards/`，双写镜像至 StreamingAssets）是内容唯一权威；Luban 与内容 SO 已废除；美术经单一 `Assets/Resources/` 根加载。效果为参数化模板 + 卡上装配引用（实参含稳定装配 id）；效果责任自陈（requires=装配错误级 / conditions=玩法级），无外部场域门禁。`contentId`/`deckId` 的主题英文是历史残留不透明主键，不是世界观。`ContentHygieneValidator` 承担索引↔磁盘、双写、断链、描述契约等卫生校验。

### 4.7 战斗规则要点（ADR-0011/0012/0013/0016/0017/0028/0034/0038）

- **攻击模式**是怪物卡必填内生几何属性（正交/斜角/全向/无），不进效果 DSL；节奏由卡级节奏源（行动/移动计数二选一）+ 节奏周期 X + 共享倒计时决定（`CardRhythm.cs`），归零即一次性开火窗口，同拍触发单向打击与技能同步触发。
- **敌方行动阶段**是报名→逐条结算→收尾的齐射（`PhaseSystem`），阶段内盘面冻结，每只怪一拍一 Batch。
- **牌面朝向**权威在 Core（`FaceUp`），背面双向惰性（不可伤、不开火、被动默认失效、倒计时冻结）。
- **机关卡** `CardKind.Trap` 双桶：可交战桶（Monster|Trap）vs 真怪物桶（仅 Monster，赏金/清关分母），集中在 `CardCombatRules`（Core/Domain）。
- **标准伤害公式**：乘区平板 → 伤害减免（`RuleId.DamageReduction`）→ 当前护甲吸收（金甲只抵甲伤）→ 扣血；三层护甲（基础/有效/当前）；无视护甲是单次伤害标记。
- **盘面稳定化**归 Core `IBoardStabilizationSystem`（唯一欠补位裁决），表现侧 `BoardStabilizationScheduler` 按「Resolve → Present → ack」逐轮推进。

### 4.8 音频 / VFX 双体系（ADR-0036/0040）

同构四层：稳定语义声明（`AudioCueAttribute` / `VfxCueAttribute`）→ 持久化绑定 JSON 单一真源（`Resources/audio/audio_bindings.json` / `Resources/VFX/vfx_bindings.json`）→ 运行时系统（`AudioSystem` / `VfxSystem`，均安装在主菜单生命周期）→ 浏览器调音工作台（Editor localhost）。业务只经 `TriggerPulseHub` 发 cue，不直调 MMSoundManager/播放器；BGM 走唯一期望音乐状态（`MusicSystem`），只由流程层提交。VFX 分附着型/独立型 Pulse 与持续视觉槽状态，失败留痕不回退、不占主线。

### 4.9 存档与平台（ADR-0041/0043）

存档颗粒度=战斗开始检查点（快照含 RNG 内部状态，恢复=重建+覆盖+RNG 还原，重跑发牌即复现开局）；快照 DTO 在 Core（`RunSaveGame.cs`），落盘经 `IRunSaveStore` 装配缝 → ES3 桥 →（有 Steam 时）云镜像装饰器。Steam 成就/平台信息走 `Flow/Platform/` 门面，后端缺位安全 no-op。详见 [`Platform桥接/`](Platform桥接/README.md)。

### 4.10 诊断关联层（ADR-0003，proposed）

表演诊断两级关联键：`chainId`（一次 InputIntent 脚本生命周期，罩住全部连锁 Batch）+ `choreoSeqId`（单动作内栈式展开，`Flow/Diagnostics/ChoreoTraceContext.cs`）。九套 Recorder（Battle/Flow/Perf/Registry/Director/Choreo…）作为输出汇，Play 结束导出 `Assets/Notes/Logs/`；日志分析用技能 `table-nine-battlelog-analysis`。

## 5. 验证与护栏现状

开发冲刺期（2026-08）原自动化测试整体清空后，仅恢复 `NineGrid.Presentation.Tests`（Editor-only，29 个文件）：音频/VFX 结构护栏与契约（`AudioStructureGuardTests`、`VfxStructureGuardTests` 等）+ `AvatarVitalityInvariantTests`（ADR-0039）。其余结构约束（IntentIntake、卡面 Commit、指针输入等）现靠 ADR + code-map 文字约定。默认验证门槛：recompile 后 Console 无新增 Error；手动 Play / QuickTest `\0`–`\9` 通道。
