# 装配与场景绑定（Setup/）

> 覆盖范围：`Assets/Scripts/NineGrid.Presentation/Setup/` 全部 4 个文件。
> 本篇是"游戏跑起来时，表现层的所有 System / Controller / Hook 是谁、在哪一刻接上的"的权威地图。

## 职责综述

`Setup/` 是表现层的**唯一生产装配入口**。三个类各司其职：

- **`PresentationSceneRoot`**（MonoBehaviour，场景组件）：MainScene 上恰好一个，持有全部场景宿主的 SerializeField 引用，负责 Hook 接线（`WireHosts`）与 Runtime 生命周期（`EnsureInstalled` / `ShutdownRuntime`）。
- **`PresentationCompositionRoot`**（纯 C# 类）：把 Present 通道、意图剧本工厂、战斗锚点排期器、全部 QF System 组装成一台可运行的表现 Runtime。
- **`PresentationSceneBindings`**（不可变数据类）：场景宿主引用快照，组合根 Install 的输入。

## 关键类型表

| 类型 | 文件 | 一句话职责 |
|------|------|-----------|
| `PresentationSceneRoot` | `Setup/PresentationSceneRoot.cs` | 场景组合根组件：持宿主引用、Hook 接线、Runtime Install/Tick/Shutdown 的唯一驱动者 |
| `PresentationCompositionRoot` | `Setup/PresentationCompositionRoot.cs` | 生产装配：Present 通道 × 剧本工厂 × BattleBeatScheduler × System 注册 |
| `PresentationSceneBindings` | `Setup/PresentationSceneBindings.cs` | 宿主绑定快照（InBattle 必填，其余可空），不持运行时状态 |
| `DisplayModeBootstrap` | `Setup/DisplayModeBootstrap.cs` | Player-only 窗口引导：按桌面分辨率选 16:9 窗口档位（1080p→1600x900，2K+→1920x1080）强制窗口化；`WindowRenderSync` 把 Win32 客户区尺寸同步到 `Screen.SetResolution`，驱动 PixelPerfect 整数倍缩放 |

## 核心流程

### 1. 场景启动（主菜单阶段）

`PresentationSceneRoot`（`DefaultExecutionOrder(-100)`，继承 `PresentationController`）在 `Awake → OnBind` 时执行 `WireHosts()`：

1. **应用会话级 System 先注册**（跨主菜单到跑图存活）：`PlayerAudioSettingsSystem.EnsureRegistered()`（重放玩家音量偏好）→ `LanguageSettingsSystem.EnsureRegistered()`（ADR-0046：注册即读 PlayerPrefs 语言偏好并装载对应翻译表）→ `MusicSystem.EnsureRegistered()` → `VfxSystem.EnsureRegistered()`。
2. `inBattle.BindSceneHosts(cardManager, cardDeck, groundField, relicManager, cardHand, fieldBattle, mainGameLoop)`——`BattleSessionController` 的依赖一律由此注入，源码禁 `FindObjectOfType` / `GameObject.Find`（#141 装配卫生）。
3. 按宿主是否存在逐个 `RequestWire` 静态 Hook：
   - `CardEntityLifecycleHook`（cards/hand/deck 三 Manager）
   - `GroundFieldGeometryHook` / `ExploreInputHook` / `BoardWalkInputHook` / `AvatarBoardFacingHook`（groundField）
   - `FieldBattlePresentationHook` / `AttackInputHook`（fieldBattle）
   - `UseItemInputHook` / `PickupInputHook` / `RecycleItemInputHook`（cardHand）
   - 无宿主参数的：`GameFlowShellHook`、`RoomChoiceCoreHook`、`RewardChoiceCoreHook`、`RelicHudHook`
4. `EnsureInstalled` 输出类 Controller：`DamageNumberOutputController`、`TriggerPulseOutputController`（并立即 `ConfigureProductionDefaults()`——**主菜单阶段即完成 FX/audio/VFX 三线 TriggerPulseHub 装配**）、`DiagnosticOutputController`、`GoldGainPresentationBinder`。
5. 流程壳 View **不在这里 Bind**：`GameFlowController.Awake` 自绑定 `GameFlowShellSystem`（单入口，避免双 Bind）。

另外 `OnBind` 里把自己的 `EnsureInstalled` / `ShutdownRuntime` 交给 `inBattle.BindRuntimeLifecycle(...)`，并订阅 `TeardownPresentationDirectorRequested` 事件（由 `SetGameFlowShellStateCommand` 在回主菜单 / 胜负 Notice 时发出）→ 收到即 `ShutdownRuntime`。

### 2. 局内开始（战斗 Runtime 安装）

`EnsureInstalled()`（由 `BattleSessionController` 经 lifecycle 委托调用）幂等执行：

```
BuildBindings() → PresentationCompositionRoot.Install(bindings)
```

`Install(PresentationSceneBindings)` 的生产装配顺序：

1. `BattleSessionSystem.EnsureRegistered` 并 `Bind(bindings.InBattle)`。
2. 造 `CoreCommandDispatcher`。
3. 造 **6 条 Present 通道**并 `session.BindPresentChannels(...)`：
   - `explorePresentChannel`、`attackBoardPresentChannel`、`useItemBoardPresentChannel`：三个 `QueuedBoardPresentChannel`，回调 `session.DrainPostKillBoardAsync`；
   - `attackHitPresentChannel`（`CombatAttackPresentChannel`）→ `IFieldBattlePresentationSystem.PlayDirectorAttackHitPresentAsync`，finally 兜底 `session.EnsureBattleEndedIfAvatarDefeated`（ADR-0039）；
   - `attackCounterPresentChannel`（`CombatCounterPresentChannel`）→ `PlayDirectorCounterPresentAsync`，同样兜底战败收口；
   - `useItemPresentChannel`（`UseItemPresentChannel`）→ `session.PlayDirectorUseItemPresentAsync`。
4. 造 **意图剧本工厂**并组装 `RoutingIntentScriptFactory`（八路）：`ExploreIntentScriptFactory`、`RevealFaceIntentScriptFactory`、`AttackIntentScriptFactory`、`UseItemIntentScriptFactory`、`NonCombatUseItemIntentScriptFactory`、`PickupIntentScriptFactory`、`RecycleItemIntentScriptFactory`、`BoardWalkIntentScriptFactory`（工厂本体在 `Flow/Presentation/`，属兄弟文档范围）。
5. `TriggerPulseOutputHook.RequestConfigureProduction()`（幂等重申三线装配）。
6. `InstallCore(...)`：
   - `EnsureRegistered` 全套 System：`PresentationInputStateSystem`、`IntentIntakeSystem`、`BattleSessionSystem`、`ChoicePresentationSystem`、`BoardSelectionSystem`、`GameFlowShellSystem`、`MusicSystem`、`AvatarWalkSystem`（实现在 `Flow/`）；
   - `InstallBattleBeatScheduler`（见下）；
   - 取或建 `PresentationRuntimeSystem` 并 `Start(scriptFactory, uiPickPreview, DirectorTrace.TimelineSink, new BoardBufferedIntentLegality(arch))` → 内部 new 出 `PresentationDirector`（唯一时间线所有者）。
   - **冲突保护**：若已有一个 `IsStarted` 的 Runtime，直接抛 `InvalidOperationException`，不接管既有运行时。

### 3. 战斗锚点排期器（ADR-0005 / ADR-0007）

`InstallBattleBeatScheduler` 用**固定顺序**注册六个 `IBattleBeatHandler`：

```
PlayerInfoHudBeatHandler → DamageFloaterBeatHandler → CardFaceStatHandler
→ CardFaceFlipBeatHandler → EffectTriggerPulseBeatHandler → GoldGainBeatHandler
```

顺序是硬约束（代码注释明示）：**飘字必须排在卡面处理器之前**——`Healed` 的 `UpdateHp` 由 `DamageFloaterBeatHandler` 旁路飘绿字并 return false，否则被 `CardFaceStatHandler` 先认领后治疗飘字永远收不到指令；`PlayerInfoHudBeatHandler` 对 Avatar 血甲只旁路写 HUD 也 return false。装配后把 scheduler 的方法逐个挂到 `BattleBeatHook`（`OnBatchOpened` / `ReportBeat` / `PresentStandalone` / `FlushUpdateFaceUp` / `FlushImpactExcept` / `QuarantineImpactWhere` / `ReleaseQuarantined`），并订阅 `Evt_PresentationBatchOpened` → `BattleBeatHook.NotifyBatchOpened`。同时 `FlipPlaybackCoordinator.Reset()`。

### 4. 每帧 Tick

`PresentationSceneRoot.Update()`：仅在已安装时，`IPresentationRuntimeSystem.Tick(deltaTime)`（驱动 Director/Timeline）+ `IVfxSystem.Tick(deltaTime)`（驱动 VFX 实例推进）。**VFX 的 Tick 与战斗 Runtime 同源于此**，但 VfxSystem 本身注册于主菜单阶段——注意 `Update` 里 `mInstalled==false` 时直接 return，即**主菜单阶段 VfxSystem 得不到 Tick**（主菜单目前无 VFX 消费者，若未来主菜单要播 VFX 需另找 Tick 源，见"坑"）。

### 5. 关停

`Shutdown(reason)`：拆排期器（`BattleBeatHook.Reset()` + `FlipPlaybackCoordinator.Reset()`）→ `TriggerPulseOutputHook.RequestResetFx()`（**只重置旧 FX 通道**，audio/VFX 通道保持应用会话，ADR-0036/0040）→ `IVfxSystem.ClearSceneInstances()`（只清附着型实例）→ `session.ClearPresentChannels()` → `runtime.Stop(reason)`（内部 ForceEndExternalHold + HardClearIntents）。

## 对外通信面

- **入口事件**：`TeardownPresentationDirectorRequested`（订阅方是 SceneRoot 本体）。
- **对 BattleSessionController**：`BindRuntimeLifecycle(EnsureInstalled, ShutdownRuntime)` 委托对。
- **对静态 Hook 矩阵**：`WireHosts` 是所有 `*Hook.RequestWire` 的唯一生产调用点。
- **对 QF Architecture**：System 注册均经 `EnsureRegistered`（幂等），无第二注册入口。

## 关联 ADR

ADR-0001（时间线/Batch-ack：Director 由此装配）、ADR-0004（IntentIntake 注册于此）、ADR-0005/0007（排期器与处理器注册顺序）、ADR-0016（FlipPlaybackCoordinator Reset）、ADR-0036/0040（音频/VFX 应用会话生命周期）、ADR-0039（Present 通道 finally 战败收口）。

## 不变量与坑

- **MainScene 恰好一个 `PresentationSceneRoot`**；`PresentationSceneBindings` 只持存活宿主（#141；`DescriptionManagerSingleton`、`GoldGainFxManagerSingleton` 字段已删，禁复活）。
- **组合根不可重复 Install**：已有已启动 Runtime 时抛异常而不是接管——排查"Presentation runtime is already registered and started"报错时，找重复 EnsureInstalled 的调用方（通常是关停路径没走完）。
- **排期器 Handler 顺序是行为语义**，不是随意列表；调整顺序会静默改变治疗飘字/HUD 行为。
- 关停时只 `ResetFx`，不 Reset audio/VFX Sink——若在关停后听不到声音/看不到 VFX，问题不在这里。
- `Update` 只在 `mInstalled` 后 Tick：主菜单阶段 `IVfxSystem.Tick` 不执行（潜在坑，见上文第 4 节）。
- `PresentationSceneBindings` 构造要求 `inBattle` 非空（ArgumentNullException），其余宿主可空——可空宿主缺失时对应 Hook 不接线、功能静默缺失，注意场景引用完整性。
