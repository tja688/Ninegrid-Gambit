# 输入门禁与平台守护

> 覆盖范围：根目录 `PresentationInputGates.cs`、`PresentationMainlineHold.cs`；
> `Systems/` 下输入门禁五件套（`IIntentIntake` / `IntentIntakeSystem` / `InputOwner` / `IPresentationInputStateSystem` / `PresentationInputStateSystem`）；
> `Platform/` 下 2 个 Windows 平台守护。共 9 个文件。
> 这是 **ADR-0004 两轴门禁**的实现全景：任何"点了没反应 / 点了两次 / 忙时怪态"类 bug 先看这里。

## 职责综述

所有玩家输入意图**只有一个入口**：`IIntentIntake.Submit`。它按两个正交轴裁决：

- **轴一（时序互斥）**：`MainlineBusy`——唯一互斥真相，来自 `PresentationDirector.IsMainlineBusy`（经 `PresentationRuntimeSystem` 只读投影）。主线忙时棋盘动作一律 `Reject`（strict-drop，不缓冲）。
- **轴二（输入所有权）**：`InputOwner`——此刻哪个表面拥有输入。意图被接纳须满足"目标表面 == 当前所有者"。

`PresentationInputGates` 是 Cards/Flow 宿主读门禁、写 external-hold 的静态薄门面；`PresentationMainlineHold` 是"须阻塞输入的表演挂主线租约"的便捷封装。`Platform/` 两个文件与门禁无关，是 Windows Player 的输入兜底与卡死取证。

## 核心流程与数据流

### IntentIntakeSystem.Submit 裁决顺序（逐行对齐实现）

```
1. targetSurface != CurrentOwner ？
     → 忙时先发冲动轻点（IAccelerationSink.Tap），然后 Reject("ownerMismatch")
2. mainlineBusy → 对当前所有者的每次点击发冲动轻点（后续仍可能 Reject）
3. IsBoardAction(kind)（Explore/Attack/Pickup/UseItem/RecycleItem/RevealFace/BoardWalk）：
   3a. UseItem 且无已选卡且 defId 属 MultiBoardSelect → RouteToBoardSelect（忙时 Reject）
   3b. Attack 且孤儿局中奖励 Pending（PendingChoiceModel.Reward 有候选、ChoiceOverlay 未激活、
       相位 InteractionLoop/RewardItemChoice）→ Reject("orphanMidBattleReward")
   3c. Core 合法性：BoardIntentLegality.TryExplainXxx（按 kind 分派；可注入 override 供测试）
       不合法 → Reject(具体 reason)
   3d. mainlineBusy → Reject("mainlineBusy")【strict-drop，先查合法性再查忙】
   3e. Pickup → 返回 Allow（由调用方 ExternalHold→Apply，不进 Director）
   3f. 其余 → runtime.TrySubmitIntent(intent) → Allow
4. IsModeOrModal(kind)：
   4a. BoardSelectBegin：忙时 Reject，否则 Allow
   4b. 奖励/房间模态（SelectRoom/EnterRoom/SelectReward/SkipHelpChoice/RefreshShop/DiscardRelic…）：
       忙时【例外】——owner==ChoiceOverlay 且 ChoiceOverlayActive 时仍放行
       （局内宝箱 Bounce 挂在 UseItem Present 主线上等待点选；拒掉会孤儿 Pending + 粘死 IsInputLocked）
5. 未知 kind → Reject("unknownKind")
```

拒绝时 `Reject()` 统一走 `BoardIntentGateDiagnostics.Collect` 富化原因、`DirectorTrace.IntentRejected` 打点、`Debug.LogWarning("[IntentIntake] Reject ...")`——排查输入问题直接搜 Console 的 `[IntentIntake] Reject`。

### 所有权轴的写入纪律

`PresentationInputStateSystem` 的 `SetOpening/SetChoiceOverlay/SetBoardSelect` **只声明"该表面在索取"**，门禁只认折算后的 `CurrentOwner`。生产写入一律经 Command（`SetOpeningPresentationGateCommand` 等，见《06-Commands与Queries》），入口是 `PresentationInputGates.SetOpening/SetChoiceOverlay/SetBoardSelect/Reset`。

`ResetGates`：清三布尔 + `BoardCardSelectModeController.End()`（防静态选卡会话与门禁布尔分裂后 `CurrentOwner` 粘在 BoardSelect）+ `ChoreoTraceContext.ClearOccupancyDesyncLatch` + `runtime.ForceEndExternalHold`。`PresentationInputGates.Reset` 还额外 `BattleUiDimmerOverlay.ForceClear` + `CardInspectOverlayPresenter.CloseIfOpen`。

### MainlineBusy 与 ExternalHold

- `MainlineBusy` 真相链：`PresentationDirector.IsMainlineBusy` → `PresentationRuntimeSystem.MainlineBusy`（BindableProperty，每次操作后 `PublishBusy`）→ `PresentationInputStateSystem.MainlineBusy` → `PresentationInputGates.MainlineBusy`。`BattleBusy`/`FieldBusy` **不是**门禁输入（ADR-0004）。
- **ExternalHold（主线租约）**：须阻塞输入但不走 Step 的表演（Pickup Apply、Drain、奖励 Drain、局内宝箱 Bounce 等）经 `BeginDirectorExternalHoldCommand` 在 Director 上挂 Hold step。`PresentationMainlineHold.TryAcquire(reason, out acquiredHere)`：已有外层 hold 则复用（acquiredHere=false），否则 TryBegin；`Release` 只在 acquiredHere 时 End。**ForceEnd** 仅供 Reset/关停路径。

### `PresentationInputGates.BattleUiOverlayActive`

只读投影 `BattleUiDimmerOverlay.IsActive || CardInspectOverlayPresenter.IsOpen`——局内 UI 叠层**挡射线但不改 CurrentOwner、不暂停主线**（与两轴门禁正交的第三类"视觉遮盖"）。

### Windows 高回报率鼠标兜底（ADR-0006）

`#if UNITY_STANDALONE_WIN && !UNITY_EDITOR` 编译隔离；`RuntimeInitializeOnLoad(BeforeSceneLoad)` 自举 DDOL GameObject，命令行 `-ng-no-rawinput` 可整体关闭（排除法用）。流程：

1. **NOLEGACY 状态机（2026-08-14 修订）**：聚焦且光标在客户区内 → `RIDEV_NOLEGACY`；聚焦且光标在标题栏/边框 → `RIDEV_REMOVE`（禁止 `dwFlags=0`）；**失焦 → 保持 NOLEGACY 不改注册**（防 Alt-Tab 切回 WM_MOUSE 洪水）。`WM_ACTIVATE`/`WM_SETFOCUS` 经 WndProc 子类化抢先重开 NOLEGACY。`onBeforeUpdate` 只做 `GetCursorPos` 注入；失焦不注入。窗口句柄：`GetForegroundWindow` + `MainWindowHandle` 一次缓存。
2. `InputSystem.onBeforeUpdate` 里 `GetCursorPos + ScreenToClient + GetAsyncKeyState`（左/右/中键）拼 `MouseState` → `InputSystem.QueueStateEvent(Mouse.current)`。
3. Win32 客户区 Y 向下 → Unity Y 向上翻转（`Screen.height - point.Y`）。

`WindowsHighPollingMouseMitigationInfo` / `WindowsHighPollingMouseMitigationRuntime` 为编译无关标记与看门狗可读快照。

### Windows 卡死看门狗

同样编译隔离 + `BeforeSceneLoad` 自举；`-ng-no-watchdog` 禁用、`-ng-hang-dump-seconds=N`（≥5）调 dump 阈值（**默认 5s**）。机制：

- 主线程 `Update`/焦点回调喂心跳；后台线程（BelowNormal，500ms 轮询）检测停滞。
- Debugger attached / 失焦且不后台运行 → 不算卡死。
- 停滞 ≥2s → 双写 `stall-in-progress.txt`（杀进程也保留）；停滞 ≥阈值 → 文本报告 + `MiniDumpWriteDump`；恢复后 `stall-recovered-*.txt` + `stalls-<session>.txt` 流水。
- **双写目录**：exe 旁 `GameLogs/HangReports/`（试玩优先）+ `persistentDataPath/HangReports`；启动写 `watchdog-alive-<session>.txt`。
- 托管/原生未处理异常 → `crash-*.txt`（尽力 dump）。报告含 `nolegacyActive` / `nativeFocus` 等 mitigation 快照。
- 保留最近 3 个 dmp、12 个 txt（每目录独立 prune）。
- game1 Development 打包自动写入试玩说明 txt 与 `启动游戏.bat` / `启动-关闭鼠标兜底.bat` / `收集诊断包.bat`。

## 对外通信面

- **收口消费方**：全部 `Submit*IntentCommand`（Commands 篇）与 `PickupInputController` / `RelicHudController` / `RoomChoiceInputController` / `RewardChoiceInputController`（直接调 `intake.Submit`）。
- **门禁读口消费方**：`IntentIntakeSystem` 自身、Cards/Flow 各 Presenter（经 `PresentationInputGates`）。
- **冲动轻点**：`IAccelerationSink`（默认 `NoOpAccelerationSink`，未来"多点即加速"的预留缝，可经 `SetAccelerationSink` 注入）。
- **测试缝**：`SetLegalityOverride`（跳过 Core 棋盘合法性）、`PresentationInputStateSystem.EnsureRegistered(arch)`。

## 不变量与坑

- **禁止任何输入路径绕过 IntentIntake**（ADR-0004 硬约束；此条**没有**对应的结构护栏测试，靠纪律与评审——注意音频/VFX 侧的结构护栏测试仍在生效，见《10》，勿混为一谈）。
- **strict-drop**：忙时棋盘动作直接丢，不缓冲、不 latest-wins（2026-08 修订，防快速连点触发两次行动）。
- **合法性先于忙判**（3c 在 3d 前）：忙时的非法点击拒绝原因是具体 illegal 理由而非 mainlineBusy，看日志时注意。
- **模态例外**：ChoiceOverlay 持有 + 激活时模态命令忙时放行——这是刻意的（局内宝箱 Bounce），别当 bug"修"掉。
- **门禁决策禁壁钟**：只依赖事件顺序 + 注入 deltaTime；未来 debounce/加速需注入时钟。
- `OccupancyDesyncLatched` 只是诊断断言，不是运行时门禁。
- Pickup 的次序纪律：**Allow → ExternalHold → Core Apply**，不得先改 Core 再抢锁（见 `PickupInputController` 注释）。
- 看门狗/鼠标兜底只在 Win Player 生效；Editor 复现不了这两条路径的问题。
