# 02 · 卡面文案、描述投影与检视

> 权威代码事实文档 · 生成于 2026-08-12 · 修订 2026-08-13（卡面图标 hover 靶表）· 覆盖 `Cards/Presentation/` 全部 17 个 .cs。

## 职责综述

本子域是卡面**可读内容**的消费端：把 Flow 侧构造的胖投影快照（`CardPresentationSnapshot`）按 Kind 路由到卡面模板节点（图标、名字、数值、描述、朝向），并实现 ADR-0035/0037 的描述体系——检查描述经**唯一投影缝** `CardFaceDescriptionProjector` 填装配初始实参后恒静态显示；`[[展示名]]`/`[code]` 双括号语法经 `CardFaceDescriptionComposer` 渲染为 TMP 富文本（内联图标打成运行时 SpriteAsset）；右键详述的「详细效果」区改为词条行（`CardGlossaryTerms` 抽词条 → `CardInspectGlossaryListView` 装行，首行留给图标 hover 解释槽，靶表见 `CardFaceIconGlossaryTargets`）。翻牌动画由 `CardFaceFlipPresenter` 忠实采样 Flip.anim 在 FacePivot 上播放。

## 核心流程与数据流

### 1. Binder 消费投影（`CardFacePresentationBinder.ApplyPresentation`）

1. `CaptureTemplateDefaultsIfNeeded`：首次记录模板自带的槽默认 Sprite 与模板描述文案（缺内容时兜底）。
2. `ApplyMainIcon`：内容图标优先，null 回退模板默认（不清空）。
3. `ApplyDirectSprites`：FaceBackground/Back 三件套/CardFrame/Banner——snapshot 为 null 的槽**不覆盖**（保留模板兜底，对应「卡背装配」缺省语义）。
4. `ApplyRarityVariants`：两组稀有度变体。①「卡框 / 横幅」槽节点下若存在「白 / 蓝 / 金」稀有度变体子节点（当前仅遗物卡标准模版），按 `snapshot.Rarity`（JSON `rarity` 投影，`ContentRarity`）只激活匹配的一个——White→白、Blue→蓝、Gold→金，Red（独特）暂无专属美术兜底金档，None/未知兜底白档。②`ApplySubIconRarityVariant`（ADR-0033 修订 2026-08-13）：「副Icon」节点下「高常规 / 中常规 / 低常规 / 特殊」档位子对象（当前仅道具卡标准模版）按 White→高常规、Blue→中常规、Gold→低常规、Red→特殊单选激活，None 整组隐藏。模板无变体子节点时均 no-op（其余 Kind 模板不受影响）。注意 `Rarity` 须随快照克隆透传（翻面/检视/数值提交/倒计时提交/作弊预览五处克隆点已补齐；编辑器预览走 `CardFacePreviewRequest.Rarity`）。
5. `EnsureFaceBackgroundHexMask`：遗物等六边框模板给矩形背景吃 Mask，防四角漏出。
6. `ApplyName` → `ApplyStats`（按 Kind 分支）→ `ApplyRhythmIconMatrix` → `ApplyBasicDescription` → `ApplyFaceOrientation` → `TryPlayIdleOrStatic`（主视觉动画，见 01 篇）。
7. `ApplyStats` Kind 路由：Avatar=攻+甲（不绑血）；Monster=攻甲血 + 行动计数（`HasActiveRhythm` 才显示，ADR-0038）；Trap=血 + `ShowActionCount` 门控的效果倒计时（ADR-0035）；道具/遗物默认不写数值槽。`SetNumeric` 在「有前值且变化」时对配对图标（`CardFaceSlotNodeMap.TryFindCompanionIcon`）播 1.1x 非阻塞脉冲——首次写入/同值重 Commit 不脉冲（Spawn、Bootstrap、视觉重刷不该跳）。
8. `ApplyRhythmIconMatrix`（仅 Monster）：有攻击模式 → 攻击模式槽按 `CardFaceAttackPatternIconResolver` 换三档近战图标；仅同步技能无模式 → 同步图标升格进攻击模式槽；皆无 → 隐藏。子图标 `Sync_Rhythm_Icon` 仅「攻击+同步」同时成立才亮（ADR-0038 图标矩阵）。

### 2. 基础描述装配（`ApplyBasicDescription`）

1. 空 `BasicDescription` 视为未接线：保留模板自带文案，不盖旧 ContentVisual 长文。
2. 以「描述源文本 + 可用图标指纹（含 catalog/style 实例与参数）」做变更检测，未变则跳过（防每次 Commit 重建 SpriteAsset）。
3. `CardFaceDescriptionComposer.Compose`：先 `ExpandDoubleBrackets` 把 `[[名字]]` 换成去括号明文（词条表命中且配色则包 `<color>`；未命中告警但仍去括号显示），再扫 `[code]`——装配槽注册表标记 `InsertableInDescription` 的代号只认高层 assembled 图标（catalog 不可反向覆盖），其余代号查词条表；命中转 `<sprite name="code">`，未命中保留原样（如 `[使用时]` 这类语义括号）。`[[词条]]` 匹配键 = 中文名 ∪ 各语言译名（ADR-0046 词条双键：未翻/已翻描述都不断链）；词条显示名与解释按当前语言取 glossary 表，缺键回中文。
4. 有内联图标时 `CardFaceDescriptionSpriteAssetBuilder.Build` 现打运行时 SpriteAsset（em 归一 + `SanitizePackedPixels` 反预乘防黑边 + 不可读贴图 Blit 拷贝），挂到 TMP 后写富文本。旧 SpriteAsset 走 `DestroyBuilt` 释放。

### 3. 描述令牌插值（`CardFaceDescriptionParamFiller`）

- 简单式 `{value}`：取第一个含该键的装配（仅兼容旧文案）。
- 限定式 `{qualifier.key}`：qualifier 与装配 `id`/`templateId` 精确或前缀（`qualifier.` 开头）匹配；多装配命中且取值不一致 → **歧义保留字面量**（作者须改精确限定式）。
- `remainingOverrides`（键=完整 `装配id.键`）命中时优先于初始实参——但 ADR-0035 阶段一后 `CardFaceDescriptionProjector.Project` 恒不传该参数，描述恒静态；带 override 的重载保留给机关 `ActionCount`/遗物计数投影路径解析初值（`EffectCountdownProjection` 在 Flow 侧）。

### 4. 右键详述（与 Flow `CardInspectOverlayPresenter` 协作）

1. 检查侧对场卡与 defId 路径都按 `Inspect` 模式重投影 `BasicDescription`（同文静态）。
2. `CardInspectDetailComposer.Compose`：faceIntro 优先取快照，缺则取 JSON `faceIntro` 并做实参插值；deckIntro 按 `deckId` 查表现 JSON（displayName+description/faceIntro），再回退玩法 Catalog `MonsterDecks.DisplayName`，最后回退 deckId 裸串（`ResolveDeckIntro` 内含 `monster_decks.json` display_name 的本地化兜底缝，与 deck JSON 共用 deckId 键，ADR-0046）。
3. 「详细效果」区：`CardGlossaryTerms.ExtractExplicitTerms` 抽 `[[词条]]`（未命中词条库仍出名字行，Matched=false）→ `CardInspectGlossaryListView.BindExplicitTerms` 克隆 `词条详细效果信息.prefab` 行；**首行**恒有一条 hover 槽（默认提示「将鼠标移到卡面预览中的图标上…」），预览卡面 hover 图标时 `ShowHoverTerm` 填临时解释、移出 `ClearHover`。
4. hover 覆盖两类图标（Flow `CardInspectIconHover` 驱动，见[检视篇 §4b](../Flow/09-指针命中、HUD与检视.md)）：描述里的 `[code]` 内联 sprite（按代号查表），以及卡面机制图标（`CardFaceIconGlossaryTargets` 按世界 AABB 命中、按词条名查表）。攻击模式与节奏源的词条名直接复用 `AttackPatternRules.Token*` / `CardRhythmRules.Token*`，不在表现层另抄中文。
5. 词条表资产 `Assets/Resources/Arts/Cards/CardFaceDescriptionIconCatalog.asset` 现状（2026-08-13）：共 84 条，按认知分区（基础属性 / 战斗规则 / 攻击模式与节奏 / 棋盘与位置 / 翻面 / 怪物技能 / 机关 / 道具与卡组 / 遗物与成长 / 怪物与流程）；`armor`/`basic_armor` 显示名已按 CONTEXT 口径改为「护甲 / 基础护甲」，`action` 改「行动计数」；卡面 JSON 已引用的全部 `[[…]]` 均有对应条目；「技能同步触发」为纯文字词条（无 code），只经卡面同步子图标 hover 到达。维护入口「NineGrid/表现层配置 → 词条」。

### 5. 翻牌（`CardFaceFlipPresenter`）

1. 关键帧硬编码自 PixelartCardTCG `Flip.anim`（9 帧阶跃采样：Y 0→-90→0 度、scale 1→1.2→1），`PlaybackSpeed=2` 实播约 0.222s，中点 `FaceSwapTimeSeconds` 切 front/back 显隐。
2. `PlayFlipAsync(targetFaceUp)`：`_playing` 期间重入直接 return（全局串行由 Flow `FlipPlaybackCoordinator` 负责排队）；起手保持当前可见面，逐帧 `SamplePose` 写 FacePivot localEuler.y 与 uniform scale，中点 `ApplyFaceOrientation` 切面；取消/结束都 `ResetPivotPose` 归零。
3. `SnapVisualFace`：无动画直接置面（对账/重放路径）。`VisualFaceUp` 是表现层本地可见朝向，规则朝向权威始终在 Core（ADR-0016）。
4. front/back 节点按名字（front/back/正面/背面/CardFront/CardBack）限深 8 层查找；`CardFacePresentationBinder.ApplyFaceOrientation` 亦有一份浅层显隐逻辑（Commit 直切路径），`RecordCommittedFaceUp` 供翻牌动画先记镜像后播视觉。

## 对外通信面

- **入**：`StandardCardView.ApplyPresentation` → Binder（01 篇）；Flow `CardFaceFlipBeatHandler`/`FlipPlaybackCoordinator` 驱动翻牌；Flow `CoreCardPresentationMapper` 与编辑器 `CardFacePreviewHost` 消费投影缝与 Composer。
- **出**：静态类只读 Content 层（`CardPresentationConfigCatalog`、`EffectAssemblyResolver`、`GameContentCatalog`）；不写 Core。
- **编辑器缝**：`SetInlineIconStyleOverride` / `SetDescriptionIconCatalogOverride` 允许配置编辑器注入未落盘草稿；`Invalidate*Cache` 改资产后清缓存。

## 不变量与坑

- **描述恒静态**：投影缝 `Project` 故意丢弃 mode 参数、不传 remainingOverrides——检查与实例同文；效果倒计时剩余只走机关 `ActionCount` 槽 / 遗物栏计数 TMP，禁止把「（还剩 X）」写回描述。
- **词条代号禁占装配槽保留名**：`IsReservedAssemblySlotCode` 覆盖全部 `CardFaceSlotCodes`；词条表 TryGet 对保留名直接拒绝。
- **`[code]` 解析优先级**：Insertable 装配槽（Main_Icon/Action_Icon）只由高层 assembled 下行，词条表不可反向覆盖；两边都未命中保留 `[原文]`。
- **SpriteAsset 生命周期**：Binder 持有并在重建/销毁时 `DestroyBuilt`（material+atlas+asset 三件），否则运行时纹理泄漏。
- **TMP UpgradeSpriteAsset NRE**：必须先 `UpdateLookupTables` 再挂 material（Builder 内注释）。
- **翻牌不改 Commit 纪律**：Handler 禁止对 `PlayFlipAsync` 直接 `.Forget()`（ADR-0016 结构护栏）；战斗通道 FaceUp 延后到命中后 FlushBeats。
- **数值脉冲只在变更时播**：`SetNumeric` 的 hadPrevious 判定是防 Spawn/Bootstrap 误脉冲的关键。
- **词条行 prefab 字号单位**：`Resources/Prefabs/UI/词条详细效果信息.prefab` 的 TMP 是 mesh 版（非 UGUI），行以 scale=1 挂进 ScrollRect Content（本地宽约 392），字号须按 Content 本地单位配（现为 200）。历史坑：曾照旧场景模板（scale=25 约定）落盘字号 8，运行时字缩小 25 倍近乎不可见，2026-08-12 修复。
- **攻击模式图标切片**：只能用 `d_33/34/35` 三片，`d_30~32` 是非攻击模式切片（Resolver 注释明确警告）。
- **「行动计数」图标不进槽代号表**：怪物与机关模板都有这个 sprite 节点，但它的语义随卡级节奏源在行动 / 移动计数间切换，故只在 `CardFaceIconGlossaryTargets` 按节点名解析；别把它塞进 `CardFaceSlotNodeMap` 的 companion 表（那会连带改数值脉冲的目标图标）。
