# 03 · 场地视图、格位命中与认领

> 权威代码事实文档 · 生成于 2026-08-12 · 覆盖场地视图/命中/认领相关 18 个 .cs（根目录 Ground* 系列、`Ground/` 的占格与认领登记、棋盘选卡模式、Avatar 朝向）。

## 职责综述

本子域实现 ADR-0023「格位命中框与认领」的命中侧：九宫格作为**单一表面**（`GroundFieldHitSurface`）注册进指针路由，命中权威是场景 `GroundAnchors/slotN` 上的 `BoxCollider2D`（场景手调尺寸，运行时只挂接/enable 永不写 size/offset）；命中解析出格号后查**认领登记**（`SlotClaimRegistry`，一格一认领者）派发悬停文案与点击语义。几何占格表（`GroundOccupancyIndex`，slot↔uid 双向表）是「占格权威 vs 几何注册」中的几何侧——逻辑真相永在 Core `BoardModel`，冲突显式报错、禁止 force-sync 自愈。`GroundFieldView` 是场地场景视图适配薄壳（锚点/布局/HitProxy/骷髅 Fusion），占格/busy/飞牌/运动全部转发给 `GroundFieldGeometrySystem`（Systems 区）持有的 `GroundMotionExecutor`（见 05 篇）。另含道具卡多选模式（`BoardCardSelectModeController`）与盘面级 Avatar 水平朝向状态。

## 核心流程与数据流

### 1. 场地面装配与命中解析

1. `GroundFieldView.Awake`：解析场景 `Anchors/GroundAnchors`（序列化字段优先，缺则 `GameObject.Find` 兜底）→ `CardSlotAnchorUtility.GetSortedSlotTransforms` 缓存九格锚点 → `EnsureHitProxies`：确保每格 `BoxCollider2D`（只挂接/isTrigger=false，**永不写 size/offset**）、销毁遗留 `GroundSlotHitProxy` 壳、挂 `GroundFieldHitSurface` 并 `BindSlotColliders` → `RefreshAllSlotHits(_ => true)` 九框恒开 → 依次 `GroundFieldGeometryHook/ExploreInputHook/BoardWalkInputHook/AvatarBoardFacingHook.RequestWire` 通知表现层装配 Controller。
2. 指针命中：Flow `PointerHitRouter` 调 `TryOverlapScreenPoint`（同平面 ScreenToWorld）→ `TryResolveSlotAtWorld` 逐格 `OverlapPoint`，记录 `_resolvedSlot/_resolvedCollider`。`HitTypePriority = PointerHitSurfacePriorities.Field`（28），`HitSortOrder = 0`。
3. 悬停：`HandlePointerEnter` / `RefreshPointerHover`（实现 `IMultiColliderPointerHitTarget`——同表面跨格 Router 不重入 Enter，须每帧刷新，否则悬停粘旧卡）→ `ApplyHoverForResolvedSlot` 查认领者：换人先 `HoverExit` 旧认领，再向 `BoardBriefTipPresenter.ShowHover` 亮简要解释（记录代数供 ClearHover 精确收回）并回调 `HoverEnter`。**无认领者格位**走 `ApplyAvatarRangeGlow`：该格为 Avatar 槽（Avatar 永不认领）时 `BoardRangeGlowFx.ShowAvatarInteractionRange` 点亮玩家可攻击范围（拖拽/手牌忙时不显示）；换到认领格、指针离面、失活时按请求者熄灭。
4. 点击：`HandlePointerDown`——UI 叠层（半黑屏/详述）激活时早退；手牌拖拽中早退；有认领者调 `claimant.Activate`，**无认领者**调 `field.OnEmptySlotClicked(slot)` → `GroundMotionExecutor.TryHandleEmptySlotClick`（BoardWalk 开启时提交跳格、否则提交 Explore；合法性交 IntentIntake，几何非空不静默吞）。
5. 右键详述：`TryResolveInspectCard` 只对认领者为 `GroundCardHitProxy` 的格返回其 `ManagedCard`（房间图标等非卡认领者不误开详述）。

### 2. 场地卡认领生命周期（`GroundCardHitProxy`）

1. 登记时机：落格/落地（`RequestPlaceCard`、`NotifyDealFlightLanded`、hop/换位完成后的 `SyncGroundCardClaim`，见 05 篇）调 `SyncClaimForSlot(slot)`；起飞/移除/换格前调 `ReleaseClaim`（ADR-0023「起飞卸认领、落地再登记」）。
2. `SyncClaimForSlot` 拒领条件：组件失活、Avatar/Unknown Kind（Avatar 是行动者永不认领）、`IsDealInFlight`（飞行中不认领）。认领体 `SlotClaimant(this, "", ActivateClaim, HoverEnterClaim, HoverExitClaim)`——场地卡不声明简要解释文案（战斗卡悬停不写简要解释，右键详述另责）。
3. `ActivateClaim` 分流：BoardSelect 模式 → `BoardCardSelectModeController.TryToggleSelection`；Monster/Trap → `FieldBattlePresentationHook.BattleOrNull().TryHandleBattleClick`（交战链，见 06 篇）;其余（道具/帮助卡）→ 过 `CanRespondToPickup` 后 `CardEntityLifecycleHook.HandOrNull().TryPickupFromGround`（拾取链，见 04 篇）。
4. `TryPassGroundInputGate` 门禁：开局表演中（openingDeal）、发牌在途（dealInFlight）、L2 收敛中（slotConverging）、无占格（noOccupancy）、根未对齐锚点（rootMisaligned，容差 0.01 世界单位²）任一命中即拒并记 `InputGateBlocked` 异常与 `BoardIntentGateDiagnostics` 控制台诊断；`RecordPickupEligibility` 把 registeredSlot/nearestSlot/正交性/orphan/ghost 等完整快照旁路给 `RegistryTraceSink`。
5. Hover 视觉：`CardVisualDriver.SetTarget(Hover/Base)` + `BoardRangeGlowFx.ShowThreatRange`（悬停怪物按攻击模式点亮威胁邻格荧光；悬停机关按效果模板邻接原子点亮影响范围、冷青色与怪物区分，见 07 篇）+ 悬停音效脉冲。**荧光清除不受悬停门禁影响**——`HoverExitClaim` 先无条件 `BoardRangeGlowFx.Hide` 再判断门禁。

### 3. 几何占格表事务（`GroundOccupancyIndex`）

- `TryRegister(slot, uid)`：目标格被其他 uid 占用 → 失败 + Error「禁止静默挤占」+ 置 `_occupancyConflictSinceClear` + `FlowFieldTraceSink.OccupancyConflict`；同 uid 迁格自动清旧格。
- `TryCommitPermutation(moves)`：旋转/换位的批量置换事务——批内 uid/目标格查重、来源在场校验、目标格只允许空或被本批 uid 占用；任一校验失败整批不动 + 置冲突标志。成功后触发 `OccupancyMaybeClear`（经 `HandleOccupancyMaybeClear` 过滤「场上仍有存活非 Avatar 卡」后通知 `FieldMaybeClearSignal`，供清场探测）。
- `Unregister` 打 `Vacate` 探针 + `OccupancyVacate` 旁路；`VacateSlotSilent/VacateUidSilent` 供旋转/换位批内成组卸格（不触发 MaybeClear）。
- 冲突标志消费：`ConsumeConflictFlag` 由交战回合尾（`SyncAfterCombatRound`）与拾取尾读取，命中则 `RequestSyncBoardFromCore`（Flow 侧对账）或仅告警——**不在本层自愈**。

### 4. 认领登记纪律（`SlotClaimRegistry`）

- 一格一认领：他 owner 占用时 `Debug.LogError` + `Debug.Assert(false)`，保留先到者不静默覆盖（冲突属流程 bug）。
- 同 owner 刷新同格允许；同 owner 认领新格前自动扫描卸掉旧格（迁格语义）。
- `ReleaseAllForOwner`：起飞/销毁时按 owner 全清（`GroundCardHitProxy.ReleaseClaim` 即走此路径，顺带熄灭威胁荧光）。

### 5. 棋盘多选选卡模式（`BoardCardSelectModeController`）

1. `Begin(itemUid, defId, requiredCount)`：经 `IntentIntakeSystem.Submit(BoardSelectBegin)` 过两轴门禁后置静态会话 + `PresentationInputGates.SetBoardSelect(true)`（输入所有权轴切到 BoardSelect 表面）。
2. 选择：场地卡点击被 `GroundCardHitProxy.ActivateClaim` 分流到 `TryToggleSelection`——`IsEligibleTarget`（GroundCardMode、非 Avatar、有占格）过滤；选中 `CardVisualTarget.Selected` 视觉 + 音效；反选允许清零仍保持会话。
3. 选满 `requiredCount`：置 `_committing`、冻结选择，异步回调 `SelectionCompletedAsync`（由 Flow 注册，完成 Core UseItem 写入与表现）；异常走 `SelectionAbortedAsync` 回手兜底；`finally` 统一 `End`。
4. 反悔路径：点击驻留在格 5 的效果卡（`BoardSelectParkedCardHitProxy`，由手牌拖放 `ParkCardForBoardSelectAsync` 武装，见 04 篇）→ `TryAbortByParkedItemClick`；流程打断 → `RequestAbort`。
5. `End` 的门禁兜底：即使静态会话已清，只要 `PresentationInputGates.BoardSelectModeActive` 仍挂着也强制收口——否则 CurrentOwner 粘在 BoardSelect，场地点击全部静默失效（注释记录的历史事故）。

### 6. Avatar 盘面朝向

- `AvatarBoardFacingState`：静态真相，`ResolveFromPointerX(pointerX, avatarCenterX)` 指针在左即 Left；`MirrorX` 供 `CardSpriteAnimPlayer.SetMirrorX` 镜像主视觉。由 Flow `AvatarBoardFacingController` 每帧写入（经 `AvatarBoardFacingHook.RequestWire` 在场地 Awake 时装配，Hook 本体见 08 篇）；不随单卡 hover 进出重置，不锁死格 5。

## 对外通信面

- **命中路由**：`GroundFieldHitSurface` 注册 Flow `PointerHitRegistry`；悬停文案走 Flow `BoardBriefTipPresenter`（ADR-0020 简要解释）。
- **意图提交**：空格点击经 `BoardWalkInputHook.TrySubmitBoardWalk` / `ExploreInputHook.TrySubmitExplore`；战斗点击经 `FieldBattlePresentationHook`；拾取经 `CardEntityLifecycleHook.HandOrNull()`；多选经 `IntentIntakeSystem` + Flow 注册的 Selection 事件。全部收口 IntentIntake（ADR-0004）。
- **System 面**：`GroundFieldView` 全部占格/运动 API 转发 `IGroundFieldGeometrySystem`（`AttachGeometryOwner` 绑定后走直连，否则查 QF 架构接口）。
- **只读投影**：`PresentationInputGates`（BattleUiOverlayActive / BoardSelectModeActive / OpeningPresentationActive / CurrentOwner / MainlineBusy）作为门禁读口。

## 不变量与坑

- **场景是命中框尺寸权威**：运行时只 enable/挂接，任何代码写 `size/offset` 都违反 ADR-0023；`RefreshSlotHit` 参数虽叫 hitEnabled，Executor 侧一律传 true（九框恒开，禁止启停 collider 表达规则）。
- **一格一认领 / 起飞不认领**：飞行、跳跃、拖拽中的对象不认领；`IsDealInFlight` 与 `SlotFrameConvergence.IsSlotConvergenceActive` 都会让点击被显式拒绝而非落空。
- **占格几何表≠规则真相**：冲突只置标志 + 诊断，`#10` 起禁止 force-sync 写回；对账由 Flow 决策。
- **悬停与点击同源**：简要解释唯一来源是当前格认领者声明的 `BriefTipText`；场地卡认领者故意留空文案。
- **`rootMisaligned` 门禁**：卡根偏离锚点 >0.1 世界单位即拒输入——这是「表演未收尾时点击」的显式拒绝面，同时打 L0 异常探针帮助定位收敛残差。
- **BoardSelect 门禁粘连**：任何 Abort 路径都必须最终走到 `End()`；先清 `_active` 再异步 End 会让 End 早退、门禁布尔残留（代码注释记录了修复约束：保持 `_active` 直至统一收口）。
- **`GroundSlotHitProxy` 仅为旧场景残留兼容**，新代码不得再引用它注册命中。
- **`GameObject.Find("Anchors")` 兜底**：View 的场景解析以序列化字段为主，Find 只是未绑定时的兜底路径（MainScene 生产装配应显式绑定）。
