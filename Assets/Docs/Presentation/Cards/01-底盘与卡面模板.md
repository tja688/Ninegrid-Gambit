# 01 · 卡牌底盘与卡面模板

> 权威代码事实文档 · 生成于 2026-08-12 · 覆盖 `Assets/Scripts/NineGrid.Presentation/Cards/` 根目录的底盘/视图类、`Slots/` 卡面槽表、`Anim/` 主视觉动画（26 个 .cs）。

## 职责综述

本子域实现 ADR-0002 的核心结构：**一套卡牌底盘 + 五套卡面模板**。局内每张卡的运行时实体由 `CardManagerSingleton` 以 Core 下发的 Uid 为键统一 Spawn/Release：先实例化底盘预制体（`老Standard Card.prefab`，持有变换塔、SortingGroup、命中代理、效果挂点），再按 `CardPresentationKind` 查显式表把对应卡面模板（玩家/怪物/道具/遗物/机关五套）挂入变换塔 L4 的 `FacePivot`。卡面上可被内容替换的视觉点位由 `Slots/` 的**装配槽表**统一编号（代号为键、中文注释为辅），排序按「卡级 SortingGroup 黑盒 + 卡面组内相对 order」两层管理。`Anim/` 负责卡面主视图（主图标位置）的帧动画播放与 Mask 锚定——切槽时一次性定位，播帧只换 sprite 不动 transform。

## 核心流程与数据流

### 1. Spawn：从 Core Uid 到可见卡牌

1. Flow 侧映射层（`CoreCardPresentationMapper` 等，属 Flow 区文档）拿到 Core `CardSpawned` 后调 `CardManagerSingleton.SpawnView(uid, defId, parent, initialMode, kind)`。
2. `SpawnView` 校验 uid（0 非法；正数=Core 卡，负数=纯表现卡）与查重后，`Instantiate` 底盘预制体（`RegisterPrefab(defId)` 注册过完整预制体的 DefId 走特例覆盖路径，不挂 Kind 卡面）。
3. `EnsureTransformTower`：确保 `CardTransformTower` L0–L4 层级存在，`LayerConvergenceDriver.Ensure` 补齐 L2/L3 收敛驱动器，并把预制体上尚未迁入塔的直系子节点兜底挂到 L4 `CardVisual` 下。
4. `MountFaceForKind`：按 `ResolveFacePrefab(kind)` 显式表选卡面模板（Avatar→玩家卡、Monster→怪物卡、HelpCard/Item/PlayerCard→道具卡、Relic→遗物卡、Trap→机关卡，ADR-0017 五套），清空 `FacePivot` 旧子物体后实例化挂入；模板若自带 SortingGroup 会被删除并告警（防第二套卡级 SG）；为卡面挂 `CardFacePresentationBinder` 并 `StandardCardView.AttachFaceBinder`。
5. 补挂 `CardVisualDriver`（`CaptureAuthoredBaseScale` 记录预制体根缩放为动效基准）、`CardEffectManager`、`CardFaceFlipPresenter`；`GroundCardHitProxy.ApplyColliderSize`（实际是**禁用**自带 collider，ADR-0023）与 `HandCardHitProxy.ApplyColliderSize`。
6. `ApplyDisplayMode(initialMode)` 落初始显示模式，`CardPresentationProbe.Spawn` 打点。

### 2. 投影提交（Commit）链

- 唯一正式通路：战斗锚点排期器（Flow `BattleBeatScheduler` → `CardFaceStatHandler`）或对等 Commit 出口构造 `CardPresentationSnapshot` → `ManagedCard.CommitPresentation(snapshot)` → 写 `CommittedPresentation` 镜像 → `StandardCardView.ApplyPresentation` → `ICardFaceBinder`（即 `CardFacePresentationBinder`，见 02 篇）。
- `StoreCommittedPresentation` 只写镜像不刷视觉，供翻牌动画先锁 Commit 再播 Flip（ADR-0016）；`ReapplyCommittedPresentation` 用于全场对账重放（含 `CardFaceFlipPresenter.SnapVisualFace`）。
- `StandardCardView` 上的 `SetAttack/SetHealth/SetArmor` 均为私有，仅在**无 Binder 的完整预制体特例**下回退使用；`PixelDigitDisplay`/`ArmorBlockDisplay` 属于该旧通路（底盘演化后主流卡面锚点为空即不构建）。护甲显示规则：≤7 显示护甲块，>7 显示 1 块 + 数字（上限 999）。

### 3. 显示模式与排序

`ApplyDisplayMode` 每次切模式都会：

1. 进入净土域模式（CardDeck/HandCard/Removed）时先 `SlotFrameConvergence.SanitizeForSanctuary`（清 L2/L3 残差，见 05 篇）。
2. 按 `CardDisplayModeVisuals.GetBaseLocalScale(mode, authoredBaseScale)` 写根缩放（倍率相对预制体基准，ADR-0024）。
3. 非卡组模式强制回 `Main` SortingLayer 并 `PropagateSortingLayerFromGroup`（回收 UI 会把卡组下沉到 `BG` 层，离组必须回 Main，否则「能点看不见」）。
4. 排序委托：手牌槽位卡 → `CardHandManagerSingleton.EnsureHandSorting`；卡组槽位卡 → `CardDeckManagerSingleton.EnsureDeckSorting`（禁止被 DisplayMode 默认序 -30 打回）；飞行抬序中（`FlightSortingChannel.IsArmed`）不覆写；否则写 `GetSortingOrder(mode, kind)` 默认值。
5. `SyncHitProxyForDisplayMode`：场地卡禁用 `HandCardHitProxy`（否则其 sort 会压过场地面、吞掉房内货架点击）。

### 4. Release 与注册表卫生

- `Release(uid)` 前先 `TryVacateFieldOccupancyBeforeRelease` 卸场地占格（防「CardManager 已 Despawn 但占格表仍登记」的幽灵格），再 Kill tween、Destroy 视图、`RegistryDelta` 打点、`CardEntityLifecycleHook.RequestNotifyReleased`（清手牌 hover 悬空引用）。
- `Release(ManagedCard)` 重载做**引用身份保护**：句柄与注册表当前实例不一致（uid 被复用）时拒绝释放并记 `RegistryMiss`，防止 await 后误杀新实体。
- `AuditRegistryIntegrity`：对比注册表与场地占格，输出 ghosts（占格有 uid 无视图）/orphans（GroundCardMode 却无占格）与「手牌卡组双持有」到 PerfLog + Console。
- `StageFieldDeadCorpseOffAnchor`：击杀 Vacate 后把尸体 y-80 移出锚点并切 RemovedMode（不 SetActive(false)，死亡特效继续），避免补位 hop 与尸体世界坐标重叠造成「凭空消失+出现」。

### 5. 卡面主视觉动画与 Mask 锚定

1. `CardFacePresentationBinder.ApplyPresentation` 末尾按 defId 查 `CardPresentationConfigCatalog`，命中则挂/复用 `CardSpriteAnimPlayer` 并 `PlayIdleOrStatic`。
2. `CardSpriteAnimPlayer.Play(slotId)`：经 `CardPresentationAnimResolve` 解析动画槽（idle/lunch 循环，其余单播）→ `CardAnimFrameSource.LoadFrames` 加载帧 → `ApplySlotTransformOnce` 一次性写入 mainVisual 的 uniformScale/offset 并经 `CardMainVisualPlacement.ApplyToRenderer` 按 `BottomCenter`（参考帧脚底贴 Mask 底边）锚定 → 逐帧只换 sprite。加载失败回退 idle 链，再失败回静态主图标。
3. `CardMainVisualMaskAnchor` 是锚定与裁剪的核心：定位在**祖先变换无关的局部空间**完成（共同祖先两侧各自累乘 local TRS，ADR-0015），拿不到共同祖先才回退世界路径；`ApplyMaskInteraction` 使主视图 `VisibleInsideMask` 且把 SpriteMask custom range 罩住其 order（背侧 -8 / 前侧 +8，见 `CardFaceSortingLayers`）；`PropagateSortingLayerFromGroup` 把 SG 层 ID 下发到全部子 Renderer/Mask（URP Mask 比对的是子节点 layerID，不 Propagate 会整段消失）；`EnsureFaceBackgroundHexMask` 让矩形背景吃遗物模板的六边 Mask。编辑器 `PreviewRenderUtility` 不跑 URP Mask 模板，预览实例（hideFlags 含 DontSave）会关掉 Mask 交互只保留定位。
4. `SetMirrorX`：Avatar 朝向镜像只改 scale.x 符号，不重算锚点（由 `AvatarBoardFacingController` 驱动，见 03 篇）。

## 对外通信面

- **入**：Flow 映射/排期层调用 `SpawnView` / `CommitPresentation` / `SetDisplayMode` / `Release`；组合根经 `CardEntityLifecycleHook.RequestWire` 绑定三 Manager（见 08 篇）。
- **出**：`CardManagerSingleton` 经 `GroundFieldGeometryHook.FieldOrNull()` 卸占格、经 `FlowFieldTraceSink`/`CardPresentationProbe` 打诊断；不直接引用 Core/Flow 类型（`CoreKind` 由 Flow 写入）。
- **资产契约**：`CardChassisPaths` 是底盘/卡面/图标路径的单一真源；Player 下只认 `Assets/Resources/` 下资产（ADR-0008）。

## 不变量与坑

- **Uid 号段**：Core 卡为正整数；BounceFan 等纯表现卡必须走 `SpawnPresentationOnly`（负数递减），否则会与洗回 NewCard 撞号挂死。
- **卡面数值禁旁路**：`StandardCardView` 数值 Setter 非公开；一切可见数值来自 `CommitPresentation`（ADR-0005）。`ManagedCard.CommitPresentation` 注释明确「仅应由战斗表演编排串行主线 / 对等 Commit 出口触发」。
- **卡面模板不得自带 SortingGroup**：挂面时强制删除；卡级排序黑盒由底盘根 SG 独占，卡面只配组内相对 order（0–99 分区表），同层同序为装配错误（`CardFaceSortingOrderValidator`）。
- **MarkFieldDead 只标记**：可见血量归零由 `KillCard` 指令的 `RemainingHp` 提交，不在此改数值。
- **`cardRoot` 场景显式绑定**：#141 起 MainScene 显式指向 `Actors/Cards`；`EnsureCardRoot` 的运行时自造仅为兜底。
- **Editor 兜底路径**：`BootstrapPrefabs` 仅在 UNITY_EDITOR 下从 AssetDatabase 兜底加载底盘与机关卡面；Player 依赖场景序列化字段，装配缺失将直接 Spawn 失败并打 Error。
- **主视觉播帧不改 transform**：位置只在切槽时算一次；跟随/镜像等都不得在帧回调里重算锚点。
- **Mask 三件套纪律**：改 SG 层 → `PropagateSortingLayerFromGroup` → 再 Sync Mask range；只做其一会导致 `VisibleInsideMask` 内容整段消失（`CardMainVisualMaskAnchor` 注释反复强调）。
