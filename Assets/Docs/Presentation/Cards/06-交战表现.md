# 06 · 交战表现（攻击 / 反击 / 致死）

> 权威代码事实文档 · 生成于 2026-08-12 · 覆盖 `Cards/Battle/` 全部 11 个 .cs 与根目录交战执行四件（`FieldBattleView`、`CardAttackBasicAdapter`、`CardAttackBasicDirectionRig`、`DirectorAttackPresentTargeting`），共 15 个 .cs。

## 职责综述

交战表现把 Core 已解算完的一次 CombatHit（玩家打怪 Hit / 怪打玩家 Counter，含致死变体）演成「蓄力→冲刺→命中帧→击退→回位/碎亡」。视觉本体是场景里按四向（Up/Down/Left/Right）烘焙的 DOTween Timeline **rig**（`CardAttackBasicDirectionRig`），运行时由 `CardAttackBasicAdapter` 把真实攻击者/受击者 Transform 与回调**重绑**进 rig 再播放；「玩家×怪物 × 意图」到手感变体（击退系数、回调时机、是否绑死亡链）的路由走 `BattleEncounterCatalogSO` → `BattleEncounterProfileSO` → `BattleBindParams`（未命中 SafeFallback）。`FieldBattlePresentationExecutor` 是 Present 执行缝：持 busy/CTS、解析目标（含嘲讽重定向与神圣决斗惩罚隔离）、在命中帧报 `Impact`、命中后 Drain 同批盘面 delta、击杀走 Vacate/FinalizeLethal。`BattleFinalStateGuard` 在播前快照、播后强制把参与者对齐回格锚。

## 核心流程与数据流

### 1. 从点击到 Present（一次玩家攻击的完整链）

1. `GroundCardHitProxy.ActivateClaim`（Monster/Trap 分支）→ `FieldBattleView.TryHandleBattleClick` → `FieldBattlePresentationExecutor.TryHandleBattleClick`：轴二校验 `OwnsProtectedField`、非 FieldDead、正交邻格；通过后 `AttackInputHook.TrySubmitAttack(slot)` 交 Flow AttackInputController → IntentIntake → Director 排 Attack 剧本（Resolve 批在 Core 解算，捕获 combatUid）。
2. Director 在 Present 步回调 `PlayDirectorAttackHitPresentAsync(clickedSlot, resolvedCombatUid, hitProjection)`：
   - 解析 Avatar（格 5）与点击受害者；点击格已空时按 resolvedCombatUid / RemovedUids 找尸体视图兜底。
   - `DirectorAttackPresentTargeting.Decide`：combatUid ≠ clickedUid 即嘲讽重定向（蓄力朝点击卡、冲刺打嘲讽卡）。
   - `willKill` 估计 = RemovedUids 含目标 / IsFieldDead / NodeCleared → `BattleIntentUtility.FromFlags` 得意图 → `ResolveBindParams`（Catalog 路由，`BattleBindResolve` 探针 + Console 日志）。
   - 神圣决斗惩罚（`HolyDuelPunishment.HolderUid>0`）：先 `BattleBeatHook.NotifyQuarantineImpactWhere` 把「决斗者脉冲 + 对玩家伤害」指令从当批隔离，待决斗者攻击 rig 命中帧再放回报点——惩罚以攻击编排打出而非玩家攻击帧掉血。
   - `PresentationMainlineHold.TryAcquire("FieldBattlePresent")` 短租主线 + `_isBusy`；PerfTrace 开 CombatHit beat + SetCombatants。
3. `CardAttackBasicAdapter.PlayBasicAttackAsync`（或 `PlayTauntRedirectAttackAsync`）：
   - 方向：受击格相对 Avatar 的正交方向 → 查 `_rigByDirection`（rig 按名字 UpLeft/Up/… 解析方向，复合名先于单轴匹配）。
   - 攻击者解析：优先格 5 Avatar 卡，其次 Inspector defaultAttacker，最后运行时 AttackerProxy。
   - `BattleFinalStateGuard.Capture` 双方快照 → `PrepareAttackerAtSlotAnchor` 归位 → `rig.ResetParticipantMotion`（Kill+L3 归零）→ `rig.BindParticipants(..., onLungeBegin: 蓄力音, onCombatHit: Impact 报点)`。
4. `rig.PlayAsync`：先 `InvalidateCachedTimelineSequence`（上一场被 KillMotion 打断时 DOTweenTimeline 缓存陈旧 Sequence，Restart 会忽略重绑 → 反击甩出屏外的历史 bug）再 Restart；轮询 Sequence 完成，途中按 `ResolveLungeBeginDelaySeconds`（最小非蓄力 delay）触发 onLungeBegin。
5. 命中帧：场景 `Dott.DOTweenCallback`（delay≤0.45 的判为闪白回调）被重挂为「Probe 命中帧 → 受击闪白 → onCombatHit（Executor 里 `BattleBeatHook.NotifyBeat(Impact)`：飘字/卡面数值/FX 在此消费）→ `TryReadVictimConfirmedKill`（onCombatHit 已写 Core 并 Commit，读 View.Health≤0 / IsFieldDead 确认真击杀）」。
6. 死亡回调（delay≥0.5 的 DOTweenCallback，仅 `BindDeathCallback` 时挂）：`_hitConfirmedKill` 未确认则**跳过**并告警（Lethal Profile 预估偏差防误播死亡）；确认则 `victimEffects.Callback(PlayDeath)`。
7. `PlayBoundRigAsync` 收尾（finally）：攻方抬序还原（`BeginAttackerSortBoost`——反击时怪必须压过 Avatar 的 -9，否则「隐身打人」）；蓄力音 `CancelScheduled`（取消路径）；`bind.IsLethal && !LastHitConfirmedKill` 时强制 restoreVictim + `StopSpuriousDeathEffect`；`ShouldKeepVictimOffField`（IsFieldDead / Health≤0）则不回锚；`BattleFinalStateGuard.RestorePairAsync` 双方对齐。
8. Executor 命中后半场：`BoardPresentationMerge.ForHitPresentDrain` 剥离主目标 Remove（击杀时 `stripVictimMotion` 一并剥离尸体 Move/Swap 位移）→ 主目标**存活**：同批 OnBattle Swap/Move/Deal 在 Vacate 前 Drain（否则 Core 已换位而表现占格仍旧 → OccupancyDesync）；主目标**已死**：先 `MarkFieldDead` + `VacateSlotForExplore`（以 Drain 前占格定尸体格，不补位）+ `StageFieldDeadCorpseOffAnchor`，**再** `DrainCombatHitBoardDeltaFromProjectionAsync`——Core 在击杀落地（KillIfDead FollowUp）前 OnBattle 旋转/换位遗物会真实移动尸体一格，表现侧不重放尸体位移（Rotate 步只带方向，旋转「无尸体的环」，终态与 Core 击杀后一致，尸体不跟转闪烁）→ Drain 后 `FinalizeLethalVictimAsync`（等死亡特效完再 Release）+ `AssertHitPresentOccupancySync` → `FlushPendingShuffleAsync`（洗入批）→ finally `EnsureBattleEndedIfAvatarDefeated` + 释放主线 + `SyncAfterCombatRound`（消费占格冲突标志则请求 Flow 对账）。

### 2. 反击 Present（怪物单向打击）

`PlayDirectorCounterPresentAsync(attackerSlot, attackerUid, counterProjection)`：攻击者优先按 uid 解析（Swap 后可能不在原格），失败回退 `TryValidateCounterParticipants`（八向邻接校验）。方向解析 `TryResolveCounterAttackDirectionForAttackerSlot`：取 Avatar→怪方向的**反向** rig；对角无专用 rig 时按对角分量正交向→任意可用四向回退，并 `WithForcedRelativeMotion` 强制相对冲刺（否则播错烘焙轴向）。命中帧同样报 Impact；结束后 Drain 反击批 delta；Avatar 被打死路径把 `AvatarDefeated` 投影交 `EnsureBattleEndedIfAvatarDefeated` 收口。

### 3. Rig 重绑机制（`CardAttackBasicDirectionRig`）

- 场景 rig 由「攻击者占位卡 + 受击者占位卡 + 一串 DOTweenAnimation + 两个 DOTweenCallback」组成；Awake 按模板归属（或按 target 出现次数推断）分桶 attacker/victim 动画、按 delay 分桶闪白（≤0.45）/死亡（≥0.5）回调，并缓存**场景烘焙 endValue**。
- 每次 Bind 先 `RestoreBakedEndValues`（相对路径会原地改写 endValueV3，不还原会让下一场 Absolute 继承上一场 Relative 的世界坐标 → 隔空击打）。
- 攻击者动画三段按 delay 窗口分类：蓄力（≤0.05，背向位移）/ 冲刺（≤0.35，朝向位移）/ 回原（其余，回 home）；`RebindAttackerMotionFromVictim` 按真实双方几何以烘焙位移幅度重算世界终点再写回 local endValue；运动目标一律 `ResolveEffectMotionTarget`（L3 EffectFrame，无塔回退卡根）。
- 受击击退恒走相对几何 `RebindVictimKnockbackFromAttacker`（烘焙值是模板占位的绝对 local，直接用会「飞到烘焙坐标再闪回」）；击退段（delay 0.35–0.55）幅度 = 烘焙幅度 × 系数；Lethal（holdAtKnockbackEnd）时回原段终点锁在击退点（碎亡前不被拽回格锚）。
- 全部字段访问走反射（DOTweenAnimation/DOTweenCallback/DOTweenTimeline 为插件类型），静态缓存 FieldInfo。

### 4. 终态守卫（`BattleFinalStateGuard`）

`RestoreAsync`：Kill tween → L3 SnapHome → 有塔走 `SlotFrameConvergence.SnapHome` 回锚（无塔 >0.02 距离先 0.12s 软补间、超时/取消硬 Snap）→ rotation 归零 → 终检仍未对齐再硬 Snap + 告警 → RefreshDisplayMode。`RestorePairAsync` 按绑参决定攻/受各自是否回锚（击杀变体受害者通常不回）。`SnapImmediate` 供单测/紧急兜底。

## 对外通信面

- **入**：Director（Flow `AttackIntentScriptFactory` / `EnemyActionPhaseScheduler`）经 `IFieldBattlePresentationSystem` → `FieldBattleView` 薄转发 → Executor；点击链见 03 篇。
- **出**：`AttackInputHook.TrySubmitAttack`（意图提交）；`BattleBeatHook.NotifyBeat(Impact)` / `NotifyQuarantineImpactWhere` / `NotifyReleaseQuarantined`（锚点报点与决斗隔离，Flow 排期器）；`IBattleSessionSystem.DrainPostKillBoardAsync` / `FlushPendingShuffleIntoPresentationAsync` / `EnsureBattleEndedIfAvatarDefeated` / `AssertHitPresentOccupancySync`；`PresentationMainlineHold`（主线短租）；音频 `BattleCombatAudioCues.AttackPrepare` + 可取消蓄力排期 `SkillEffectTrapRelicAudioCues.ScheduleAttackCharge`。
- **先手还击语义**：本层不裁决出手顺序——`MonsterStrikesFirst` 在 Flow 入队前裁决，本层只按导演给的 Hit/Counter 顺序播。

## 不变量与坑

- **combatUid 必须来自 Resolve 批捕获值**：致死会卸掉嘲讽 RuleModifier，Hit 后再 Resolve 会把重定向判丢（`DirectorAttackPresentTargeting` 存在的全部理由）。
- **死亡链双保险**：Profile `bindDeathCallback` 只是「预估会死」；真死与否以命中帧后 `TryReadVictimConfirmedKill` 为准——未确认则跳过死亡回调、强制回锚并停掉误播的死亡特效。
- **Timeline 缓存失效**：Restart 前必须 `InvalidateCachedTimelineSequence`（Kill + 反射清 Sequence 属性），否则重绑不生效。
- **烘焙值还原**：每次 Bind 前 `RestoreBakedEndValues`；OnValidate 会重建烘焙缓存。
- **决斗惩罚不丢失**：任何失败路径（决斗者不可用/不邻接/rig 未到命中帧）都 `NotifyReleaseQuarantined` 放回隔离区由后续 FlushBeats 兜底消费。
- **击退系数锁区间**：怪受击 [1,3]、玩家受击 [0.3,1]，Profile OnValidate 与 ToBindParams 双重 clamp。
- **玩家主动开战只认四向正交**；对角能力仅存在于 Counter（敌方斜角近战 Present），且回退 rig 必须强制相对运动。
- **SafeFallback 不是正常路径**：Catalog 未命中打 LogError；生产 Catalog 应至少覆盖四意图双通配。
