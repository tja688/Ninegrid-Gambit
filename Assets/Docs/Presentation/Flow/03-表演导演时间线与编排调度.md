# 表演导演、时间线与编排调度 —— Director · Timeline · Step · Channel · Scheduler

> 权威代码：`Flow/Presentation/` 下编排骨架（共 27 个文件，见文末小节清单）。
> 关联 ADR：[ADR-0001 统一时间线 / Batch-ack](../../../../docs/adr/0001-battle-presentation-unified-timeline-batch-ack.md)、[ADR-0004 两轴门禁](../../../../docs/adr/0004-input-intake-two-axis-gating.md)、[ADR-0034 盘面稳定化](../../../../docs/adr/0034-board-stabilization-refill-batch-ack.md)、ADR-0012（敌方行动阶段）、ADR-0016（翻牌门控）、ADR-0018（触发可见因果）

## 职责综述

这是 ADR-0001「统一时间线 + 批次锁步」的实现骨架。核心结构一句话：**`PresentationDirector` 独占两条 `BattleTimeline`（主线 mainline + 旁路 bypass），主线上的 Step 交替执行「请 Core 解算一批」（`ResolveBatchStep`）与「播一段表演并回执」（`PresentStep`），Core 一次只前进一批，表演未 ack 前 Core 不解算下一批**。主线在跑 = 唯一输入互斥真相（`IsMainlineBusy`）；旁路装饰道不占互斥。

Director 与 Timeline 是**普通 C# 深模块**（无 MonoBehaviour），由 `PresentationRuntimeSystem`（Systems/）持有并每帧 `Tick(deltaTime)`；剧本由各 `IntentScriptFactory`（[意图篇](04-意图门禁与剧本工厂.md)）在意图被接纳时构建入队。

## 核心流程

### 1. 一拍的完整生命周期（Batch-ack 时序）

以任意锁步批为例（`ResolveBatchStep` + `PresentStep` 成对入队）：

1. **ResolveBatchStep.Tick**：调 `gate.TryOpenNextBatch`。门先查 `sync.ActiveBatchId > 0`（上一批未 ack）→ 是则 `WaitHasOpen` 驻留重试；否则执行 `resolveAndOpen` 回调——即发 Core 命令（经 `CoreCommandDispatcher`）解算 + `sync.OpenBatch`。解算回调同时把 EventLog 切片投影（`IntentBatchProjection.Build` → `PostKillBoardPresentationResult`）`Enqueue` 进对应 Present 通道。失败 → `Aborted`（时间线清空、主线立即 idle，`DirectorTrace.ScriptAborted`）。
2. **PresentStep.Tick**（时序严格分六段）：
   - 等 `gate.HasOpenBatch`，取 `ActiveBatchId`；
   - **翻牌前置刷**（`flushFaceUpBeforeBegin`，默认 true）：`BattleBeatFlush.FlushUpdateFaceUp()` 只消费 pending 的 UpdateFaceUp 指令（hop/移位通道先翻牌）；战斗通道（攻击/反击 Present）传 false——当批 FaceUp 留到通道后 `FlushBeats`（**命中后再翻**，ADR-0016）；
   - 等 `FlipPlaybackCoordinator.IsIdle` → `channel.Begin(batchId)`（通道开始异步播）→ `DirectorTrace.PresentBegin`（可选开 Choreo 追踪段）；
   - 每帧 `channel.Tick`，等 `channel.IsComplete` → **两相冲刷第一相（ADR-0048）**：`BattleBeatFlush.FlushImpactOnly(TriggerEffect)` 单独演触发脉冲（派发 >0 时停 `TriggerCadenceSec` 节拍——基准 0.35s，经 `BattlePresentationSpeed` 两倍速 = 0.175s）；
   - **效果打击编排（ADR-0050）**：`EffectStrikeHook.PlayAllPendingStrikes` 串行播完当批剩余打击组（场上卡造成的伤害/破坏逐个「攻击动作 + 受击反馈」，命中帧冲刷该组暂扣飘字/血甲）；未装配/异常即完成，残留暂扣由下一段 FlushBeats 兜底放行 → **第二相**：`BattleBeatFlush.FlushBeats()`（其余 Impact→Settled，与非锁步路径同构）→ 再等翻牌 Idle；
   - `gate.TryAcknowledge(batchId)`（= `sync.FinishBatch`）→ `DirectorTrace.PresentAck` → Finished。ack 被拒则驻留重试并记 `PresentAckRejected`。
   - 全程有 stall 诊断：等待超过 `DirectorTrace.PresentStallThresholdSec` 周期性记 `PresentStall`。
3. **不变量**：`PresentationSyncBatchGate` 与 `IsInputLocked` 解耦——无阻塞指令的批次仍算打开中，必须 FinishBatch 才能开下一批。

### 2. Director 的门禁与租约

- `TrySubmitIntent(intent)`：主线不忙 → `DirectorTrace.BeginChain()`（诊断连锁根，绑一次剧本生命周期）→ `mScriptFactory.BuildScript(intent, mMainline)` → 接纳；忙 → **strict-drop 拒收**（ADR-0004 修订，不缓冲；`HasBufferedIntent` 恒 false，构造参数 `bufferedIntentLegality` 仅兼容装配签名）。
- `HardClearIntents(reason)`：Phase 变更 / 战败 / 换层使剧本上下文失效——主线与旁路一并 `Clear()`，外部租约强制释放。`BattleTimeline.Clear` 会对在跑 Step 补 `StepExit` 诊断。
- **外部租约**：`TryBeginExternalHold` 向主线入队 `ExternalMainlineHoldStep`（谓词轮询直至释放），保证 Apply/Present step 结束后表演窗口仍持忙；已持有时拒绝重入（嵌套由 `PresentationMainlineHold` 计数处理）；`ForceEndExternalHold` 清场用。典型持有者：Pickup 飞入手牌、RewardDrain、`BoardPresentDrain`（`BoardPresentationPlayer`）。
- **旁路**：`StartBypass(step)` 入 bypass 时间线，与主线并行 Tick，不占输入互斥（装饰表演专用）。
- `Tick`：先 Tick 两线；主线整条跑空时 `DirectorTrace.ClearChain()`（defer 补牌等兄弟 batch 仍在同一脚本内时不清）；每次状态变更 `PublishBusy` 推给诊断。

### 3. 盘面稳定化（BoardStabilizationScheduler，ADR-0034）

`Append(timeline, arch, dispatcher, boardChannel, boardSlot, onProjected, onStable)` 的内部 Loop 用 `TimelineBranchStep` 递归展开：

```text
TimelineBranchStep( 条件 = IBoardStabilizationSystem.NeedsRefill )
  ├─ true  → EnqueueSlice：ResolveBatchStep(gate: ResolveBoardStabilizationCommand)
  │          + PresentStep(棋盘通道, choreoKind:"Refill")
  │          + 再入队一个检查分支（递归）           ← 下一轮解算必然发生在本轮 Present ack 之后
  └─ false → Complete：IBoardStabilizationSystem.Complete()；onStable 回调
```

- 欠补位判定完全归 Core（`NeedsRefill`）；表现侧只管 pacing。没有欠补位时只通过空检查，不开空批。
- `MaxSlices = 64` 保险丝：超出即抛（表演切片预算耗尽，说明 Core 稳定化死循环）。

### 4. 敌方行动阶段（EnemyActionPhaseScheduler，ADR-0012 / ADR-0038）

由攻击/探索剧本工厂在互动剧本末尾 `Append`：

1. **参战预检**：盘面存在 `CardRhythmRules.HasActiveRhythm` 的怪物才进入阶段；否则直接只挂稳定化。
2. **报名批**：`RegisterEnemyActionPhaseCommand`（Core 冻结行动名单）→ 棋盘通道 Present。
3. **逐条批**（`TimelineBranchStep` 递归）：`ResolveNextEnemyActionCommand` 解算一条单向打击；解算回调记录打击者 uid/slot、扫描批内是否有 `DamageDealt`（`mLastStrikeHadDamage`）与 `AvatarDefeated`——
   - 有伤害 → 投影入 **Counter 通道**，`PresentStep(..., "CounterHit", flushFaceUpBeforeBegin:false)`（敌方开火同战斗通道：伤人触发的 FaceUp 如 rise_up 延到命中后再翻）；
   - 无伤害（位置不满足作废/纯推进）→ 棋盘通道 `"EnemyActionMiss"`。
   - 打完一条后分支：Avatar 未败且仍有 pending → 下一条；否则进收尾。
4. **收尾批**：`ResolveEnemyActionFinaleCommand`（统一处理阶段内累积死亡，盘面冻结解除）→ 棋盘通道 → 挂稳定化。

### 5. 五个 Present 通道

通道是「解算回调 Enqueue 摘要 → PresentStep.Begin 消费」的一次性信箱，完成态由异步 play 回写：

| 通道 | Enqueue 载荷 | Begin 行为 | 空批语义 |
|------|-------------|-----------|---------|
| `QueuedBoardPresentChannel` | `PostKillBoardPresentationResult` | 异步 `DrainPostKillBoardAsync`（盘面步骤流缓释） | 空 delta 直接 Complete；**但 AvatarDefeated / NodeCleared 不算空**（战败/清场收口不得被跳过） |
| `CombatAttackPresentChannel` | 点击格 + 已解算战斗目标 uid（嘲讽重定向后可能≠点击格卡）+ 摘要 | `PlayDirectorAttackHitPresentAsync`（lunge/命中/中间 Drain） | `!Accepted && !AvatarDefeated` 才跳过——AvatarDefeated 必须走 play，否则 finally 无法 EnsureBattleEnded |
| `CombatCounterPresentChannel` | 反击者格 + uid + 摘要 | `PlayDirectorCounterPresentAsync` | 同上 |
| `UseItemPresentChannel` | 摘要 | `PlayDirectorUseItemPresentAsync` | `!Accepted` 跳过 |
| `ShufflePrefixedPresentChannel` | —（包装内层通道） | sink 有 pending 先走 Shuffling 假 tick 段，清 sink 后再 `inner.Begin` | 仅 EditMode/假时钟形态；运行时用牌路径在 `PlayDirectorUseItemPresentAsync` 内直接 Flush |

### 6. 洗回卡组表演（Shuffle 家族）

链路（消费端在 [`BoardPresentationPlayer`](02-战斗会话与批次投影.md)）：Core 产生 `ShuffleIntoDrawPile` 类事件 → `ShuffleIntoDeckScheduler.EnqueueFromEventLog` 扫切片入 `ShuffleIntoDeckPresentSink`（跳过已在卡组视图的 uid）→ Present 时机（Drain 前 / 用牌 Present 开头 / 命中批）`FlushPendingShuffleIntoPresentationAsync`：`ShuffleBurstGrouper.Partition` 把同 ActionId 多张分成**爆发炸开组**（死亡格原点向四周炸开再吸入卡组，`CardBurstScatterIntoDeckPresenter`）+ 散单（逐张 `AddCardAtFromOriginAsync` / 场上卡 `LaunchReturnFieldCardToDeck` 并 await settle）→ 收尾 `SyncVisualOrderFromDrawPile` 对齐 Core 抽牌堆顺序。原点解析 `ShuffleBurstOriginResolver`：死亡格锚点优先，**禁止** StageFieldDead 后的尸体 live transform（y-80 会导致炸开全程离屏）。

### 7. 翻牌串行与生成引导

- `FlipPlaybackCoordinator`：静态串行队列 + 泵。`Enqueue(presenter, targetFaceUp)` 后泵逐条 `PlayFlipAsync`（每条先发 `card.lifecycle.flip` 音效脉冲）；卡销毁/取消不堵队列；`Reset` 以 Generation 作废在途泵。`IsIdle` 是 PresentStep Begin 前与 ack 前的双侧门控。
- `CardFaceGenerationBootstrap.ApplyFromEventLog`：开局等非锁步路径把 EventLog 里的生成类指令（CardSpawned/CardDealt/AvatarAppeared/倒计时/CardFaceChanged）重放给 `CardFaceStatHandler` / `CardFaceFlipBeatHandler`——批内翻面（刺客领袖 OnDeal）在发牌表演收束后才经同一 Handler 提交并串行播翻。`ApplyFaceHistoryForUid`：视图重 Spawn（手牌回复等）按事件日志重放该 uid 全部数值指令，避免只套生成绝对值把战斗中变化钉回。

### 8. 占格对账退场门（OccupancyForceSyncGuard）

`RecordForbiddenSync(reason, detail)`：记录一次**被禁止**的强制对账请求（计数 + PerfTrace `DirectorScriptAborted` + 断言），**永远返回 false**——调用方不得继续 heal。这是 ADR-0001「`SyncBoardOccupancyFromCore(force)` 硬对账退场，降级为永不应触发的断言」的落点；调用入口 `BattleSessionExecutor.AssertOccupancySyncForbidden`。

## 不变量与坑

- **Present 未 ack，Core 不解算下一批**——由 `PresentationSyncBatchGate.TryOpenNextBatch` 的 `WaitHasOpen` 强制。
- `TimelineStepStatus.Aborted` 是终态失败：时间线清空、主线立即 idle，勿与 Continue 驻留混淆。
- 战斗通道（Attack/Counter）**必须**在 AvatarDefeated 时照常走 play，即使 `Accepted=false`——否则 CompositionRoot finally 无法 `EnsureBattleEnded`（0 血僵尸局）。
- `TimelineBranchStep` 是「运行时展开剧本」的唯一正规方式——条件在 Tick 时才求值，保证分支决策看到的是上一批 Present 完成后的 Core 状态。
- 洗回表演**只**由 Present 前缀 / Drain Flush 播出，禁止 fire-and-forget 旁路泵（传送卡等无盘面 delta 的洗回也必须在用牌 Present 主线内 Flush，见 `BattleSessionExecutor.UseItem` 注释）。
- 主线忙不忙只认 `PresentationDirector.IsMainlineBusy`；`BattleBusy`/`FieldBusy` 不是门禁输入（须阻塞输入的表演改为持主线 Step 或外部租约）。
- `DelayStep` 累计的是注入 deltaTime，不读壁钟——门禁/编排可测试性约束（ADR-0004）。
