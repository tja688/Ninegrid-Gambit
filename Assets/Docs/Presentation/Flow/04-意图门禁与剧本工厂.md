# 意图门禁与剧本工厂 —— InputIntent · 合法性裁决 · IntentScriptFactory · Avatar 走格

> 权威代码：`Flow/Presentation/` 下意图与剧本区（共 22 个文件，见文末清单）。
> 关联 ADR：[ADR-0004 输入收口两轴门禁](../../../../docs/adr/0004-input-intake-two-axis-gating.md)、ADR-0010（棋盘合法性归 Core 内容）、ADR-0012（战败仍计互动）、ADR-0017（拾取拒战斗目标）、ADR-0026（离开机关清关）、ADR-0032（非战斗相位用牌）

## 职责综述

玩家的每一次点击/拖放都先变成一枚不可变的 `InputIntent`，经 `IntentIntakeSystem`（Systems/，非本目录）两轴裁决（**MainlineBusy × 输入所有权**）+ `BoardIntentLegality` 内容合法性后，才由 `RoutingIntentScriptFactory` 分派给具体工厂，把「一次互动的完整锁步剧本」编成 Step 序列入队主线 `BattleTimeline`。本目录是这条链的**数据载体（Intent）、裁决规则（Legality）与剧本编写者（Factory）**三段。

核心纪律（ADR-0004 修订后）：主线忙时**一律 strict-drop 拒收**，不缓冲（`IntentDisposition.BufferToDirector` 枚举仍在但语义已退役）；模态选择（selectRoom / selectReward 等）在 ChoiceOverlay 持有时即使主线忙也放行（宝箱 Bounce 挂在 UseItem Present 内的现实所迫）。

## 核心流程

### 1. 意图提交全链

```text
View/Controller 构造 InputIntent
  → IPresentationIntentRuntime.TrySubmitIntent   （IntentIntakeSystem 两轴裁决 + BoardIntentLegality）
  → IntentDisposition:
      Reject             → 发 *IntentRejectedEvent（可选 IAccelerationSink.Tap）
      RouteToBoardSelect → BoardCardSelectModeController 进多选模式（见会话篇）
      Allow              → PresentationDirector.TrySubmitIntent
                            → RoutingIntentScriptFactory.BuildScript(intent, mainline)
                            → 匹配工厂入队 ResolveBatchStep / PresentStep / BranchStep …
```

**kind → 工厂路由表**（Routing 无中央 switch，靠子工厂内部 kind 守卫）：

| Kind | 工厂 |
|------|------|
| explore | ExploreIntentScriptFactory |
| attack | AttackIntentScriptFactory |
| useItem | InteractionLoop → UseItem；其余相位 → NonCombatUseItem |
| pickup | PickupIntentScriptFactory |
| recycleItem | RecycleItemIntentScriptFactory |
| revealFace | RevealFaceIntentScriptFactory |
| boardWalk | BoardWalkIntentScriptFactory → AvatarWalkRunner |
| boardSelectBegin / selectRoom / enterRoom / selectReward / skipHelpChoice / refreshShop / discardRelic | 非工厂路径（模式切换 / ChoiceOverlay 即时处理，在 IntentIntakeSystem） |

### 2. 合法性裁决（BoardIntentLegality）

只裁 **BoardModel/Phase 内容**，不裁表演时序（忙时互斥由 IntentIntake 的 MainlineBusy 轴承担）：

| Kind | 核心规则 |
|------|----------|
| boardWalk | AvatarWalk 启用；Phase 允许 MoveAvatar；格号合法非同格；路径可达（尊重 WalkDestination/SoftBlock 软占） |
| explore | AvatarWalk 未独占；Phase 允许 ClickEmpty；目标空格且邻接 Avatar；非 SoftBlock |
| attack | AvatarWalk 未独占；Phase 允许 Attack；邻接正面战斗目标；**不拒嘲讽重定向点击**（实际目标由 `ResolvePlayerAttackTargetUid` 在 Resolve 层重定向） |
| revealFace | 邻接背面非 Avatar 卡 |
| useItem | Phase 允许 UseItem；item 在 ItemSlots 且已注册；ADR-0032 卡级相位可用性（usableOutsideBattle） |
| recycleItem | Phase 允许 RecycleItemSlot；item 在 ItemSlots |
| pickup | **刻意不查 CanExecute**（与 `PhaseSystem.ApplyPickupCard` 对齐）；邻接非战斗目标卡（ADR-0017 拒 Monster/Trap）；idle 交导演锁步剧本 |

**相位矩阵**（`IsBoardCommandPhaseWithoutLock`，`IsInputLocked` 时用于区分「时序锁」与「内容非法」）：InteractionLoop 全开七命令；RoomChoice 允许 Pickup/MoveAvatar/UseItem(卡级)/Recycle；RoomEvent 允许 MoveAvatar/EnterRoom/Recycle；RewardItemChoice 允许 MoveAvatar/UseItem(卡级)/Recycle。拒绝时 `BoardIntentGateDiagnostics.AppendPhaseReject` 附快照（[诊断篇](10-诊断与日志（Diagnostics）.md)）。

### 3. 攻击剧本（AttackIntentScriptFactory，最复杂垂直切片）

玩家先攻 `BuildPlayerFirstScript`：

1. `ResolveBatchStep`：`CombatHitCommand(attacker, target)` 解算 + 开批；投影入命中通道。
2. `PresentStep(命中通道, flushFaceUpBeforeBegin: false)`——伤人翻面延到命中后（ADR-0016）。
3. `AttackPostHitBranchStep` 三分支：
   - **击杀** → `EnqueueKillAftermath`：独立批 `AdvanceInteractionCountCommand`（#75 互动计数独立开批，防 OnInteract 效果漏进 Fill 窗）→ Present → 盘面稳定化 → `EnqueueRotateThenSettle`（`ResolvePostKillRotateCommand` + Present + 再稳定化）→ 敌方行动阶段。
   - **未击杀且 Avatar 未败** → `EnqueueCounterAftermath`：反击批（怪→玩家 CombatHit，反击通道，slice="AttackCounter"）→ Present → 再分支（未败：非击杀互动推进 + 稳定化 + 敌方行动；已败：静默 `InteractionCountAdvanceStep`，ADR-0012 战败仍计一次互动）。远程武器 `RuleId.CounterAttackBanned` 跳过反击。反击各裁决路径必打 FlowTrace `Rhythm/CounterVerdict` 打点（firstStrike / counterScheduled / skipBanned〔附禁反击修正来源清单〕/ skipAvatarDefeated / skipInvalid / skipNoChannel / rejected）——「怪没反击」与「怪被禁反击」可从日志区分；打点失败不影响结算。
   - **Avatar 已败** → 仅静默互动推进。
4. 特殊路径：`IsNodeCleared()`（ADR-0026 击破离开机关）→ 跳过 Fill/融合/敌方行动，只 Rotate 收场（slice="LeaveTrapClear"）。

怪物先攻 `BuildMonsterFirstScript`（`phase.MonsterStrikesFirst`）：反击批先行 → Avatar 未败才轮到玩家还击批 → 接常规命中后分支。

### 4. 其余剧本形态

- **Explore / RevealFace**（同型）：Resolve+Present（ClickEmpty/RevealFace）→ 独立互动计数批 → 稳定化 → Rotate 批 → 再稳定化 → 敌方行动。
- **UseItem（战斗）**：Apply 批（`ResolveUseAndProject` 检测 CardKilled）→ 用牌通道 Present → 击杀则 Rotate/稳定化收场，未击杀 `mOnResolvedWithoutKill` 回调 + 稳定化——**无反击/敌方行动链**（用牌不消互动节奏）。
- **UseItem（非战斗，ADR-0032）**：单 Tick `NonCombatUseApplyStep`——`ApplyUseItemCommand` → `BattleBeatFlush.PresentEventLogSlice` 非锁步冲 HUD → `TryPresentRelicRewardChoiceFromCore`（宝箱卡 `.use` 补开 Bounce 三选一）→ 选完重刷房内场地板。无 Batch-ack。
- **Pickup**（锁步，ADR-0001/0012）：`ApplyPickupCardCommand` 拾卡分拍 + Present（盘面 delta / 效果打击）→ 互动计数批 → 稳定化 → 旋转 → 再稳定化 → 敌方行动分拍 → 收尾回调（教程 Step7 通知）。手牌入手动画经 `PickupIntentFlushHook` 持主线租约承接；切片节拍由 PresentStep 消费，Hand 不再自行冲刷。**Recycle**：单 Apply Step + 静态 FlushHook 通知 Hand 做离手动画；只冲 `UpdateGold`（#61 避免 Remove 指令与碎裂双通道）。
- **BoardWalk**：单步 `SetDestination`；`AvatarWalkRunner.RunLoopAsync` 逐跳——`AvatarWalkPathfinder.TryGetNextStep` → `MoveAvatarCommand` → `HopAvatarToSlotAsync` + 脚步音；Hopping 中改目标等落地重规划；无路径/被拒清欲望。`SetEnabled` 切换会改格位命中策略（任意空格 ↔ 中心正交邻格）。

## 不变量与坑

- **忙时一律 Reject**：`BufferToDirector` 与 `IBufferedIntentLegality` 是缓冲时代遗产，不得据枚举名恢复缓冲行为。
- **互动计数独立开批**（#75）：不得把 `AdvanceInteractionCountCommand` 并进命中批，否则 OnInteract 触发效果的事件混入错误切片。
- **反击解算后才知战败**：不可在反击 Present 前预挂敌方行动阶段——分支必须用 `TimelineBranchStep` 在 Tick 时求值。
- **嘲讽不在门禁层拒**：合法性允许点非嘲讽邻怪，重定向发生在 Resolve；门禁若拒会出现「明明能打却点不动」。
- **Pickup 不查 CanExecute** 是刻意对齐 Core `ApplyPickupItem` 的行为，勿「补全」。
- **AvatarWalk 独占**：Hopping 期间 explore/attack/pickup/revealFace 全拒（avatarWalkExclusive），走格不被其他棋盘动作打断。
- `RoutingIntentScriptFactory` 是**遍历全部**子工厂而非 first-match——新工厂必须严守「不匹配 kind 立即 return」，否则一意图双剧本。
