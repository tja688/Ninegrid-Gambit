# 战斗会话与批次投影 —— BattleSession · 投影协调 · 盘面表演播放器 · 卡面映射

> 权威代码：根下 `BattleSessionController.cs`、`Flow/BattleSession/`（14 个），以及根下五个投影/扫描器（`BoardPresentationStepProjector` / `CoreCardPresentationMapper` / `ShuffleIntoDeckPresentationScanner` / `SkeletonFusionPresentationScanner` / `HelpCardBoardSelectResolver`），共 20 个文件。
> 关联 ADR：[ADR-0001 统一时间线 / Batch-ack](../../../../docs/adr/0001-battle-presentation-unified-timeline-batch-ack.md)、[ADR-0007 统一表现管线](../../../../docs/adr/0007-unified-presentation-pipeline.md)、ADR-0005（卡面 Commit 时机）、ADR-0021（清关结算归 Core）、ADR-0025（购领接手牌）、ADR-0035（倒计时投影）

## 职责综述

这一区是「一场战斗节点从入场到结算」的会话宿主与批次消费端。分四层：

- **`BattleSessionController`**（MonoBehaviour，场景 View）：只做场景宿主引用绑定（Card/Deck/Field/Hand/Relic/Selector/Battle/PanelRouter），实现 `IBattleSessionView`，把 Runtime 安装/关闭回调接给 `PresentationSceneRoot`；全部业务转发给 Executor。
- **`BattleSessionExecutor`**（internal partial，普通 C# 类，由 `BattleSessionSystem` 持有）：会话生命周期真正的执行体——BootstrapRun、StartBattleNode、开局表演、奖励选择、棋盘多选、用牌表演、结算唤醒、战斗结束事件。
- **`CoreBatchProjectionCoordinator`**：解算批回调的统一投影协调——把 Core EventLog 切片投影成表演摘要（`CombatHitPresentationResult` / `PostKillBoardPresentationResult`），路由伤害飘字、结算排期等副作用。
- **`BoardPresentationPlayer`**：盘面表演的实际播放器——Drain 盘面步骤流（Move/Rotate/Swap/Deal/Remove）、洗回卡组、骷髅合体、发牌视图解析。

投影三件套（`BoardPresentationStepProjector` + 两个 Scanner）与卡面映射器（`CoreCardPresentationMapper`）是纯静态工具，供上述执行体与 [导演篇](03-表演导演时间线与编排调度.md) 的通道复用。

## 核心流程

### 1. 会话装配与生命周期

- `BattleSessionSystem`（Systems/）在场景绑定时 `Executor.Bind(IBattleSessionView)`：装配五个 Present 通道（棋盘 / 攻击 / 反击 / 用牌 / 洗回 sink）、注册意图批投影处理器（`RegisterPresentationIntentHandlers`——explore/attack/board/counter/useItem 各批的 `On*BatchProjected` 回调 + 拒绝事件）、`EnsurePresentationRuntimeInstalled`（导演 Runtime 起转）。
- `Unbind/UnbindIfView`：撤场时注销处理器、`CancelPresentationWork`（作废 Presentation token）、`TeardownPresentationRuntime`。
- Presentation token（`EnsurePresentationToken/RenewPresentationToken`）：所有异步表演共用的取消令牌，换节点/撤场时统一作废。

### 2. 开局序列（Opening）

`StartBattleNodeAsync(options, ct)` → `StartBattleNodeInternalAsync`：

1. 记录 `NodeEventLogStart`（本节点 EventLog 起点，后续所有切片投影的下界）。
2. `phase.StartNode(options)` Core 解算（发牌/开局注入全部落进 EventLog）。
3. `CaptureOpeningPresentationPlan`：从 EventLog 捕获开局表演计划——`CaptureOpeningDeckAdds`（判定 `IsOpeningGrantSource` 的卡组加入项）与 `CaptureOpeningHandDeals`（手牌发牌项 + `ResolveHandDealSourceSlotIndex` 源格解析）。
4. `PresentOpeningAsync`：卡组视图落场 → 手牌逐张从卡组飞入（发牌动画）→ `ApplyOpeningHandRestores`（恢复模式手牌回复）→ `CardFaceGenerationBootstrap.ApplyFromEventLog`（生成类 + 开局批内 Impact 甲血数值重放，批内翻面收束后串行播翻）→ `WaitPresentationIdleAsync`。
5. 开局探针：`LogDeckOptionsProbe` / `LogBoardDeckProbe` / `LogAvatarDefeatProbeAfterStartNode`（FlowTrace 取证）。

### 3. 解算批投影（CoreBatchProjectionCoordinator）

- **命中批**：`ApplyCombatHitFromCore(startIndex)` 扫 EventLog 切片 → `CombatHitPresentationResult`（伤害/致死/反击致死/AvatarDefeated/命中后 HP）；`ResolveAvatarHpAfterHit` 从 `ModifyBaseStat`/`UpdateHp` 指令回读；`RecordCombatHitFlowSummary` 记 FlowTrace。
- **盘面批**：`ResolvePostKillBoardFromCore` / `FillBoardDeltaFromEventLog` → `PostKillBoardPresentationResult`（`BoardPresentationStepProjector.Project` 产出的步骤流 + 洗回条目 + PickedUid）。
- **回调路由**：`OnExploreBatchProjected` / `OnAttackHitBatchProjected` / `OnAttackBoardBatchProjected` / `OnAttackCounterBatchProjected` / `OnUseItem*` ——各自把摘要 `Enqueue` 进对应 Present 通道。玩家命中批与怪→玩家批（反击/先手/齐射伤害）都经 `RecordIntentCombatOpDiagnostics` 落 battlelog `CombatHit` op（含 attacker/target 快照；reason 由派发方经 `CombatHitTraceContext` 标注：IntentFirstStrike/IntentCounterHit 等，缺省按反击记）——否则 battlelog 只有 StartNode，反击缺席、献身类 OnRemove 效果无法从日志核对。
- **结算排期**：`ScheduleNodeSettlementAfterBoardPresent`——投影发现 `NodeSettlementReadiness.IsPostClearPhase`（RoomChoice/RewardItemChoice/ClearCheck/NodeCompleted/isNodeCleared）时，`AwaitDirectorIdleThenSettleAsync` 等导演主线 idle 后再 `TryEnterNodeSettlement`，保证清关表演播完才唤醒主循环。

### 4. 盘面表演播放（BoardPresentationPlayer）

`DrainPostKillBoardAsync(result)` 持外部租约（`BoardPresentDrain`）执行：

1. **洗回前缀**：先 `CollectPendingDealOrder(result)` 记下本批 Core 发牌序（Deal Step 流为权威，回退扁平 `Deals`；供卡组序对账把待飞出卡按真实抽出序排队首），再 `FlushPendingShuffleIntoPresentationAsync`（见下）。
2. **融合预扫**：`BuildFusionDrainState`——`SkeletonFusionPresentationScanner.Collect` + `BuildParticipantIndex`；participant 的单独 Remove 步在 `TryHandleFusionRemoveStepAsync` 拦截，改为整组「参与者飞聚 → 结果卡出现」（`EnsureFusionResultView`），`PurgeFusionResultsFromShuffleQueue` 防结果卡再被洗回队列双播。
3. **步骤流 Drain**（`DrainBoardStepsAsync`）：逐 Step 播放——Move（Sync 逐跳 / Async 折叠端点）、Rotate/Swap（`Sync` 恒同步收束）、Deal（`ResolveOrSpawnDeckCardForDeal` 解析或补 Spawn 卡组视图，`TryClearGhostOccupantForDeal` 清幽灵占位）、Remove（碎裂/卸尸）。`DrainDealsAsync` 开头除 Flush 洗回外还带 `pendingDealUids` 再对账一次卡组序（超时 0.5s）：批内洗了牌却没产生洗入表演条目（融合结果 / 快递交换 / 上批漏账）时，不对账就会「顶牌不是飞出的那张」。
4. **占格对账豁免过滤**：`FilterOccupancyDiffForPendingVacate`——尚在 Drain 中的 pending vacate uid 不算 desync；真 desync 走 `HandleDrainAfterOccupancyDesync` 记 anomaly（不 heal，见 [导演篇](03-表演导演时间线与编排调度.md) 的 `OccupancyForceSyncGuard`）。
5. `AssertHitPresentOccupancySync`：命中 Present 后 Core↔表现占格必须一致，不一致断言。

**洗回链路**：`PresentShuffleIntoDeckFromEventLog`（扫描入 sink）→ `FlushPendingShuffleIntoPresentationAsync` → `DrainPendingShuffleIntoPresentationCoreAsync`：burst 组走 `PresentBurstScatterShuffleGroupAsync`（原点炸开散卡→吸入卡组），散单 `PresentOneShuffleIntoDeckAsync`（`TryResolveShuffleIntoOrigin` 起点：场上活卡 → 死亡格锚 → 卡组口）→ `SyncDeckVisualOrderFromCoreAsync` 终对账。`ShouldDeferBoardTimelineSync/FlushDeferredBoardSync`：Drain 中的卡组时间线同步推迟到 Drain 收束。

### 5. 奖励选择与未用帮助卡（Choice）

- `PresentRewardChoiceFromCoreAsync`：读 `PendingChoiceModel.RewardOptions` → `SelectorManagerSingleton.BeginBounceChoice`（Bounce 扇形三选一，[房间篇](08-房间流程与场地板.md)）→ `WaitBouncePickAsync` → 选中 `SubmitSelectReward(index)` / 跳过 `SubmitSkipHelpChoice`（都经 IntentIntake）→ `RecordRewardChosenFlow`。
- **未用帮助卡折金**（节点结算时）：`PresentUnusedHelpCardSettlementFromEventLogAsync` → `CollectUnusedHelpCardUidsFromCore` + 表现侧补集 → 逐张 `VanishHelpCardWithGoldAsync`（碎裂 + 金币飞入 HUD，金额 `ResolveUnusedHelpCardGoldPerCard` 从 EventLog 回读）→ `SweepRemainingHelpCardViewsAsync` 兜底清残留视图。

### 6. 棋盘多选模式（BoardSelect）

帮助卡 `MultiBoardSelect`（如 swap_card 换位）：

1. IntentIntake 判 `RouteToBoardSelect` → `BoardCardSelectModeController`（Cards 区）进入选择模式，卡先「停车」到保留位。
2. 完成回调 `OnBoardSelectionCompletedAsync`：`TryAwaitDirectorIdleForBoardSelectAsync` → `TryValidateBoardSelectTargets`（`HelpCardSelectedCardsSpec`：可交战桶 / 仅真怪 ADR-0017）→ 通过则提交 useItem 意图；失败/中止走 `OnBoardSelectionAbortedAsync` → `WaitForHandReadyForRestoreAsync` + `RestoreBoardSelectItemToHandAsync`（道具回手），残留停车卡 `VanishParkedBoardSelectItemIfPresentAsync`。
3. 单拖目标（`SingleDragTarget`）路径在手牌拖放侧：`ValidateHandDragApplyAsync` / `TryResolveSingleDragTarget`（拒绝记 `LogHandDragApplyReject`）。

### 7. 结算唤醒与战斗结束

- `TryEnterNodeSettlement`：`NodeSettlementReadiness.IsReady(phase, pending)` 通过才 `RaiseSettlementReady` → `SendEvent(BattleSessionSettlementReadyEvent)` + View 兼容回调 → Shell 转 `GameFlowSignal.SettlementReady` 唤醒 Orchestrator 的 `mSettlementTcs`。
- `RaiseBattleEnded(victory)` → `SendEvent(BattleSessionEndedEvent)`；`EnsureBattleEndedIfAvatarDefeated`（`ShouldRaiseBattleEndedForAvatarDefeat` 判 HP≤0 且未 raise）是攻击/反击通道 finally 的兜底——即使 Present 异常也不得漏发战败。

### 8. 投影与映射纪律（根下静态工具）

- **`BoardPresentationStepProjector.Project`**：线性扫 EventLog，`CardMoved` 按 ActionId 缓冲成 Move 批（`SerialVisible` 逐跳拆步 / `CollapsedEndpoint` 折叠端点、Commitment=Async），遇 Rotate/Swap/Deal/Remove flush；Rotate/Swap/Deal/Remove 恒 Sync；`exchangeToDraw`/`shuffleExisting` 离场**不投影 Remove**（交洗回表演，与 Scanner 豁免配套）。
- **`CoreCardPresentationMapper` 双路径**：视觉可随时从一卡一 JSON 刷（`ApplyVisualsPreservingCommittedStats` 强制写回已提交攻防血）；数值只经 Commit 出口（Spawn/Deal 指令、`CardFaceStatHandler`、Countdown 指令，ADR-0005/0035）；`TryRead` 的 ActionCount 恒 0（只经 `UpdateActionCount` 指令提交）；`SyncAllSpawnedCards` 只重放已提交快照不对账 Core；展示卡快照战斗数值恒 0（JSON stats 仅 Catalog 造卡用）；Editor DisableDomainReload 下每次 `BindFreshContentCatalog`。
- **`ShuffleIntoDeckPresentationScanner`**：识别 `CardDealt` 四类前缀（`shuffleInto:`/`shuffleRandom:`/`shuffleExisting:`/`exchangeToDraw:`）→ Entry（含 cause/actionId/trigger uid/fromBoardSlot）；预扫 `EffectTriggered` 建 actionId→trigger 映射、`CardKilled/Removed` 建 uid→死亡格映射。
- **`SkeletonFusionPresentationScanner`**：三个融合技（`skill.recombine_head/recombine_body/strong_combo`）的 `EffectTriggered` 起批，向后扫至「≥2 个 Remove + 首条洗入结果」闭合；**不能按 actionId 截断**（ExecuteEffect 与 Remove/ShuffleInto 各自独立 ActionId）；遇下一融合 trigger 即 break。
- **`HelpCardBoardSelectResolver`**：从 Catalog `*.use` effect JSON 轻量解析（substring，非完整 parser）`SelectedCards` atom → count=0/1/≥2 三分支 + prompt（effect DesignText 优先，`swap_card` 硬编码兜底）。

### 9. 作弊旁路（BattleSessionCheat）

QuickTest/Dev 专用，刻意不进 `IBattleSessionSystem` 生产接口：`TrySetAvatarHp/Attack`（直写 CardRegistry Stats + Mapper 刷卡面）；`TryAttachSkillsToBoardMonsters`（一怪一技，不够则 Spawn `monster.melee_3` 白板宿主；挂完须当场 `RunToCompletion` + `PresentEventLogSlice` 冲刷 OnActivate 修饰符）；`EnsureQuickTestFlamePropsIfNeeded`（火焰技能通道补 `trap.flame`）；`TryForceNodeVictory`（等价 ADR-0026 击破离开机关 + `ClearResidualCombatFieldViews` 显式清残留视图）；`TryBeginCrossFloor`（黑屏过场 + Core 直写楼层，第三层拒绝）。

## 不变量与坑

- **`NodeEventLogStart` 是切片下界**：所有投影 `startIndex` 从这里起算，跨节点残留事件不得混入。
- **数值 Commit 纪律**：任何路径不得旁路 `CommitPresentation` 直接 `Set*` 卡面数值；视觉刷新必须走 `ApplyVisualsPreservingCommittedStats` 保数值。
- **洗回豁免配对**：Projector 不投影 `exchangeToDraw`/`shuffleExisting` 的 Remove ↔ Scanner 把它们收进洗回表演——两边只能改其一会双播或漏播。
- **融合批次闭合**不按 actionId 截断；participant 的 Remove 必须被融合表演拦截，否则「先单独碎裂再飞聚」。
- **战败兜底**：攻击/反击 Present 的 finally 必须 `EnsureBattleEndedIfAvatarDefeated`——通道对 AvatarDefeated 的「必须 play」规则正是为此服务。
- **结算必须等导演 idle**：`ScheduleNodeSettlementAfterBoardPresent` 不得在盘面表演中途唤醒主循环，否则清场表演被 Overlay 打断。
- 作弊清关无 post-kill present，必须 `ClearResidualCombatFieldViews` 显式卸视图，否则残留 GroundCard 盖住房间图标。
