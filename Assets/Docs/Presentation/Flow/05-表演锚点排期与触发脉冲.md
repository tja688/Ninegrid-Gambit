# 表演锚点排期与触发脉冲 —— BeatScheduler · Handler 链 · TriggerPulseHub · Cue 声明 · 金币表现

> 权威代码：`Flow/Presentation/` 下锚点排期与脉冲区（共 33 个文件，见文末清单）。
> 关联 ADR：ADR-0005（卡面数值 Commit 时机）、ADR-0016（翻牌门控）、ADR-0018（Impact 冲刷时机 / 触发可见因果）、ADR-0028（有效护甲）、ADR-0035（倒计时投影）、ADR-0036（音频跨会话生命周期）、ADR-0040（VFX 独立型不占 ack）、ADR-0048（两相 Impact 节拍 + 触发脉冲链级去重）、ADR-0050（效果打击统一表演 + 打击暂扣区 + 交战两倍速）

## 职责综述

Core 每批解算会产出 `PresentationInstruction`（结算指令：UpdateHp / ShowDamage / UpdateFaceUp / TriggerEffect / UpdateGold …）。本区回答「**这些指令在表演的哪个锚点（Beat）、由谁消费**」：`BattleBeatScheduler` 是唯一分发点，把 pending 指令按报点（Impact / Settled）派给注册顺序固定的 `IBattleBeatHandler` 链；装饰类输出（飘字/音效/VFX/金币）经 `TriggerPulseHub` 三通道「发即完成」，不占主线 ack。

`AudioCue` / `VfxCue` 系列文件是**发射语义注册表**：稳定 cue ID + 权威发射点标注，全项目音视效的声明中心。

## 核心流程

### 1. Handler 链与认领语义

注册顺序（`PresentationCompositionRoot.InstallBattleBeatScheduler` 装配，**顺序即契约**）：

```text
① PlayerInfoHudBeatHandler   Avatar 血/甲 HUD —— 旁路刷新后 return false（指令继续下传）
② DamageFloaterBeatHandler   飘字/受击音/VFX —— ShowDamage return true；治疗 UpdateHp、
                             加甲 UpdateArmor 旁路飘字后 return false；
                             加攻 ModifyBaseStat(Attack, Delta>0) 旁路发 vfx.combat.attack_gain 后 return false
③ CardFaceStatHandler        卡面数值 Commit —— UpdateHp/Armor/ActionCount、Countdown、
                             ModifyBaseStat、KillCard、Spawn/Deal/ShowAvatar、OfferReward 全认领 true
④ CardFaceFlipBeatHandler    UpdateFaceUp —— Commit FaceUp + FlipPlaybackCoordinator 串行播翻
⑤ EffectTriggerPulseBeatHandler  TriggerEffect —— FX/音效/VFX 脉冲，装饰消费 true
⑥ GoldGainBeatHandler        UpdateGold —— 广播 GoldGainPresentationRequested，true
```

`BattleBeatScheduler.TryDispatch` 按序调用，**第一个返回 true 的处理器消费并移出 pending**。关键顺序依赖：**飘字必须在卡面前**——治疗的 `UpdateHp` 需 ② 先飘绿字再 false 放行给 ③ Commit；颠倒则治疗飘字永远收不到。Settled 后仍有 pending → `DiagnoseUnconsumed` 断言（未消费诊断）。

### 2. 报点时序（Beat）

- `OnBatchOpened(batchId)`：新批开门，pending 与打击暂扣区换代（上一批残留 `DiagnoseDiscardedPending`，lane 标注 pending/strikeHeld）。
- `ReportBeat(Impact)`：装饰类（飘字/金币/TriggerEffect）在此消费。**两相 Impact（ADR-0048）**：命中帧与 Drain「首个 Remove 前」锚点只走 `FlushImpactExcept(TriggerEffect)`（飘字/血甲即时、尸体消失前可见）；`TriggerEffect` 统一留到 PresentStep 通道完成后由 `FlushImpactOnly(TriggerEffect)` 单独演出（返回派发条数，>0 时 PresentStep 停 `TriggerCadenceSec` 节拍——基准 0.35s÷倍速=0.175s——再进打击/冲其余 Impact）。批内可见顺序固定：**运动停稳 → 触发脉冲 → 效果打击（逐个）→ 飘字/血甲 → Settled**。
- **打击暂扣区（ADR-0050）**：`HoldStrikeImpactWhere(谓词)` 在开批后把效果伤害 Impact 指令（ShowDamage/UpdateHp/UpdateArmor，负向）移入第三泳道——命中帧 `FlushImpactExcept`、全量 `ReportBeat(Impact)`（决斗惩罚帧）均不冲刷；打击组命中帧经 `FlushStrikeHeldWhere(组谓词)` 放行（飘字/血甲/受击音/VFX 与卡面 Commit 同帧）；`ReportBeat(Settled)` 前兜底全放，指令永不丢失。`PresentStandalone` 保存/恢复暂扣区。归因与编排见 `EffectStrikePlan` / `EffectStrikeChoreographer`（`Cards/Battle/`）：打击者 = 同批 `EffectTriggered.Message==SourceDefId` 的持有卡且当前占格（判定加固：主索引→双向表扫描→补牌飞行中）；交战/单向打击（无 SourceDefId）、`skill.holy_duel`（隔离区专用编排）、**骷髅融合技能（专属融合表演）**、离场来源（手牌道具）、**`EffectStrikePresentationRules` 登记的直伤回退卡**不入组。**切片「先开批后 Drain」不变量（补记 d）**：`PresentEventLogSliceWithStrikesAsync` 接受调用方 Drain 委托，OpenBatch（建计划/暂扣）先于 Drain——拾取/奖励 Choice 的移除呈现才找得到打击组（滚石纯移除打击不再静默降级）。**诊断**：打击组降级冲刷与「未播即被新批覆盖」均 Warning 级。
- `ReportBeat(Settled)`：收束帧——卡面数值/翻牌在此提交。
- `FlushUpdateFaceUp`：Present Begin 前只冲翻牌（hop/移位通道先翻牌，战斗通道传 false 延到命中后，ADR-0016）。
- **隔离区**：`QuarantineImpactWhere` / `ReleaseQuarantined`——神圣决斗惩罚指令隔离至决斗者攻击帧再放行（该帧保持全量 `NotifyBeat(Impact)`，是 ADR-0048 的显式例外）；开新批即丢弃隔离区。
- `PresentStandalone`：非锁步单指令直发（开局引导等）。
- `BattleBeatFlush` 门面：`FlushBeats()`（Impact→Settled 一次冲完，锁步 PresentStep 第二相与非锁步路径同构）；`FlushImpactOnly(kind)`（第一相）；`PresentEventLogSlice*` 系列把 EventLog 切片映射成指令再走同一 Handler 链（非战斗用牌/回收/开局路径）。
- **触发脉冲链级去重（ADR-0048）**：Core 对每个含 qualifying 事件的动作都发独立 `EffectTriggered`（光环 refresh 在挂起位移落地批/补牌批/旋转批各一条）；`EffectTriggerPulseBeatHandler` 经 `TriggerPulseChainDedup.TryMarkFirst(CardUid, Message)` 收敛为同链一次（FX+VFX+音频一并静默），复位点在 `PresentationDirector`（新链接单 / 主线跑空 / HardClear）。

### 3. TriggerPulseHub 三通道

| 通道 | 生产装配（`TriggerPulseOutputController.ConfigureProductionDefaults`） | 语义 |
|------|------|------|
| FX | `CardEffectTriggerPulseSink` | `fx.card.{uid}` 旧卡面效果脉冲；卡不在场静默丢弃；机关卡（Trap）不演缩放脉冲 |
| Audio | `DebouncingTriggerPulseSink(AudioTriggerPulseSink, 0.05s)` | `AudioCueRequest` → `IAudioSystem`；同 cue 去抖 |
| Vfx | `VfxTriggerPulseSink` | 类型化 `IVfxSystem.RequestCue`，可带空间上下文返回 `PresentationPlan` |

纪律：`SafePulse*` 吞异常不拆主线；通道关闭记 degraded trace；`ResetToNull` 全清 / `ResetFxToNull` 仅清 FX（**音频跨战斗会话**，ADR-0036）；禁止 legacy `sfx.effect.<uid>` 动态绑定。

### 4. 金币表现（#199/#203）

链路：Core `GoldModified` → `GoldGainPresentationScheduler`（扫切片，跳过 Delta=0 与 `unusedHelpCards` 原因）或 `GoldGainBeatHandler`（锁步 Impact）→ 广播 `GoldGainPresentationRequested` → `GoldGainPresentationBinder`（[HUD 篇](09-指针命中、HUD与检视.md)）：花费 SnapGold；增益经 `TriggerPulseHub.PulseVfx(economy.gold_flight)` 拿到首达/末达延迟计划 → 驱动 HUD 数字时间窗。UI/FX 单向消费，不回写 `PlayerModel`。

### 5. Cue 声明纪律

- `AudioCue.cs`：按域分组的静态声明类（交互/UI、卡牌生命周期、战斗、技能效果、Avatar 脚步、房间经济等），每条带 `[AudioCue]` 权威发射点标注；`CombatOutcomeAudio` 与飘字**同缝分诊**（block/absorb/hp/heal/armor 一处判定，音画对齐）；`SkillEffectTrapRelicAudioCues.ResolveCueId` 按 trap./relic./skill. 前缀路由。
- `BattleVfxCues.cs`：与音频同缝同分诊（ADR-0040 独立型 VFX 不占 ack）；甲伤 VFX 偏移 0.28 避免与血溅重叠；统一经内部 `VfxPulseEmit.PulseAt` → Hub。
- `ProjectileVfxCues.PulseFromTo`：返回 `PresentationPlan` 命中延迟，编排据此对齐飘字/扣血时点。

## 不变量与坑

- **Handler 顺序是行为契约**：①②在③前是治疗/血甲飘字能工作的前提；装配处调序即无声坏。
- **装饰不占主线 ack**：飘字/金币/脉冲全部发即完成；需要阻塞的表演走 Present 通道或外部租约。
- `CardFaceStatHandler` **只认指令绝对值**，不读 `CardRegistry`/`IStatSystem`——Core 回读会把批间中间态钉进卡面。
- `ModifyBaseStat(Armor)` 只刷 HUD 不刷卡面甲（基础甲与战斗剩余甲分轨）。
- 无效 uid 的 UpdateFaceUp 仍 `return true` 空消费——否则 Settled 未消费断言误报。
- 隔离区在开新批时丢弃：神圣决斗惩罚若跨批未释放即静默失效，属设计内。
- 手牌 HelpCard 的 OnSelfUsed 不在 FX 脉冲列（卡已离场）；道具槽音频不受棋盘门禁。
