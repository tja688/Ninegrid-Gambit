## 二、22 张「策划有、实现无」— 按原子能力分类

### ✅ 已有原子，直接拼模板（约 14 张）

只需新建 `tpl.relic.*` + 遗物 JSON，参考现有 skill/help/relic 模板：

| 策划遗物 | 参考模板 / 原子组合 |
|---|---|
| **废物剑** | `OnKill` + `Heal`（同打金刀/弹弓族） |
| **血液循环** | `OnDamageTaken` + `Heal`（触发器已有，遗物侧未用） |
| **血液暴力** | `HpBelow` 50% + `Modifier` 攻+2（类似 taunt 条件修饰） |
| **血再生** | `OnBattle` + `HpBelow` + `Heal`（≈ `tpl.skill.survival_wisdom.battle`） |
| **复合盔甲** | `OnNodeStart` + 按攻换算 `GainArmor`（≈ `tpl.relic.heavy_armor.node_start`） |
| **金血** | `OnDamageTaken` + `ModifyGold`（按失血；需 value 表达式接事件） |
| **陷阱格** | `OnMoveToSlot` 格1 + 对移动怪 `DealDamage`（改 `skill_air_strike_slot1` 目标） |
| **旋转倒刺** | `OnEvent CardMoved` + 对移动怪 `DealDamage`（改 `hot_observation` 目标为 Self） |
| **锐利长剑** | `OnKill` + `AddModifier` 攻+1 `UntilBattleEnds`（关末即战斗结束会清） |
| **金属血液** | `OnDamageTaken` + `GainArmor`（等量甲） |
| **血液迸发** | `OnDamageTaken` + `RandomMonster` + `DealDamage`（等量伤） |
| **狂战士斧** | `HpBelow` + `RuleModifier DamageMultiplier` ×2（条件规则修饰） |
| **转速引擎** | `OnRotate` + `Rotate`（**触发器/动作都有，全库尚无 OnRotate 模板**，逻辑简单） |
| **除甲刀 / 超越维度 / 金色宝箱 / 废物增幅器 / 腐朽顺劈斧 / 铁盾 / 身体潜力** | 见上表旧卡重写 |

**共享积木**（不必每张新建底层逻辑）：

- 属性：`tpl.shared.4`（基础甲）、`tpl.shared.5`（血上限）、`tpl.relic.wood_sword.base`（攻）
- 道具联动：`tpl.heal_player_on_use_help_card`、`tpl.gain_armor_on_use_help_card`
- 旋转：`tpl.help.rotation_wheel.use`、`tpl.skill.space_mastery.battle`

### ⚠️ 原子「差一点」— 小扩展即可拼（约 6 张）

| 策划遗物 | 卡点 | 建议 |
|---|---|---|
| **打卡刀** | 每移除 5 张**怪物**洗入随机常规道具 | `OnCumulative` 现只支持 `armorLost/hpLost/damageDealt`，**缺 `monsterRemoved` 计数** |
| **旋转技巧** | 每移除 6 张怪洗入旋转轮 | 同上 |
| **恐怖面罩** | 本关每移除 6 张怪随机移除场上普通怪 | 同上 + `RemoveCard` 过滤普通 |
| **废物循环机** | 每用 9 张道具洗入随机道具 | 缺 **helpCardUsed 累计**（或 `OnUseHelpCard` 的 every N） |
| **废物躯体** | 每用 3 张道具 +1 血上限 | 同上 |
| **血魔** | 每受 5 点伤害 +1 血上限 | `OnCumulative` 的 `hpLost` 只计**进血**；策划「受到伤害」可能含甲吸收，需 **`totalDamageTaken` metric** |
| **荆棘甲** | 按**本次战斗损甲**伤人 | 有 `OnSelfArmorLostCumulative`，但面向卡主；玩家战损甲→伤敌的**交战 scope 累计**要确认或补一条 |

这类属于：**1 个原子小扩展（给 OnCumulative 加 metric）+ 纯 JSON 模板**，不是重做伤害管线。

### ❌ 必须新造或明显扩内核（约 3 张）

| 策划遗物 | 原因 |
|---|---|
| **泡沫盔甲** | 本关首次甲归零后，**下一次受伤仅首段为 0**（多段只免疫第一段）。现有 `ward/庇佑` 是整次伤害变 0；`skill.blessing` 是 Once 全额免疫。**缺「首段 / 多段」语义** |
| **锻造器具** | 关初若甲≥5 扣 5 甲，并使**本遗物基础甲永久 +1**。遗物只有 `RelicDefIds` 列表，**无 per-relic 运行时成长**；`ModifyBaseStat` 改的是玩家 |
| **金剑** | 遗物提供攻 +8，**战斗时这份攻 -1（下限 0）**，击杀永久 +1。需要**带来源的动态遗物攻贡献**（非简单玩家 Modifier 叠层） |

## 三、已有内核但「还没接到遗物」的能力

这些在 skill/trap/help 里已有，遗物侧还没用：

| 能力 | 原子/规则 | 现状 |
|---|---|---|
| 伤害减免 | `RuleId.DamageReduction` | 枚举 + 公式已接（ADR-0028），**无任何 relic 模板** |
| 受伤触发 | `OnDamageTaken` | 有触发器，**遗物未用** |
| 旋转联动 | `OnRotate` + `Rotate` | 有触发器/动作，**全库无模板** |
| 获得时一次 | `OnActivate` + `Spawn` + `DeactivateSelfEffect` | 凤凰羽毛用过 fatal 路径，**金色宝箱可照抄** |
| 随机道具入战斗卡组 | `ShuffleRandomContent` + `HelpCard` | 怪物侧常用，**遗物打卡刀等可复用** |
| 额外 flat 伤害 | `RuleId.DamageFlatDelta` | 石庇护等在用，**肌肉反击可拼** |

## 五、一句话总结

- **不是「差几个遗物没填表」**，而是：**约 20 张能靠现有原子拼出来**；**9 张旧卡要换效果而非改名**；**6 张卡在一个计数/累计原子上**；**3 张（泡沫甲、锻造器、金剑）要动内核或遗物数值模型**。
- 你体感「主要差遗物」准确；若先做遗物，建议顺序：**拼模板批 → 扩展 OnCumulative metric → 泡沫甲/遗物成长**。
