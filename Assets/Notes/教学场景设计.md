# 独立教学关卡模块：完整设计与实现需求

请基于当前游戏已有的战斗、卡组、存档、怪物、道具、遗物等系统，新增一套**独立的一次性教学关卡模块（Tutorial Module）**。

核心原则是：

* 教学模块尽可能复用现有系统。
* 不修改、不破坏现有普通关卡流程。
* 教学模块拥有自己独立的进入判断、教学卡组和流程状态。
* 教学过程中通过特殊的「教学机关卡」在场地内直接向玩家展示教学文字。
* 整个教学采用**受控发牌 + 分阶段推进**的方式完成。
* 如果实现过程中遇到我没有明确说明的细节，请按照正常玩家直觉和常见教学关卡设计自行补全，不需要因为小问题停下来询问。
* 先保证整个教学关卡能够完整跑通，具体图标、美术资源和部分文案后续我会继续调整。

---

# 一、教学模块的整体定位

这是一个与普通游戏流程相互独立的教学模块。

它本质上是一个特殊的战斗房间 / 教学关卡，但不要让它影响现有正常关卡逻辑。

需要支持两种进入方式。

## 1. 首次进入游戏

通过现有存档系统判断：

```text
玩家是否已经完成过教学？
```

如果没有完成过教学：

```text
启动游戏
→ 进入教学模块
→ 完成教学
→ 标记 TutorialCompleted = true
→ 正式进入正常游戏流程
```

如果已经完成：

```text
启动游戏
→ 跳过教学
→ 正常进入游戏
```

这里建议存储一个类似：

```text
TutorialCompleted
```

的永久存档字段。

注意：

**不要通过“是否存在存档”简单判断，而应该有一个明确的教学完成状态。**

---

# 二、主菜单需要支持重复进入教学

即使玩家已经完成教学，也需要在主菜单中提供一个：

```text
教学 / Tutorial
```

入口。

玩家通过主菜单进入教学时：

* 可以重新体验完整教学。
* 不影响正常游戏进度。
* 不修改普通关卡状态。
* 不修改当前正式游戏的卡组、金币、血量、道具等内容。
* 再次完成教学也没有额外奖励。
* 不需要重新触发“第一次游戏”的逻辑。

也就是说：

```text
首次教学 = 强制引导
主菜单教学 = 独立试玩
```

二者使用同一套教学关卡。

---

# 三、教学模块的数据应该独立

新增一个专门的：

```text
Tutorial Deck
教学卡组
```

所有教学专用卡必须统一放在这里。

尤其是：

```text
Tutorial Mechanism Card
教学机关卡
```

不要把这些卡混入正常游戏卡池。

---

# 四、教学中可以复用的内容

以下对象优先复用游戏现有内容：

* 怪物
* 道具
* 遗物
* 战斗系统
* 攻击系统
* 卡牌旋转 / 场地移动机制
* 行动计数
* 攻击范围
* 道具拾取
* 道具使用
* 怪物详情界面
* 离开房间逻辑
* 道具出售逻辑

如果普通系统已经支持这些能力，不要重新制作一套 Tutorial 专用实现。

教学模块只负责：

```text
控制发什么牌
控制什么时候发牌
控制什么时候进入下一阶段
显示教学内容
监听教学目标是否完成
```

---

# 五、教学机关卡

新增一种专门用于教学的机关卡。

暂时可以使用占位图标和简单美术。

我后续会补充正式图标。

需要支持修改：

```text
Name
Description
HP
Icon
```

教学机关卡默认可以被玩家攻击。

如果没有特殊说明：

```text
HP = 6
```

---

# 六、最重要的文本限制

教学内容主要通过：

```text
教学机关卡 Description
```

展示。

但是：

**单张教学机关卡的描述最多只能放 16 个字符。**

因此不要尝试把一整句话放进一张卡。

应该将一句完整教学内容拆成多张卡，例如：

```text
卡1
卡2
卡3
卡4
```

然后玩家按照自然阅读顺序，可以把这些卡的内容拼起来。

需要特别注意：

### 教学卡的排列顺序必须符合阅读习惯。

优先按照玩家能够自然理解的：

```text
左 → 右
上 → 下
```

或者当前游戏场地实际最符合直觉的顺序排列。

不要随机打乱教学文字。

如果场地会发生旋转，则应保证：

```text
这一轮教学首次出现时
玩家能够顺畅阅读完整内容
```

后续旋转可以作为教学内容的一部分。

---

# 七、教学流程采用状态机

建议整个 Tutorial 使用明确的阶段状态，例如：

```text
TutorialStage.Intro
TutorialStage.Monster
TutorialStage.Items
TutorialStage.Exit
TutorialStage.Completed
```

或者：

```text
Stage1
Stage2
Stage3
Stage4
Completed
```

不要通过零散 bool 拼接整个流程。

每一阶段负责：

```text
进入阶段
↓
清理上一阶段
↓
生成当前阶段教学卡
↓
生成当前阶段特殊对象
↓
监听教学目标
↓
满足条件
↓
进入下一阶段
```

---

# 八、第一轮教学：基础场地与旋转机制

## 教学目标

让玩家理解：

1. 开局会发 8 张卡铺满整个场地。
2. 玩家完成一次交互后，整个场地上的卡会旋转 / 移动一轮。
3. 击破卡牌后会进行补牌。
4. 通过攻击教学机关卡来推进教学。

---

## 第一轮开始

教学开始后：

```text
直接发 8 张教学机关卡
```

正好铺满整个场地。

这一轮不要出现：

* 正常怪物
* 普通道具
* 普通遗物

只出现教学机关卡。

---

## 8 张卡的文字内容

这 8 张卡的 Description 组合起来，需要讲明白：

```text
战斗开始时
会发出八张卡
铺满整个场地

完成一次行动后
所有卡牌
都会转动一格

攻击这些机关
继续进行教学
```

这里只是表达意思。

实际实现时请根据：

```text
每张 Description ≤ 16 字符
```

重新拆分和优化。

要求：

* 简短
* 易读
* 不要写成长句
* 玩家站在场地中能按照排列顺序自然读完

其中至少有一张机关卡需要明确提示：

```text
攻击机关继续
```

---

# 九、第一轮的推进逻辑

所有第一轮教学机关：

```text
HP = 6
```

玩家击破任意一张教学机关卡后：

```text
机关死亡
↓
补发 1 张教学机关卡
↓
整个场地按照正常规则旋转一次
```

这里主要是为了让玩家亲自看到：

```text
击破
→ 补牌
→ 场地旋转
```

这套核心循环。

---

玩家需要：

```text
累计击破 2 张教学机关卡
```

之后进入第二轮。

也就是说：

```text
DestroyCount == 1
→ 补牌
→ 旋转
→ 继续第一轮

DestroyCount == 2
→ 第一轮结束
```

---

# 十、第一轮结束时

进入第二轮之前：

**把第一轮残留的所有教学机关卡全部强制清除。**

不要让上一轮残留内容进入下一阶段。

然后重新生成第二轮需要的 8 张卡。

---

# 十一、第二轮教学：怪物机制

## 教学目标

让玩家理解：

* 怪物卡是什么。
* 怪物具有攻击范围。
* 怪物具有行动计数。
* 行动计数结束时怪物会发动行动。
* 怪物会检查玩家是否位于攻击范围内。
* 如果位于攻击范围内，则攻击玩家。
* 如果怪物技能也受到行动计数控制，则同时触发技能。
* 可以查看怪物详细信息。
* 可以通过击破其他卡牌让场地旋转，从而改变怪物位置。

---

# 十二、第二轮发牌

第二轮重新生成：

```text
8 张卡
```

其中包含：

```text
1 张教学用怪物卡
+
7 张教学机关卡
```

怪物优先直接复用一个现有的：

```text
行为简单
攻击方式容易理解
攻击范围明显
```

的基础怪物。

不需要专门制作 Tutorial Monster，除非现有怪物完全不适合教学。

---

# 十三、第二轮教学机关内容

教学机关需要组合说明：

```text
怪物拥有
行动计数

计数结束时
怪物开始行动

如果你处于
攻击范围内
怪物会攻击你

部分怪物技能
也会同时触发

右键怪物
查看详细信息
```

同时需要让玩家理解一个重要策略：

```text
击破其他卡牌
可以让场地旋转
从而调整怪物位置
```

文案仍然必须满足：

```text
单张 Description ≤ 16 字符
```

---

# 十四、第二轮玩家操作

这一阶段允许玩家：

```text
攻击教学机关卡
```

教学机关卡可以持续补充。

也就是说：

```text
玩家击破教学机关
→ 补发新的教学机关
→ 场地继续按照正常规则旋转
```

可以理解为：

```text
教学机关无限补牌
```

目的是让玩家可以通过反复行动：

```text
调整怪物位置
体验怪物行动计数
理解攻击范围
```

---

# 十五、查看怪物详情提示

教学机关中需要明确告诉玩家：

```text
右键怪物
查看详细信息
```

如果游戏当前查看详情的实际操作不是右键，则以现有游戏真实操作方式为准。

不要为了教学重新创造另一种查看方式。

---

# 十六、第二轮结束条件

当玩家：

```text
击杀教学怪物
```

立即完成第二轮。

然后：

```text
清理所有残留教学机关
清理该阶段剩余内容
进入第三轮
```

---

# 十七、第三轮教学：道具系统

## 教学目标

让玩家理解：

* 场地中会出现帮助玩家的道具卡。
* 玩家可以在攻击 / 交互范围内拾取道具。
* 道具可以拖动到场地中央使用。
* 部分道具需要进一步选择目标。
* 治疗类道具可以直接作用于玩家。
* 攻击类道具需要指定攻击对象。

---

# 十八、第三轮发牌

这一轮生成：

```text
教学机关卡
+
飞刀
+
治疗药水
```

必须保证：

```text
1 张飞刀
1 张治疗药水
```

都会出现。

其余位置用教学机关卡填充。

---

# 十九、第三轮道具选择

直接复用游戏已有：

```text
飞刀
治疗药水
```

不需要制作 Tutorial 版本。

---

# 二十、第三轮教学内容

通过教学机关说明：

```text
场地会出现
可以拾取的道具

进入交互范围
点击即可拾取

将道具拖到
场地中央使用

治疗药水
可以恢复生命

飞刀使用后
还需要选择目标
```

实际文字请继续根据：

```text
每张最多 16 字符
```

进行拆分。

---

# 二十一、第三轮结束条件

不要以：

```text
拾取
```

作为完成条件。

需要玩家真正：

```text
使用治疗药水
+
使用飞刀
```

两件事都完成后：

```text
PotionUsed == true
KnifeUsed == true
```

才算完成第三轮。

不要求使用顺序。

也就是说：

```text
先药水后飞刀
```

或者：

```text
先飞刀后药水
```

都可以。

---

# 二十二、第三轮结束时

两件道具都使用完成后：

```text
清理所有残留教学机关卡
清理教学阶段临时内容
进入第四轮
```

---

# 二十三、第四轮教学：离开房间与战利品机制

这是最后一轮。

## 教学目标

告诉玩家：

1. 战斗中可以通过击破「离开机关 / 门」主动离开房间。
2. 不一定必须击杀所有普通怪物才能逃跑。
3. 但是只有清光怪物之后，场地里残留的道具才会自动卖掉换成金币。
4. 如果玩家提前逃跑，残留的道具不会自动出售。
5. 因此玩家需要在收益和生存之间做选择。
6. Boss 房不能提前逃跑。
7. Boss 房只有击杀 Boss 后，出口才会出现。

---

# 二十四、第四轮生成内容

生成：

```text
1 张离开机关卡
+
若干教学机关卡
```

如果场地为 8 个位置，则：

```text
1 个离开机关
+
7 个教学机关
```

---

# 二十五、第四轮教学文案

这些教学机关组合起来，需要表达：

```text
击破离开机关
可以离开房间

击杀全部怪物后
剩余道具
会自动卖成金币

如果提前离开
剩余道具
不会自动出售

如果状态不错
可以继续周旋
寻找更多道具

如果生命危险
也可以直接逃跑

Boss 房中
必须击杀 Boss
出口才会出现
```

这里不要完全照抄长句。

请根据卡牌位置和：

```text
Description ≤ 16 字符
```

重新组织成更自然的短句。

---

# 二十六、第四轮完成条件

玩家：

```text
击破离开机关
```

之后：

```text
离开教学战斗
↓
TutorialStage = Completed
```

如果这是玩家第一次进入游戏：

```text
TutorialCompleted = true
保存存档
进入正式游戏流程
```

如果是从主菜单主动进入：

```text
直接返回主菜单
```

不要影响正式游戏存档。

---

# 二十七、教学中的死亡处理

为了避免第一次教学体验被打断，建议教学中做一定程度的容错。

如果当前游戏已经存在死亡 / 失败流程，可以选择：

```text
教学死亡后
重新开始当前教学阶段
```

或者：

```text
重新开始整个教学
```

优先选择：

```text
重新开始当前阶段
```

这样不会让玩家重复已经学会的大量内容。

不要让教学死亡直接污染正式游戏存档。

---

# 二十八、受控发牌系统

整个教学模块最重要的地方之一，是：

```text
不能完全使用正常随机抽牌
```

需要支持 Tutorial Controlled Draw。

也就是教学模块可以明确指定：

```text
这一阶段需要出现什么卡
出现在哪个时间
必要时出现在哪个位置
```

例如：

### Stage 1

```text
8 × Tutorial Mechanism
```

### Stage 2

```text
1 × Monster
7 × Tutorial Mechanism
```

### Stage 3

```text
1 × Knife
1 × Healing Potion
6 × Tutorial Mechanism
```

### Stage 4

```text
1 × Exit Mechanism
7 × Tutorial Mechanism
```

具体排列位置可以根据阅读顺序进行调整。

---

# 二十九、不要让正常随机系统破坏教学

教学关卡内：

* 不应该随机抽到无关怪物。
* 不应该随机抽到无关遗物。
* 不应该随机抽到普通事件。
* 不应该因为正常卡池规则导致关键教学卡没出现。

教学卡生成必须具有确定性。

可以保留正常的：

```text
发牌动画
卡牌入场动画
旋转动画
死亡动画
补牌动画
```

只是生成内容由 Tutorial Controller 控制。

---

# 三十、建议的模块结构

可以根据当前项目架构调整，但逻辑上建议类似：

```text
TutorialManager
```

负责：

```text
当前教学阶段
进入教学
进入下一阶段
监听目标完成
结束教学
首次完成存档
```

例如：

```text
TutorialManager
    CurrentStage

    StartTutorial()
    StartStage1()
    StartStage2()
    StartStage3()
    StartStage4()

    CompleteStage()
    CompleteTutorial()
```

---

另外可以有：

```text
TutorialDeck
```

负责存放：

```text
TutorialMechanismCards
TutorialExitCard
```

---

以及：

```text
TutorialStageConfig
```

负责定义每一阶段：

```text
SpawnCards
CardPositions
TutorialTexts
CompletionCondition
InfiniteRefill
CleanupRule
```

如果项目已有 DataAsset / ScriptableObject / Config 数据结构，优先使用现有体系，不要为了 Tutorial 单独创造完全不同的数据架构。

---

# 三十一、阶段切换必须彻底清场

每一阶段切换时需要特别注意：

上一阶段的：

* 教学机关
* 临时怪物
* 临时道具
* 临时监听器
* 补牌逻辑
* 阶段任务状态

都必须正确清理。

避免出现：

```text
Stage 1 的卡
残留到 Stage 2
```

或者：

```text
Stage 2 的无限补牌
继续影响 Stage 3
```

这样的状态污染。

---

# 三十二、教学过程中不要影响正常游戏资源

Tutorial Session 最好视为独立临时 Session。

进入教学前：

不要修改玩家正式游戏中的：

* 当前 HP
* 金币
* 卡组
* 遗物
* 道具
* 当前房间
* 地图进度
* 战斗进度

教学结束后：

也不要把教学里的：

* 伤害
* 消耗
* 道具
* 金币
* 卡牌

带回正常游戏。

唯一允许永久保存的内容是：

```text
TutorialCompleted = true
```

---

# 三十三、卡牌文字设计原则

教学机关不是传统 UI 弹窗。

它本身就是教学内容的一部分。

所以文本应该：

```text
短
直接
一个卡片只表达一个信息点
按照场地顺序连续阅读
尽量使用玩家已经能看到的名词
```

例如不要写：

```text
当敌对单位的行动计数到达其阈值后，
系统将自动检测当前玩家所在位置……
```

应该写成类似：

```text
怪物拥有
行动计数

计数结束
怪物会行动

进入攻击范围
你会受到攻击
```

重点是：

**让玩家扫一眼就明白。**

---

# 三十四、教学卡名称也可以参与表达

因为 Description 有 16 字限制，所以：

```text
Name
```

也可以配合 Description 进行教学。

例如：


# 三十五、需要避免的问题

实现时特别避免以下情况：

### 1.

不要把教学流程直接硬编码进普通关卡逻辑。

### 2.

不要让 Tutorial 卡进入正常随机卡池。

### 3.

不要让重新进入 Tutorial 修改正式存档资源。

### 4.

不要因为正常 RNG 导致教学需要的卡没有出现。

### 5.

不要让上一阶段残留对象影响下一阶段。

### 6.

不要用大量弹窗替代场地教学机关卡。

场地卡牌本身就是这次教学设计的核心特色。

### 7.

不要要求玩家严格按照唯一操作顺序完成可以自由完成的教学。

例如第三轮：

```text
飞刀 → 药水
```

和：

```text
药水 → 飞刀
```

都应该允许。

### 8.

不要为了 Tutorial 重做已经存在的怪物、道具、攻击、拾取和房间退出系统。

优先复用。

# 三十七、验收标准

完成之后至少保证以下情况全部成立：

* [ ] 新玩家第一次进入游戏会自动进入教学。
* [ ] 完成教学后再次启动不会自动进入。
* [ ] 主菜单可以随时重新进入教学。
* [ ] 重玩教学不影响正式游戏进度。
* [ ] Tutorial 使用独立教学卡组。
* [ ] 教学机关不会进入普通卡池。
* [ ] 第一轮正确生成 8 张教学机关。
* [ ] 第一轮击破第一张后可以补牌并旋转。
* [ ] 第一轮击破第二张后进入第二轮。
* [ ] 第二轮正确出现一个教学怪物。
* [ ] 第二轮机关可以持续补牌。
* [ ] 玩家可以利用旋转改变怪物位置。
* [ ] 击杀怪物后进入第三轮。
* [ ] 第三轮必定生成飞刀和治疗药水。
* [ ] 玩家必须实际使用两件道具。
* [ ] 两件道具使用顺序不限。
* [ ] 第四轮正确生成离开机关。
* [ ] 第四轮完整解释普通房间逃跑与道具出售机制。
* [ ] 第四轮解释 Boss 房出口规则。
* [ ] 击破离开机关后结束 Tutorial。
* [ ] 教学阶段之间不会出现残留对象或监听器污染。
* [ ] 所有教学 Description 均满足最多 16 字符限制。
* [ ] 教学文字按照场地排列后可以自然连续阅读。

# 三十八、实现优先级

目前请按照以下优先级完成：

```text
1. 教学模块可以完整独立运行
2. 四个教学阶段状态正确
3. 受控发牌正确
4. 阶段完成条件正确
5. 阶段切换与清理正确
6. 首次进入 / 主菜单进入逻辑正确
7. 教学存档状态正确
8. 教学机关文字可以正常展示
9. 卡牌排列符合阅读习惯
10. 最后再处理美术与细节
```

图标、美术、最终名称和部分最终文案暂时都不是重点。

可以先使用占位资源。

如果实现过程中遇到当前需求没有明确规定的细节：

**请优先按照现有游戏架构、现有交互习惯以及正常教学关卡设计做合理实现，不需要因为非关键细节停止开发。**

最终目标不是单独做一套新的游戏系统，而是在现有战斗系统之上，加上一层：

```text
独立 Tutorial Controller
+
Tutorial Deck
+
受控发牌
+
阶段任务
+
教学机关卡
```

从而完成一套稳定、可重复体验、不会污染正式游戏流程的完整教学关卡。
