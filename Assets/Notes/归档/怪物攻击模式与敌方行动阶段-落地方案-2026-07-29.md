# 怪物攻击模式与敌方行动阶段 — 落地方案

> **非权威。** 决策权威在 [ADR-0011](../../docs/adr/0011-monster-attack-pattern-intrinsic.md) / [ADR-0012](../../docs/adr/0012-enemy-action-phase-volley.md) / [ADR-0013](../../docs/adr/0013-action-countdown-unified.md)，领域语言权威在根目录 `CONTEXT.md`。本文只记实施顺序、拆票与迁移清单。

## 一句话

怪物从「只会被玩家打」变成「按自己的攻击模式主动出手」：每张怪物卡必填一个攻击模式，每次九宫格互动的结算链末尾追加一次敌方齐射。

## 先攻的结论（这轮的起点）

原「先攻」**没有 bug 可修**。设计文档与代码完全一致，两者都只裁决「玩家发起交战时谁先造成伤害」，从不产生额外攻击——`CombatEngagementOrder.MonsterStrikesFirst` 唯一的消费点是 `AttackIntentScriptFactory` 与 `PhaseSystem.Attack` 的入队顺序交换。「只有正交才触发」也不是先攻的限制，而是九宫格互动本身只允许打正交相邻卡，先攻寄生在这条链路上继承来的。

唯一挂了先攻的量产怪是石头人（`hp:1 / armor:4 / attack:2`，格 6 条件先攻），1 血几乎必被一刀带走，先攻的唯一可观测效果是它死前多打 2 点——这是「感觉从来没触发过」的来源。

处置：规则与代码全部保留（零回归），仅玩家可见名称改为**先手还击**。

## 实施顺序（有强制依赖）

### 阶段一 · 底层收敛（不含新机制，但行为敏感）

**T1 — 拆开 `ResolveInteractiveRotation`。** 把「互动计数 +1 / 补牌 / 旋转」拆成三件独立事；互动计数改为**每次九宫格互动无条件 +1**。

- 现状偏差：该函数只在击杀路径被调用（`PhaseSystem.Attack` 里 `if (ContainsEventSince(..., CardKilled, targetUid))`），导致未击杀的战斗不累计 `interactionCount`，与 `战斗机制.md` 矛盾。
- **这一步会改变现有行为**：依赖 `OnInteract` 的遗物/技能触发频率上升到设计值。必须单独成票，不要和新机制混在一起，否则回归来源分不清。

**T2 — 行动计数统一为倒计时语义。** 改 `OnSelfMoveTrigger`（模运算 → 倒计时）、`OnCumulativeTrigger`（阈值减 → 倒计时减 delta），给 `OnInteractTrigger` 补 `every` 参数。

- 无外部干预时行为等价，但受影响内容需回归：`tpl.skill.flame_breath.move`、`tpl.skill.stroll.move`、`tpl.skill.strong_combo.move` 等 `OnSelfMove` 系模板。
- `CoreCounterKeys` 新增攻击模式专用保留前缀，与 `EffectCounterPrefix` 隔离。
- 注意 `counterKey` 的存储含义反转（已累计量 → 剩余量）。

**T3 — 新增几何谓词「对角相邻」。** 行列差均为 1。既有 `SlotId.IsAdjacentTo` / `IBoardSystem.AreAdjacent` 的正交语义**不动**；`RuleId.VirtualAdjacency` 仍只服务怪-怪融合。纯新增，零风险。

### 阶段二 · 新机制（数据先行）

**T4 — 卡数据新增 `attackPattern` 必填枚举 + 加载期校验。** 取值：普通近战 / 斜角近战 / 全向近战 / 普通远程 / 无。缺失即装配错误。同票把 61 只怪批量写 `无`（行为中性，等价于当前现状）。

**T5 — Core 敌方行动阶段。** 报名 / 逐条结算 / 收尾三个分拍入口（参照现有 `ResolvePostKillFill` / `ResolvePostKillRotate` 风格）+ 单向打击伤害动作 + 行动名单冻结（uid 升序）+ 逐条资格复核 + 阶段内盘面冻结 + 玩家死亡即终止。收尾段只补牌与通关检查，**不旋转**。

**T6 — 表现层时间线编排。** 每只开火的怪一个 Batch、串行 ack；复用现成 Counter 通道（`Battle_Counter_Default` / `Battle_Counter_Lethal_Default`），不新增通道语义。

**T7 — 行动倒计时上卡面。** 新增 Core 事件类型 → `PresentationInstructionKind` → `PresentationEventMap` 的 Beat 归属 → `CardFaceStatHandler`。按 ADR-0005，**不得**在 View 上自己减倒计时。

### 阶段三 · 内容与打磨

**T8 — 五套模式图标 + `Action_Icon` 接线。** 目前无任何模式图标素材，接线前只能落模板兜底图。

**T9 — 61 只怪逐只定模式。** 从 `无` 改为设计意图值。

**T10 — 先攻 → 先手还击 的玩家可见改名。** 代码侧 `RuleId.FirstStrike`、`CombatEngagementOrder`、两条效果模板标识符**不动**。

## 卡面槽位对照

三个位置早已存在、目前恒为 0 / 未接线，本次结清：

| 载体 | 存什么 |
|------|--------|
| JSON `stats.action` | 该模式的阈值 N（作者填） |
| 卡面槽 `Action_Icon` | 攻击模式图标 |
| 卡面槽 `ActionCount` | 行动倒计时（3 → 2 → 1 → 开火） |

`monster.big_orc` 的卡面描述已写着「在[Action_Icon]后攻击玩家」，本次从预告变成事实。

## 待议项（不阻塞规则落地）

1. **`OnBattle` 是否收紧为交战作用域。** `DealDamageAction` 无条件 raise `TriggerPoint.OnBattle`，而它实际语义是「任意伤害动作之后」。现有 11 条模板全部带 `targetKind: Monster`，所以单向打击今天不会命中任何一条——风险是结构性的。倾向收紧并据此定义「每战斗 N 次」不计单向打击，**未定案**。
2. **攻击力 0 的怪。** `monster.big_stone`（0/1/5）与 `monster.fire_priest`（0/12/8）零反击，玩家砍它们不付血量代价，因而能免费冻结盘面。两者只能填 `无`。或调数值、或限制同场投放、或明确定为「可用来买时间的安全沙袋」。
3. **模式图标美术。**
4. **平衡实测。** ADR-0013 的期望间隔表以「每次互动都旋转」为一阶近似；实际未击杀不旋转，需实测校正。
