## 二、具体缺口清单

### 缺口 1：覆盖层适配器 — ✅ 已闭合（2026-06-24）

**落地**：`TableNineOverlayAdaptor` + `SelectionOverlayController` + `SelectionOverlayFsm`；复用 `SelectionOverlayPreviewTool` 同源原子表演；MainScene `Selet Performance` 接线。

**覆盖场景**：帮助卡三选（可跳过）、宝箱/遗物 OfferReward（可跳过）、房间二选一、进房确认、stat_boost 攻/甲/血（均无跳过）。

**跳过规则**（`SelectionOverlaySkipRules`）：`help.*.choice`（含 `help.choice`）与 `relic.*` 池最右追加跳过卡 → `SkipHelpChoiceCommand`；其余场景不显示跳过。

**剩余缺口**：遗物跳过 +20 与帮助卡 +10 未在 `SkipHelpChoice` 分流；`ItemCardInteractionFsm` 尚未自动调起 stat_boost 覆盖层。

### 缺口 2：TableNineEffectAdaptor 未接入场景

**现状**：代码存在（132行），`PresentationBatchPlayer` 声明了 `[SerializeField] private TableNineEffectAdaptor effectAdaptor` 并有 GetComponent 兜底，但**场景中未挂载该组件**。

**影响**：`EffectTriggered` 和 `ApplyModifier` 指令在批次中被静默跳过。虽然当前两个表演都是 0s 占位直通，但至少应该接入场景以保证管线完整。

**修复**：在 `PresentationBatchPlayer` 同级 GameObject 上添加 `TableNineEffectAdaptor` 组件。

### 缺口 3：ContentCatalog 场景运行时未加载

**现状**：`ContentCatalogBootstrap.Load` / `IContentSystem.Load` 仅在测试中被调用。`InGameFlowShellFsm.RunBoot()` 只调 `InitialGameFactory.Create()`，不加载任何内容目录。

**当前影响**：不阻塞 MVP。`DevStartNodeTool` 用 `NodeDeckOptions.CreateDefaultBattle()` 硬编码了 6 张卡牌（player.strike / player.guard / player.coin / monster.slime / monster.bat / monster.guard），不依赖 catalog。

**后续影响**：要跑真实数据（不同节点不同怪物、道具效果、奖励池等），必须接入 catalog 加载。Luban JSON 数据已存在于 `Assets/StreamingAssets/TableNine/LubanData/`。

### 缺口 4：无悬停信息展示组件

**现状**：整个表现层没有任何 `OnPointerEnter/Exit`、`OnMouseEnter/Over`、`ShowInfo`、`CardInfoDisplay`、`CardTooltip` 等组件。`CardHoverPerformance` 仅做缩放+wobble 动画，无文字/UI 信息展示。

**用户需求**：鼠标悬停卡牌时显示 Info Text（CardUid / DefId / HP / Attack / Armor 等），作为 MVP 的"简陋但够用"信息查看方式。

### 缺口 5：道具使用选择链路中段断裂

**现状链路**：

```
Command层（selectedCardUids + selectedOption 三参数构造） ✅
    ↓
PhaseSystem.UseItem 透传参数到 UseItemAction ✅
    ↓
UseItemAction 把参数序列化进 ItemUsed 事件 Message 字符串 ✅
    ↓
效果系统消费参数驱动 stat_boost 等效果 ❌ —— 参数进了 Message 但无人解析
    ↓
ItemUseProfileResolver 推导交互模式 ❌ —— 类不存在
    ↓
PendingChoiceKind 支持 OptionOverlay ❌ —— 仅 None/Reward/Room
    ↓
表现层 OverlayFSM 管理道具选项 ❌ —— 不存在
```

**影响**：蓝图设计的"道具 OptionOverlay（stat_boost 选属性）"功能在内核和表现层都缺乏支持。当前 `UseItemCommand` 只传 `itemUid` 就能触发道具效果（效果系统按 JSON 配置执行），但"玩家选属性再生效"的交互链路不完整。

**对 MVP 的影响**：不阻塞。MVP 可以先用"无选择道具"（即 ApplyZone 型，直接使用不需要选目标/选项），或暂时跳过道具使用功能。

### 缺口 6：CardHoverPerformance.cardPreviewPrefab 场景中为空

**现状**：`CardHoverPerformance` 的 `cardPreviewPrefab` 字段在场景中未赋值（`{fileID: 0}`），悬停时无卡面预览。不过多个 Performance 脚本有"为 null 时生成纯色 Sprite 占位"的兜底逻辑。

### 缺口 7：根目录存在过期 MainScene.unity 副本

**现状**：`Assets/MainScene.unity`（12837行）是较旧副本，缺少 ItemAdaptor / StatusAdaptor / DevStartNodeTool / InGameFlowShellFsm / EffectAdaptor。`Assets/Scenes/MainScene.unity`（13654行）才是当前有效主场景。

**风险**：误打开旧场景导致组件缺失、功能异常。

### 混乱 2：选择系统的"三套设计意图"打架

1. **蓝图原始设计**：PendingChoice（内核选择）和 OptionOverlay（道具选项）是两条分支，通过判断节点区分

用户说的"做了一个非常灵动的多选一的选择表现，把它给所有需要进行待选择的效果来用"，对应的是 `SelectionOverlayPreviewTool` 中验证过的完整选择流程（入场→悬停→确认→退场）。这个流程在预览工具中**已经能跑通**，但缺少一个适配器把它从"预览模式"切换到"生产模式"。

## 四、关键控制器失效风险

### 风险 1：选择阶段内核不卡但表现层"黑屏"

当节点通关后，内核发出 `RewardOffered` 事件 → 进入 `RewardItemChoice` 阶段 → 表现层收到批次 → 6 条覆盖层指令静默穿透 → 批末发送 `PresentationFinishedCommand` → 内核解锁 → 但玩家什么都没看到 → 内核认为选择已完成但实际无人选 → **可能死锁或自动跳过**。

**验证需要**：检查内核在 `RewardItemChoice` 阶段如果没有收到 `SelectRewardCommand` 是否会卡住，还是 `PresentationFinishedCommand` 解锁后仍等待玩家选择。根据 Command 清单文档，`SelectRewardCommand` 仅在 `RewardItemChoice` 且未锁输入时合法——这意味着批次播放完后（解锁），玩家需要手动选择奖励。但如果没有选择 UI，玩家无法选择，游戏会**卡在 RewardItemChoice 阶段**。

### 风险 2：EffectAdaptor 为 null 时的防御

`PresentationBatchPlayer` 的路由代码中，如果 `effectAdaptor == null`，EffectTrigger/ApplyModifier 指令会被跳过（不报错）。但需要确认 `CanHandle` 调用前是否有 null 检查——如果没有，会抛 NullReferenceException。

### 风险 3：根目录 MainScene.unity 误用

如果误打开 `Assets/MainScene.unity`（旧副本），ItemAdaptor / StatusAdaptor / DevStartNodeTool / InGameFlowShellFsm 等组件缺失，导致功能异常且不易定位原因。

### 阶段 1：覆盖层接入（预计 2-3 天，核心攻坚）

这是**最关键的一步**——让选择系统从"预览模式"切换到"生产模式"。

**1-1. 创建 TableNineOverlayAdaptor**

新建 `Adaptors/TableNineOverlayAdaptor.cs`，实现 `CanHandle` / `PlayInstruction` 模式：

```
认领指令：
  OfferReward, OfferRooms     → 入场（SelectionOverlayEntrancePerformance.Play）
  SelectReward, SelectRoom    → 确认+退场（SelectionOptionConfirm + SelectionOptionFallOff）
  SkipReward                  → 全部退场
  ResolveRoom                 → 房间结算（可选占位）

输入数据来源：
  OfferReward  → batch.Snapshot.RewardOptions（List<RewardEntry>）
  OfferRooms   → batch.Snapshot.RoomOptions（List<RoomKind>）
  
输出 Command（玩家选择后）：
  SelectRewardCommand(optionIndex)
  SkipHelpChoiceCommand()
  SelectRoomCommand(optionIndex)
  EnterRoomCommand()
```

**1-2. 注册到 PresentationBatchPlayer**

在 `PresentationBatchPlayer` 中添加 `[SerializeField] private TableNineOverlayAdaptor overlayAdaptor`，并在路由链中加入 overlay 适配器。

**1-3. InGameFlowShellFsm 接线**

将 `ApplyScreen()` 中的 `Debug.Log` 替换为实际的覆盖层激活/停用逻辑：
- `RewardScreen` / `RoomChoiceScreen` → 激活覆盖层交互
- 其他屏幕 → 停用覆盖层

**1-4. 创建覆盖层选项卡生成器**

选择表演需要 `List<Transform>` 作为选项卡。需要从 `CoreViewSnapshot.RewardOptions` 或 `RoomOptions` 创建选项卡 GameObject：
- 奖励选项：用 `SelectionOptionVisual.CreatePreviewCard` 创建占位卡
- 房间选项：用简单 UI Button 或占位卡
- 每个选项卡挂上点击/悬停检测，驱动对应 Performance

**1-5. 玩家选择→Command 回传**

选项卡点击后发送对应 Command：
- 奖励选择 → `SelectRewardCommand(optionIndex)` 通过 `CoreCommandDispatcher.Send()`
- 房间选择 → `SelectRoomCommand(optionIndex)`
- 跳过 → `SkipHelpChoiceCommand()`
- 进入房间 → `EnterRoomCommand()`
