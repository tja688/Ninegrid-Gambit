## Context

重新设计现有音频编辑器，使 AI 全量绑定后的人工验收形成一条完整工作流：Play Mode 中最新音频事件持续冒泡，人工可立刻抓取并固定某条记录，查看触发来源与实际播放结果，直接试听、停用、替换并调整绑定；同时保留清晰的非运行时静态音频绑定管理能力。计划还将基于现有 Unity/音频接口给出 HTML 动态界面的可行性结论，并选定唯一实现路线。

## Approach

### 1. Deepen the runtime audio seam for live authoring

1. In `Assets/Scripts/NineGrid.Foundation/NineGrid.Content/Audio/AudioBindingCatalog.cs`, add exact parser `public static bool TryFromJson(string json, out AudioBindingCatalog catalog, out string error)`. It must reject null/blank, malformed JSON, a null DTO, or a null `bindings` collection and leave `catalog=null`; `FromJson` keeps its current tolerant runtime-loading behavior by delegating and returning an empty catalog on failure. The live workbench uses only the strict method so a bad browser patch cannot silently replace the active catalog with an empty one.
2. In `Assets/Scripts/NineGrid.Presentation/Systems/AudioSystem.cs`, replace the construction-only catalog dependency with a mutable current catalog and add the editor/development interface below to `IAudioSystem` under the existing `#if UNITY_EDITOR || DEVELOPMENT_BUILD` guard:
   ```csharp
   AudioWorkbenchSnapshot GetWorkbenchSnapshot();
   AudioWorkbenchApplyResult ApplyWorkbenchCatalog(string catalogJson);
   AudioWorkbenchPreviewResult PreviewWorkbenchBinding(string bindingKey, bool includeBindingDelay);
   bool StopSfxSource(string sourceId);
   ```
   Add `AudioWorkbenchSnapshot`, `AudioWorkbenchApplyResult`, `AudioWorkbenchPreviewResult`, and `AudioCueAggregate` beside `AudioHistoryRecord`. `AudioWorkbenchSnapshot` contains immutable copies of monotonically increasing `Revision`, `History`, current `PlayingSources`, and aggregates grouped by final `BindingKey` with `CueId` fallback. Each aggregate carries `Requested`, `Played`, `Suppressed`, `Cooldown`, `Unbound`, `BackendFailure`, `LastTime`, `LastFailureReason`, and the latest 32 request timestamps for the sparkline/burst badge.
3. Give every `AudioHistoryRecord` an assigned `long Sequence` from an `mNextHistorySequence` counter in `AddHistory`; this is the stable capture ID used by pinning. Also store the full request context already available to `RecordTrace`: `CardDefId`, `SkillId`, `RoomId`, `ItemDefId`, `ContentId`, and `DiagnosticCardUid`, plus the `SourceId` returned by the playback adapter. Populate these fields for every outcome where the request is known; scheduled/cancelled records keep their schedule fields and have no source ID.
4. Extend `AudioHistoryOutcome` with exact member `Suppressed`. Treat a resolved binding with `enabled=false` as `Suppressed` rather than `Unbound`: record its `CueNote`, `BindingKey`, request context, and trace kind literal `AudioCueSuppressed` with reason literal `"workbench binding disabled"`, then skip variant selection/playback. This makes the user's rule exact: switching off without saving is temporary work-copy suppression; saving the same dirty binding makes it permanent in `audio_bindings.json`. Suppressed triggers continue entering history and aggregates.
5. `ApplyWorkbenchCatalog(string catalogJson)` uses `AudioBindingCatalog.TryFromJson`, atomically replaces only the catalog used by future requests, increments `Revision`, and returns `{ Succeeded, Revision, Error }`. Invalid input fails without replacing the prior catalog. Preserve cue-level burst windows and recent-play timestamps across apply; clear `mLastPlayedAt` and `mLastVariantIds` because they are keyed by obsolete `AudioBinding` instances. Already scheduled cues retain their `AudioCueRequest` and resolve against the newest catalog when their callback reaches `RequestCue`; already playing sources are not restarted or stopped.
6. Extend `IAudioPlaybackDiagnosticsAdapter` in `Assets/Scripts/NineGrid.Presentation/Systems/AudioDiagnostics.cs` with `bool StopSfxSource(string sourceId)`. Implement it in `MMSoundManagerAudioPlaybackAdapter`: look up the registered source, call `MMSoundManager.FreeSound` when the manager exists or `AudioSource.Stop()` otherwise, remove `sfxSources` / `sfxClipKeys` / `sfxCueIds`, and return false for empty, unknown, or already-dead IDs. `AudioSystem.StopSfxSource` delegates only when its playback adapter implements this diagnostics interface. Keep all MMSoundManager access inside the adapter so `AudioStructureGuardTests` remains valid.
7. Extend `AudioBackendResult` with `SourceId`; change `Success` to exact signature `AudioBackendResult Success(string actualClipKey, string sourceId = null)`. `MMSoundManagerAudioPlaybackAdapter.Play` returns its stable `sfx-source:<instanceId>` ID. Existing fake adapters remain source-less through the optional parameter; update every exact `AudioBackendResult.Success(` callsite returned by repository search.
### 2. Make the existing editor sessions the single authoring authority

   ```csharp
   bool TryCreateDraft(string cueId, out AudioBindingEditorEntry entry, out string error);
   bool TryReplaceWorkingDto(string originalBindingKey, AudioBindingDto replacement, out AudioBindingEditorEntry entry, out string error);
   AudioBindingCatalogDto BuildWorkingCatalog();
   string BuildWorkingJson();
   void LoadFromSnapshots(string savedJson, string workingJson, IEnumerable<AudioBindingEditorDeclaration> declarations, IEnumerable<AudioBindingEditorClipOption> clipOptions);
   ```
   `TryReplaceWorkingDto` locates by current/historical binding key, keeps `cueId`, `note`, `module`, and `authoringStatus` authoritative from the session, and copies only editable fields: `enabled`, `clipKey`, `volumeDb`, `startOffsetSeconds`, `bindingDelaySeconds`, `minimumIntervalSeconds`, `variants`, and the five selectors. Clamp start offset, delay, interval, variant weight, and variant offset to `>=0`; reject a null replacement or a binding-key collision. Add equivalent `TryReplaceWorkingDto(string state, MusicBindingDto replacement, ...)`, `BuildWorkingJson`, and `LoadFromSnapshots` to `MusicBindingEditorSession`.
2. Add `AudioWorkbenchEditorState` as the single editor-side owner of both sessions, focus, status, and conflict state. After every SFX mutation, it calls `IAudioSystem.ApplyWorkbenchCatalog(session.BuildWorkingJson())` when Play Mode is active; it never writes disk. `TrySave` / `TrySaveAll` remain the only persistence paths and continue marking SFX rows `authoringStatus="humanConfirmed"`; save, revert, and reload immediately re-apply the resulting SFX work copy. Already playing audio is untouched.
3. Preserve unsaved work across Play Mode domain reloads with `UnityEditor.SessionState`, key literal `NineGrid.AudioWorkbench.Transient.v1`. Store exact baseline SFX/BGM JSON, current working SFX/BGM JSON, focused binding key, and status after every mutation and again in `beforeAssemblyReload`. On restore, if both current disk JSON strings equal their stored baselines, call `LoadFromSnapshots` and continue. If either disk file changed, keep the transient payload intact, load current disk into the live sessions, block save/revert/apply commands, and show two explicit recovery actions: `恢复临时版本并覆盖磁盘` and `丢弃临时版本并使用磁盘`. The first restores old baseline+working snapshots and requires a confirmation before the next save; the second clears the SessionState payload. No silent merge or silent loss.
4. Before `TrySave` / `TrySaveAll`, validate `BuildWorkingCatalog()` with `AudioBindingCatalogHygieneValidator.Validate` using `KnownClipKeys` and declared cue IDs. Reject critical duplicate key, coverage conflict, missing/forbidden clip, invalid variant/parameter, or orphan findings without writing disk; return all messages to the browser error panel. Keep BGM persistence on its existing session validation behavior.
5. Reuse `FindEntryForHistory`, `ComputeBindingKey`, `FindClipOption`, `AudioBindingEditorPreview`, and the current clip-option list. Browser commands expose only: `createDraft`, `replaceSfxBinding`, `replaceMusicBinding`, `saveBinding`, `saveAll`, `revertBinding`, `revertAll`, `reloadFromDisk`, `previewBinding`, `previewClip`, `stopPreview`, `stopSfxSource`, `runAiBindPreserve`, `pingClipAsset`, `stopUnknownMusic`, `previewMusic`, `endMusicPreview`, `recoverTransient`, and `discardTransient`. `pingClipAsset` resolves `AudioBindingEditorClipOption.AssetPath`, sets `Selection.activeObject`, and calls `EditorGUIUtility.PingObject`. `copyTriggerSource` stays client-side because the snapshot already carries both source strings.
6. For Play Mode SFX preview, add `AudioWorkbenchPreviewResult PreviewWorkbenchBinding(string bindingKey, bool includeBindingDelay)` to the editor/development `IAudioSystem` interface. It finds the exact current binding by `BindingKey`, ignores `enabled` so a temporarily/permanently muted binding can still be auditioned, rejects only missing/broken material, selects a valid variant with the existing variation logic, and calls the adapter with current volume/start offset and optional delay without touching cooldown, burst counters, or normal history. Return actual clip, variant, source ID, and failure reason. Outside Play Mode, `AudioWorkbenchEditorState` falls back to the existing `AudioBindingEditorPreview` (`AudioUtil`) path; this fallback previews clip/start offset only and the UI labels that limitation.
### 3. Replace the window renderer with an editor-hosted HTML application

1. Replace the UI-heavy `AudioBindingEditorWindow.cs` implementation with an editor-only launcher in the same `NineGrid.Content.Editor` assembly; keep the menu path literal `NineGrid/音频/声音绑定调音工作台`. The menu calls `AudioWorkbenchServer.EnsureStarted()` and opens its authenticated URL through `Application.OpenURL`. Move `AudioBindingEditorPreview` into `AudioBindingEditorPreview.cs`. Delete the old UI Toolkit renderer after migrating its behaviors; do not leave a fallback window or a second session owner.
2. Add `[InitializeOnLoad]` static `AudioWorkbenchServer`, copying lifecycle/dispatcher patterns from installed `com.unity.pipeline` (`EditorPipelineStartup`, `BasePipelineServer`, `Dispatcher`) without referencing its internal implementation. Expose read-only `public static string LaunchUrl { get; }` for the launcher, deterministic verification, and reconnect diagnostics. Bind `HttpListener` through `http://+:{port}/`, preferring the port stored in `SessionState` and otherwise selecting the first free port in `7910–7939`; reject any non-loopback `RemoteEndPoint`, serve only the exact Host/Origin values `http://127.0.0.1:{port}` and `http://localhost:{port}`, and close/recreate on Editor quit/recompile. Own a `ConcurrentQueue` main-thread dispatcher pumped by `EditorApplication.update` with at most 32 RPC jobs and one state broadcast per tick.
3. Generate a 32-byte cryptographic token once per Editor session, encode it base64url, and persist token+port in `UnityEditor.SessionState` keys `NineGrid.AudioWorkbench.Token.v1` and `NineGrid.AudioWorkbench.Port.v1` so an already-open browser can reconnect after domain reload. The launcher opens `http://127.0.0.1:{port}/#token=<token>`. Static `GET /`, `/styles.css`, and `/app.js` require no token but return a strict Content-Security-Policy (`default-src 'self'; connect-src 'self'; script-src 'self'; style-src 'self'; object-src 'none'; base-uri 'none'`), `X-Content-Type-Options: nosniff`, and `Cache-Control: no-store`. All `/api/*` calls require `Authorization: Bearer <token>`; `/stream` requires a same-origin WebSocket upgrade followed within 5 seconds by JSON `{ "type":"hello", "token":"...", "afterRevision":<long> }`. Reject payloads over 1 MiB, unsupported methods, unknown commands, invalid enum/outcome values, and non-finite numeric patch fields.
4. Use `HttpListenerContext.AcceptWebSocketAsync(null)` for `/stream`; do not add Vuplex, CEF, WebView2, Fleck, npm, a package registry, or a frontend build step. If a one-time server self-check proves WebSocket upgrade unsupported on the actual Unity Mono runtime, disable `/stream` and expose authenticated long-poll `GET /api/events?afterRevision=<long>&timeoutMs=25000`; return immediately on a newer revision or after the timeout. Both transports use the same envelopes:
   ```json
   { "type":"snapshot", "protocolVersion":1, "revision":42, "payload":{...} }
   { "type":"delta", "protocolVersion":1, "revision":43, "payload":{...} }
   { "type":"commandResult", "requestId":"...", "ok":true, "payload":{...}, "error":"" }
   ```
   After reconnect/domain reload the client always requests and replaces state from a full `snapshot`; deltas are accepted only when `revision == currentRevision + 1`, otherwise the client requests another snapshot.
5. Add plain `index.html`, `styles.css`, and `app.js` under constant asset root `Assets/Scripts/NineGrid.Foundation/NineGrid.Content.Editor/AudioWorkbenchWeb/`; the server reads these exact files once per domain and never writes them. JavaScript is dependency-free ES2020, uses keyed Maps and a fixed row pool/overscan virtual list, and keeps pins/filters/column widths in `localStorage` key literal `NineGrid.AudioWorkbench.Ui.v1`; binding work copies never enter browser storage.
6. Use the already-resolved `Newtonsoft.Json` package for protocol DTO serialization/deserialization; do not use `JsonUtility` for envelopes containing dictionaries/lists and do not add a package dependency. The server's full snapshot includes: play-mode/connection state; SFX and BGM disk/work copies plus dirty/conflict flags; cue declarations; clip options with resource key/asset path/duration; runtime history/aggregates/playing sources; music desired/current state/history/audit/anomalies; and status/error messages. Deltas are limited to appended audio/music records, aggregate/source changes, focused/dirty session changes, and command results. Compare runtime `AudioWorkbenchSnapshot.Revision`, latest history `Sequence`, session serialized fingerprints, and music history count each update; emit nothing when all are unchanged.
### 4. Implement the capture-first interaction model

1. The single browser workbench has three top navigation modes: `实时抓音`, `静态绑定库`, and `BGM`. Default to `实时抓音` whenever Play Mode is active and `静态绑定库` otherwise. Shared dirty/conflict state, focused binding, `保存全部`, `回撤全部`, `重载磁盘`, AI bind, connection badge, and errors remain visible across modes.
2. `实时抓音` uses a three-column desktop layout with draggable separators and these exact responsibilities:
   - left `实时流`: newest-first virtual list, one row per `Played`, `Suppressed`, `Cooldown`, `Unbound`, `BackendFailure`, `Scheduled`, or `Cancelled`; `Requested` is hidden by default but available as a filter. New rows receive a 600 ms highlight, never change selection, and auto-follow only while the user is within 24 px of the newest edge;
   - center `已固定`: Space/click pins by `AudioHistoryRecord.Sequence`. Pinned snapshots survive runtime-ring eviction in `localStorage`, preserve the original event fields, and keep `BindingKey`/CueId links to current authoring data. Re-pinning focuses the existing card; unbound events use `CueId` and can create a base draft;
   - right `检查与调音`: show outcome, cue note/ID, all five request context IDs, actual clip/variant, binding key/selectors, diagnostic source, authoritative emitter, time, reason, schedule/source IDs. Actions are `固定/取消固定`, `停止本次播放` (only while SourceId is in `PlayingSources`), `试听当前绑定`, `定位素材`, `复制触发源`; below them render enabled, searchable base clip, dB, start offset, binding delay, minimum interval, variants, and selectors plus `保存此条`/`回撤此条`.
3. Filters are text, module, outcome chips, and exact `只看异常 = Suppressed | Cooldown | Unbound | BackendFailure`. `暂停流入视图` continues capture/server aggregation but queues DOM additions until resumed; `清空视图` clears only the browser's unpinned row store. Shortcuts while focus is outside input/textarea/select/contenteditable: `Space` pin, `E` toggle enabled/hot-apply, `P` preview, `Ctrl+S` save selected, `Esc` close picker/clear selection; call `preventDefault` for handled keys.
4. The top frequency rail is derived from `AudioCueAggregate`, sorted by abnormal count descending, then request count, then last time. It shows cue/note, request/played/suppressed/cooldown/unbound/backend counts, last seen, and a 32-sample sparkline. Clicking an aggregate applies its binding/cue filter and selects its newest event. Mark `高频` when at least 4 requests occur inside any 1-second span, matching existing `AudioSystem` burst constants.
5. The enabled toggle labels the state exactly: dirty `enabled=false` → `临时静音（未保存）`; saved `enabled=false` → `已永久禁用`; dirty `enabled=true` over a saved-disabled row → `临时恢复（未保存）`. Revert restores the saved state and hot-applies it. Suppressed rows continue to appear so the operator can prove that an emitter still fires after silencing it.
6. `静态绑定库` uses a virtualized table driven by all declarations/bindings, with columns note, cue ID, module, clip/pool size, selector summary, AI草稿/人工确认, enabled, dirty, broken, and latest runtime outcome. Filters: dirty, unbound, broken, AI draft, disabled. It reuses the same right editor and supports create draft, AI initial bind, per-row/all save, per-row/all revert, and disk reload; switching modes never clones the session.
7. `BGM` reproduces the current editor's complete behavior: desired/current state, current clip/generation, current and retiring source counts, history, `LastAudit`, overlap anomalies, explicit stop-unknown action, all `audio_music.json` editable fields, per-state save/revert, and safe preview/end-preview. BGM work-copy changes do not hot-swap the live music catalog in this ticket; preview is the immediate audition path and saved changes take effect on the next runtime system installation, matching current `MusicSystem` construction semantics.
8. Use a warm-console browser visual language derived from `ContentVisualWarmConsoleUi.Theme`: layered brown surfaces, amber left stripes, off-white text, 6/8 px radii, bottom dividers, dense 12–14 px typography. Do not port UXML/USS or the old full-page foldout layout; prioritize stream scan speed, stable row height, visible state color, and a fixed detail editor.

## Assumptions & contingencies

- The primary interface is an external same-origin HTML workbench in the system browser, not a docked EditorWindow. Unity 6.3 has no official embedded WebView package in this project; embedded Chromium/WebView options add native binaries/licensing and weaker Editor integration. The static editor is also rendered in this one browser workbench, per the single-workbench choice; Unity retains only launcher/server/editor-state modules.
- Runtime persistence follows the chosen rule: every SFX edit hot-applies to future triggers, but only explicit save writes formal JSON; disabling without saving is temporary silence, saving makes it permanent. Unsaved work survives Play Mode/domain reload through SessionState and never silently overwrites externally changed disk data.
- HTML transport defaults to built-in `HttpListener` WebSocket. If the actual Unity Mono runtime fails the startup upgrade self-check, use the specified authenticated long-poll endpoint with the same protocol/revision rules; do not add a third-party networking or browser package.
- BGM remains preview-plus-save rather than live catalog hot-swap because `MusicSystem` owns current/retiring generation state and the request did not require mid-track rebinding. If implementation discovers an existing safe mutable music-catalog seam, do not use it in this ticket; preserve the explicit behavior above.
