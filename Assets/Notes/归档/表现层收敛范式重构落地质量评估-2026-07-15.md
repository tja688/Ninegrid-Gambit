# 表现层收敛范式重构落地质量评估

> 日期：2026-07-15  
> 依据：`.cursor/plans/表现层收敛范式重构_4ce851e6.plan.md`、`Assets/Notes/多层级代理约束收敛驱动控制-范式设计.md`  
> 范围：只评估表现层重构落地质量与下一步目标，不评估 Core 内部设计。

## 一句话结论

这轮重构已经完成了从“世界空间竞争写 `transform.position`”到“固定塔 + L2/L3 局部收敛 + Step/Commitment 契约”的主体迁移，尤其是场上卡主路径的地基质量明显高于普通救火式重构。

但当前状态还不能称为“范式全闭环”。它更准确地处在：**核心地基可信、主战斗/盘面路径已接入、诊断和测试骨架较完整，但协调层与执行层仍未完全绑死，Legacy/fallback/净土边界仍会把旧范式重新带进复杂域**。

后续目标不应再继续扩新概念，而应收敛到四件事：**退役 Legacy 回退、收口无塔和 DOTween fallback、把栅栏/租约接到真实 driver 完成事件、用 Perf/Core 日志证明全流程没有旧 writer 重新抢位**。

## 原范式目标复述

原设计要根治的不是某个移动 bug，而是一个范式病：

- 多个系统直接写同一张卡的 world position。
- 完成依赖阈值、预算、取消令牌等间接条件。
- 跨流程靠 `TryReleaseFlightForHop`、替身、追坐标等握手交接。
- lunge、hop、deal、fusion 等语义混在同一 Transform 上互相 `KillMotion`。

新范式的最低成功标准应是：

- 场上卡有固定 L0-L4 塔，运行时换格不换父。
- 格位位移写 L2，特效位移写 L3，两个层互不抢写。
- 所有可承诺的复杂域表演都有明确 sourceTime，到点必达。
- StepProjector 只输出带 `CommitmentKind` 的有序 Step，执行层消费 Step，而不是 Flow 层散落直调 Field 动画。
- 同步表演通过 lease 或同等机制保护承诺，异步表演可被后发先至或同步征用。
- 诊断能看到 commitment、barrier、lease、handoff，而不是事后凭画面猜。

## 当前已高质量落地的部分

### 1. 数学与塔地基基本可信

`ConvergenceCurve1D`、`ConvergenceCurve`、`LayerConvergenceDriver` 已经实现了有限时长五次 Hermite 收敛：

- `LayerConvergenceDriver.ConvergeTo` 用当前 local position + 当前速度重解曲线。
- `Tick` 每帧写目标层 `localPosition`。
- 完成时强制落到 `_targetLocal`，并触发 `Completed`。
- `Evict` 在复杂域吐真实速度，`Admit` 保存接手速度，接口形态已经付了后续 B 阶段升级的“前提税”。

`CardTransformTower` 固定 L0-L4，并由 `CardManagerSingleton` / `StandardCardPrefabSetup` 装配。这个方向正确：塔不是临时代理父节点，而是每张卡自己的固定局部空间结构。

### 2. L2/L3 语义拆分已经成型

`SlotFrameConvergence` 承担 L2 格位收敛：

- 就位约定是 L0 在格锚、L2.local = 0。
- 补牌通过 `BeginDealFromLaunch`：L0 先落目标格，L2 从起飞 local 收敛回 0。
- 换格/旋转/hop 通过 `ConvergeVisualToWorld` 写 L2 目标。
- `SlotDealFlightService` 已替代旧补牌飞行协调器，把“飞行中被 hop 改目标”变成 L2 redirect。

`EffectFrameConvergence` 承担 L3 特效位移：

- lunge 等有塔路径已经可以走 L3 out-and-back。
- 融合可用 L3 同步撞中点，再 `ParkRootAtWorld` 固化。
- L2/L3 分层让“格位正在动”和“受击/lunge 正在动”不再天然互相抢同一个坐标。

这部分是整个重构质量最高的区域，也是后续继续推进时最不应该推翻的区域。

### 3. Step/Commitment 契约已经进入主 Drain 路径

`BoardPresentationStepProjector` 已输出 `BoardPresentationStep[]`，每个 Step 带：

- `BoardPresentationStepKind`
- `CommitmentKind`
- `MultiHopProjectionStrategy`
- Moves / Deals / RemovedUids 等 payload

`InBattleManagerSingleton.DrainPostKillBoardCoreAsync` 已优先消费 `Steps`，位移类 Step 走 `BoardMotionStepScheduler.ExecuteMotionStepAsync`，再进入 `GroundFieldManagerSingleton.ApplyBoardMovesAndHopAsync`。

这意味着 Flow 层不再总是散落直调具体 Field 动画，而是有了“有序 Step[]”这个统一入口。对照计划里的阶段 4，这个最危险的大切换点已经基本落地。

### 4. 租约与诊断骨架存在，而且方向正确

`LeaseArbiter` 覆盖了设计中的四象限：

- Async vs Async：后发先至。
- Sync 持锁被 Async 抢：拒绝。
- Async 被 Sync 抢：同步征用并采样 handoff。
- Sync vs Sync：纪律 B 报警。

`GroundFieldManagerSingleton` 已在 Sync L2 hop 中调用 `IssueSyncL2Lease` / `ReleaseSyncL2Lease`，并通过 `ConvergenceDiagProbe` 写 lease / handoff / barrier / commitment 类诊断。这说明本轮不只是重构代码结构，也在把“设计纪律”变成可观测事件。

### 5. 测试覆盖集中在正确层级

已有测试覆盖面较合理：

- 曲线：到点、C1 重定向、极端预算、通用维度。
- 塔：结构与驱动器。
- L2/L3：坐标换算、独立层写入、融合中点。
- 租约：四象限与 handoff。
- BeatGrid：共享 sourceTime 与 barrier 语义。
- StepProjector：S/C 多跳投影与 commitment。

这些测试大多避开主观“看起来丝滑”，而验证纯逻辑语义，方向正确。

## 当前尚未闭环的关键问题

### 1. 栅栏还不是“真实就位栅栏”

`BeatGrid` 当前注册的是 `BeatConvergenceSlot` 纯逻辑槽。它的完成判定是：

- 当前时钟 elapsed >= sourceTime。

它不直接绑定 `LayerConvergenceDriver.Completed`，也不验证某张卡某层真的完成。因此它更像“时间预算栅栏/诊断栅栏”，而不是严格的“执行层完成栅栏”。

这有两个后果：

- 如果 driver 被 redirect、取消、停住或无塔 fallback 吞掉，BeatGrid 自己仍可能认为时间满足。
- 真正等待仍主要依赖 `SlotFrameConvergence.AwaitDriverAsync` 的轮询，而不是 barrier 统一收束。

这不等于当前一定有 bug，但它说明“铁律1：承诺时刻必然就位”的系统级证明还没闭合。

### 2. 租约主要接入 L2 Sync hop，L3 和部分 Async 仍未纳入仲裁

生产路径中 lease 最明确的接入点是 `GroundFieldManagerSingleton` 的 L2 Sync hop / swap。L3 的 lunge、fusion、受击类动作更多是直接调用 `EffectFrameConvergence`，暂未看到同等的 L3 lease 申请。

这与“按层独占，非整卡”的设计并不矛盾，但目前还没有形成全复杂域统一纪律：

- L2 Sync 有租约。
- L2 Async 多数只是后发先至。
- L3 主要靠分层隔离和调用顺序，而不是仲裁。
- `CommitmentKind` 在 `SlotFrameConvergence` 中也有一部分只是诊断参数，不等价于所有写入都过 `LeaseArbiter`。

如果后续出现“融合 L3、受击 L3、战斗终态复位”并发，仍需要专门纪律。

### 3. Legacy 回退和双轨数据仍保留

`BoardPresentationStepProjector.ProjectionResult` 同时输出：

- `Steps`
- `LegacyMoves`
- `LegacyDeals`
- `LegacyRemovedUids`

`DrainPostKillBoardCoreAsync` 在 `stepCount == 0` 时仍会走 `DrainLegacyBoardDeltaAsync`。

这在过渡期合理，但它会带来两个风险：

- 后续新增 Core event 或某条流程漏投影 Step 时，会静默落回旧 Drain。
- 团队维护时可能继续依赖 Legacy 字段，不自觉延长双轨寿命。

只要 Legacy 回退还活着，就不能说执行入口已经完全唯一化。

### 4. 无塔 fallback 仍会重新写 world position

典型路径：

- `SlotFrameConvergence.SnapHome` 无塔时 `card.Transform.position = anchorWorld`。
- `EffectFrameConvergence.ParkRootAtWorld` 无塔时 `root.position = worldPosition`。
- `BattleFinalStateGuard` 存在多处 force snap / soft tween fallback。
- `SkeletonDeckPresentationManager` 融合无塔时仍可 `DOMove`，结果卡也有直接设 world position。

这些 fallback 在迁移期能救场，但从范式角度看，它们是旧世界写入的回流口。后续应尽量把“无塔”从可运行 fallback 改成开发期错误或一次性自动补塔。

### 5. `KillMotion` 仍是跨语义核按钮

`CardDeckTween.KillMotion` 本质是对 Transform 执行 `DOKill(false)`，当前仍被 L2、L3、手牌、卡组、战斗复位等多处调用。

新范式理想状态下，“停止哪个语义层”应该是分层的：

- 停 L2 格位收敛。
- 停 L3 特效收敛。
- 停净土域 DOTween。
- 停 hover/scale/rotation 反馈。

但现在 `KillMotion(root)` 仍可能跨语义清理。只要 DOTween 与 convergence driver 共存，或者某个反馈 tween 和位移 tween 共用同一 root，这个 API 就仍然有误伤空间。

### 6. 净土域保留 DOTween 是合理的，但边界还没磨完

计划中允许手牌、牌库、纯战斗黑盒暂不重写。当前 `CardHandManagerSingleton`、`CardDeckManagerSingleton`、`CardDeckTween` 保留 DOTween/position 写入，符合“净土域内部不动”。

真正风险不是净土域仍用 DOTween，而是边界：

- 同一张 `ManagedCard` 从手牌/牌库进入场上时，是否一定已经完成 Evict/Admit。
- 场上卡是否可能仍被手牌 hover/drag 或 deck tween 影响。
- 净土域 `Evict()` 当前 C 阶段速度恒 0，局部边界还没有逐个打磨到 B 阶段真实速度。

### 7. 策略 C 还停在可测能力，不像产品路径

`BoardPresentationStepProjector` 支持 `MultiHopProjectionStrategy.CollapsedEndpoint`，测试也覆盖了 N 跳折叠成 1 个 Async Step。但 `FillBoardDeltaFromEventLog` 当前默认调用没有传入策略配置，实际主路径更像固定 `SerialVisible`。

这不是缺陷，但它意味着“S/C 按表演贴标签”的内容侧工作尚未开始。当前只是技术能力存在，并未产品化。

## 旧病灶清除程度

### 已明显清除

以下旧病灶在当前代码里未再作为主路径存在：

- `GroundSlotDealFlightCoordinator`
- `GroundSlotDealDecoyTracker`
- `TryReleaseFlightForHop`
- 补牌飞行中靠替身/握手释放给 hop
- Flow 层在主 Drain 中直接散落调 Field 位移动画

补牌与 hop 的关系已改成 L2 redirect，这是一项实质性范式迁移。

### 仍残留为风险入口

需要继续追踪的残留类型：

- 无塔 fallback 的 `transform.position = ...`。
- `BattleFinalStateGuard` 的 force snap / soft restore。
- `SkeletonDeckPresentationManager` 融合无塔 DOMove 与结果卡直接设位。
- `CardTweenDirectionalPunchEffectSO` 对 root 做 `DOPunchScale`。
- `CardDOTweenSequenceEffectSO` 对 root 做 `DOLocalMove`。
- `CardHandManagerSingleton` 的拖拽/布局 position 写入。
- `CardDeckTween.MoveToWorld`、ripple、卡组布局等净土域 writer。
- `CardDeckTween.MoveHopToWorldAsync` 这类已无调用但容易被误用的死入口。

这些不都必须立刻删除。关键是把它们标清楚：哪些是净土域允许，哪些是复杂域 fallback，哪些是死代码，哪些应该迁 L3。

## 落地质量评分

### 架构方向：A-

方向是对的，而且没有做成“新系统包旧系统”的表面重构。固定塔、曲线、L2/L3、Step 契约、lease、诊断都已经在代码里有实体。

扣分点是调度/栅栏尚未和真实 driver 完成事件闭合，Step 与 Legacy 双轨还在。

### 主路径迁移：B+

战斗后盘面、旋转、换位、hop、补牌飞入这些复杂域核心路径已经基本迁走。`SlotDealFlightService` 替代旧补牌飞行协调，是重要成果。

扣分点是无塔 fallback、融合/战斗终态、Punch/Sequence、Legacy 回退仍可能把旧 writer 带回场上卡。

### 测试质量：B+

纯逻辑层测试质量不错，覆盖了最该覆盖的数学与仲裁语义。

扣分点是缺少更接近生产链路的集成测试：

- StepProjector -> Drain -> BoardMotionStepScheduler -> GroundFieldManager -> L2 driver。
- 环移中补牌 redirect。
- Sync lease 与 Async redirect 的真实 ManagedCard 路径。
- L3 fusion / lunge 并发边界。

### 诊断成熟度：B

已有 commitment、lease、barrier、handoff、motion begin/end 等诊断点，方向很好。

扣分点是目前还缺少“用日志证明旧路径不再触发”的闭环指标，例如 Legacy Drain 次数、无塔 fallback 次数、root position writer 次数、barrier 未绑定真实完成次数。

## 建议的下一步目标

### P0：把主路径从“可用”推进到“唯一”

1. 给 `DrainLegacyBoardDeltaAsync` 加强诊断：每次触发都写 CoreLog/PerfLog，包含 requestId、moves/deals/remove 数量、触发来源。
2. 连续复测确认主流程 `stepCount == 0` 的比例。如果正常战斗链路长期为 0，把 Legacy 标成 deprecated。
3. `DrainLegacyBoardDeltaAsync` 即使暂不删，也要显式传 `CommitmentKind.Sync`，让旧回退在诊断语义上和 Step 路径对齐。
4. `FillBoardDeltaFromEventLog` 若遇到有 board delta 但无法投影 Step，应报警，而不是只回填 Legacy。

验收口径：正常战斗、拾取、空槽点击、使用手牌、奖励后补牌等路径，Perf/Core 日志里 Step 路径覆盖率接近 100%，Legacy 触发必须可解释。

### P1：关闭复杂域 fallback 回流口

1. 所有场上卡进入复杂域前强制 `CardTransformTower` + L2/L3 driver 存在。
2. 将 `SlotFrameConvergence` / `EffectFrameConvergence` 的无塔 fallback 从“静默写 position”改为开发期错误或一次性补塔。
3. 梳理 `BattleFinalStateGuard`：优先通过 L2/L3 归位，保留 force snap 只作为异常恢复，并写强诊断。
4. `SkeletonDeckPresentationManager` 的融合结果卡和无塔 DOMove 路径迁到塔接口。

验收口径：复杂域场上卡没有无诊断的 direct world-position fallback；所有 fallback 都能在日志中被统计。

### P2：把栅栏从时间语义升级为执行语义

1. 让 BeatGrid 注册真实 layer driver 或一个 driver-completion adapter，而不是只注册纯逻辑 `BeatConvergenceSlot`。
2. barrier 满足条件应包含：时间到、所有注册 driver complete、承诺未被未诊断抢占。
3. 将旋转/多卡同步动作的 barrier 结果写入 PerfLog，包含 beatId、registrationCount、sourceTime、actualArriveDelta。
4. 对 redirect 拉长 sourceTime、driver 被取消、无塔无法注册等情况写明确报警。

验收口径：barrier 不再只是“sourceTime <= budget”，而是能证明参与卡的实际 layer 已完成。

### P3：拆分 `KillMotion` 语义

1. 保留 `CardDeckTween.KillMotion` 给净土域 DOTween，但不要让它成为复杂域通用停止入口。
2. 新增或明确分层 API：`StopSlotFrameConvergence`、`StopEffectFrameConvergence`、`KillDeckTweenOnly`、`KillFeedbackTweenOnly`。
3. 将 L2/L3 的 stop/redirect 语义从 DOTween kill 中剥离。
4. 对仍调用 `KillMotion(root)` 的复杂域路径逐个标注理由。

验收口径：看代码能一眼判断“这次停止的是哪个语义层”，而不是靠 root DOKill 模糊清场。

### P4：L3 与内容侧标签产品化

1. Punch / DOTweenSequence 中涉及位移的部分迁到 L3；缩放、旋转可暂留视觉通道，但必须确认不作用于会破坏塔语义的 root。
2. 融合、lunge、受击、击退按需要补 L3 lease 或至少补 L3 commitment 诊断。
3. 将多跳策略 C 接入配置或明确删除公共入口；不要长期停留在“测试支持但产品不用”的状态。
4. 开始逐表演贴 `Sync/Async`、`SerialVisible/CollapsedEndpoint` 标签，并记录内容侧默认值。

验收口径：每个复杂域表演都能回答三个问题：写哪一层、是否承诺、能否被抢占。

### P5：边界从 C 阶段逐个升级到 B 阶段

1. 先不全域重写手牌/牌库。
2. 只挑最容易穿帮的边界做 B 阶段真实速度：牌库飞入场、场上回库/融合结果、手牌打出到场上或目标。
3. 每个边界独立改 `Evict()` 吐真实速度，接口不变。
4. 用 PerfLog 对比升级前后的速度跳变与位置跳变。

验收口径：不是追求所有边界一次丝滑，而是每次升级一个边界都不改变统一接口。

## 建议近期计划

### 第一个短迭代：观测与退路收窄

目标：先知道旧路还在不在跑。

- 给 Legacy Drain、无塔 fallback、force snap、root DOMove fallback 加统一诊断标签。
- 跑一次完整战斗/拾取/使用手牌/奖励流程。
- 产出一份“旧 writer 触发清单”。

这一步风险最低，但能决定后续删代码的信心。

### 第二个短迭代：复杂域无塔归零

目标：让场上卡复杂域默认一定有塔。

- Spawn 和进入场上时强制补塔。
- 将复杂域无塔 fallback 改成报警。
- 清理 `MoveHopToWorldAsync` 等死入口。
- 给融合结果卡补塔路径。

### 第三个短迭代：真实 barrier

目标：把同步动作从“await driver + 事后 barrier 诊断”收束为“barrier 管 driver 完成”。

- BeatGrid 注册 driver completion adapter。
- 旋转、swap、multi-card move 都通过同一种 barrier 语义收束。
- 记录 actual arrive 与 committed sourceTime 的偏差。

### 第四个短迭代：L3/特效位移收敛

目标：减少 root 级 DOTween 对复杂域卡的影响。

- Punch 迁 L3 或视觉子层。
- Fusion 无塔 fallback 迁塔接口。
- BattleFinalStateGuard 改成异常恢复器，而不是常规对齐器。

## 当前不建议做的事

- 不建议立刻重写手牌/牌库净土域。当前收益不如先关复杂域回流口。
- 不建议马上做完整 DAG。没有真实 barrier 前，DAG 只会让问题更难定位。
- 不建议把纪律 B 全局升级为纪律 C。先用诊断找真实冲突热点，再局部升级。
- 不建议继续扩展新表演能力。当前更需要把已有能力的 writer 边界、fallback 和日志闭环做硬。

## 最终判断

这次重构不是“方案写得大、代码只动皮毛”。代码里已经能看到范式核心结构，并且主路径迁移力度足够大：

- 塔和五次收敛是真地基。
