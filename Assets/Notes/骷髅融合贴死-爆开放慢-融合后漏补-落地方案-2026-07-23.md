## 0. 一句话目标

1. **融合**：两卡（或多卡）必须**视觉贴死叠在同一点**再闪白；结果卡**出现在该贴合点**（哪里融合就在哪产出）。  
2. **死后炸开两张卡**：明显放慢，散开停稳可读。  
3. **融合后空场**：只要牌堆有牌、场上因融合空槽，就**立刻**入队 `FusionRefill`，不再出现「等下一次点击才补」。

## 1. 问题 3（融合后漏补）— 硬证据与根因

### 1.1 Log 坐实（chainId=15，末次 `strong_combo`）

| tMs | 事件 | 含义 |
|-----|------|------|
| 55213 | `DirectorIntentAccepted` attack chain=15 | 击杀连锁开始 |
| 55219–56809 | batch28 `CombatAttackPresentChannel` + `ShuffleBurstScatter` | 击杀 + 散架炸开 |
| 56817 | `SkeletonFusion/DrainStateBuilt` `fusionCandidates=3` **`refillGateArmed=1`** | 门已武装；本 Present 将播融合 |
| 56817–57361 | 同批 `dealFlight*` | 同 batch 内还有发牌飞入（PostKillFill 痕迹） |
| 57360–58924 | `PresentBegin/End` `skill.strong_combo` resultUid=28 | 融合播完 |
| 58924 | PresentEnd：`refillGateArmed=1`，payload 写 `refillScheduled=1` | **埋点把 gateArmed 算进 scheduled（误报）** |
| 58924 后 | **无** `AftermathRefillSchedule`，**无** `FusionRefill` batch | 漏补 |
| 58927–59281 | batch30 `QueuedBoardPresentChannel` ~350ms ringShift | 像 PostKillRotate 表演，不是补牌 |
| 62414 | 下一 intent | 空窗约 3s |

对比同局**成功**的两次融合 PresentEnd：

- t=18137 / 22329：`refillGateArmed=0` → 走 `AftermathRefillSchedule` → 有 `FusionRefill` Present（~420–450ms）  
- t=58924：`refillGateArmed=1` → **跳过** Aftermath → 门闩后续又**没产出** FusionRefill

### 1.2 代码根因（两层）

**A. PresentEnd 过度信任「门已武装」**

[`BoardPresentationPlayer.cs`](Assets/Scripts/NineGrid.Presentation/Flow/BattleSession/BoardPresentationPlayer.cs) 约 1193–1214：

```csharp
// 埋点误报：gateArmed 也被写成 refillScheduled=1
["refillScheduled"] = alreadyScheduled || gateArmed ? "1" : "0",

// 行为：门武装就跳过 Aftermath
if (!gateArmed && !alreadyScheduled)
{
    FusionRefillAftermath.TrySchedule(exclude);
}
```

`gateArmed` 只表示 Attack 击杀剧本里 `AppendAfterRotatePresent` **挂了分支**，不表示 FusionRefill **已经入队**。

**B. Attack 击杀剧本只在「Rotate Resolve」上 trackFusion**

[`AttackIntentScriptFactory.EnqueueKillAftermath`](Assets/Scripts/NineGrid.Presentation/Flow/Presentation/AttackIntentScriptFactory.cs)：

```text
PostKillFill  Resolve (trackFusion: false) → Present
PostKillRotate Resolve (trackFusion: true)  → Present
AppendAfterRotatePresent(() => mLastRotateHadFusion) → FusionRefill
```

chain15 里 **融合动画发生在 batch29**（与 dealFlight 同批），batch30 才是短 ringShift。最符合证据的解释：

- `strong_combo` 的 EventLog / 表演落在 **Fill 侧 Present**（发牌落位后邻接触发，或 Fill 的 board drain 吃到了融合 Remove）；  
- Fill **不** `trackFusion` → `mLastRotateHadFusion` 仍为 false；  
- PresentEnd 因 `gateArmed` 跳过 Aftermath；  
- Rotate Present 之后 `AppendAfter` 见 `hadFusion==false` → `DisarmRefillGate`，**不入队** FusionRefill。

旁路路径（gateArmed=0）反而正常，因为会走 Aftermath。

### 1.3 修复方案（必须三刀齐下，防双入队）

#### 刀 1 — PresentEnd：只信 `IsRefillScheduled`

文件：`BoardPresentationPlayer.TryHandleFusionRemoveStepAsync` PresentEnd 段。

- 埋点：`refillScheduled` **只**写 `FusionRefillScheduler.IsRefillScheduled`；`refillGateArmed` 单独写。  
- 行为：融合 Present **成功结束后**，若 `!IsRefillScheduled`，**一律** `FusionRefillAftermath.TrySchedule(exclude)`（含 ResultUid），**不要**因 `gateArmed` 跳过。

#### 刀 2 — Aftermath：允许「门武装但尚未 scheduled」时入队

文件：`FusionRefillAftermath.TrySchedule` + `CreateProductionScheduler`。

- 旧：`if (IsRefillGateArmed || IsRefillScheduled) return false;`  
- 新：`if (IsRefillScheduled) return false;`  
- 入队成功后：`MarkRefillScheduled()` + `DisarmRefillGate()`（生产 scheduler 里 `EnqueueRefillBatches` 已 Mark；确保 Disarm，避免脏门）。

#### 刀 3 — AppendAfter：已 scheduled 则不再二次入队

文件：`FusionRefillScheduler.AppendAfterRotatePresent` 的 enqueue 回调：

```csharp
t =>
{
    if (IsRefillScheduled)
    {
        DisarmRefillGate();
        return;
    }
    enqueueFusionRefill(t);
    MarkRefillScheduled();
    DisarmRefillGate();
};
```

`hadFusion==false` 分支仍 `DisarmRefillGate()`（若 Aftermath 已 Mark+Disarm，这里 Disarm 幂等即可）。

#### 刀 4（推荐加固，防同类再漏）— Fill 也 trackFusion，或 Present 侧 sticky

任选其一（实现时二选一即可，优先 A）：

- **A（推荐）**：`EnqueueKillAftermath` 里 PostKillFill 的 `ResolveAndProject(..., trackFusion: true)`，与 Rotate 共用 `mFusionExcludeResultUids` / `mLastRotateHadFusion`（Fill 触发融合时 OR 进 flag，不要 Clear 掉 Fill 已收集的 exclude）。注意 Rotate Resolve 里现有 `into.Clear()`——`TryCollectResultUids` 会 Clear 列表；若 Fill 已写入 exclude，Rotate 再 track 会清掉。应改为：
  - `TryCollectResultUids` 增加不 Clear 的重载，或  
  - Fill/Rotate 各自收集后 `OR` 进 `mLastRotateHadFusion` 与 exclude 列表（Append 去重）。
- **B**：融合 `PresentBegin` 时 `FusionRefillScheduler.MarkFusionPresented(resultUid)`；`AppendAfter` 的 `hadFusion` 改为 `mLastRotateHadFusion || HasFusionPresentedThisChain`。

**最低交付**：刀 1–3 已能修 chain15 类漏补；刀 4 防止「门闩路径自己该入队却因 track 窗口错位」依赖 Aftermath 兜底。

### 1.4 测试（EditMode）

2. **`AppendAfter_WhenAlreadyScheduled_DoesNotDoubleEnqueue`**

## 2. 问题 1 — 融合贴死 + 结果卡对齐

### 2.1 根因

[`SkeletonDeckPresentationManager`](Assets/Scripts/NineGrid.Presentation/Cards/SkeletonDeckPresentationManager.cs)：

- `ComputeMergeCenter` 用 **L0 `transform.position`**，不用 `SlotFrameConvergence.GetVisualWorldPosition`。  
- Crash：`EffectFrameConvergence.ConvergeVisualToWorldAsync(..., parkRootOnComplete: true)` → `ParkRootAtWorld` **只清 L3，不清 L2**。  
- 参与卡若残留 L2（deal/hop；本局融合前有 `MissingMotionEnd` on uid 26/27），Park 后视觉 = `mergeCenter + L2`，两卡**叠不齐**就闪白。  
- 结果卡 `SnapHome` 清 L2 不清 L3，易与贴合点错位。

### 2.2 选定手感

**先撞向中点动画 → 强制贴死（L0=点且 L2/L3 归零）→ overlapHold → 闪白 → 结果卡同点弹出。**

### 2.3 改动清单

**A. `SkeletonDeckPresentationManager.cs`**

1. `ComputeMergeCenter`：对每张参与卡用 `SlotFrameConvergence.GetVisualWorldPosition` 求均值。  
2. Crash 前：对参与卡 `CardDeckTween.KillMotion` + 停掉 L2/L3 driver（避免未结束 motion）。  
3. `CrashParticipantsToCenterAsync` 之后新增 `HardStickParticipantsAt(mergeCenter)`：  
   - 每张：`SlotFrameConvergence.SnapHome(card, mergeCenter, "Skeleton.HardStick")`  
   - 再：`EffectFrameConvergence.SnapHome(card, "Skeleton.HardStick")`  
   - 断言/探针：两卡 `GetVisualWorldPosition` 距离 &lt; `1e-3`（或现有 `PositionEpsilon`）。  
4. `RevealResultCardAsync`：`SnapHome` 到**同一** `mergeCenter` 后，再 `EffectFrameConvergence.SnapHome`；不要用参与卡 Clear 前的旧格锚点。  
5. （可选）贴死后用参与卡视觉点再读一次 `mergeCenter` 写死，防止 Crash 漂移。

**B. 时长** — [`SkeletonDeckLayoutSettings`](Assets/Scripts/NineGrid.Presentation/Cards/SkeletonDeckLayoutSettings.cs) + 场景序列化同步：

| 字段 | 旧 | 新 |
|------|----|----|
| `fusionCrashDuration` | 0.32 | **0.45** |
| `fusionOverlapHoldDuration` | 0.05 | **0.18** |

场景：[`MainScene.unity`](Assets/Scenes/MainScene.unity)、[`UITestSence.unity`](Assets/Scenes/UITestSence.unity) 内嵌 `SkeletonDeckLayoutSettings` / `GroundFieldLayoutSettings` 一并改（Unity YAML 里已有这些字段）。

**C. 测试**

扩展 [`EffectFrameConvergenceTests`](Assets/Scripts/NineGrid.Presentation/Tests/Cards/EffectFrameConvergenceTests.cs) 或新建 Skeleton 测：

- 两卡人为不同 L2 残差 → Crash+HardStick 后视觉重合；  
- 结果卡视觉位 == mergeCenter。
