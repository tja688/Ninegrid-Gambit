> 过程笔记，**非权威**。长期不变量见 [ADR-0020](../../docs/adr/0020-board-as-interaction-surface.md) / [ADR-0021](../../docs/adr/0021-run-progression-in-core.md) / [ADR-0022](../../docs/adr/0022-node-loadout-model.md)；词汇见根目录 `CONTEXT.md`；代码现状见 `docs/code-map/`。

## 目标

把新版设计案（`Assets/Docs/九宫格登神`，只取流程部分）彻底落进现有代码与配置，交互形态从「浮层 UI」换成「自然卡牌—图标」：整局的选择都发生在九宫格的 9 个格子上。

**M1 验收线**：主菜单 `\` → `0` 进流程测试通道，能走完 3 层 × 8 节点 = 24 个节点并通关。期间玩家可正常跳格、踩图标选房、进下一关、进战斗；战斗内按一个键即可清怪清关，回到选房。

## M1 · 骨架贯通

目标：24 节点能连着跑通并通关，交互形态换成图标 + 走位。房间内容一律最简（消费房 / 特殊房只放一个离开图标，不放货架）。

### T1（#84）· Core：跑图进度与节点编排

- `RunModel.NodesPerFloor` 9 → 8
- 新增节点类型编排（见 ADR-0021 表）：节点 1/5 随机战斗房；2/3/6 用前房选定；4 消费房、7 特殊房且**不进 `InteractionLoop`**；8 层主房
- 清关后放出的选项族按节点序号裁决（战斗族 / 消费族 / 特殊族 / 下楼）
- 删除 `CompleteNodeIfCleared` 里的 `OfferRewardChoiceAction("help.choice", 3)`
- 清关那一拍结算**全部**未使用道具卡（场上 + 道具卡格），并清掉残留机关卡
- 困难房出现门槛按层重新数（每层节点 5、6 清关时才可能给）

验收：Core EditMode 覆盖节点编排全表、通关判定、清关结算范围、困难房门槛。

### T2（#85）· Core：房间枚举与开局注入模型

- `RoomKind` 新增 `Attribute` / `TreasureReward` / `ItemReward`，删 `Battle` / `Event`
- `RoomDefinition` 删 `GoldDelta` / `MaxHpDelta` / `HealToFull`，改注入声明（目标侧 + 固定卡 id / 池 + 数量 + 可否重复）
- 房间内容 JSON 同步迁移；保留 `iconPrefab` 覆写入口
- **列出缺图清单**交给人在编辑器里补（道具奖励房无图；困难房 / 卡店 / 金币房的默认映射待人确认）

依赖 T1。验收：Catalog 校验绿；每种 `RoomKind` 都有可解析的注入声明或显式「无注入」。

### T3（#86）· Core/Content：怪物侧序列制

- 怪物卡 JSON 新增 `sequence`(1–5) / `level`(普通/层主)，全量回填
- `NodeDeckRule` schema 换成「节点 → 序列 1..5 各抽几张」，`node_deck_rules.json` 改 8 行（节点 4/7 无怪物行）
- 每层开局随机绑定一套未用过的主题卡组，记入 `RunModel`
- `MonsterDeckKind` 降级为仅标 `Reserve`

依赖 T1。验收：三层抽到三套不重复；各节点怪物总数与序列分布符合设计案表。

### T4（#87）· Core：玩家侧卡组重生成

- `HelpCardStacks` 退役；`PlayerModel` 改持有卡组容量（初始 6）/ 道具卡来源池 / 固定卡列表 / 携带卡包
- 战斗节点开局：按容量随机生成 → 叠固定卡 → 叠房间注入卡 → 倒空携带卡包
- 关卡结束全清
- M1 阶段固定卡与携带卡包可为空集合，但接口与持久位要就位
- 同步改 `BattleSessionExecutor.RunInventorySnapshot` 的 preserve 清单

依赖 T1。验收：连跑 24 节点，每关玩家侧卡组容量正确、结束全清、金币结算数额正确。

### T5（#88）· 表现：房间图标落格 + 走上去驻留提交

- 清关后按 Core 给出的选项族 Spawn 场地图标：双图标落格 1 / 格 3，单图标落固定单格
- 放宽 `AvatarWalkPathfinder`：**途经仍仅空格，终点可为图标格**
- 踩上图标 → 表现侧驻留计时 1 秒 → 向 IntentIntake 提交 `EnterRoom`；期间跳走即取消；**不做进度条**
- 计时器**不得**进 IntentIntake / 两轴门禁（`IntentIntakeStructuralTests` 护栏）
- 进房硬切：图标退场 → 下一房重新发牌 → Avatar 直接出现在格 5

依赖 T1、T2。验收：EditMode 覆盖终点放宽、驻留取消、驻留提交只发一次；结构护栏仍绿。

### T6（#89）· 表现：简要解释文字框与楼层提示接线

- 接 `Panels/简要解释文字框`：悬停场地图标 / 导航图标 / 就地选项卡 / 商店货架时出文案，移开即空
- 战斗内普通卡牌**不触发**它（那是右键详述面板的活）
- 接 `楼层提示` 下的标准世界文字，显示「第 X 层 · 节点 Y」
- 胜负 Notice 从旧通道迁到简要解释文字框

依赖 T5。验收：手测四类悬停对象；无悬停时为空。

### T7（#90）· 表现：退役旧浮层

- 删 `RoomChoicePresenter` 与场景 `RoomChoisePanel` 接线
- 删旧属性三选一 UI（`Attack` / `Armor` / `Hp` 选项卡路径）
- 保留 `BounceFanChoicePresenter`，只留宝箱开遗物一条入口
- `SelectorManagerSingleton` 只剩 Bounce 路由

依赖 T5。验收：全流程无浮层出现；宝箱开遗物仍正常。

### T8（#91）· DevTest：`\0` 流程通道 + 跳过战斗键

- `QuickTestDeckCatalog` 的 `\0` 由 `walkSandbox` 改为流程通道；删 `StartWalkSandboxNode` 及其相关分支
- 战斗内容与正式开局一致（白板怪、正常发牌），叠 QuickTest 的 HP99 / ATK5
- 跳过战斗键：复用 `BattleSessionCheat.TryForceNodeVictory()`（移除场上 + 战斗卡组 + 敌池全部真怪物，走正常清关链路），**仅 QuickTest 模式生效**，绑一个空闲键
- 同步已改写的 ADR-0019「历史」段

依赖 T1、T5。验收：`\` → `0` 能连跑 24 节点通关。

## M2 · 房间就地交互

目标：消费房与特殊房有真内容，商店能买、卡店能升级、奖励房能拿。

### T9（#92）· 商店房

4 件货架（1 宝箱卡、1 随机属性道具卡、1 恢复药水、1 食品卡）+ 1 张刷新选项卡 + 1 个离开图标，共 6 个占格对象。**任意距离点击即买**，扣金币，卡牌碎裂消失，进携带卡包。金币不足时拒绝并在简要解释文字框提示。刷新初价 10 金币，每次翻倍。

### T10（#93）· 卡店房

3 张服务选项卡（道具卡数值强化 / 道具卡固定 / 卡组扩容，各 50 金币）+ 刷新 + 离开。「道具卡固定」需要一次二级选择（从来源池挑一张）——**表现方案在本票内定**，是整个模型里唯一的嵌套选择。

### T11（#94）· 特殊房

宝箱奖励房（1 宝箱卡 + 3 随机道具卡）/ 道具奖励房（2 属性卡 + 3 随机道具卡）。卡落格上，点击逐个拿走进携带卡包；**踩离开图标即放弃**，不自动收尾。

### T12（#95）· 战斗房注入内容落地

属性 / 金币 / 宝箱 / 恢复 / 困难五种战斗房的注入配置真正生效；困难房额外向怪物侧注入本层序列 3、4 各 1 张。
