# 音频实时协作 · 统一台账

> 多 AI + 人 协作实时调整游戏音频的**唯一记录文档**。凡是「游戏运行中临时改动 / 添加音频」的会话：先读本文档开头「规范」，再在末尾追加会话记录；真正落地时回到这里更新状态。

## 规范（所有 AI 必须先读）

### 1. 系统真源与固定路径

| 内容 | 位置 | 说明 |
|------|------|------|
| SFX 绑定 | `Assets/Resources/audio/audio_bindings.json` | 唯一真源（schema 3）。`cueId` + 五维选择器（cardDefId/skillId/roomId/itemDefId/contentId）→ 素材、音量、起播点、绑定延迟、最短间隔、随机池、enabled |
| BGM 绑定 | `Assets/Resources/audio/audio_music.json` | 六状态：`MainMenu` / `RunExploration` / `Battle` / `BossBattle` / `Victory` / `Defeat` |
| 音频素材 | `Assets/Resources/audio/SFX/…`、`Assets/Resources/audio/BGM/…` | 绑定里的引用形如 `audio/SFX/斩击`（无扩展名） |
| 素材清单 | `Assets/Resources/audio/audio_manifest.json` | GUID/哈希/loadPolicy；**新增素材必须登记** |
| 声音提示声明 | `AudioCueAttribute`（`Assets/Scripts/NineGrid.Presentation/Flow/Presentation/AudioCue.cs`） | 稳定 cueId + 中文说明 + 权威发射者 + 允许上下文 |
| 架构约束 | `docs/adr/0036-audio-cue-binding-and-music-ownership.md`、`docs/code-map/presentation.md` | 业务代码**禁止**直调 AudioKit / MMSoundManager |

### 2. 游戏运行中临时改动的纪律

- **Play 运行期间只经运行时缝改动，不得直接改写正式 JSON**，除非人明确说「保存」。
- 临时生效通道：
  - SFX 绑定热应用：`IAudioSystem.ApplyWorkbenchCatalog(json)`（严格 `TryFromJson`，失败不替换旧 catalog，只影响后续请求）
  - SFX 试听：`IAudioSystem.PreviewWorkbenchBinding(bindingKey)`
  - SFX 停止：`IAudioSystem.StopSfxSource(sourceId)` / `StopAllSfxSources()`
  - BGM 停止单源：`IMusicSystem.StopMusicSource(sourceId)`（经 `MusicSystem.EnsureRegistered()` 取）
  - BGM 整局静音（仅本次运行）：MMSoundManager Music 轨 mixer 参数 `MusicVolume` → `-80dB`（纯运行时，Play 结束自动还原；原始值先 `GetFloat` 记录）
  - 动态发声测试：execute_code 内 `TriggerPulseHub.PulseAudio(new AudioCueRequest(...))` 或 `IAudioSystem.RequestCue(...)`
- 结构护栏：新声音必须走「稳定 cue → 绑定」；**禁止**动态 `sfx.effect.<uid>` 绑定键；禁止业务代码直调播放器。

### 3. 落地规则（只有人确认保留才落地）

- SFX：改 `audio_bindings.json`；人工确认后该行 `authoringStatus = "humanConfirmed"`；新素材放 `Resources/audio/SFX` 并登记 manifest。
- BGM：改 `audio_music.json`；**不 live 热换**，下次运行时安装生效。
- 新增 Cue（无现成声明）：先找该动作的权威发射点，声明 `AudioCueAttribute` + 接线 + 绑定，再走验证门槛（recompile 后 Console 无新增 Error）。
- 涉及接口 / 装配变化时更新 `docs/code-map/`，必要时修订 ADR。
- 验证门槛见 `docs/code-map/tests.md`；音频交付护栏见 `AudioStructureGuardTests` / `AudioDeliveryHygieneTests`。

### 4. 状态机

```
临时生效 → 待确认 →（人确认保留）→ 已确认保留 → 已落地
                         ↘（人否决）→ 已回滚 / 不落地
```

- `不落地`：纯本次运行调试（如整局静音），不写 JSON，Play 结束即消失。

### 5. 协作规则

- 执行 AI 追加条目：写清「游戏动作 / cueId / BindingKey / 改动内容 / 临时实现方式 / 会话日期」。
- 落地 AI 更新同一条目状态，并贴实际改动点（文件 + 行/字段）与验证结果。
- 每会话开头新建 `## 会话 <日期>` 小节；同类改动更新原条目，不重复建条。
- 入 doc 前先重读本文档与 `audio_bindings.json` / `audio_music.json` 现状，避免冲突。
