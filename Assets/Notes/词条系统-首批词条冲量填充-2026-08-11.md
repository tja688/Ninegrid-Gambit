## 使用说明

- **匹配键**：词条表按 `displayNameZh`（名字）与描述中的 `[[名字]]` **精确匹配**；下表「词条名」即匹配键。
- **分区**：`partition` 单一分区，本文按认知分区分组，未归类的落 `Others`。分区名可由你调整，条目照搬即可。
- **颜色 / 图标**：本批一律不配置覆盖色与 code/sprite（原有图标词条保留其 code），后续按视觉需要补。
- **状态标记**：
  - `已用未配`：卡面描述已写 `[[…]]`，词条表缺条 → **本批最高优先**（右键详情当前显示空解释）。
  - `修订`：词条表已有条目，建议改名或改写解释。
  - `新增`：卡面尚未引用，作为系统理解词条前置填充。

## 四、待定夺问题（导入前请确认）

1. **「防御」改名「护甲」**：现有 `armor` / `basic_armor` 两条的显示名为「防御 / 基础防御」，与 CONTEXT「文案用护甲，不用防御」冲突。卡面描述中没有 `[[防御]]` 引用，改名无副作用，建议直接改。
2. **背面惰性口径**：设计文档《翻面机制》写「背面朝上的卡牌技能仍然生效」，实装（ADR-0016）为背面双向惰性：不可被伤害、不推进计数、被动默认失效。本文按实装写；若设计文档口径才是目标，请先定案再录词条。
3. **「历战」同名双义**：怪物技能 `skill.battle_hardened`（累计造成 2 伤则攻 +1）与遗物 `relic.battle_hardened`（战斗时攻击 +2，仅对当前敌人）同名。目前只有怪物卡面引用 `[[历战]]`，本文按怪物技能写；建议遗物侧改名（如「历战徽记」）或避免在遗物描述中使用 `[[历战]]`。
4. **「链接」系命名**：`skill.link_attack_bonus` 的技能 JSON 显示名是「邻接攻击+1」，卡面却引用 `[[链接]]` / `[[链接近战]]`。词条按卡面用词建条即可，但建议顺手把技能 JSON 显示名统一为「链接」。
5. **「潜伏」vs「潜伏近战」**：技能 JSON 名为「潜伏近战」，卡面统一写 `[[潜伏]]`。建议：新建「潜伏」正式条目，「潜伏近战」测试条目改为同文或删除（保留则两键同文，避免解释漂移）。
6. **「近战6」占位名**：`monster.melee_6` 显示名仍是占位符「近战6」，被「呼唤」词条解释引用。等该怪定名后回来同步词条文案。
7. **「吸收」数值**：设计文档为血 +2，实装参数为血 +4，本文按实装。
8. **「斜角相邻」vs「斜交相邻」**：策划案用「斜交相邻」，攻击模式实装名用「斜角近战」。本文取「斜角相邻」与攻击模式用词对齐；若你偏好「斜交」，改词条名即可。
9. **「穿透」**：CONTEXT 明令穿透未有机制定案前不建词条，本批未收录，仅有「无视护甲」。
