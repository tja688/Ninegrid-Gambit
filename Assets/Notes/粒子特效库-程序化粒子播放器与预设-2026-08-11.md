> 过程笔记（非权威）。代码现状见 `docs/code-map/presentation.md`「#205 程序化粒子播放器」段；长期契约见 [ADR-0040](../../docs/adr/0040-vfx-cue-binding-persistent-state-workbench.md)。
> **本文是给「落地接线 AI」的交付说明书**：每个预设是什么、当初为谁设计、怎么绑、推荐参数、可调方向。

## 一、这批东西是什么

给 VFX 系统新增了第三种播放器 `particle`（前两种：`sprite-sheet` 素材翻页、`gold-flight` 金币程序化），
用 **运行时程序化装配 Unity ParticleSystem（Shuriken）** 的方式提供 27 个粒子预设：

- **21 个一次性 Pulse 预设**：命中火花、血屑、护甲碎裂、治疗光尘、死亡烟尘、机关火花、胜利彩纸……
- **6 个持续 State 预设**（`particle.loop.*`）：燃烧余烬、治疗泉、毒瘴、稀有星光、虚空紫幕、环境浮尘。

**零美术依赖**：所有粒子贴图（柔光圆点/像素方块/星芒/圆环/碎片）运行时程序化生成；
加色发光走新 shader `NineGrid/VFX/ParticleAdditive`（`Assets/Resources/VFX/Shaders/`，随包收录）。

**技术选型说明**：选 Shuriken 而非 VFX Graph——本项目是 URP 2D Renderer + Sorting Layer 排序的像素卡牌，
VFX Graph 输出不参与 2D 排序层、也无法运行时组图；Shuriken 的 `ParticleSystemRenderer`
完整支持 `sortingLayerName/sortingOrder`、`useUnscaledTime`、纯代码装配，与 ADR-0040 播放器契约完全对齐。

### 代码位置

| 文件 | 职责 |
|---|---|
| `NineGrid.Content/Vfx/VfxParticlePresetIds.cs` | 稳定预设 ID 表（绑定 JSON 用这里的 ID） |
| `NineGrid.Content/Vfx/VfxPlayerRegistry.cs` | `particle` 注册：Pulse+State、变体池、参数覆盖白名单 |
| `Systems/Vfx/VfxParticlePresetLibrary.cs` | **预设参数真源**（调手感改这里） |
| `Systems/Vfx/VfxParticleTextureBank.cs` | 程序化贴图与共享材质（形状 × 混合模式） |
| `Systems/Vfx/VfxParticleEmitterRig.cs` | 预设 + 绑定参数 → ParticleSystem 装配 |
| `Systems/Vfx/VfxParticlePulsePlayer.cs` / `VfxParticleStatePlayer.cs` / `VfxParticlePlayerFactory.cs` | 播放器与工厂（已接 `DefaultVfxPlayerFactory`） |
| `Tests/Flow/VfxParticlePlayerContractTests.cs` | 契约护栏：预设表↔库一一对应、生命周期、参数映射、卫生 |

## 二、怎么接入（给接线 AI 的操作手册）

### 路径 A：给已有 cue 换装 / 加变体（改 JSON 即可，不动代码）

`Assets/Resources/VFX/vfx_bindings.json` 里现有 14 条 cue 绑定全部是 `aiDraft` 的 sprite-sheet。
把任意一条的 `playerId` 换成 `particle`、`materialKey` 换成预设 ID 即完成换装，例如把血伤换成粒子血屑：

```json
{
    "cueId": "vfx.combat.hp_damage",
    "note": "血量受伤红色像素碎屑",
    "module": "Battle",
    "enabled": true,
    "playerId": "particle",
    "spatialOwnership": "independent",
    "materialKey": "particle.blood_spray",
    "timeBase": "scaled",
    "authoringStatus": "aiDraft"
}
```

我**没有**改动现有绑定（避免未经人工预览就整体换视觉），换装决策留给接线阶段。
更推荐的做法是 sprite-sheet 主体 + 粒子叠加（见路径 B 的双 cue 或变体池）。

### 路径 B：新触发点位（三步，与音频 cue 完全同构）

1. **声明 cue**（稳定 ID，禁动态拼接）——参照 `Flow/Presentation/BattleVfxCues.cs`：

```csharp
[VfxCue(
    "vfx.trap.flame_burn",
    "烈焰机关灼烧爆燃",
    "Battle",
    nameof(EffectTriggerPulseBeatHandler),
    VfxCueContexts.CardDefId | VfxCueContexts.SkillId)]
public const string FlameBurn = "vfx.trap.flame_burn";
```

2. **权威发射者发射**——首选既有一行辅助 `VfxPulseEmit.PulseAt`（`BattleVfxCues.cs`，内部即
   `TriggerPulseHub.PulseVfx` + 位置快照 `VfxSpatialContext`）：

```csharp
VfxPulseEmit.PulseAt(FlameBurn, diagnosticSource, cardDefId, skillId, worldPositionSnapshot, uid);
```

   需要带 `Amount` / 域宿主等完整空间上下文时才用裸 Hub：

```csharp
TriggerPulseHub.PulseVfx(
    new VfxCueRequest(FlameBurn, diagnosticSource, cardDefId, skillId,
        string.Empty, string.Empty, string.Empty, uid),
    new VfxSpatialContext("trap-burn", null, worldPositionSnapshot, uid));
```

3. **加绑定**到 `vfx_bindings.json`（`playerId: "particle"` + 预设 ID）。

护栏提醒：业务禁止直调 `IVfxSystem.RequestCue` / `IVfxPulsePlayer.StartPulse`（`VfxStructureGuardTests`），
一律走 `TriggerPulseHub.PulseVfx`；发射缝优先复用既有 Audio/VFX 同缝（`DamageFloaterBeatHandler`、
`EffectTriggerPulseBeatHandler`、`CardEffectManager` 等，见 code-map「首批接线」段）。

### 路径 C：持续状态（State 绑定，`particle.loop.*` 专用）

`stateBindings[]` 写法同 cue，多 `exitMode` 字段。粒子 State 推荐 `"exitMode": "segment"`：
退出时停止发射、在场粒子自然放完（比 immediate 硬拆自然得多；`exitLoopLimit` 对粒子无意义，随便填 1）：

```json
{
    "stateId": "vfx.state.card_burning",
    "note": "卡面持续燃烧余烬",
    "module": "Battle",
    "enabled": true,
    "playerId": "particle",
    "spatialOwnership": "attached",
    "materialKey": "particle.loop.ember",
    "timeBase": "scaled",
    "exitMode": "segment",
    "exitLoopLimit": 1
}
```

注意：目前项目里 **State 侧还没有生产发射先例**（`stateBindings` 为空、`SetSlot` 在护栏白名单里只允许
`VfxSystem.cs` 自己）。接线 State 时需要按 #201 的期望槽模型建立授权发射点（`IVfxSlotOwner` 宿主 +
guard 白名单扩项），这是接线票自己的活，别绕过护栏。
另：附着型粒子**不支持 SpriteMask 裁剪**（`ParticleSystemRenderer` 无 maskInteraction），
需要遮罩的场合用 independent + 位置快照替代。

### 绑定字段 → 粒子语义映射（重要，与 sprite-sheet 不同）

| 绑定字段 | 粒子语义 | 默认 |
|---|---|---|
| `materialKey` | **预设 ID**（`VfxParticlePresetIds`，卫生校验会查表） | 必填 |
| `fps` | **数量覆盖**：Pulse=单次爆发粒子数；State=每秒发射数。0=用预设默认 | 0 |
| `scale` | 整体缩放：尺寸、速度、发射半径、重力、漂移全部等比 | 0→1 |
| `speed` | 模拟速度（时间倍率，调「快慢手感」不改形态） | 1 |
| `tintR/G/B/A` | 整体乘色（叠在预设配色上，做主题变体的主力） | 白 |
| `startOffsetSeconds` | 发射延迟（对应 `main.startDelay`） | 0 |
| `timeBase` | `scaled` / `unscaled`（胜负结算等暂停场景用 unscaled） | scaled |
| `variants[]` | 预设变体池：加权随机 + 默认避免连续重复；`fpsTrim`/`scaleTrim` 叠加微调 | — |
| `bindingDelaySeconds` / `minimumIntervalSeconds` | 系统级排期延迟 / 最短间隔（防刷屏），与其他播放器一致 | 0 |

变体池示例（同一 cue 随机三选一血击反馈）：

```json
"variants": [
    { "variantId": "spray", "materialKey": "particle.blood_spray", "weight": 2 },
    { "variantId": "spark", "materialKey": "particle.hit_spark", "weight": 1, "scaleTrim": -0.2 }
]
```

### 预览方式

- Play Mode 下 `NineGrid/视觉特效/VFX 绑定调试工作台` → 静态绑定库 → 预览（`PreviewWorkbenchBinding` 忽略 enabled，可先绑 `enabled:false` 试看）。
- 或 EditMode 快速冒烟：本次交付验证用的就是 `execute_code` 直接构造 `VfxParticlePlayerFactory` + `Simulate`。

## 三、预设总表与逐个说明

尺寸参照：卡面约 3.8×4.9 世界单位、格距 5×5.5。所有预设按「独立型、卡面中心快照」调参；
写「叠加」的预设指与现有 sprite-sheet 绑定做双绑定/双 cue 组合时的推荐角色。

### A. 战斗反馈（8 个）——设计给 `DamageFloaterBeatHandler` 的 Impact 同缝

| 预设 ID | 一句话 | 为谁设计 | 推荐 cue |
|---|---|---|---|
| `particle.hit_spark` | 白金星芒径向迸射 | 任何打击命中的通用强调层 | 叠 `vfx.combat.hp_damage` / 攻击命中帧 |
| `particle.blood_spray` | 红色像素碎屑上喷下坠（同血伤飘字色 #CB3834） | 血量受伤主反馈 | `vfx.combat.hp_damage` |
| `particle.armor_shatter` | 青灰三角碎片翻滚下坠（同护甲字色 #5E7E74） | 护甲吸收伤害 | `vfx.combat.armor_absorb` |
| `particle.block_spark` | 白色短促环缘火星 | 完全格挡的「硬」反馈 | `vfx.combat.block` |
| `particle.heal_motes` | 绿色光尘从卡底缓升 | 治疗生效 | `vfx.combat.heal` |
| `particle.armor_gain_rise` | 蓝光点自环缘向心收拢升起 | 获得护甲「镀甲感」 | `vfx.combat.armor_gain` |
| `particle.death_puff` | 灰黑软团缓涨缓散 | 单位死亡衬底烟 | `vfx.combat.death`（Burn 精灵表退场的衬底层） |
| `particle.bone_chips` | 骨白像素碎屑迸出 | 骷髅系（`deck.skeleton_legion` 等主题）死亡叠加 | `vfx.combat.death` 按 `selectorCardDefId` 定向 |

**调参方向**：
- 打击感不够 → `fps` 加数量（hit_spark 14→20）或 `scale` 1.2；嫌吵 → `minimumIntervalSeconds: 0.08`。
- 想区分轻击/重击 → 同 cue 两条绑定按 `selectorSkillId` 定向，重击 `scale:1.5, fps:24`。
- blood_spray 的康复版：`tint` 转绿就是「毒液飞溅」，转紫是「诅咒飞溅」——像素碎屑形状通吃。

| 预设 ID | 一句话 | 为谁设计 | 推荐 cue |

## 四、复用与变体创作指南

三层复用，从便宜到贵：

1. **绑定层**（不动代码）：`tint`×`scale`×`fps`×`speed` 四个旋钮 + 变体池。
   同一个 `hit_spark`：tint 绿=毒击、tint 冰蓝+speed 0.7=寒击、scale 1.6+fps 24=暴击。
2. **预设层**（改 `VfxParticlePresetLibrary`）：复制相邻预设改参数即可；新增预设要同步
   `VfxParticlePresetIds`（两处 + `sAll` 数组），漏了会被 `PresetLibrary_MatchesContentPresetIdTable` 测试当场抓住。
   loop 预设 ID 必须带 `particle.loop.` 前缀（Pulse/State 分轨卫生靠这个前缀裁决）。
3. **形状层**（改 `VfxParticleTextureBank`）：现有五种贴图（SoftDot/Pixel/Spark/Ring/Shard）；
   新形状加枚举 + Bake 函数即可，材质缓存自动生效。

**想换真美术贴图时的磁盘候选**（素材盘点结论，扩展 TextureBank 支持 sprite 输入时优先用）：

- `Assets/Arts/Images/PixelartCardTCG/PNG/CardEffects.png`（PPU 16）：软圆光斑/星芒/放射火花/烟雾点图集，与卡面像素密度最贴；
- `Assets/Arts/Images/Png/Textures/texture1~225.png`（PPU 32）：225 张通用小形状（星芒如 `texture150`）；
- `Assets/Arts/Images/Png/Items/glow.png` / `shadow.png`：十字辉光与阴影团块；
- `Assets/Plugins/Feel/MMTools/Accessories/MMVFX/MMParticles/`：16 张专业粒子贴图（Dust/Flare/Hit/Smoke/Star 等，插件附带可借用）；
- 已在 Resources 的 `VFX/particleDust.png`（`CardEdgeDustFx` 在用，PPU 32）。

项目像素基准 PPU=32；程序化贴图无 PPU 概念（粒子尺寸直接世界单位），换 sprite 素材时注意保持世界尺寸不变。

设计约定（建议延续）：
- **像素碎屑类**（Pixel/Shard、Alpha 混合、Point 过滤）表达「实体物」：血、甲、骨、纸屑；
- **发光类**（SoftDot/Spark/Ring、Additive）表达「能量/魔法」：火花、治疗、技能、星光；
- 语义色对齐既有系统：血 #CB3834、甲 #5E7E74（与飘字同源，别自创色）。

## 五、运行语义与边界（接线时须知）

- **排序**：独立型 `Main` 层、order 5000 + 预设 `SortingOrderDelta`（0~3，火花类高、烟尘类低）；附着型经域宿主 `TryGetSortingBounds` 协商，与 sprite-sheet 播放器同规。
- **空间**：独立型接纳时固定世界位（`PositionSnapshot`，无快照时原点）、挂 `VfxIndependentSpatialRoot`，宿主死亡不中断；附着型宿主丢失即正常收尾（Pulse/State 都是）。
- **失败语义**：未知预设 ID / loop-Pulse 错配 → `BackendFailure`（结构化原因）；绑定缺 materialKey → `Unbound`。全部进 VFX 诊断（`VfxDiagnostics` / 工作台可观察），不抛入玩法。
- **性能**：预设数量 1~24（彩纸 90），`maxParticles` 上限 clamp 512；每 Pulse 一个 GO，播完即毁（与 gold-flight 同策略，量级远低于池化阈值）。Pulse 另有 15s 失效兜底。
- **EditMode 测试注意**：`Simulate()` 后系统进入暂停态、`IsAlive` 恒真——完成判定用粒子数/发射态兜底（rig 已内置；写新测试别直接断言 `IsAlive`）。
- **卫生门禁**：`vfx_bindings.json` 里 particle 绑定的预设键、Pulse/State 分轨由 `VfxBindingCatalogHygieneValidator` 校验（`missing-material` 级、进 `VfxDeliveryHygieneTests` 关键项）；工作台断链筛选同样认识预设键。
