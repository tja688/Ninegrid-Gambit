# 行动计数统一为倒计时语义，开火窗口一次性

## 决策

1. **「每 N 次」统一为倒计时语义。** 计数器存的是「还差几次」：置为 N，相应行为每发生一次 −1，减到 0 即触发并重置为 N。取代现有的两套数学。
2. **开火窗口是一次性的。** 倒计时归零的那一拍就是窗口；若攻击模式开火资格不通过（位置条件不满足 / 被禁止行动），**取消本次单向打击并把倒计时重置为 N**，不保留蓄力、不停在 0 等下一拍。
3. **卡级节奏共享倒计时（ADR-0038）。** 攻击模式与**技能同步触发**共用卡级「还差几次」（节奏周期 X）。非同步、非双通道节奏的 DSL 效果仍可用独立 key（`EffectCounterPrefix + instanceId + …`）或 `OnCumulative` 等，与卡级共享倒计时隔离。
4. **`OnInteract` / `OnSelfMove` 的独立 `every`。** 仍可用于**未**升格为技能同步触发的效果；同步技能不得再自带节奏 `every`（改订阅开火窗口）。
5. **`OnSelfMove` 的 `every` 从「累计 % N == 0」迁移为倒计时**；`OnCumulative` 的按量累计表达为「倒计时减去 delta，每跨过一个 N 阈值产生一次逻辑触发，并保留跨阈值后的余量」。
6. **倒计时可被效果加减速**；攻击模式本身不可被改写（[ADR-0011](0011-monster-attack-pattern-intrinsic.md)）；节奏源与周期亦为出生属性（[ADR-0038](0038-card-rhythm-dual-channel.md)）。

### 已被 ADR-0038 废止的条款

- 「攻击模式与效果禁止共用同一个计数值」——在卡级单 X、同拍触发模型下改为**必须共用**卡级共享倒计时。
- 用模式表频率（3/5）充当 N 的隐含前提；N 现为卡级节奏周期。

## 为什么

**一套数学同时解决三件事。**

- **卡面直读。** 卡面「行动计数」槽显示的就是倒计时本身，不需要「频率减累计」的换算，卡面也不需要知道频率是多少。
- **可被效果加减速而不错位。** 「使目标怪的行动计数 +1」在倒计时下是自然的加法；在模运算下修改计数值会让该效果的**相位永久偏移**——它不是延后一次，而是从此以后每次都错开。
- **三套收敛成一套。** 现状是 `OnSelfMove` 用模运算（只增不减、永不清零）、`OnCumulative` 用阈值减、`OnInteract` 根本没有 `every`（技能想复用互动计数写不出来）。同一个「每 N 次」概念有三种行为。

**窗口模型是唯一让几何梯度与节奏可调并存的选择。** 玩家默认在中心格 5，正交是 2/4/6/8、对角是 1/3/7/9；顺时针旋转路径上正交与对角严格交替。窗口模型下「打不着就浪费窗口」使位置限制有意义；蓄力模型会让位置条件退化。节奏快慢现由卡级 X 配置（ADR-0038），不再锁死在模式枚举上；下表仅作历史期望间隔参考（旧模式表频率）：

| 模式 | 位置条件 | 旧频率参考 | 窗口模型期望 | 蓄力模型期望 |
|------|----------|------------|--------------|--------------|
| 普通近战 | 正交 | 3 | 6 拍 | 3.5 拍 |
| 斜角近战 | 对角 | 3 | 6 拍 | 3.5 拍 |
| 全向近战 | 八向 | 3 | 3 拍 | 3 拍 |

（已废止的 `普通远程` 几何模式见 ADR-0011 修订说明；远程改由 `远程武器` 技能表达。）

**关于「错过窗口是否浪费了时间」**：玩家确实可以通过控制旋转（砍不死就不旋转）压制某只怪的窗口，但这不是免费的——砍不死的怪每拍都会回击。玩家是用血量买压制，时间被兑换到了别处（详见 [ADR-0012](0012-enemy-action-phase-volley.md)）。

**关于「为什么曾不共用同一个计数值」**：旧模型下模式频率与技能 `every` 可不同（如 3 对 2），共用会互相偷拍。ADR-0038 规定同卡只有一个节奏周期 X 且同步技能同拍触发后，共用成为正确模型；分轨独立 `every` 仅留给非同步效果。

## 考虑过的替代

- **蓄力模型（打不着就保持满蓄，一旦位置合适立即开火）**：否决——见上梯度倒挂。它更「直觉」，但会让位置条件退化为「延迟半拍」，四个模式几乎只剩频率差异。
- **错过窗口时倒计时重置为 1（下一拍再试）**：否决——介于窗口与蓄力之间，漏洞与梯度都变浑。
- **统一为累计语义（沿用 `OnCumulative` 的频率减）**：否决——卡面显示需要 `频率 − 累计` 的换算，卡面因此要知道频率，与「卡面只消费已提交的可见值」相冲突（[ADR-0005](0005-card-face-beat-commit.md)）。
- **统一为模运算**：否决——无法支持效果加减速而不错位相位。
- **最小改动：攻击模式自用倒计时，DSL 侧只给 `OnInteract` 补 `every`**：否决——长期三套语义共存。
- **攻击模式与效果共用同一个计数值**：当时否决（见上「曾不共用」）；**已被 ADR-0038 逆转**——同步技能与攻击模式共用卡级倒计时。

## 后果

- **现有 `every` 内容行为等价但需回归。** 受影响的是 `OnSelfMove` 系模板等。无外部干预时倒计时与模运算完全等价，但迁移必须覆盖；同步技能升格后应去掉节奏 `every`。
- **`OnCumulative` 的 `counterKey` 存储含义反转**（从「已累计量」变成「剩余量」），跨存档兼容性需确认。
- **`OnCumulative` 严格消费按量 delta。** 一次事件若跨过多个频率，按跨过的频率数生成多个逻辑触发，不能只开火一次后吞掉余量。
- **累计效果的计数器不按战斗/节点清除。** 生产中的固定 `counterKey` 写在持久 Avatar 的 `CounterBag` 上；`SetupNodeDeck` / `NodeStarted` 只重置战斗内容，不得清除该累计值。新 run 由 Avatar 生命周期自然重置。
- **卡级共享倒计时**用保留 key（可延续/替换原 `AttackPatternCountdown`）；与 `EffectCounterPrefix` 明确隔离。
- **倒计时上卡面必须走结算指令链路**，不能在 View 上自己减（见 ADR-0012 后果）。
- **「每战斗 N 次」只数交战。** 与 [ADR-0012](0012-enemy-action-phase-volley.md) 定案一致：`OnBattle` 仅在交战作用域内 raise，单向打击不计（#78）。
- **一阶估算的前提是「每次互动都旋转」。** 实际上未击杀的战斗不旋转，因此上表是长期期望而非逐局保证；平衡调参时应以实测为准。
