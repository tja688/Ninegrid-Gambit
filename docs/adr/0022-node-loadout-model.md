# 关卡装填模型换代

## 决策

一个战斗节点开局要装填哪些牌，改由下列规则共同决定；旧的「持久帮助卡栈 + 分档卡组 + 进房即改数值」三件套退役。

### 1. 怪物侧：主题卡组 + 序列制

- **每层开局**从主题怪物卡组里随机抽 **1 套未用过的**，记入 `RunModel`；三层各一套，互不重复。
- 每套固定 5 张，按 **序列 1–5** 排列，序列 5 即该套的**层主**。
- 怪物卡 JSON 新增 `sequence`（1–5）与 `level`（普通 / 层主）。
- `NodeDeckRule` 由「`level1/2/3_min/max` + `elite_count` + `boss_count` + `deck_kind`」改为「**节点 → 序列 1..5 各抽几张**」，总数为该节点固定值。
- `MonsterDeckKind` 降级：不再决定哪层用哪档卡组，只保留 `Reserve` 标记（不参与随机）。

### 2. 玩家侧：每关重生成（仍有效）

`PlayerModel.HelpCardStacks` 退役。玩家侧持有的是**生成规则**而非牌堆：

| 持有物 | 含义 | 跨节点 |
|--------|------|--------|
| 玩家侧卡组容量 | 初始 6，可花金币扩容（卡店） | ✅ |
| 道具卡来源池 | 通用卡组 + 所选角色卡组 | ✅ |
| 固定卡列表 | 卡店「道具卡固定」服务写入 | ✅ |
| ~~携带卡包~~ | **已退役** → 见 [ADR-0025](0025-item-slots-run-persistent-hold.md) | — |
| 道具卡格 | 已入手道具；容量 3…5 | ✅（跑图内） |

每个战斗节点开局：按**玩家侧卡组容量**从来源池随机生成 → 叠加固定卡 → 叠加房间注入卡。~~不再倒空携带卡包。~~ 关卡结束时玩家侧卡组（发牌侧）全清；**道具卡格不清、不兑金**（ADR-0025）。离开机关插入见 [ADR-0026](0026-leave-trap-sole-clear-condition.md)。

### 3. 房间：开局注入

`RoomDefinition` 的 `GoldDelta` / `MaxHpDelta` / `HealToFull` 删除，改为**注入声明**：往玩家侧 / 怪物侧注入哪些卡（固定卡 id、或从某池按权重抽 N 张、可否重复）。

- 金币房 = 注入 1 张金币卡；恢复房 = 注入 1 张食品卡；宝箱房 = 注入 1 张宝箱卡
- 属性房 = ~~从血量卡 40% / 加甲卡 40% / 加攻卡 20% 抽 2 张（可重复）~~ → 改为**玩家三选二会话**：进房生成 3 个加权候选（可重复），选 2 张加入玩家侧卡组，选择结果经 `RunModel.AttributePickDefIds` 在下一战斗开局注入（[ADR-0031](0031-attribute-room-pick-two.md)）
- 困难房 = 从金币卡 / 宝箱卡 / 食品卡 / 三张属性卡里抽 2 张（不可重复）+ 向怪物侧注入本层卡组的序列 3、序列 4 各 1 张

`RoomKind` 新增 `Attribute` / `TreasureReward` / `ItemReward`，删除 `Battle` 与 `Event`。

### 4. 携带卡包（已退役）

~~商店买到的、奖励房拿到的卡进携带卡包……~~ **整概念退役。** 购入与奖励产出一律直写**道具卡格**；满则拒入。详见 [ADR-0025](0025-item-slots-run-persistent-hold.md)。

## 为什么

四处改动看似独立，实际是同一件事：**旧模型把「玩家拥有什么」表达成一个持久牌堆，新设计把它表达成一套每关重跑的生成规则。** 只要 `HelpCardStacks` 还在，房间就只能往栈里塞卡、商店就只能往栈里塞卡、卡组容量就无处安放——所以必须整体换代，逐件迁移会产生两套并存的真相。

怪物侧同理：旧的 `deck_kind` 分档回答「这一关该用弱怪还是强怪」，新设计回答「这一层是什么主题、这一关抽主题里的第几梯队」。两个问题的答案维度不同，`level1/2/3_min/max` 无法承载 5 档序列。

房间从「改数值」改为「发卡」：新设计里恢复房不直接回血，而是给一张食品卡让玩家自己挑时机用——这把房间收益变成了玩家可调度的资源，也让房间效果统一走同一条内容管线。

（后续修正：商店/奖励不再经携带卡包中转，改为直写道具卡格持续持有——ADR-0025。）

## 后果

- 现有 `node_deck_rules.json` / `monster_decks.json` / 全部 `monster_*.json` 需要迁移；`RewardSystem.BuildNodeDeckOptions` 与 `ConsumeHelpCardStacksForNode` 重写。
- 卡组容量、固定卡、道具卡数值强化是**跨节点持久**的；道具卡格容量与内容亦然（ADR-0025）。
- 「道具卡固定」服务需要一次二级选择（从来源池里挑一张），是本模型里唯一的嵌套选择。
