# 关卡装填模型换代

## 决策

一个战斗节点开局要装填哪些牌，改由下列规则共同决定；旧的「持久帮助卡栈 + 分档卡组 + 进房即改数值」三件套退役。

### 1. 怪物侧：主题卡组 + 序列制

- **每层开局**从**本层难度档**的主题怪物卡组里随机抽 **1 套未用过的**，记入 `RunModel`；三层各一套，互不重复。
- 难度档与层号对齐（策划 `怪物卡.md`）：**普通**（`deck_kind=WeakElite`）→ 第 1 层池；**中等**（`StrongElite`）→ 第 2 层池；**困难**（`Boss`，卡组难度非怪物层主 rank）→ 第 3 层池。契约见 `ThemeDeckFloorTierMapping` + `MonsterDeckFloorPool`。
- **怪物成长数值叠加（节点+层双轨）**：① 每满 4 个全局节点（跨层累计，1 起）所有怪物卡攻击 +1、血量 +2；② 每进入一个新层（第 1 层为基准 0）攻击 +1、血量 +2；两轨相加（任意主题卡组；`MonsterFloorStatScaling` 在 `CreateDraft` 注入）。
- 每套固定 5 张，按 **序列 1–5** 排列，序列 5 即该套的**层主**。
- 怪物卡 JSON 新增 `sequence`（1–5）与 `level`（普通 / 层主）。
- `NodeDeckRule` 由「`level1/2/3_min/max` + `elite_count` + `boss_count` + `deck_kind`」改为「**节点 → 序列 1..5 各抽几张**」，总数为该节点固定值。
- `MonsterDeckKind`：`Reserve` 不参与随机；`Unknown` 不参与正式主题随机；`WeakElite` / `StrongElite` / `Boss` 只决定进入哪一层随机池。

### 2. 玩家侧：每关重生成（仍有效）

`PlayerModel.HelpCardStacks` 退役。玩家侧持有的是**生成规则**而非牌堆：

| 持有物 | 含义 | 跨节点 |
|--------|------|--------|
| 玩家侧卡组容量 | 初始 6，可花金币扩容（卡店） | ✅ |
| 道具卡来源池 | 通用卡组 + 所选角色卡组 | ✅ |
| 固定卡列表 | 卡店「道具卡固定」服务写入 | ✅ |
| ~~携带卡包~~ | **已退役** → 见 [ADR-0025](0025-item-slots-run-persistent-hold.md) | — |
| 道具卡格 | 已入手道具；容量 3…5 | ✅（跑图内） |

每个战斗节点开局：固定卡占**玩家侧卡组容量**预算格，剩余容量从来源池随机生成 → 叠加房间注入卡（注入不占容量）。固定与扩容互斥权衡：多固定则每关可控但总量少，多扩容则总量多但随机性大。~~不再倒空携带卡包。~~ 关卡结束时玩家侧卡组（发牌侧）全清；**道具卡格不清、不兑金**（ADR-0025）。离开机关插入见 [ADR-0026](0026-leave-trap-sole-clear-condition.md)。

### 3. 房间：开局注入

`RoomDefinition` 的 `GoldDelta` / `MaxHpDelta` / `HealToFull` 删除，改为**注入声明**：往玩家侧 / 怪物侧注入哪些卡（固定卡 id、或从某池按权重抽 N 张、可否重复）。

- 金币房 = 注入 1 张金币卡；恢复房 = 注入 1 张食品卡；宝箱房 = 注入 1 张宝箱卡
- 属性房 = 从血量卡 40% / 加甲卡 40% / 加攻卡 20% 抽 2 张（可重复）加入玩家侧卡组；进房直接开战，无三选二会话（[ADR-0031](0031-attribute-room-pick-two.md) 已废止）
- 困难房 = 从金币卡 / 宝箱卡 / 食品卡 / 三张属性卡里抽 2 张（不可重复）+ 向怪物侧注入本层卡组的序列 3、序列 4 各 1 张

`RoomKind` 新增 `Attribute` / `TreasureReward` / `ItemReward`，删除 `Battle` 与 `Event`。

### 4. 携带卡包（已退役）

~~商店买到的、奖励房拿到的卡进携带卡包……~~ **整概念退役。** 购入与奖励产出一律直写**道具卡格**；满则拒入。详见 [ADR-0025](0025-item-slots-run-persistent-hold.md)。

## 为什么

四处改动看似独立，实际是同一件事：**旧模型把「玩家拥有什么」表达成一个持久牌堆，新设计把它表达成一套每关重跑的生成规则。** 只要 `HelpCardStacks` 还在，房间就只能往栈里塞卡、商店就只能往栈里塞卡、卡组容量就无处安放——所以必须整体换代，逐件迁移会产生两套并存的真相。

怪物侧同理：旧的 `deck_kind` 分档曾短暂退役为「仅 Reserve」；现恢复为**层号对齐的难度池**（普通/中等/困难 → 1/2/3 层），与「这一层是什么主题」正交；另以「节点+层」双轨叠加攻击/血量（每满 4 个全局节点攻 +1、血 +2；每进新层攻 +1、血 +2，两轨相加）。`level1/2/3_min/max` 仍无法承载 5 档序列。

房间从「改数值」改为「发卡」：新设计里恢复房不直接回血，而是给一张食品卡让玩家自己挑时机用——这把房间收益变成了玩家可调度的资源，也让房间效果统一走同一条内容管线。

（后续修正：商店/奖励不再经携带卡包中转，改为直写道具卡格持续持有——ADR-0025。）

## 后果

- 现有 `node_deck_rules.json` / `monster_decks.json` / 全部 `monster_*.json` 需要迁移；`RewardSystem.BuildNodeDeckOptions` 与 `ConsumeHelpCardStacksForNode` 重写。
- 卡组容量、固定卡、道具卡数值强化是**跨节点持久**的；道具卡格容量与内容亦然（ADR-0025）。
- 「道具卡固定」服务：二级选择从来源池**均匀随机 3 张**候选（可重复、可含已固定 defId），玩家选 1 张写入固定列表；每张固定占 1 格容量预算；预算满则拒购。是本模型里唯一的嵌套选择。

## 修订（2026-08-12）：开局自动摇房限定注入 ≤1 的战斗房

策划确认**无升级开局的道具卡上界为 7**（容量 6 + 房间注入 1）。属性房自动注入 2 张（ADR-0031 废止三选二后恢复）与「注入不占容量」叠加，节点 1/5 自动摇房若命中属性房会出现 6+2=8 张，打破该上界。收口：`RewardSystem.EnsureOpeningRoomAssigned` 的自动摇房池排除属性房（与既有精英房排除并列），只在金币/恢复/宝箱房中摇；属性房与困难房仍经清关后选房进入（玩家主动选择，注入 2 张照旧）。
