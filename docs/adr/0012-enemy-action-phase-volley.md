# 敌方行动阶段：报名—结算—收尾的齐射，阶段内盘面冻结

## 决策

怪物的主动出手不是「若干条效果被自然触发」，而是**一次齐射**：每次九宫格互动的结算链末尾追加一个**敌方行动阶段**，由三段构成。

1. **报名。** 全场怪物的行动倒计时各 −1；归零者按**进场先后（uid 升序）**排成**行动名单**。名单一经冻结不再增删——阶段中途进场的怪不参与，中途被效果加速的怪不能插队。

2. **逐条结算。** 按名单顺序逐条来。每条在真正出手前**复核开火资格**：本卡仍在场上存活、位置条件满足、未被禁止行动。
   - 资格通过 → 造成一次**单向打击**：走标准伤害公式（护甲吸收、伤害减免、`DamageMultiplier` / `DamageFlatDelta`），伤害量取怪物的**有效攻击**（含光环、复仇累计等修正），触发 `OnDamageTaken` / `OnFatalDamage` / 免死。**玩家不反击。**
   - 一次打击与它引发的一切反应（反甲、反伤、免死）**视为同时发生**：即使本卡因反伤当场死亡，它这次的伤害仍然成立。
   - 资格不通过 → 取消本次行动，倒计时重置为阈值（见 [ADR-0013](0013-action-countdown-unified.md)）。
   - 玩家死亡 → 阶段立即终止，名单剩余条目不再结算，进入 Defeat。

3. **收尾。** 本阶段累积的全部死亡在此统一处理：**补牌 + 通关检查，不旋转**。

**阶段内盘面冻结**：报名与逐条结算期间不补牌、不旋转。

**一次九宫格互动至多旋转一次。** 旋转是玩家互动的产物，仍按原有条件（击杀 / 拾卡 / 点空格）在玩家侧结算时发生；敌方行动阶段自己不产生旋转。

**分拍粒度**：每一条开火各占一个 Core 解算批次，串行 ack。

**互动计数与盘面重构解耦。** 现有 `ResolveInteractiveRotation` 把「互动计数 +1 / 补牌 / 旋转」焊在一个函数里，而它只在击杀路径被调用，导致**未击杀的战斗不累计 `interactionCount`**——与 `战斗机制.md`「clickMonster 属九宫格互动、会累计 interactionCount」矛盾。本决策要求三者拆开：计数每次互动无条件 +1；旋转按原条件；敌方行动阶段独立于两者。

## 为什么

**「A 被反甲反死，但 A 的伤害依旧成立」不是特例，它就是齐射语义。** 这条直觉和 `战斗机制.md` 里既有的「若双方同时受到致命伤害，则双方同时死亡」是同一条规则，只是从「一次交战」推广到「一次齐射」。一旦承认它，「多怪同拍攻击」的模型就不是一串独立效果，而是一个有明确报名时刻、明确结算顺序、明确收尾时刻的**阶段**。

**盘面冻结是这个模型真正的承重墙**，它一次性买到三样东西：

- **位置条件在阶段内稳定。** 于是「名单快照 vs 逐条实时判定」这个两难基本自行消解：盘面不动，两者结果相同，只剩效果位移这一个例外需要靠逐条复核兜住。
- **玩家读得懂。** 齐射全程盘面不变，「谁打到了我、谁没打到」是可以从画面上直接对上的。
- **保住既有节奏。** 「一次互动引发一次盘面重构」不会因为齐射打死三只怪就变成连转三格。

**为什么名单冻结、但资格逐条复核。** 倒计时归零是「我这拍准备好了」，属于怪物自己的状态，不该被别人的行动取消；位置与存活是「我现在打不打得到」，本来就该看当下。两者遵循各自的直觉，拆开判定比统一快照或统一实时都更符合预期，也避免了「已经被推远了还能打到我」和「计数被反复抹掉」两类怪相。

**为什么每只怪一拍而不是整阶段一拍。** 卡面数值必须经表演锚点提交（[ADR-0005](0005-card-face-beat-commit.md)），伤害数字与倒计时变化各自需要落在自己的报点上；玩家死亡的中断点落在批次之间才干净。整阶段一拍会把这份复杂度从 Core 转移到锚点排期器里，还要在 Batch 内部实现中断。

**为什么「未击杀不计数」必须一并修。** 新机制下这个偏差会直接改变玩法：玩家砍一只砍不死的怪，敌方时钟完全不动。它今天的表现只是「依赖互动计数的遗物触发偏少」，容易被当成数值问题忽略。

**关于「玩家砍肥怪冻结盘面」是否是漏洞**：不是。交战自带代价——砍不死的怪每拍都会回击。玩家用血量买「压制斜角威胁」，时间没有白流，只是被兑换成了别处的伤害。这长出了一个真实的两难：击杀 → 旋转 → 盘面重排（斜角怪可能转进正交，威胁上升）但不吃回击；不击杀 → 不旋转 → 斜角怪持续错过窗口（威胁被压制）但每拍挨一下。这条平衡依赖「不存在无伤让你砍的怪」这一**内容不变量**，攻击力 0 的怪是它的已知空洞（见 [ADR-0011](0011-monster-attack-pattern-intrinsic.md) 后果）。

## 考虑过的替代

- **敌方行动只是结算链的附加段（挂 `OnInteract` 后触发即完事）**：否决——最省事，但没有任何阶段作用域，「盘面冻结」「名单冻结」「玩家死亡终止」全都只能靠散落的布尔标志表达，而这正是仓库在输入门禁上刚清理掉的形态（[ADR-0004](0004-input-intake-two-axis-gating.md)）。
- **回合模型（玩家回合 ↔ 敌方回合交替）**：否决——本作玩家的「一步」是一次九宫格互动，且互动自身的结算链中间就带旋转，硬套回合会引入「回合开始/结束触发」「回合内资源」等一整套本作没有的概念。
- **整个敌方行动阶段一个 Batch**：否决——见上「为什么每只怪一拍」。
- **全部快照（阶段开始时把「谁打、打多少、打不打得到」一次算完）**：否决——最可预测，但会出现「已经被效果推远了还能打到我」这类明显违反直觉的结果。
- **全部实时（倒计时与位置都逐条重算）**：否决——允许效果「打断」齐射，战术深度更高，但可预测性差，且容易长出「反复抹掉敌方计数」的强组合。
- **每次打击后立即补牌 + 旋转**：否决——齐射打死多只怪会连转多格，玩家读不出盘面因果，且与「一次互动至多一次盘面重构」的既有节奏冲突。
- **敌方行动阶段的收尾也旋转**：否决——一次互动会出现两次旋转（玩家侧一次、敌方收尾一次），节奏与位置类技能的语义都会变浑。
- **在旋转之前开火（用玩家点击时看到的格位）**：否决——「所见即所得」更友好，但会把攻击模式与「每移动 N 次」类位置触发劈在结算链两半；且怪物「先就位再出手」更贴合齐射直觉。代价是玩家需要预判一次旋转，而旋转是确定性的顺时针一格、且有表演可看。

## 后果

- **`PhaseSystem` 的分拍入口需要扩张。** `ResolveInteractiveRotation` 拆成「计数」「补牌」「旋转」三件独立事，并新增敌方行动阶段的报名 / 逐条结算 / 收尾入口。既有 `ResolvePostKillFill` / `ResolvePostKillRotate` 的分拍风格是模板。
- **表现层新增一段时间线编排，但不新增通道语义。** 单向打击是「怪打玩家」，可直接复用现成的 Counter 通道（`Battle_Counter_Default` / `Battle_Counter_Lethal_Default`）。
- **行动倒计时上卡面需要一条完整新链路。** 按 [ADR-0005](0005-card-face-beat-commit.md)，卡面数值只能经表演锚点上的结算指令赋值，不得在队列外直读 Core。因此需要新增 Core 事件类型 → `PresentationInstructionKind` → `PresentationEventMap` 里的 Beat 归属，不能在 View 上自己算倒计时。
- **依赖互动计数的现有内容触发会变勤。** 「未击杀不计数」修复后，`OnInteract` 类遗物/技能的触发频率上升到设计值。这是修正漏计，但属可观测的平衡变化，需要过一遍相关内容。
- **`OnBattle` 仅交战作用域（已定案，#78）。** `DealDamageAction` 只在 `IBattleScopeSystem.IsEngagementActive`（`BeginPlayerMonsterEngagement`…`EndBattleScopeCleanup`）为真时 raise `TriggerPoint.OnBattle`。交战作用域外的伤害（含单向打击）不触发 OnBattle；「每战斗 N 次」只数交战。既有带 `targetKind: Monster` 的模板在交战路径上行为保持。
- **单向打击不开交战作用域**，因此 `UntilBattleEnds` 作用域的临时修正不会被敌方行动提前洗掉。
- **确定性可测。** 名单顺序（uid 升序）、盘面冻结、收尾时刻均为确定量，齐射可被 EditMode 完整覆盖并可从战斗日志重放。
- **进场先后序的可读性代价。** 玩家无法从盘面直接读出同拍多怪的开火顺序（格位序也做不到，因为盘面每拍在转）；「资历序」比格位序更容易被接受为「先来先打」，且卡面倒计时能让玩家看出**谁**要打，只是看不出**谁先**。
