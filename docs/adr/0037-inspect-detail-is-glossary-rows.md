# 右键详述权威改为词条行

## 决策

1. **右键详情「详细效果」区只展示词条行**，动态装入 ScrollView 多行；**不再**拼接效果模板 `design_text` / 局内挂载效果文案，也**不再**用预览卡面 hover 填临时解释槽。
2. **双语法**（卡面不变）：`[[展示名]]` = 显式文字词条（卡面去括号显示，可着色）；`[code]` = 内联图标（卡面换 sprite）。
3. **匹配键**：`[[…]]` 与词条表 `displayNameZh`（名字）**精确匹配**；`[code]` 仍按代号查表（装配 Insertable 槽优先）。
4. **按卡种装配词条行**（`CardInspectGlossaryAssembler`）：
   - **怪物**：检查描述抽出的 `[[词条]]`（技能，默认在前）→ 实际用到的攻击范围图标词条（正交攻击 / 斜向攻击 / 全向攻击）→ 实际用到的行动/移动计数图标词条 → `extraGlossaryTerms`。攻击模式为「无」或无活跃节奏则不写对应行。旧名 `普通近战` / `斜角近战` / `全向近战` 与新名互为别名去重。
   - **道具 / 遗物**：首条 = 表现层 `displayName` + 策划效果正文（`inspect_effect_copy.json`，缺则回退检查描述）→ 检查描述里出现的 `[code]` 图标词条 → 追加词条。不把 `[[文字词条]]` 拆成独立行。
   - **机关**：同道具，但若有行动/移动计数，插在首条之后、描述图标之前。
5. **图标词条常驻列表**：有图标的词条行标题为 `[code]` + 展示名，正文为词条介绍；无图标则只显示名称。不把攻 / 甲 / 血、技能同步触发自动塞进怪物列表。
6. **无词条时效果区可空白**，不回退旧堆砌，也不留 hover 占位提示。
7. **词条编辑入口**为表现层配置编辑器左侧顶层「词条」；内联图标与文字词条同一张项目级表（升格自 `CardFaceDescriptionIconCatalog`）。
8. **卡级词条配置栏位**：每张卡的「词条配置（右键详情）」栏。**基础填充**（怪物）= 检查描述里 `[[词条]]` 自动抽取（只读展示，不落盘）；**追加** = 搜索词条表选入的隐藏词条，落 JSON `extraGlossaryTerms`。与已装行重名一律去重；未命中词条表的名称仍出名字行（`Matched=false`）。检查描述是珍贵空间；「常规怪物」这类普适词条走追加，不写进每张怪的描述。
9. **策划文案权威**：共享词条 / 技能介绍以策划文档为准覆盖 AI 草稿；卡专属首条正文以策划「效果」行为准（不用「文本描述」简化句），落 `inspect_effect_copy.json`（键 = contentId）。行标题以表现层 `displayName` 为准。

## 为什么

旧详述把效果原子 / 模板 `design_text` 一股脑塞进单个 TMP，玩家读的是程序语言拼装；ADR-0037 初版改成词条行后，图标词条又藏进 hover，道具卡检查描述往往只有 `[HP]` 没有 `[[ ]]`，详情栏几乎空白。玩家反馈要直接展示：技能、范围、计数和描述里用到的图标都应落在词条列表里。

## 后果

- `CardInspectDetailComposer` 的 SkillDetails / design_text 路径退出玩家右键 UI（背景介绍 / 牌组介绍仍可保留）。
- `CardInspectIconHover` 与词条栏首行 hover 槽废除；`inspect.hover_hint` 等 UI 键删除。
- ADR-0009 §5「`[code]` 仅 Inspect hover」修订为本决策的常驻列表规则；`CONTEXT.md`「详细描述」「描述方括号引用」「词条」同步。
- 描述格计量：`[[…]]` 与 `[…]` 各计 1 格（卡面仍如此）。
- 内核 `AttackPatternRules.Token*`（普通近战 / 斜角近战 / 全向近战）不改；玩家可见攻击范围词条名为正交攻击 / 斜向攻击 / 全向攻击。
- 卡专属效果正文不进项目级词条表，避免 `[[暴力]]` 误匹配单卡效果。
