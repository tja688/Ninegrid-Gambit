# 右键详述权威改为词条行

## 决策

1. **右键详情「详细效果」区只展示词条行**，从该卡**检查描述**中的 `[[展示名]]` 按出现顺序抽出（去重保序），动态装入 ScrollView 多行；**不再**拼接效果模板 `design_text` / 局内挂载效果文案。
2. **双语法**：`[[展示名]]` = 显式文字词条（卡面去括号显示，可着色；默认进详情列表）；`[code]` = 内联图标（卡面换 sprite；默认**不**进详情列表）。
3. **匹配键**：`[[…]]` 与词条表 `displayNameZh`（名字）**精确匹配**；`[code]` 仍按代号查表（装配 Insertable 槽优先）。
4. **图标词条解释**：仅在右键详述的**卡面预览**上 hover 图标时，填入一条可复用临时解释槽；移出清空。战斗内场上卡面不挂此行为。解释槽恒在词条栏**首行**——列表可滚动，落末尾时词条一多就滚出视野。
   覆盖两类图标（补记 2026-08-13）：
   - **描述内联 `[code]` sprite**：按代号查词条表。
   - **卡面机制图标**：攻击 / 护甲 / 血量伴随图标、倒计时图标（语义按卡级节奏源在行动计数 / 移动计数间切换）、攻击模式图标（按 `AttackPattern` 给对应近战词条；模式为「无」而挂同步技能时该槽升格为同步子图标）、是否有技能同步触发子图标。靶表由 `CardFaceIconGlossaryTargets` 登记，词条查询键是词条名（`displayNameZh`），攻击模式与节奏源直接复用 Core token 常量。
   
   卡面图标**不长命中体、不进 `PointerHitRegistry`**：命中按世界 AABB 包含指针计算，多个相交取面积最小者；显隐随投影变化的槽命中时按 `renderer.enabled` 复核——**图标看得见才解释**。
5. **无 `[[词条]]`** 时效果区可空白（保留首行 hover 提示槽），不回退旧堆砌。
6. **词条编辑入口**为表现层配置编辑器左侧顶层「词条」；内联图标与文字词条同一张项目级表（升格自 `CardFaceDescriptionIconCatalog`）。

## 为什么

旧详述把效果原子 / 模板 `design_text` 一股脑塞进单个 TMP，玩家读的是程序语言拼装，而非共享机制语汇；与 ADR-0009「词条是项目级共享语汇」脱节。检查描述已是卡级人手概括，用 `[[词条]]` 显式点名需要解释的机制，详情与卡面不可能脱节。

## 后果

- `CardInspectDetailComposer` 的 SkillDetails / design_text 路径退出玩家右键 UI（背景介绍 / 牌组介绍仍可保留）。
- ADR-0009 §5「同一方括号码两种展开」修订为双语法；`CONTEXT.md`「详细描述」「描述方括号引用」同步。
- 描述格计量：`[[…]]` 与 `[…]` 各计 1 格。
- 词条表须覆盖卡面上每个机制图标的语义，否则 hover 只能显示「（未配置词条介绍）」。「技能同步触发」为此新增（2026-08-13）。
- 玩家不再需要把全部图标词条堆进词条栏：重复与无效信息留在 hover 里按需取用。
