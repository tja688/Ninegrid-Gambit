## 读写约定

- **写** → `NineGridArchitecture.Interface.SendCommand(...)`
- **读** → `SendQuery` / `GetSystem<T>()` 只读 API
- **下→上** → struct Event（多数在 `Flow/Presentation/`）或 BindableProperty
- **编排** → `PresentationDirector` / `BattleTimeline` / `IPresentChannel`（普通 C# 深模块，由 System 持有）
- **先手还击** → `AttackIntentScriptFactory` 入队前经 `IPhaseSystem.MonsterStrikesFirst`（或 `MonsterStrikesFirstQuery`）裁决；Present 通道按攻方角色选择（Hit=玩家打怪，Counter=怪打玩家），先手还击只交换入队顺序，不改通道语义。**反击批入队前另查 `RuleId.CounterAttackBanned`**（远程武器：不先手也不反击，反击动作整批跳过；齐射走 `EnemyActionPhaseScheduler` 不受影响）
- **命中批盘面 delta** → `FieldBattlePresentationExecutor` 在 lunge 后 `Drain` 同批 OnBattle 步骤。**[ADR-0044](../adr/0044-battle-window-deferred-board-motion.md) 后**：交战窗内效果 DSL 的旋转/换位/移格在 Core 侧挂起（`BattleScopeSystem.TryDeferBoardMotion`），命中/反击批常态**不再含**效果位移——它们延至互动计数批（或齐射收尾批）落地，观感为「打 → 挨反击 → 盘面转」。命中批 Drain 与尸体处理机制保留为防御：主目标**存活**时正常重放位移（Vacate 前 Drain）；主目标**已死**时先 MarkFieldDead + Vacate + 离锚、再 Drain（`ForHitPresentDrain(stripVictimMotion)` 剥离尸体 Move/Swap）。主目标尸体 Remove 照旧剥离，走 Vacate/FinalizeLethal。中间 Drain 的 `drainAfter` 占格断言豁免「待 Vacate 主目标」(`C0/Puid`)；Drain 后 `AssertHitPresentOccupancySync` 做最终断言。Fill/Rotate 仍属击杀后剧本。漏 Drain 或真 desync 仍会 `OccupancyDesyncLatched`
- **九宫格互动计数** → `IPhaseSystem.AdvanceInteractionCount` 与盘面稳定化/旋转分步；攻击/探索剧本在稳定化前推进计数，用道具路径不调用（ADR-0012 / #75）。**ADR-0044**：互动计数批是交战挂起位移的落地锚点（先落位移再 +1 计数），其盘面 delta 经既有 `EnqueueInteractionAdvanceBatch` 投影呈现；齐射侧锚点在 `ResolveEnemyActionFinale`，道具侧在 `ExecuteUseItem` 收尾
- **盘面稳定化 / 补牌** → Core `IBoardStabilizationSystem` 的 `NeedsRefill` 与 `ResolveNextSlice` 是唯一欠补位/补牌裁决；Flow `BoardStabilizationScheduler` 在每轮 Present ack 后重新检查并逐轮推进。融合/重组结果的 `deferRefill` 由 Core 临时排除并在稳定后恢复，旧 `DrainRefill` / `FusionRefill` 专用表现路径已删除。
- **敌方行动阶段** → `RegisterEnemyActionPhase` / `ResolveNextEnemyAction` / `ResolveEnemyActionFinale` 分拍；**ADR-0038 / #184**：仅节奏源=行动的卡在报名链 −1；移动源在换格推进归零后由报名收走；开火窗同拍单向打击 + `OpenCardRhythmFireWindow`（`OnCardRhythmFire` 同步技能）。导演仍由 `EnemyActionPhaseScheduler` 挂攻击/探索剧本末尾（`ActionCountdownChanged` → Settled → `UpdateActionCount`）（ADR-0012 / #81）。**齐射开拍门禁**：`EnemyActionPhaseScheduler.HasParticipatingEnemy` 与 Core 报名同谓词——盘面 **Monster 或 Trap** + 正面 + 活跃节奏；纯机关场（教学阶段3）也须开拍，不得仅因无 Monster 跳过。**斜角近战 Present**：Core 对角合法开火后走既有 Counter 通道；`CardAttackBasicAdapter` 放开对角门禁，场景无对角 Timeline 时相对冲刺回退四向 rig（玩家主动开战仍只正交）
- **行动倒计时上卡面** → Core `ActionCountdownChanged`（`ResultValue`=剩余）经 `PresentationEventMap` Settled → `CardFaceStatHandler` Commit `ActionCount`；禁止 View 队列外直读 Counters（ADR-0005 / #81）。`Action_Icon` 节点名候选含「攻击模式」；`Sync_Rhythm_Icon`↔「是否有技能同步触发」；矩阵见 ADR-0038。**临时接线**：`CardFaceAttackPatternIconResolver` + `CardFacePresentationBinder.ApplyRhythmIconMatrix` 已按局内怪物 `AttackPattern`（Core 投影）切换攻击模式槽图标（`1786242411378_d` 子 Sprite：正交 / 全向 / 斜角三档）；倒计时类型图标由 `ApplyRhythmCountIcon` 按 JSON `rhythmSource` 换成词条「行动计数 / 移动计数」Sprite（机关模板默认移动计数，怪物模板默认行动计数）。
- **效果倒计时 UI（ADR-0035 / #156）** → 效果触发器（`OnSelfMove`/`OnInteract`/`OnCumulative`，DSL `projectKey`）推进计数器后由 `CommitEffectCountdownRemainingAction` 广播 `EffectCountdownChanged`（`ResultValue`=剩余、`Message`=令牌键）→ `PresentationEventMap` Settled → `CardFaceStatHandler` → **机关** `CoreCardPresentationMapper.CommitCountdownRemaining` 写 `CommittedCountdownRemaining` + `ActionCount`/`ShowActionCount`（`EffectCountdownProjection`）；**遗物** `SourceDefId=relic.*` 优先路由 `RelicHudHook.CommitCountdownRemaining` 刷新图标「计数」TMP。描述保持静态。禁止 View 直读 Core 计数器（ADR-0005 / ADR-0035）
- **稀有度上卡面** → JSON `rarity` 经 `CoreCardPresentationMapper.TryApplyJsonPresentation` 投影为 `CardPresentationSnapshot.Rarity`（`ContentRarity`；解析失败 = `None`），与既有 `FrameColor` 稀有度染色并行；快照克隆路径（翻面 `CardFaceFlipBeatHandler` / 检视 `CardInspectOverlayPresenter` / 数值提交 `CardFaceStatHandler` / 倒计时提交 `CoreCardPresentationMapper.CloneForCountdownCommit` / 作弊预览 `BattleSessionCheat`）均透传 `Rarity`；`CardFacePresentationBinder.ApplyRarityVariants` 两组变体：①「卡框 / 横幅」槽节点下「白 / 蓝 / 金」子变体（当前仅 `遗物卡标准模版.prefab`）——White→白、Blue→蓝、Gold→金，**Red（独特）暂无专属美术兜底金档**，None/未知兜底白档；②道具卡副图标（ADR-0033 修订 2026-08-13）——「副Icon」节点下「高常规 / 中常规 / 低常规 / 特殊」档位子对象（当前仅 `道具卡标准模版.prefab`）按 White→高常规、Blue→中常规、Gold→低常规、Red→特殊单选激活，None 整组隐藏；编辑器卡面预览经 `CardFacePreviewRequest.Rarity` 同语义。模板无变体子节点时 no-op，其余 Kind 模板不受影响

- **处理器** `IBattleBeatHandler`：`CardFaceStatHandler` 只从指令赋值 → `ManagedCard.CommitPresentation`（含 `OfferReward` 按 DefId 匹配 Bounce 负 uid 卡；`MaxHp` 取 `RemainingHp` 作当前血；`UpdateHp` 顺带提交同事件 `RemainingArmor`；`ModifyBaseStat(Armor)` **不**写卡面甲；`UpdateArmor`/`UpdateHp` 找不到卡或无 View 时 `LogWarning`）；`PlayerInfoHudBeatHandler` 对 Avatar 血甲旁路写 HUD（`MaxHp` 走 `ApplyHpAndMaxHp(RemainingHp, ResultValue)`；`ModifyBaseStat(Armor)` 写基础/有效甲 HUD；return false 留给卡面认领）；装饰 `DamageFloaterBeatHandler` / `EffectTriggerPulseBeatHandler` / `GoldGainBeatHandler` 均在 Impact 消费飘字、FX、金币（金币 #198 由 Settled 改至 Impact，尸体 Vacate 前保出生点；击杀/移除赏金与拾取加金在 `GoldModified` 写 `CardUid`），不占主线 ack；数值 Commit 后 `CardFacePresentationBinder` 可对配对图标做非阻塞缩放装饰（不占 ack）
  - **飘字**：`DamageFloaterBeatHandler` 须排在 `CardFaceStatHandler` 之前——`ShowDamage` 在 Impact 认领（return true）；对 `Healed` 的 `UpdateHp` 只旁路飘绿色治疗字（取 `Delta` 实际生效量）并 return false，否则 UpdateHp 已被卡面处理器认领、治疗飘字收不到指令；对 `ArmorChanged` 增甲的 `UpdateArmor` 旁路飘绿灰护甲字（取 `Delta`，复用 `ArmorDamage` 色）并 return false（卡面 CurrentArmor 专用，不写 HUD 基础护甲；减甲仍只走 `ShowDamage` 拆分甲伤，避免与负 Delta 双轨）。显示模式经 `DamageFloaterBeatHandler.DisplayMode` 内部切换（预留 UI 接线）：`SplitDamage`（默认）按 `DamageDealt` 的 `WithDamageSplit(armorDamage, hpLoss)` 拆分量（甲吸收含金甲代偿；IgnoreArmor 时甲伤为 0）分别飘血量红字（`HpDamage`）与护甲绿灰字（`ArmorDamage`），血/甲两字各带随机抖动免重叠；`TotalDamage` 飘 `DamageDealt.Amount` 白色总伤害（旧逻辑）。动态表现收口在 `DamageNumberManagerSingleton`：按 `DamageNumberKind` 映射颜色（总伤害白 / 治疗绿 / 血伤 `#CB3834` / 甲伤 `#5E7E74`）；数值在 `[scaleFromNumber=1, scaleToNumber=25]` 线性映射 1x~2x（区间依内容分布：日常单发 1~10，精英/Boss 与成长叠伤可达 15~25），时长同步插值 `[baseLifetime=0.8s, maxLifetime=1.6s]`；拆分飘字走独立收窄区间 `[splitScaleToNumber=12]` 与稍长时长 `[splitBaseLifetime=0.9s, splitMaxLifetime=1.7s]`（补偿拆分数值变小）、抖动半径 `splitJitterRadius=0.35`。每次生成显式 `SetColor`（防对象池颜色残留）；Spawn 后同步设置即可生效（插件下一帧 Restart/Start 才拷 lifetime、UpdateText 每帧重算 numberScale）
  - **护甲显示**：卡面甲 = 当前护甲（只认 `ArmorChanged` / 生成类 `RemainingArmor` / `BaseStatModified(CurrentArmor)`；**禁止**用 `ModifyBaseStat(Armor)` 的基础甲 `ResultValue` 写卡面）；玩家信息 HUD 甲 = 有效/基础护甲（`ModifyBaseStat(Armor)` 只驱动 HUD）。Core：`ModifyBaseStat(Armor)` 按实际基础变化量同步 `CurrentArmor` 并追加 `ArmorChanged`；节点开战 `ResetCurrentArmor` 在 `FillEmptySlots`（`AvatarAppeared`）之前，值变化时亦发 `ArmorChanged`。UI 文案用「护甲」不写「防御」（「防御」仅 `ContentRole` 投放粗轴）。标准伤害公式 / 伤害减免 / 无视护甲见 [ADR-0028](../adr/0028-damage-formula-armor-and-reduction.md)
- **统一冲刷** `BattleBeatFlush.FlushBeats`（Impact→Settled）：`PresentStep` 就位回执前调用；非锁步（房间/选择/拾取）走 `PresentEventLogSlice`；Bounce spawn 后走 `PresentLatestEventOfType(RewardOffered)`（单条 PresentStandalone）
- **翻牌门控** `FlipPlaybackCoordinator`：Handler 入队串行 `PlayFlipAsync`；`BattleBeatScheduler.FlushUpdateFaceUp` / `BattleBeatFlush.FlushUpdateFaceUp` 供 `PresentStep` 在 hop 通道 `channel.Begin` 前只刷 FaceUp；战斗通道可跳过前置刷、把 FaceUp 留到 `FlushBeats`；Idle 门控在 Begin 与 ack 两侧（ADR-0016）
- **生成绝对值** `CardFaceEventValues.WithFaceAbsolutes`：`CardSpawned` / 带 uid 的 `CardDealt` / `AvatarAppeared` 写入造卡/发牌时攻甲血；攻取 `GetFaceAttack`（有效攻，**怪物另加 `EnemyAttackDelta` 规则**——龙鳞甲全场-1、邻接光环+1 等；`PhaseSystem.GetAttackDamage` 直接复用同一函数，显示与结算单一口径）
- **统一对账缝**（[ADR-0045](../adr/0045-unified-card-face-stat-projection.md)，Core 侧自动 diff-emit）：`ActionPipelineSystem.ResolveAction` 在每个动作（含嵌套触发/FollowUp）自身事件入日志后调用 `CardFaceReconciliation.ReconcileAfterAction`——`CardFaceLedgerModel` 按表现层消费语义从事件日志学习「已投影值」，对盘面九格 + Avatar 用结算同源 oracle（攻=`GetFaceAttack`；玩家攻=`GetProjectedPlayerBattleAttack` 下一击投影，含 `DamageMultiplier`/`DamageFlatDelta`、Once 消耗后自动回退；甲=`GetCurrentArmor`；血=基础血；倒计时=`AttackPatternCountdown`）重算并 diff，有差才追加绝对值提交事件（`BaseStatModified`/`ActionCountdownChanged`，`Cause=faceReconcile`，沿用 Settled 锚点、紧邻因果动作）。任何新增数值源（遗物/技能/原子/规则装卸/拓扑变更）**零手工接线**；旧 `Append*FaceCommit` 补扫家族已删除（清单见 ADR-0045）。**`ModifyBaseStat` 模板原子的 Attack 分支仍须提交 `GetFaceAttack` 而非基础值**（持有区卡不在对账范围，主事件必须自带正确绝对值）；命中帧血甲仍由交战动作显式发 Impact 事件，对账缝只补漏不抢拍；表现层继续不对账、不直读 Core。回归护栏：`CardFaceReconciliationRegressionTests`（含随机动作风暴不变量：事件重放卡面值==oracle）

- **开局引导** `Flow/Presentation/CardFaceGenerationBootstrap`：非锁步 Opening 从事件日志按序重放生成类指令 **与同切片 Impact 卡面数值**（`ArmorChanged`/`HpChanged`/`Healed`/`BaseStatModified`/`CardKilled`；生成/翻面仍限 Settled）——否则 OnNodeStart `GainArmor`（复合盔甲等）会被 `AvatarAppeared` 钉回旧甲且对账缝不再补发；BoardSelect 视图重 Spawn 用 `ApplyFaceHistoryForUid` 重放该 uid 全量数值指令
- **报点（ADR-0048 两相 Impact + ADR-0050 效果打击）**：攻击/反击命中帧 → `FlushImpactExcept(TriggerEffect)`（命中飘字/血甲即时，触发脉冲后置；**打击暂扣指令不受本锚点冲刷**）；用道具 Present：Vacate 前 `FlushImpactExcept(TriggerEffect)`（保飘字坐标）。奖励 Choice：有盘面 Drain 时先 `PresentEventLogSliceExcluding(TriggerEffect)`，Drain 后再 `PresentEventLogSliceOnly(TriggerEffect)`；空 delta 仍整批 `PresentEventLogSlice`。盘面 Drain：**首个 Remove 前** `FlushImpactExcept(TriggerEffect)`（尸体消失前飘字必须可见；无 Remove 时不再尾部兜底冲刷）。禁止在首个 Deal 前抢跑（ADR-0018）。神圣决斗惩罚帧例外：`ReleaseQuarantined + NotifyBeat(Impact)` 全量（刻意对齐决斗 rig；不含打击暂扣区）。`PresentStep`：FaceUp 先刷 → 通道（运动全部落地）→ `FlushImpactOnly(TriggerEffect)` 演触发脉冲 → 有脉冲则停 `TriggerCadenceSec`（基准 0.35s，经 `BattlePresentationSpeed` 两倍速 = 0.175s）→ **效果打击串行编排**（`EffectStrikeHook.PlayAllPendingStrikes`）→ `FlushBeats`（其余 Impact + Settled）→ 等翻牌 Idle → `TryAcknowledge`。批内可见顺序固定：**运动停稳 → 触发脉冲 → 效果打击（逐个）→ 飘字/血甲 → Settled**
- **效果打击统一表演（ADR-0050）**：场上卡造成的伤害/移除一律走「攻击动作 + 受击反馈」串行表演。归因：伤害/移除事件 `SourceDefId` → 同批更早 `EffectTriggered.Message` 匹配的持有卡 = 打击者（零 Core 改动；交战/单向打击无 SourceDefId 不入组、`skill.holy_duel` 走隔离区、离场来源如手牌炸弹降级原冲刷）。计划构建 `Flow/Presentation/EffectStrikePlan`（纯函数），编排 `Cards/Battle/EffectStrikeChoreographer`（开批经 `Evt_PresentationBatchOpened` 建计划 + 暂扣；`PlayStrikesInvolving` 在退场呈现前消费——`PresentSkillRemovedCardsAsync`、UseItem 卸尸、攻击 Present 主目标卸尸三处；`PlayAllPendingStrikes` 在 PresentStep 两相之间消费其余；**第四消费点（ADR-0050 补记 2026-08-13c/d）**：拾取与奖励 Choice 的盘面 Drain 切片经 `BattleBeatFlush.PresentEventLogSliceWithStrikesAsync` 消费，且**先开批后 Drain**——OpenBatch（打击计划构建/暂扣）先于调用方 Drain 委托执行，Drain 中的移除呈现才找得到打击组（滚石纯移除打击在拾取转盘路径不再静默降级；Choice 原 Excluding/Only 双旁路批退役））。**按卡直伤回退**：`Flow/Presentation/EffectStrikePresentationRules`——互殴打击为默认，登记效果容器 defId 即回退旧直伤冲刷（不建组、不暂扣）。**排除来源**：交战/单向打击（无 SourceDefId）、神圣决斗、骷髅融合技能（专属融合表演）、离场来源、借甲自然流失。**诊断**：打击组降级冲刷与「未播即被新批覆盖」均 Warning 级进 Console 抓取轨。打击 rig 复用 `CardAttackBasicAdapter.PlayEffectStrikeAsync`（强制相对冲刺/相对击退、不绑死亡回调、受击者将被移除时不回锚；**返回 bool**：参与者/rig 缺失静默跳过时如实上抛，编排器按降级冲刷处理），经 `IFieldBattlePresentationSystem.PlayEffectStrikePresentAsync` 暴露；装配缝 `Flow/Presentation/EffectStrikeHook`（组合根注入）。**命中反馈兜底（ADR-0050 补记 2026-08-13b）**：`CardAttackBasicDirectionRig` 把命中帧反馈（闪白 + onCombatHit）打包为可补发动作——Sequence 生成失败或被外部 `KillMotion`/`DOKill` 中途杀掉时，`PlayAsync` 末尾兜底补发并留 `命中帧未经 Timeline 触达` 告警，攻击/打击反馈永不静默丢失。**交战表演全局两倍速**：`Flow/Presentation/BattlePresentationSpeed.CombatMultiplier = 2`（rig Sequence timeScale / 兜底延迟 / TriggerCadence 单点调速；卡面受击闪白等 SO 资产时长未缩放，见 ADR-0050 已知限制）
