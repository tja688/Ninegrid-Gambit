# 卡面数值锚点排期

## 一、根因（不是"接线断了"）

三条独立的错叠在一起，缺一不会有现在的现象：

1. **Core 核先行**：`CoreCommandDispatcher.Send` 调 `ActionPipeline.RunToCompletion()`，一个 Command 进去，本拍动作加所有连锁触发全部算完才 `OpenBatch`。表演开始播时 Core 里已是终值。
2. **卡面直读 Core**：`CoreCardPresentationMapper.TryRead` 用 `GetModel<CardRegistry>()` + `IStatSystem.GetEffectiveInt`。配合第 1 条，它在物理上**不可能**取到中间值。
3. **提交时机各写各的**：同一批里，受害者护甲走命中帧（`FieldBattlePresentationExecutor.ApplyHitFrameVisuals`，时机对、取值错），石头爱好者的攻击 +1 走解算时刻（`CoreBatchProjectionCoordinator.OnAttackHitBatchProjected` 第 540 行同步调 `PresentEffectTriggersFromEventLog` → `TrySyncStoneLoverCardPresentation`，动画还没开始播）。这就是"抬手就涨"。

JSON 那条是第四个独立问题：`CoreCardPresentationMapper.TryApplyJsonPresentation` 在 `dto.stats.attack > 0` 时用静态 JSON 盖掉刚读出的战中值，把卡面钉回出生值。

## 二、既有资产（不用发明）

- `PresentationEventMap` 已登记 38 个流程节点，带 `InstructionKind` / `RequiresPlayback` / `LocksInput`。它就是"全局 hooks 节点表"。
- `PresentationBatch.Instructions` 每批都在生产，带 `Sequence`。全仓**没有任何表现层运行时代码消费过它**。
- `CoreGameEvent` 已带 `RemainingHp` / `RemainingArmor`，是**结算后绝对值**，不是增量。
- `CardAttackBasicAdapter` 的三个 `Play*Async` 重载已带 `Action onCombatHit`，攻击/反击报点零成本。
- `PresentationEventMap.FindMissingCoreEvents()` 是现成的穷尽性检查套路。

## 三、设计决策（这一节是给下一票 AI 的意图基石）

### D1 显示值只来自指令，永不读 Core

卡面显示值的唯一来源是排期器交来的指令，指令携带结算后绝对值，卡面做**赋值**不做累加。因此不存在影子状态，不会累积漂移。

### D2 不做兜底、不做强制对账

漏接就让它错着，明晃晃地错。穷尽性靠**测试期**保证（每个 `CoreEventType` 必须有显式 `Beat` 归属），不靠运行时补救。诊断只报不改：`Settled` 后若仍有未消费指令，`Debug.LogError` + `Debug.Assert`，值一动不动。

### D3 锚点表并进 Core 的 `PresentationEventMap`，不新建第二张表

`PresentationEventMap` 本来就是 Core 持有的表演契约表（`LocksInput` 直接决定 `RequiresAcknowledgement`）。加一列 `Beat` 后，一行看完一个事件的完整表演契约，穷尽性免费。代价：`PresentationBeat` 枚举住在 `NineGrid.Core`，表演层加节拍要改 Core。已接受。

### D4 v1 只有三个锚点

- `Impact` — 攻击/反击的现成 `onCombatHit`
- `Settled` — `PresentStep` 通道完成后、`TryAcknowledge` 之前（四条剧本通用）
- `None` — 显式声明不上卡面，也算归属，但要写理由

零动画方法签名改动。**升级路径写进 `PresentationBeat` 的注释**：若观感上"攻击涨得太晚"，加 `PostImpact`，在 `onCombatHit` 内延时后二次报点即可，不需要重构排期器。

### D5 数值只分两层，"定义值路径"这个概念不存在

- **权威值**：Core 此刻的真相，含跨战斗持久的 run 级修正
- **卡面显示值**：玩家看到的，由指令流在锚点驱动，**有意滞后于权威值**

JSON 的 `stats` 降级为纯内容作者输入，经 `CardPresentationBusinessOverlay.ApplyToCatalog` 一次性进 Catalog 给 Core 造卡用，**表现层从此不读它**。

依据：一张"每打出一次全局伤害 +1"的卡，预览时显示出生值就是错的。所以展示卡走定义值这条路从根上不成立，全世界只有一条路。

### D6 提交是瞬时的，跳字是装饰

沿用 `CONTEXT.md` 既有教义（`_Avoid_: 用 digit animate 代替提交时机`）。锚点处赋值瞬时完成，任何数字滚动/回弹是旁路装饰道的事，不占主线、不参与 ack。

### D7 无 uid 展示卡：本票不动，但路已探明

真正无 uid 的只有 Bounce 三选一（奖励/商店/属性）。`RewardEntry` 在 Core 里已是实体，`RewardOffered` 已是正式指令。下一票给 `RewardEntry` 补投影数值即可走同一条路，`ApplyVisualsByDefId` 随之删除，**不需要"合成批次"这种特例**。

遗留内容设计题（不影响架构）：玩家还没拿到的奖励卡，该显示定义值还是"拿了就是"的当前值。算法在 Core，两种都支持。
